# M129 — Re-publish shared texture atlases

## Контракт

- **Reuse** существующего варианта `(atlas_key, width, height)` никогда не загружает новый Image Asset в Roblox. Все потребители одного варианта используют один действующий `published_id`.
- **Republish** изменённых байтов того же варианта — новая публикация изображения. Старый Roblox Image Asset ID не переиспользуется и не перезаписывается; Open Cloud выдаёт другой ID. Если точно такие же новые байты уже опубликованы под единственным подтверждённым ID, реестр использует эту готовую публикацию без дублирующей загрузки.
- Вариант идентифицируется семейством и разрешением, **не** именем модели. При Republish обновляются все его потребители, включая Location Assets и Real Estate.
- Само имя файла остаётся `<atlas_key>_<width>x<height>_atlas.png` (или JPEG). Система проверяет фактический размер изображения.

## Транзакционность и история

- `texture_atlas_replacements` — таблица подготовленных версий. Во время staging действующий ID, SHA, путь и привязки **не меняются**.
- Новые байты кладутся в неизменяемую папку `assets/source/texture-atlases/<family>/<resolution>/revisions/<sha256>/`. Предыдущий файл не перезаписывается.
- `texture_atlas_pending_uploads` регистрирует попытку **до** вызова Open Cloud. Если ответ неоднозначен, повторная загрузка заблокирована до ручной сверки операции.
- После успешного ответа активные `source_sha256`, `published_id` меняются одной транзакцией. Предыдущий ID и SHA остаются в `texture_atlas_publications`; revision всех общих bindings увеличивается, Studio Sync требуется заново.
- Ошибка Studio Sync не отменяет успешную публикацию. Интерфейс показывает ожидание синхронизации и её причину.
- Повторный выбор файла с идентичными байтами **не** вызывает новую публикацию.

## Авторский процесс

1. Открыть Location Assets, выбрать зарегистрированную модель через **edit**.
2. Нажать **choose PNG/JPG**, указать изменённый файл с тем же стандартным именем семейства/разрешения.
3. Вместо `own / new` автоматически выбирается зарегистрированный variant; кнопка становится **Republish atlas · new Roblox ID**.
4. Подтвердить изменение **всех** моделей, использующих этот вариант. Новый ID появится после успешной публикации, затем запускается Studio Sync для затронутых Location Assets и домов.
5. При недоступной Studio повторить Sync без новой загрузки изображения.

Скрипты миграции старых несовпадающих имен отсутствуют: текущие legacy публикации не изменяются. Копию `.control-center/game1.db` сохранить до применения патча и первого запуска Control Center.
