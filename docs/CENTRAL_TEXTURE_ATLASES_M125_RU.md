# M125 · Central Texture Atlas Registry (Location Assets adapter)

Основание: `game1_diag_2026-10-23_12-22-59.zip` и Atlas Registry ТЗ v2.

## Реализовано

- Общая SQLite-модель `texture_atlas_families`, `texture_atlas_variants`, `texture_atlas_publications`, `texture_atlas_bindings` по `(consumer_type,consumer_id)` и история `texture_atlas_legacy_publications`. Код не зависит от того, как называется модель-владелец: опубликованный Image Asset ID принадлежит **варианту**, а не его потребителям.
- Новый источник `<atlas_key>_<width>x<height>_atlas.png` / `.jpg` / `.jpeg`. Размер сверяется с фактическими пикселями; исходное имя сохраняется. `atlas_key` может содержать подчеркивания, цифры, пробелы и Unicode. Устаревшие имена сохраняются и помечаются ⚠️.
- Источники новых атласов: `assets/source/texture-atlases/<atlas_key>/<width>x<height>/<filename>`; повторный импорт того же SHA256 идемпотентен, конфликт разных пикселей при той же семье и разрешении не перезаписывается.
- Регистрировать вариант можно независимо от модели. Выбирать/публиковать вариант — из Asset Manager. Подключение двух моделей к одному опубликованному варианту **не делает новую Image-публикацию**. Новая публикация выполняется только если байты ещё не имеют единого опубликованного ID.
- Перед новым upload фиксируется запись в `texture_atlas_pending_uploads`. Если Roblox ответил неоднозначно/процесс оборвался, повторный автоматический upload блокируется до ручного разбора операции.
- В Location Assets удалён `location-asset-rail`. В библиотеке под `deco-texture-filename`: точки золото → фиолетовый → синий → зелёный → серый, сортировка по `width*height`, текущий вариант выделен; дополнительные варианты доступны через `+N`. Поиск атласа вместо выбора модели-владельца. Старый owner-based reuse оставлен **только для обратной совместимости**.
- Нажатие опубликованной точки: оптимистичная смена binding → экспорт прежнего runtime-контракта → адресный Studio Bridge schema 2 `targetSlug`/`bindingRevision` → текстуры на всех `Workspace`-моделях с атрибутом `Game1DecoAssetSlug` и на уже существующих managed ServerStorage-моделях. Не клонирует модели и не изменяет их CFrame, Scale, Asset IDs.
- Студийная ошибка оставляет привязку `pending_studio_sync`, появляется Retry. Подтверждение старой ревизии не закрывает новую. Обычный `Sync Studio` без target по-прежнему работает по schema 1.

## Важно о миграции legacy

1. Миграция **аддитивная**: создаёт новые таблицы и индексирует старую историю; не удаляет файлы и не заменяет ни один существующий Image/Model Asset ID. Существующие `texture_reference_slug` и runtime-экспорт работают до явного перевода модели на атласный variant.
2. Старые имена не сообщают физического разрешения, а диагностический дамп не содержит сами исходные изображения. Поэтому **нет автоматической миграции всех старых ассетов на новые варианты**. Исторические Image Asset IDs сохранены, а конфликтные группы (например, `wooden_post_kit.png` с одним SHA256, но разными Image IDs) остаются требующими ручной проверки: новый upload в такой группе блокируется.
3. Без подтверждённого выбора валидного канонического ID нельзя объявить подобный конфликт решённым и автоматически менять уже размещённые модели. Для этих старых групп сначала необходимо проверить Image IDs и выбрать каноническую публикацию; M125 не предлагает автоматическое угадывание.
4. Замену пикселей *того же family+resolution* нужно проводить отдельной явной версионированной процедурой; M125 безопасно отклоняет неявное перезаписывание уже зарегистрированного варианта.
5. Новый алгоритм изменения TextureID/SurfaceAppearance требует установить обновлённый Studio-плагин; выполнение в настоящем Roblox Studio Edit/Play подлежит ручному smoke-test.

## Резервная копия и откат

Перед запуском после применения патча при остановленном Host Agent сохранить `.control-center/game1.db`, `assets/manifests/location-assets.json` и `src/shared/world/LocationAssetRegistry.luau` в отдельный каталог с датой. Патч можно откатить `git apply -R` (при отсутствии последующих коммитов/правок), а базу вернуть из *этой* копии после остановки Host Agent. Источники атласов, добавленные после резервной копии, следует отдельно экспортировать, иначе откат их привязок потеряет смысл. Нельзя восстанавливать старую SQLite-копию после длительной продукционной работы без сверки новых публикаций.
