# M94 Hotfix — Workspace-wide Location Assets / WeaponBounce по факту контакта

**База:** M94 после применения `game1_m94_revert_weapon_passthrough.patch`. Патч `game1_m94_weapon_bounce_post_contact.patch` отдельно **не устанавливать**: его функциональность включена в этот общий хотфикс.

## Почему перестал работать мирный отскок

`EnvironmentAssetService` индексировал только `Workspace.Game1DecoAssets`. Модель, перенесённая в другую папку Workspace, оставалась опубликованной Location Asset с `Game1DecoAssetSlug`, но выпадала из `GetRegisteredSnapshot()`. `WeaponEnvironmentCollision` строит фильтры только из этого реестра, поэтому не видел её в `Blockcast` / `GetPartsInPart`.

## Решение

- Единственный источник идентичности объекта — `Game1DecoAssetSlug` на Model и опубликованная запись `LocationAssetRegistry`. Расположение Model внутри Workspace не влияет на её регистрацию. `Game1DecoAssets` остаётся стандартной папкой для авторинга, но не является обязательным игровым контейнером.
- Сканирование всех потомков Workspace выполняется **один раз при старте**, далее обслуживаются `Workspace.DescendantAdded/Removing`. Для зарегистрированных моделей учитывается изменение атрибута и отписка при удалении. Объекты не регистрируются, если slug пустой, неизвестен или статус не `PUBLISHED`.
- Сервис среды сохраняет собственный индекс `model -> definition` и номер ревизии. Система оружия использует индекс, обновляя `RaycastParams/OverlapParams` только при смене ревизии; при каждой атаке Workspace полностью не сканируется.
- `WeaponEnvironmentCollision.Query` сохраняется без изменений. В активном окне HitStart/HitEnd запрос выполняется всегда. После обнаружения реального контакта `AttackService` запускает отскок **только** если у Character `InCombat ~= true` и число активных преследователей Monster/NPC равно нулю. Иначе оружие проходит через объект, не прерывая возможность наносить урон целям.
- `HostilePursuitRegistry` принадлежит серверу: каждый враг сообщает о выборе/сбросе цели; удаление и смерть очищают записи; несколько преследователей суммируются. Физический `CanCollide` оружия не меняется.

## Проверка в Studio

1. Помести опубликованный неразрушаемый Location Asset с корректным `Game1DecoAssetSlug` внутри `Workspace.Game1DecoAssets`, ударь его в мирном состоянии во время HitStart/HitEnd: должен быть отскок.
2. Перенеси модель в `Workspace.Buildings/Test/`, перезапусти Play, повтори удар: тот же отскок. Проверь также перенос во время Play.
3. Аналогичный неразрушаемый объект с вложенным MeshPart и объект с атрибутом `destructible=true`: только первый должен вызывать отскок.
4. Monster или боевой NPC преследует игрока **до нанесения первого урона**: контакт обнаруживается, но отскок подавлен.
5. Во время `InCombat=true`, включая случай без преследователей: отскок подавлен. После выхода из боя и ухода последнего преследователя отскок возвращается.
6. Удали зарегистрированную модель из Workspace и добавь обратно: реестр и фильтры обновляются, а отскок снова работает.

**Не менялись:** Weapon Volume, геометрия swept-проверки, физические свойства экипированного оружия, нанесение урона, анимационные окна, публикация FBX, Asset Manager, БД.

## Автопроверки и ограничения

`python system/verify/verify.py`; `python -W error::ResourceWarning -m unittest discover -s system/verify -p 'test_*.py' -q`. Тесты контрактов проверяют границы кода, но реальную геометрию и live-изменения иерархии Workspace необходимо проверить в Roblox Studio.

## Откат

Из корня репозитория: `git apply -R --check <patch>` и `git apply -R <patch>`. Обратное применение возвращает проект к состоянию **после исходного отката** M94.
