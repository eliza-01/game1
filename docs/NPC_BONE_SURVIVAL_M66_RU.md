# M66 · Целостность скелета NPC при публикации и загрузке в Studio

## Причина

Регистрация FBX и сборка игрового рига — разные этапы. `NpcRigFactory` после M64 сохраняет исходные кости, однако он не может восстановить `Bone`, которые не вошли в опубликованный Roblox Model Asset. У зарегистрированных 12.10.2026 NPC `guard_01` (74 кости, 62 кости с влияниями) и `warsmith` (71/59) оригинальные FBX по метаданным содержат вершины с 5 и 7 костными влияниями соответственно. До M66 временный FBX публикации лишь усиливал слабые веса и не ограничивал общее число влияний на каждой вершине.

## Разделение ответственности

- `system/asset-manager/bone_weight_survival.py`: общий, независимый от Blender алгоритм нормализации и ограничения костных влияний до четырёх. Для каждой исходной кости гарантирует ненулевое устойчивое влияние хотя бы на одну вершину или завершает обработку ошибкой. Не содержит названий конкретных NPC.
- `prepare_character_publication_fbx.py`: адаптер Blender. Обрабатывает только **временную копию** FBX, не меняет оригинальные кости, их rest transforms и иерархию, не переносит правки в исходные ассеты.
- `character_analysis.py`: после экспортирования повторно анализирует готовый FBX, отклоняя модель с превышением четырёх влияний или исчезнувшими влияниями на кости.
- `monster_store.py`: хранит версию алгоритма публикации для каждого NPC, при обновлении версии создаёт новый Roblox Model Asset ID даже при неизменном исходном FBX, не меняя другие данные NPC или его анимации.
- `host_agent.py` и `Game1Bridge.server.luau`: передают ожидаемые имена костей из зарегистрированного FBX и сверяют полный список с загруженной Roblox-моделью **до** замены шаблона в ServerStorage. При несовпадении показывают недостающие имена и не трогают старый шаблон.
- `NpcRigFactory`: остаётся без изменений, не добавляет кости в runtime и не переподчиняет их.

## Применение к существующим NPC

1. Применить M66 и обновить Control Center / Host Agent, установить Studio Bridge и перезапустить Studio для активации нового плагина.
2. В Asset Manager → NPCs выбрать **Publish** для каждого ранее зарегистрированного NPC с уведомлением о новой версии подготовки модели. Будет создан **новый** Asset ID; загружать FBX повторно не нужно, если исходный файл на месте.
3. Нажать **Sync Studio**. Успешная синхронизация означает, что список имён всех костей в опубликованной модели полностью совпадает с реестром. При ошибке исходный шаблон не заменяется.
4. Перезапустить Play и проверить штатные анимации, включая idle_special.

Важно: имеющиеся старые Roblox Model Asset ID не изменяются; публикация новой версии требует Open Cloud. Автоматические тесты гарантируют работу алгоритма на синтетических данных, а не поведение Roblox Open Cloud: окончательное подтверждение — **Sync Studio** с подсчётом фактических `Bone` в загруженной модели.
