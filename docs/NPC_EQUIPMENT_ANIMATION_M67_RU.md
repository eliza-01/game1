# M67 · NPC Equipment & Animation Subtypes

## Разделение ответственности

- **NpcEquipmentStore** — отдельная таблица `npc_loadouts` в NPC SQLite, ссылки на оружие по slug. Не изменяет модель NPC, оружие, публикацию или анимацию. Экспортирует `assets/manifests/npc-equipment.json` и `src/shared/npc/NpcEquipmentRegistry.luau`.
- **NpcEquipmentService** — читает loadout при создании NPC, создаёт для каждой руки визуальную модель через общий Character/NPC `WeaponEquipService.EquipVisual`. Не наделяет NPC боевым AI или бонусами статов игрока.
- **WeaponAttachmentController** — один клиентский solver для Character и NPC; обновляет положение моделей, используя оригинальные `Weapon_R_Bone` / `Weapon_L_Bone`. Нет добавления искусственных костей. `disarm` скрывает видимые части **только для клиентской презентации**, сохраняя loadout и игровые asset references.
- **NpcAnimationTaxonomy** — имена/типы `base`, `1hs`, `2hs`, `bow`; профиль задаётся для каждой записи, а не для NPC целиком. Если в Character `WeaponRegistry.attackMovementByType` добавляется новый animationSet, расширение допустимых NPC типов производится в одной таблице таксономии, а не по slug NPC.
- **NpcIdlePresentation** — запускает/заканчивает special, выставляет `NpcWeaponDisarmed`; `Stop` восстанавливает экипировку даже при смерти/выходе из мирного состояния. Взвешенный выбор остаётся прежним.
- **NpcAnimationTracks** — базовые клипы доступны всем оружейным подтипам; совместимые `base` specials участвуют в weighted choice; death приоритетно универсален.

## Контракт названия

`<npc_slug>_<type>_<slot>[_variant].rbxm[x]`: например `guard_01_base_idle_special_01.rbxm` или `guard_01_1hs_combat_idle.rbxm`.

При сканировании старые `guard_01_1hs_idle.rbxm` и имена без явно указанного типа остаются `1hs` (обратная совместимость). UI позволяет сменить subtype; ожидаемое имя рассчитывается автоматически. Сервер строго проверяет, что **имя и тип согласованы**, иначе возвращает конкретное ожидаемое имя.

Полная миграция сохраняет IDs клипа и привязки, `weight`, `disarm`, Roblox `asset_id`, SHA, ревизию и историю публикаций. Меняется координата `(NPC,weapon_set,slot,variant)` и локальное имя источника. Если текущая папка сканирования всё ещё содержит исходный файл с тем же SHA, он также переименовывается, чтобы повторный scan не восстановил старую категорию. Повторная публикация не нужна, если содержимое не менялось.

## Правила экипировки

- `right` / `left`: независимые слоты, пустое значение означает None.
- Доступны только опубликованные оружия из общего `WeaponStore`.
- Сохранение loadout не зависит от открытого Roblox Studio. Отдельная кнопка **Sync weapon templates to Studio** синхронизирует модели выбранного оружия в ServerStorage. Ошибка синхронизации не отменяет выбор оружия.
- Удаление оружия, указанного в любом NPC loadout, блокируется с указанием NPC-пользователей.
- При двух разных профилях оружия текущий анимационный set определяется **основной правой рукой**, а если она пуста — левой. Позднее отдельный dual-wield policy может использовать обе руки для выбора нового set. Обе визуальные модели следуют своим костям независимо.
- До первой настройки оружия существующий NPC продолжает использовать исторический set `1hs` для совместимости с ранее зарегистрированными анимациями.
- NPC не получает агро/атаки автоматически только из-за выданного оружия.

## Ограничения этапа

При `disarm` оружие временно скрывается в клиентской презентации. Анимация не создаёт оружие на земле, не переставляет его на пояс и не меняет слоты инвентаря. Это отдельное будущее поведение с сокетами кобуры/ножен. Внутри Play уже созданные NPC не перестраиваются динамически при изменении Asset Manager: для проверки новой экипировки перезапустите Play.

Тесты покрывают SQLite и реестры, совместимость миграций, сохранение публикации и повторное сканирование. Фактическая визуальная привязка к костям проверяется только в Roblox Studio.
