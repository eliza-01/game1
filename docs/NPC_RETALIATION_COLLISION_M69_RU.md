# M69 — реактивный NPC, возврат домой и политика физических тел

## Контракты и ответственность

- `DamageService` остается единственным серверным источником применения урона. Уведомление о **подтвержденном попадании с положительной силой атаки** (даже если защита поглотила урон) публикует отдельный `ActorDamageSignals`, ничего не зная об AI.
- `NpcCombatAIService` подписывается на это событие и только при `retaliateWhenAttacked` выбирает **игрока, нанесшего урон**. Непрошеного поиска игроков рядом больше нет. Настройки и состояние индивидуальны для каждого экземпляра NPC.
- `ActorChaseNavigator` остается единственным компонентом пути и MoveTo. Возврат домой использует его, а не телепорт по всей дистанции.
- `NpcAnimationService` показывает `run` при возвращении, не имитируя игровое `InCombat`.
- Спавнер задает исходное местоположение и направление при создании каждого экземпляра. AI запоминает `HumanoidRootPart.CFrame` после создания. Спавн с радиусом создает отдельный дом для каждого экземпляра.

## Поведение

1. Без нападения NPC стоит на месте. Пассивный (`retaliateWhenAttacked=false`) NPC не атакует даже после получения урона.
2. При положительном атакующем воздействии от игрока NPC реагирует только если агрессор находится внутри `pursuitRadiusStuds` **от места спавна**. Проверка радиуса сохраняется в течение преследования.
3. В бою сохраняются дистанция атаки, поворот к цели, видимость и серверная валидация попадания из M68. Оружейный volume NPC не используется.
4. При смерти цели задержка возврата случайно выбирается из `0, 0.5, 1.0, ..., returnDelaySeconds` (верхний предел включительно). Если цель вышла за домашний радиус, возврат начинается сразу.
5. По прибытии в пределах `0.8` studs NPC восстанавливает исходный `CFrame`, включая yaw; далее ожидает нападения. Временная остановка движения не сбрасывает выбранное оружие.
6. После повторного спавна жизненный цикл начинается заново с отдельным домом и таймерами.

## Данные / миграция

- `monster_behavior` в изолированной базе `game1_npcs.db` получает `retaliate_when_attacked` и `return_delay_seconds`. Предыдущий `aggressive` одноразово переносится в флаг ответа на агрессию; старое автоматическое обнаружение игроков отключается. `aggro_radius_studs` переиспользуется для **домашнего радиуса преследования**, без удаления старого значения.
- База `game1.db` для монстров и их поведение не меняются.
- API и реестр NPC используют `retaliateWhenAttacked`, `pursuitRadiusStuds`, `returnDelaySeconds`, `attackRadiusStuds`.
- Значение задержки: `0..600` секунд, шаг `0.5`; значение `10` означает диапазон `0..10`, а не всегда ожидание 10 секунд.

## Столкновения: важное ограничение

`ActorCollisionPolicy` централизованно назначает **физическим навигационным корням** Characters, Monsters и NPC одну коллизионную группу с взаимными физическими столкновениями и столкновениями с миром. `RootCollider`, хитбоксы и визуальные meshes не становятся физическими препятствиями. Стоящие NPC дополнительно фиксируются (`Anchored`) и поэтому не сдвигаются при толчке. При преследовании/возврате NPC снова динамический.

**Нельзя гарантировать «ни пройти друг сквозь друга, ни сдвинуть» для двух одновременно движущихся динамических тел при обычных физических столкновениях Roblox.** Для строгого инварианта нужен выделенный серверный kinematic motor с sweep/reservation и клиентским предсказанием, объединенный с Character/Monster/NPC navigation. Не заменять такое решение телепортированием каждый кадр, высокими массами или отключением физических столкновений.

## Дамп

Корневой `dump_game1_diag_no_models.bat` не включает 3D-модели, изображения, текстуры, аудио, видео, `.env.local` и типичные каталоги сторонних зависимостей. Перечень исключенных двоичных ассетов с путями, временем, размером и SHA-256 записывается в `_dump/model_files.json`. В базе `.control-center` могут оставаться пользовательские данные; перед передачей сторонним лицам проверьте содержимое.
