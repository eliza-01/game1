# M156 · Real Estate · авторский pivot при замене house FBX

## Причина

Старый точечный Sync заменял `HouseRig` в ServerStorage без выравнивания по
существующему дому. Для размещённых копий применялась матрица
`placedHouse.CFrame * templateHouse.CFrame:Inverse()`.

`MeshPart.CFrame` привязан к геометрии импортированного меша и может изменяться
после редактирования FBX (в том числе при смещении центра геометрии). Авторский
origin находится в `MeshPart:GetPivot()`, учитывающем `PivotOffset`. Позиция
модели в библиотеке сама по себе ничего не гарантирует о положении при Sync.

## Исправление

- Единая `StudioRealEstateHouseFrame` для поиска house MeshPart, вычисления
  относительных трансформаций по авторскому pivot и выравнивания рига.
- Точечная замена `house`: новый HouseRig в ServerStorage привязывается к pivot
  предыдущего; размещённые HouseRig — к pivot каждого заменяемого экземпляра.
- Полный Sync выравнивает новую сборку по старому шаблону до его замены.
- Visual и Collision Sync используют тот же pivot, а не геометрический CFrame.
- Если после `PivotTo` авторский pivot не совпадает, операция завершается ошибкой
  до уничтожения старого размещённого рига.
- Новый визуальный house закреплён (`Anchored = true`), не меняя механику двери.

## Границы проверки

Этот патч устраняет проверяемые дефекты синхронизации, но не доказывает, что
новый FBX сохранил ожидаемый авторский origin/UV и непрозрачную текстуру.
Если импортированный asset сам содержит иной origin или прозрачность в атласе,
нужна проверка самого опубликованного MeshPart в Studio.

Изменения Studio plugin требуют закрыть Studio и повторно выполнить
`system/studio-plugin/install.ps1`. Другие runtime-подсистемы не меняются.
