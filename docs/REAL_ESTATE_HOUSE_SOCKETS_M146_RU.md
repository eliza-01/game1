# M146 · Взаимодействия через пространственные сокеты Real Estate

Основа: Game1Bridge / M131—M145. Совместимый аддитивный runtime: нет новых публикаций FBX/Model/Image, нет SQLite-миграций, Studio-плагин не меняется.

## Контракт слоёв

- `src/shared/world/HouseSocketContract.luau` — список точных имён сокетов, действия, типы и радиусы по умолчанию. Единый источник данных для клиентской подсказки, сервера и Test Loadout.
- `src/server/world/HouseSocketService.luau` — учёт управляемых размещённых домов, фактических сокетов и серверная проверка взаимодействий (положение живого персонажа, радиус, cooldown). Нет полного обхода Workspace при нажатии F. Старые дома учитываются единственным проходом при старте; новые — по событиям.
- `HouseDoorService` — поворот `DoorAssembly` относительно hinge pivot, авторитет сервера. Сохраняет эталонный закрытый pivot; `Bone.Transform` не меняется.
- `HouseSocketEffects` — дым и временные Parts для сундука и навесного замка. Эти Parts не загружаются в Roblox как ассеты.
- `src/client/world/HouseSocketPromptController.luau` — единая F-подсказка: [F] «Открыть дверь»/«Закрыть дверь», «Открыть сундук», «Осмотреть замок», «Вызвать лифт». В одной круглой рамке с квадратной клавишей. Используется Roblox `ProximityPrompt` в режиме `Custom`, включая его собственное управление клавишами и LOS.
- `src/client/dev/HouseSocketDebugController.luau` + `src/server/dev/HouseSocketDebugService.luau` — только Studio: Test Loadout → HOUSE SOCKETS; проверка наличия, отдельный радиус 2—30 studs на каждый тип сокета, визуализация областей; TP к `land_spawn_01`, floor 01/02. Телепорт рассчитывает сам сервер, клиент не присылает координаты.

## Действия

| Сокет | Поведение |
|---|---|
| `door_01_handle_inside_socket` | F, открыть/закрыть единую DoorAssembly |
| `door_01_handle_outside_socket` | F, то же, другая сторона; Roblox показывает одну доступную F-подсказку по приоритету близости и видимости |
| `door_01_padlock_01_socket` | Временный Part, F, сообщение «Замок пока недоступен» |
| `chest_01_socket` | Временный Part, F, сообщение «Сундук пока недоступен» |
| `elevator_01_socket` | F в пределах заданной зоны, ответ-заглушка без передвижения платформы |
| `chimney_01_socket` | Постоянный ParticleEmitter; F не предусмотрена |
| `land_spawn_01_socket`, `house_floor_01_spawn_01_socket`, `house_floor_02_spawn_01_socket` | Только Studio TP; в игре F не показывается |
| `door_01_hinge_socket` | Служебный pivot; интерактива нет |

Заглушки не означают наличие готового сундука, замка, системы доступа или лифта. Начальные значения радиусов указаны в общем контракте и могут уточняться во время Play. Настройки отладки персональные для игрока, не записываются в Real Estate DB и недоступны в опубликованной игре.

## Что должно существовать в Workspace

Игровая сборка использует **размещённые** дома (`Game1RealEstateSlug` на корневом Model, без `Game1RealEstateTemplate = true`). Сервер не активирует подсказки внутри ServerStorage-шаблона. Новый дом должен появиться в Workspace с уже заданным атрибутом владельца шаблона.

**Важное ограничение M133**: при публикации Roblox способен удалить невзвешенные корневые Bone домашнего рига. У `house_level4_01` это, среди прочего, `chimney_01_socket`, `elevator_01_socket`, `chest_01_socket` и три spawn-сокета. Если реально загруженный Model Asset их не содержит, сервер не угадывает позиции по именам и не создаёт им фальшивые Attachment. В Output отображаются отсутствующие имена, в Test Loadout — `○`. Дочерние door handles восстанавливает действующий Studio Bridge (M133) относительно импортированного hinge. Для пропавших корневых сокетов понадобится отдельно проверенная опора/корректировка FBX импорта, без изменения весов наугад.

## Проверка в Studio

1. После `git apply` синхронизировать Rojo / запустить Play с размещённым `house_level4_01`.
2. Открыть Test Loadout → HOUSE SOCKETS; нажать REFRESH. `●` = импортированный/восстановленный реальный socket, `○` = отсутствует.
3. Включить `RANGES: ON`, выбрать отдельные радиусы 2—30 studs кнопками `−/+`; убедиться, что зоны видны только в Studio.
4. Подойти к ручке снаружи: должна быть единственная подсказка `[F] Открыть дверь`. Нажать F, проверить, что движется именно `DoorAssembly`, а текст меняется на «Закрыть дверь». Повторить с внутренней стороны.
5. Если есть сокеты `chest`, `padlock`, `elevator`, проверить F и явный ответ «пока недоступен». Для chimney — дым без взаимодействия.
6. Проверить TP на доступные spawn-сокеты. Сервер ставит персонажа на 3 studs выше точки.
7. Проверить Output `[game1][house-socket] ... missing`; при отсутствии sockets не считать блокировку ошибкой клавиши F.

## Ограничения автоматических проверок

Контрактные Python-проверки и весь набор системных unittest проверяют маршрутизацию и защитные условия. Они **не** заменяют запуск Play для физики, анимации DoorAssembly, видимости Prompt за коллайдером и сверки мировых координат FBX. Реальное число сохранённых при публикации Bone нельзя установить только по SQLite/Blender-снимку.
