# M150 — House Sockets: кастомный персонаж

Этот патч применяется **строго поверх M149**. Он исправляет интеграцию с
существующим персонажем game1 (`ControllerManager`, `RootCollider`,
`NavigationRoot`, `CustomCharacter`, `LifeState`).

- Общий `CharacterSpatialRoot` проверяет наличие живого персонажа и находит
  его корневую деталь. Для стандартного Humanoid сохраняется fallback.
- Сервер использует этот корень для проверки дистанции до сокета и Studio TP.
- Клиент game1 выбирает один ближайший доступный F-сокет из уже созданных
  сервером ProximityPrompt и посылает на сервер **ссылку на Socket**, а не
  координаты. Сервер проверяет принадлежность сокета дому, расстояние и cooldown.
- Список промптов кешируется событиями; 10-Гц обновление не сканирует Workspace.
- Реализация подъёма двери, точек петель, импортированного DoorRig/armature,
  костей и Studio Sync **не изменяется**. Неверный pivot и проблемы рига
  исправляются отдельно после подготовки FBX в Blender.
- В Studio серверное сообщение об ошибке двери показывает причину, а не только
  «Дверь недоступна».

Проверки: тесты, `system/studio-plugin/validate_luau.py`. Фактическое
поведение Studio Play следует проверить вручную: TP, видимость F, F-заглушки;
открытие двери зависит от корректной подготовки DoorRig.
