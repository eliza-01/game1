# M112 · Real Estate: произвольное число мешей

База: M111, установленный поверх дампа `game1_diag_2026-10-19_03-14-13.zip`.

## Контракт FBX

- В FBX должен присутствовать **ровно один меш `house`**. Остальные меши (`door`, `repair`, `stone_fence_01_kit`, ...) могут иметь произвольные имена и количество.
- Имена уникальны без учёта регистра и не должны содержать разделителей пути. Никакие кости, арматуры или веса не обязательны.
- Все имеющиеся кости и их rest transforms проверяются до публикации **отдельного** Model Asset для каждого меша. Общая арматура допускается, но каждый экспорт содержит её независимую копию; интерфейс показывает предупреждение.
- Анализатор, подготовка FBX, реестр и Studio Sync используют один порядок: `house` первым, затем остальные имена по алфавиту.

## Текстуры и публикация

- Каждому обнаруженному мешу соответствует строка `02 · mesh textures` и собственный Image Asset, либо ссылка Reuse на опубликованную текстуру, либо `mesh:house` для использования выбранного локального атласа дома **до регистрации**.
- Все Model Assets публикуются отдельно. Для самостоятельной публикации картинки используется scope `image:<mesh_name>`. `model` публикует только изменившиеся модели, `all` — изменившиеся модели и изображения. Прежние IDs сохраняются до успешного завершения новых операций.
- Старые регистрации остаются действительными: если в FBX только `house`/`door`, они обрабатываются как обычные два меша. При замене FBX удалённые меши исключаются из *активной* публикации и синхронизации, исторические данные публикаций остаются в SQLite.

## Studio

- Плагин получает `rigAssetIds`, `expectedMeshes`, `textures` с динамическими ключами.
- Он загружает и проверяет все риги и кости **до** замены шаблона в `ServerStorage`; при ошибке существующий шаблон не меняется.
- `HouseRig` остаётся точкой основного импорта, остальные получают `DoorRig`, `RepairRig`, `Stone_fence_01_kitRig` и т. д. Реальные ID всех Model/Image Asset сохраняются как JSON-атрибуты `Game1RigAssetIds` и `Game1TextureAssetIds`.

## Граница проверки

`verify.py`, Python regression и JavaScript syntax проверяются локально; загрузка настоящего FBX через Blender и импорт всех частей через Roblox Studio требуют проверки в редакторе. Не менялись боевые AI и механика владения недвижимостью.
