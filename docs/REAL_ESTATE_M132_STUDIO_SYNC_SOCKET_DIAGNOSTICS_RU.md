# M132 · Real Estate: восстановление Studio Sync при неполном наборе сокетов

## Почему возникает ошибка

`house_level4_01` успешно регистрируется и публикует раздельные Roblox Model Asset IDs.
Studio Sync использует `AssetService:LoadAssetAsync` и загружает опубликованные Model Assets заново. Наличие костей в исходном Blender FBX или в экземпляре, вручную импортированном в Roblox Studio, **не доказывает**, что эти кости присутствуют в экземпляре, загруженном из опубликованного Model Asset ID.

В M131 любая отсутствующая кость с суффиксом `_socket` останавливала сборку ещё до помещения шаблона в `ServerStorage`. Именно поэтому появлялась пустая папка `real_estate/<slug>/model`: транспорт создавал каталоги до проверки опубликованного ассета.

## Новый контракт

- `door_01_hinge_socket` является **обязательным Bone**, поскольку определяет pivot `DoorAssembly`. Если отсутствует — остановить Sync, сохранить существующий шаблон, вывести список костей именно загруженного Model Asset.
- Остальные `_socket` являются **опциональными для сборки геометрии**. Их отсутствие не останавливает установку шаблона, но явно отмечается как отключенная возможность взаимодействия. Никаких сокетов с выдуманными координатами не создаётся.
- Сокет положения может импортироваться как `Bone` или как обычный `Attachment`; для него проверяется точное имя. Если сокет ручки/замка присутствует, проверяется его реальная связь с hinge.
- В созданном шаблоне: `Game1RealEstateSocketContractComplete` (bool), `Game1MissingRealEstateSockets` (JSON-массив `part/socket`); в ответе Bridge: `socketContractComplete`, `missingSockets`, `rigWarnings`.
- Интерфейс Asset Manager подчёркивает неполную готовность шаблона. Условия доступности будущих игровых функций должны проверяться игровыми контроллерами отдельно.
- В случае ошибки очищаются только **созданные этим вызовом** пустые папки назначения; существующие папки или рабочие шаблоны не удаляются.

## Границы

Не меняются Roblox Model/Image IDs, пайплайн FBX, веса двери, Atlas Registry, SQLite, позиции уже размещённых домов и логика открытия двери. Не происходит публикация или перепубликация ассетов.

## Приёмка в Roblox Studio

1. Закрыть Studio, установить обновлённый Studio-плагин, открыть Studio и повторить `Sync Studio` для `house_level4_01`.
2. При наличии hinge создаётся `ServerStorage/real_estate/house_level4_01/model/house_level4_01` с `DoorAssembly` и `DoorRig`; если другие сокеты исчезли из **опубликованного** Model Asset, увидеть их в `rigWarnings` и `Game1MissingRealEstateSockets`.
3. Сравнить список Bones внутри импортированной вручную модели и внутри `DoorRig` из `LoadAssetAsync`; при расхождении разбираться именно с сохранением опубликованной модели, не подменять положение сокетов.
4. Если hinge отсутствует: Sync должен прерваться с перечнем реально загруженных Bones, не разрушив ранее существующий шаблон.
5. Ошибку `rbxassetid://203785492 Asset type does not match requested type` диагностировать отдельно; данный ID не был обнаружен в текущем исходном коде проекта.

Результаты автоматических Python-тестов не заменяют этот ручной тест на опубликованных ассетах Roblox.
