# M134 · Real Estate collision mesh contract

## Зачем

В `house_level4_01` GroundSensor попадал в `restoration`, который использовал приблизительную collision geometry (`Default`), и получал ложную наклонную нормаль у порога. Физику архитектуры отделяем от визуальных мешей. **Это авторский pipeline, а не изменение игрового контроллера**.

## Blender и названия

- Отдельная простая геометрия коллизий в том же FBX сцены, что и `house`.
- Имя содержит самостоятельный токен `col`: `COL_Floor`, `wall_col_01`, `house_col`, `col_stairs`. Совпадение нечувствительно к регистру. `column` не распознаётся как коллайдер.
- **Один `house_col` разрешён**: один MeshPart может включать несколько несвязанных простых объёмов. Но Roblox не обещает точного физического представления сложного вогнутого объединения; особенно проверять двери, лестницы, пороги, дырки и примыкания. При неверной физике делить геометрию на несколько лёгких `COL_*` мешей. Система уже поддерживает несколько.
- Не включать в статический общий `house_col` дверное полотно, которое будет поворачиваться через `DoorAssembly`; для него понадобится отдельная динамическая collision assembly.
- Сам collider без материалов и UV допустим. **Image Asset и Atlas Variant ему не нужны.** Он публикуется как отдельный Model Asset, как прочие меши.
- `house` + `house_armature` остаются обязательными; `house_col` необязателен, для старых домов миграции геометрии нет.

## UI

В каждом разделе меша есть `No Collide`; для визуальных мешей по умолчанию **ON**, для имени `*_col`, `col_*` — **OFF**. Старые явные значения сохраняются при редактировании. `glass · 0.02` остаётся независимым от коллизий. Collider помечен `Physics mesh · no atlas`, для него скрыты браузер текстур и reuse. Дополнительный Model Asset публикуется кнопками `publish FBX` / `republish ... rig`, но **никогда** `publish image`.

## Studio Sync

| Свойство | Визуальный MeshPart, No Collide ON | Collider, No Collide OFF |
|---|---|---|
| `CanCollide` | false | true |
| `CanQuery` | false | true (GroundSensor / raycast) |
| `CanTouch` | false | false (не триггер) |
| `Transparency` | 0 или 0.02 (glass) | 1 |
| `CastShadow` | исходное | false |
| `CollisionFidelity` | исходное | `PreciseConvexDecomposition` |
| `Anchored` | исходное | true |

Checkbox `No Collide` можно отключить и у обычного меша, если конкретной части нужна физика. `No Collide` на collider разрешено включить для временного теста: он останется невидимым, но перестанет физически взаимодействовать и участвовать в raycast. Упрощение геометрии предпочтительнее дорогой `PreciseConvexDecomposition`; профилировать CPU/PhysicsParts на большой карте.

Все флаги применяются к шаблону ServerStorage; при синхронизации сохраняются positions у управляемых экземпляров Workspace. Если добавлен новый `COL_*` rig, существующие управляемые экземпляры дома получают *только* недостающую физическую модель с вычислением transform из своего `house` MeshPart. Управляемые коллайдеры обновляются; посторонние папки и ручные детали не удаляются. Без уникального anchor (`house` MeshPart) обработка этого экземпляра пропускается с предупреждением.

**Важно:** до регистрации collider у старого дома включение `No Collide` на всех визуальных мешах сделает дом нефизическим. Добавьте collider и опубликуйте его Model Asset **до** применения такой настройки в Studio. В текущем дампе отсутствует новый Blender FBX/коллайдер, поэтому реальная проверка контактов на игровой карте ещё необходима.

## Публикации и совместимость

- `Model Asset ID` каждой геометрической части — отдельная публикация, новый ID при re-upload; старые остаются в истории.
- Изменение флагов не вызывает публикацию Model/Image и не изменяет Atlas Registry.
- Старые опубликованные дома, их записи SQLite, авторские исходники и ID не мигрируются автоматически. В таблице опций новых полей не добавлено: `mesh_options_json` уже существует.
- Для нового коллайдера потребуется публикация **нового Model Asset** (`house_col`); существующий `house`/`door` Image ID не меняется.

## Проверка Studio

1. Blender: `house_col` — простой collider, без визуальных деталей, в FBX вместе с `house`.
2. Real Estate: инспекция видит `house`, `door`, `house_col`; `house_col` не спрашивает PNG; checkbox `No Collide` у него OFF.
3. Зарегистрировать новую версию FBX и опубликовать модели. Проверить, что для `house_col` нет Image Asset ID.
4. Нажать Sync Studio; в шаблоне `house_col.Transparency == 1`, `CanCollide/CanQuery == true`, `CanTouch == false`.
5. Проверить уже размещённый управляемый дом и новый шаблон. В Play на пороге проверить `GroundSensor.HitNormal`, `SensedPart` и опоры пола; включить Studio collision visualization.
6. Если `house_col` с одним сложным вогнутым MeshPart снова даёт некорректную форму, упростить/разбить его на несколько `COL_*` вместо усложнения Roblox physics fidelity.
