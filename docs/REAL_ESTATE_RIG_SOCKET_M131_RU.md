# M131 — Real Estate socket and hinge rig contract

Дата: 2026-10-27. Изменения поверх M130; миграция SQLite не требуется.

## Назначение

Новый FBX `house_level4_01` использует отдельные риги дома и двери. **Имена костей сами по себе не доказывают связь с Mesh**: Blender-анализатор берёт Armature исключительно из фактического Armature Modifier / Parent. `house` с `house_armature` по-прежнему обязателен; дверь и все интерактивные функции факультативны.

### Дом: пространственные сокеты (могут отсутствовать у других моделей)

- `chimney_01_socket` — дымоход;
- `elevator_01_socket` — зона лифта;
- `house_floor_01_spawn_01_socket` — первый этаж;
- `house_floor_02_spawn_01_socket` — второй этаж;
- `chest_01_socket` — исходная позиция сундука;
- `land_spawn_01_socket` — участок перед домом.

Сокеты не являются костями для движения элементов дома. Их имена и трансформы должны пережить экспорт; скрипты движения лифта, размещения сундука и дымохода не входят в M131.

### Дверь: жёсткая подвижная сборка

- `door_01_hinge_socket` — root, точный pivot петель.
- `door_01_handle_inside_socket`, `door_01_handle_outside_socket`, `door_01_padlock_01_socket` — дочерние сокеты hinge.
- Все вершины дверного Mesh должны быть привязаны **только** к `door_01_hinge_socket` с весом `1.0`.
- Подготовка FBX не меняет ни одного веса этого mesh; старое автоматическое распределение весов на сокеты для этой двери отключено. Если исходный риг не соответствует правилу, подготовка прервётся с объяснением.

Blender round-trip должен сохранить названия, родителей и rest pose. Studio Sync проверяет наличие реально импортированных сокетов; отсутствие опубликованного сокета является ошибкой, а не «успешной» синхронизацией.

### Studio-сборка

Новый `DoorAssembly` создаётся *только* для двери с опубликованным `door_01_hinge_socket`:

```
RealEstateTemplate
├── HouseRig (house MeshPart + house bones)
└── DoorAssembly (Model.WorldPivot = hinge.TransformedWorldCFrame)
    └── DoorRig (door MeshPart + door bones)
```

У `DoorAssembly` нет PrimaryPart, поэтому его WorldPivot находится именно на hinge. Изменение WorldPivot не перемещает MeshPart. В атрибуте `Game1DoorClosedLocalPivot` хранится закрытый pivot сборки относительно `house.MeshPart.CFrame` в JSON-массиве из 12 компонентов CFrame. Runtime DoorController может затем двигать всю сборку `Model:PivotTo`, **не изменяя** `Bone.Transform`. M131 не создаёт игровой контроллер и не включает анимацию открытия.

Возможность двигать assembly, сохраняя позицию костей, проверена на уровне контракта/кода; визуальный тест в Roblox Studio с настоящим опубликованным FBX обязателен.

### Совместимость

- Старые `door_bone` и `chimney_bone` не объявлены ошибками и не требуют подтверждения предупреждений. Старые двери без hinge импортируются в прежний `DoorRig`, без `DoorAssembly`.
- Отсутствие двери, как прежде, допускается.
- Для статичных/старых мешей остаётся legacy-подготовка с временными FBX-якорями M113; канонический исходный FBX не меняется.
- Новая дверь не получает таких якорей: авторские веса `1.0` остаются неизменными. Возможность сохранить *непривязанные по весам* дочерние сокеты полностью зависит от Blender/Roblox import; если импорт их отбрасывает, синхронизация выдаст понятную ошибку, а старый шаблон не будет заменён.
- Atlas Registry, Roblox Image/Model Asset IDs, sqlite, публикации и уже размещённые экземпляры **не переписываются автоматически**. Новый модельный FBX потребует обычную новую публикацию Model Asset с новым ID.
- `chest_01` и `padlock_01` пока не выделяются автоматически в отдельные сервисы/публикации: в M131 нет скрытой переклассификации по именам или Blender Collections.

### Проверить в Studio

1. Экспортировать `house_level4_01` FBX с четырьмя костями двери и шестью костями дома.
2. Открыть Real Estate → выбрать FBX → посмотреть роли bones (`hinge`, `socket`, `bone`) и предупреждения.
3. Зарегистрировать новую ревизию модели, опубликовать требуемые Model Assets (новые ID), сделать Studio Sync.
4. Убедиться, что есть `DoorAssembly`, его pivot совпадает с петлями, `DoorRig` находится внутри сборки; все сокеты присутствуют внутри своих MeshPart.
5. В копии шаблона вручную вызвать `DoorAssembly:PivotTo(DoorAssembly:GetPivot() * CFrame.Angles(0, math.rad(90), 0))` и убедиться, что дверь/кости перемещаются совместно без skin-деформации. Ось вращения следует проверить **в координатах Roblox**; не пытаться использовать поворот одновременно с Bone.Transform.
6. Убедиться, что старый дом без hinge и дом без двери по-прежнему загружаются.
