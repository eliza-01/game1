# Лицо, эмоции и события анимации · v1

Дата решения: 2026-10-31. Владелец библиотеки — Character ID; общие части принадлежат rig profile human.

## Принятые решения

1. Четыре жёстких лицевых контроллера: face_eye_l/r и face_brow_l/r под face_head. Одна кость на глаз/бровь, один вес 1.0 на соответствующую часть. Меши eyes_01_l/r и eyebrows_01_l/r разделены для независимых изменений размера.
2. Кость задаёт положение и поворот. Моргание, размеры MeshPart, выбор формы/меша и эффекты выполняет игровой контроллер. Не заменять масштабирование сотнями деформирующих костей.
3. Сложный изгиб не получается одним изменением Size: для него используется подходящий сменный меш или композиция простых мешей в runtime.
4. Спираль — один статический eyes_01_spiral без костей/весов. Его экземпляры крепятся к контроллерам глаз. Начальная фаза правого экземпляра 180 градусов; отражения геометрии нет; вращение синхронное вокруг локальной оси Z.
5. Тело, лицевой клип и программное состояние лица — разные области управления. Лицевые клипы не должны содержать каналы движения тела. Runtime-контроллер не перезаписывает Bone.Transform, которым в этот момент управляет Animator.
6. Моргание — один запрос полного цикла закрыть/открыть. Остановка клипа, смена персонажа и переключение состояния обязаны завершать временные эффекты и восстанавливать исходные размеры.

## Маркеры и документ клипа

Обычный маркер Blender не переносится автоматически через стандартный FBX в Animation Event Roblox. Разметку храним в Action.pose_markers, отдельно для каждого клипа. Экспортёр читает маркеры и сохраняет сопроводительный `<clip>.animation.json`.

Строка маркера: `blink` либо `blink|{"duration":0.16,"side":"both"}`. Суффикс .001, автоматически добавленный Blender одноимённому маркеру, не является именем события. Маркер — данные, не Python/Luau-код.

```json
{
  "schema_version": 1,
  "clip_name": "emotions_idle",
  "source_action": "face_idle",
  "fps": 30,
  "frame_start": 1,
  "frame_end": 480,
  "looped": true,
  "mode": "skeletal",
  "animation_file": "human_male_emotions_idle.rbxmx",
  "animation_sha256": "<sha256 bytes of the exported animation>",
  "rig": {"id":"human","revision":2,"asset_id":"99890351983275"},
  "events": [
    {"id":"event_0001","frame":63,"time":2.0666666667,"name":"blink","parameters":{"duration":0.16,"side":"both"}}
  ]
}
```

Время вычисляется как `(frame - frame_start) / (fps / fps_base)`, с учётом фактической частоты кадров; в документе fps уже является effective FPS. Не путать номер кадра с номером ключа или миллисекундами. Привязка к SHA256 защищает от случайного применения документа к другому файлу анимации. События сортируются по времени с сохранением порядка нескольких событий на одном кадре.

Поддерживаемый начальный словарь: blink; face_state; face_reset; eyes_set; eyes_spin_start; eyes_spin_stop. Параметры имеют строгую схему, имена неизвестных событий отклоняются. Для чисто программных эмоций mode=procedural, файл анимации и его hash отсутствуют, но диапазон кадров и события остаются.

## Пользовательский процесс

Вся разметка выполняется в Blender: выбрать клип → поставить маркер → экспортировать анимацию с документом → зарегистрировать пакет в Animations. Ручного добавления событий в Studio нет.

Документ является частью данных проекта, привязанной к семантическому клипу. Контроллер читает события по времени воспроизведения соответствующего AnimationTrack, учитывает остановку, паузу, цикл и скорость. Запрещено заменять это task.delay от момента Play: он рассинхронизируется при изменении скорости. Нативные GetMarkerReachedSignal и sidecar-события нельзя одновременно включать для одной и той же разметки.

Экспорт сразу в пригодный к загрузке Roblox формат требует отдельной проверки осей/поз на опубликованном риге. Native RBXMX экспорт предпочтителен для автоматического пути без ручной подготовки в Studio; FBX может оставаться дополнительным артефактом. Само наличие FBX+JSON ещё не означает, что существующий загрузчик умеет публиковать такой пакет.

## Emotions

Отдельный semantic scope `emotions`: idle, combat_idle, happy, happy_sharp_caret, happy_thick_caret, sad, blink, closed, indignant_surprise, dizzy_spiral, look_around, nausea_wave, raised_eyebrow. Старый idle_combat_open_eyes сопоставляется с combat_idle; старый сужающий глаза combat idle сохраняется только как исходный материал, не становится новым стандартом боя.

Файлы: `<character_id>_emotions_<state>.rbxmx` и одноимённый `.animation.json`. Программное состояние может иметь только документ и не требует публикации пустого Animation Asset. Для боя глаза не сужаются; меняются брови/состояние. У счастливых/печальных вариантов смена формы не добавляет костей.

## Риг и совместимость
