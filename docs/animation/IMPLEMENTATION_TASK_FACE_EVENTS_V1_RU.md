# ТЗ: emotions и документы анимаций

Дата: 2026-10-31. Основание: FACE_AND_EVENTS_V1_RU.md. Не требует новых лицевых костей, ручной разметки в Studio или переноса ID из RobloxLineage.

## Цель

Автор размечает лицевые события в Blender и получает пакет, который библиотека Characters регистрирует вместе с событийному документом. Во время игры события управляют четырьмя жёсткими частями лица, сменными мешами и статической спиралью. Существующие Animation Asset ID и анимации тела сохраняются.

## Этапы реализации и приёмка

1. **Каталог emotions.** Добавить semantic scope в общий каталог, классификатор имён, пути хранения, реестр, UI-фильтр, Filename Rules. Добавить отдельный раздел emotions в Character Animation Library. Base/weapon сценарии остаются прежними. Проверки: классификация всех поддержанных состояний, legacy filenames, сортировка/Show missing/переход по правилам.
2. **Документ клипа.** Чистая валидация schema_version=1, диапазона кадров/effective FPS, событий/параметров/хэша файла. Отдельное хранение документа и native Animation Asset: изменение sidecar не должно создавать новый Asset ID. Строгая идентичность пары, bounded размеры/число событий, ошибка вместо игнорирования испорченного документа.
3. **Экспортёр Blender.** Pose markers конкретного Action, параметры JSON, экспорт документа. Native animation export без ручной подготовки в Studio: сверять с фактическим bind опубликованного human revision 2. Зафиксировать оси и начало времени на тестах; экспортировать только каналы выбранной области, не навязывать лицом позу тела. Восстанавливать Action, slot, frame, pose/selection после экспорта. Операции не изменяют геометрию/веса.
4. **Подготовка существующего материала.** Работать с текущим human_male_face_bones.blend и резервным исходником. Сохранить пять полезных rigid-motion клипов. Вынести моргания из исходного face_idle в маркеры. Девять программных состояний оформить как событийные дорожки/документы, не пустые скелетные анимации. Для стандартного combat_idle выбрать открытые глаза. Тело и donor m_fighter не изменять, неподдерживаемые семантики отметить в отчёте.
5. **Регистрация пакета.** Native .rbxm/.rbxmx + sidecar импортируются атомарно; чисто программный документ регистрируется без cloud upload. Не сканировать sidecar второй раз как отдельный клип, если рядом есть его native файл. Старые файлы без документов работают. Подмену выбранных файлов между Scan и Register обнаруживать по хэшам обоих файлов.
6. **Runtime.** Выделенный event player и face presentation controller с одним владельцем размеров/видимости. Проигрывание по AnimationTrack.TimePosition; нулевой маркер, speed changes, pause, loop, stop, respawn, reverse/seek имеют явную политику. Для procedural состояний отдельные логические часы. Не менять combat/locomotion алгоритмы. Временные эффекты чистятся на смене клипа/персонажа; все соединения и экземпляры уничтожаются. Отсутствие новых мешей на legacy персонаже не вызывает ошибок.
7. **Связки эмоций и мешей.** Сервер хранит разрешённое состояние/контекст; визуализация локальная и должна работать для наблюдаемых персонажей. Моргание одним событием, а не двумя независимыми обязательными close/open. Спираль повторно использует один меш, начальная фаза 180°, синхронное вращение. Поддержка парных лицевых MeshParts в регистрации выполняется до переключения live-сборки на новый rig.
8. **Интерфейс и развёртывание.** Показывать режим clip/procedural, документ, число событий, недостающие зависимости. Не предлагать публиковать JSON как Roblox Animation. Отдельно показать ошибки/очередь, сохранить published IDs. Обновить только затронутые службы/статические файлы.

## Верификация

- Unit: validator, filenames/emotions, регистрирование пары, race между Scan/Register, сохранность Asset ID при metadata-only update, legacy data.
- Чистый scheduler: first frame, несколько событий одного времени, pause, speed, несколько циклов, stop/restart, backward seek, отсутствие дублей.
- Blender: реальные 77 костей, четыре лицевых канала-контроллера, корректный документ для каждого экспортируемого клипа, отсутствие донорских/телесных каналов в эмоциях.
- Studio: тестовый персонаж и временная анимация без облачной публикации, проверка положения/поворота и срабатывания blink по документу. Не заявлять визуальную готовность реальных парных ассетов без их импорта.
- Общие verify.py / unittest / JS checks; существующие проблемы полного набора тестов документировать отдельно от проверок этой функции.
