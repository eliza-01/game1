# M117 · Alpha-aware texture binding

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Контракт

Для зарегистрированных и опубликованных Image Asset IDs Host Agent вычисляет
`usesAlpha` (`true` / `false`) из фактических пикселей выбранного PNG/WebP:
`true`, если существует пиксель с альфой меньше 255; в остальных случаях
`false` (JPEG всегда непрозрачен). Если исходный файл отсутствует или не
читается, значение **неизвестно** (`null` / ключ отсутствует), а не `false`.
Перепубликация текстуры при повторном Sync не требуется.

- **Location Assets**: read-only поле `textureUsesAlpha` в ответе каталога и
  генерируемом `LocationAssetRegistry`; для shared/reuse берётся файл
  владельца. Если текстура изменилась без публикации, режим считается
  неизвестным до публикации новой версии.
- **Weapons, Monsters, NPC**: необязательное `usesAlpha` у текстурных
  элементов команды Studio Model Sync. Признак вычисляется из сохранённого
  `source_path`, без новых колонок SQLite.
- **Real Estate**: такой же `usesAlpha` у каждого текстурного слота,
  включая mesh-reuse и ссылки на текстуры из Location Assets.
- **Game1Bridge / StudioTextureAppearance**: устанавливает `TextureID` +
  `SurfaceAppearance.ColorMap` на тот же Image Asset ID. При известном режиме
  назначает `AlphaMode = Transparency` или `Overlay`, при неизвестном режиме
  существующее значение **не перезаписывает**. Прочие карты PBR сохраняются.
  Повторное применение к уже синхронизированному мешу ничего не делает.
- **EnvironmentAssetVisuals**: отдельный серверный адаптер с тем же контрактом
  для размещённых Location Assets при игровом старте/динамическом добавлении.

Для импортированных/скинированных MeshParts `TextureID` никогда не очищается:
это зафиксированное в старом проекте требование совместимости.

## Границы

Система не меняет изображения, FBX, риги, Bone, Asset IDs, таблицы SQLite,
политику публикации или MeshPart.Transparency. Не использует режимы Blend/Cutout
как разные сущности: оба случая альфа <255 используют старый
`SurfaceAppearance.AlphaMode = Transparency`.

Это применяется к отдельно зарегистрированным Image Assets. У Character
Archetypes сейчас нет самостоятельного контракта публикации текстур, поэтому
существующие встроенные FBX-материалы Character Studio Sync намеренно не
переписываются. Неизвестный альфа-режим (отсутствует источник, Pillow и т. п.)
не принуждается к Overlay.

## Проверка в Studio

Закрой Studio → установи обновлённый Game1Bridge → снова открой Studio.
Перезапусти Host Agent/Control Center, чтобы каталог и Lua Registry получили
`textureUsesAlpha`. Повтори **Sync Studio** для существующих ригов; новая
публикация Image Asset/Model Asset для этого не нужна. В DecoManager обнови
список/текстуры размещённых объектов. Проверить модель с прозрачным PNG,
непрозрачным PNG/JPEG и skinned rig; убедиться, что ColorMap и TextureID
содержат одинаковые ID, AlphaMode соответствует фактическому источнику.
