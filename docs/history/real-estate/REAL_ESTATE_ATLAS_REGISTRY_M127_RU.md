# M127 · Real Estate как потребитель Central Atlas Registry

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Область изменений

- **Имя недвижимости и FBX не изменяется:** `house_level2_01` (тип, уровень, вариант).
- **Новые имена атласов:** `<atlas_key>_<width>x<height>_atlas.png`, например `house_level2_01_2048x2048_atlas.png`. Размер проверяется по содержимому PNG/JPEG. Атлас может иметь самостоятельное имя семейства и использоваться разными моделями.
- **Общий источник данных:** таблицы `texture_atlas_families`, `texture_atlas_variants`, `texture_atlas_bindings` в `.control-center/game1.db`, реализованные в M125. Для Real Estate ключ привязки — `consumer_type='real_estate'`, `consumer_id='<estate-slug>:<mesh-name>'`. Никаких новых таблиц публикации изображений для Real Estate.
- **Image Asset ID принадлежит варианту, не дому и не mesh:** выбор `atlas:<variantId>` или нажатие точки никогда не вызывает Image Upload; опубликованные варианты всех семейств доступны для reuse. Опубликовать *ранее неопубликованный* новый вариант можно через существующую публикацию Real Estate, которая делегирует операцию общему реестру. Повторные uploads идентичных проверенных байтов не делаются; конфликт legacy ID блокирует автоматический выбор.
- **Модели/риги:** `house`, необязательный `door` и произвольные дополнительные mesh обрабатываются по существующему контракту. `mesh:house` продолжает использовать выбранный атлас дома без второй публикации. При явном выборе другого варианта для door связь с house снимается только для door.
- **UI:** варианты показываются под текстурой каждой опубликованной части; слева направо — по убыванию площади, золотая/фиолетовая/синяя/зелёная/серая точки. Активная подсвечена, tooltip содержит разрешение и имя. Несоответствующие старые имена отмечаются ⚠️, без принудительной миграции.
- **Studio Sync:** нажатие на опубликованный вариант сохраняет привязку и вызывает существующий Real Estate Studio Sync. Обновляется управляемый шаблон в ServerStorage; дополнительно текстуры обновляются у моделей в Workspace с явным атрибутом `Game1RealEstateSlug`, без изменения их CFrame и размеров. После подтверждения Studio отмечается синхронизированная ревизия отдельной mesh-привязки. При недоступной Studio привязка остаётся сохранённой, статус `pending_studio_sync`, доступен retry.
- **Legacy:** существующие Image IDs/Model IDs, FBX, rigs, старые ссылки `location:<slug>`, `estate:<slug>:<part>` и `mesh:house` не переписываются. Исторические записи Real Estate индексируются общим реестром только по реально опубликованному SHA256 и ID. Никакой автоматической конвертации имен/источников.

## Ограничения

1. Реальное взаимодействие с Roblox Studio требует ручной проверки. Испытать опубликованную модель с двумя вариантами и клоном в Workspace; убедиться в обновлении текстуры и неизменности расположения.
2. M125 запрещает молча заменять содержимое зарегистрированного варианта при тех же имени/разрешении. Новая редакция атласа требует отдельно согласованной процедуры версионирования.
3. Runtime изменения шаблонов во *время Play* не гарантируются: речь о синхронизации Studio Edit.
4. Undo для переключения привязки в локальной SQLite-базе не привязан к Roblox Studio Undo. Предыдущий вариант выбирается повторным нажатием на его точку.
