# M160 · Спавны этажей и прицеливание по объёмной зоне лифта

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Телепорт

- `elevator_01_socket` / `elevator_02_socket` / `elevator_03_socket` — **только точки вызова** лифта.
- При выборе **этажа 1** прибытие происходит к `house_floor_01_spawn_01_socket`.
- При выборе **этажа 2** прибытие происходит к `house_floor_02_spawn_01_socket` (в том числе при подъёме с первого).
- Оба spawn используют `HouseSpawnOrientation.Upright` и 3 studs вертикального зазора; нестандартные трансформации костей Blender не поворачивают персонажа на бок.
- Если назначенный spawn отсутствует, телепортация отклоняется с сообщением «Целевой этаж недоступен»; подмены его лифтовым сокетом нет. Для третьего этажа сохранён прежний необязательный `elevator_03_socket` как точка назначения.

## Прицеливание / взаимодействие

- У elevator есть **независимые радиусы**:
  - `USE` (по умолчанию **10 studs**) — расстояние между root персонажа и сокетом, валидируемое сервером; больше радиуса нельзя взаимодействовать.
  - `AIM` (по умолчанию **5 studs**, допустимо 1–16) — радиус невидимой сферической области вокруг кости, на которую смотрит курсор/центр экрана. Пересечение луча мыши с этой сферой показывает E/F; прицел точно на Bone не требуется.
- Другие взаимодействия дома сохраняют прежнее поведение. Проверка AIM выполняется **только клиентом для показа UI**; сервер не принимает от клиента координат или произвольных целей и заново валидирует реальный socket Instance, направление кнопки, дистанцию и cooldown.
- Поддерживаются и ControllerManager, и Humanoid. Лифтовый ProximityPrompt локально подавляется для обоих видов персонажей, чтобы действие через native Prompt не обходило наведение; E/F отправляются по существующему `HouseSocketInteract` RemoteEvent.
- AIM не выполняет трассировку препятствий — это намеренно широкая невидимая интерактивная область, а не коллизия здания. Если попало несколько зон лифта, выбирается ближайшее к камере пересечение.

## House Sockets Studio

- Высота окна уменьшена на **15% относительно M159**, включая ограничение по высоте viewport: `min(1547px, 85% доступной высоты)` с минимальной высотой 220 px.
- У лифтовых строк два независимых регулятора `USE · reach` и `AIM · hover`, оба в studs. Отображаются в одном списке, значения изменяются отдельными `−/+`.
- `RANGES: ON` показывает **бирюзовую** сферу USE и **янтарную** сферу AIM. Отладочные Parts не имеют столкновений, touch или query; удаляются после выключения визуализации.
- Серверный `SetTestHouseSocketHoverRadius` доступен только в Studio, принимает только elevator socket names и ограничивает радиус; состояние хранится на Player, не в базе.

## Требуется тест в Roblox Studio Play

1. 1-й этаж: E лифта → персонаж на `house_floor_02_spawn_01_socket`.
2. 2-й этаж: E лифта → персонаж на `house_floor_01_spawn_01_socket`.
3. Находясь вне USE, наведение на AIM не показывает кнопку. Внутри USE — показывает, даже без точного прицеливания на кость. Вне AIM — скрывает.
4. С `RANGES: ON` изменяйте AIM и USE независимо; обе сферы и фактическое поведение должны соответствовать вводимым числам.
5. Проверить стандартный Humanoid и кастомный ControllerManager, E/F на 3-этажной конфигурации, а также ситуацию отсутствующего целевого spawn.

**Границы:** shared policy, серверная проверка входа/назначения, клиентская подсказка и Studio-only debug. Исходные FBX, модели, кости, публикация, дверь и замок не менялись.
