# M130 · Real Estate: Atlas Library, безопасное удаление, glass и restoration

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Контракты

- `RealEstateStore` продолжает использовать **общий** `AtlasRegistry`; второй реестр и собственный путь перепубликации не создаются.
- Раздел **Uploaded atlases** показывает семейства и варианты общего реестра (в том числе используемые Location Assets). Для старых Real Estate публикаций без стандартного варианта отображается `legacy`.
- Фильтры: все атласы, используемые выбранным домом, используемые или именованные для выбранного дома.
- `Republish · new ID` вызывает существующий endpoint `POST /api/texture-atlases/variants/{id}/republish` (M129). Для legacy-ассета доступен последовательный путь `Replace / republish`: выбор исходника, сохранение выбранного mesh, публикация только его изменённого Image Asset.
- **Никакого reimport Image Asset с прежним ID не существует.** При изменённых байтах и успешном Open Cloud публикуется новый Image Asset ID. Пока публикация не завершена, текущие ID продолжают работать. Переиспользование без изменений не публикует повторно.

## Удаление дома

- `DELETE /api/real-estate/{slug}`; у дома нет зависимостей через `estate:{slug}:{mesh}` и нет незавершённых операций. Если фоновая публикация идёт, запрос отклоняется.
- Перед удалением реестровых строк полный снимок строки и истории публикации сохраняется в `.control-center/real-estate-retired/{slug}_{timestamp}.json`.
- Локальные FBX/PNG в `assets/source/real-estate` **не удаляются**. Общие атласы и Roblox Asset IDs **не удаляются**. Привязки этого дома к атласам удаляются, чужие привязки не меняются.
- Управляемые Studio-шаблоны уже в открытом Place **не удаляются автоматически**. При необходимости их нужно удалить отдельно после проверки размещённых копий. Это намеренное разделение административного удаления записи и потенциально разрушительного изменения открытого Place.

## Стекло

- Checkbox `glass · 0.02` хранится отдельно от публикации модели/атласа в `mesh_options_json`. Создание этой колонки выполняется автоматически и сохраняет остальные поля и публикации.
- Для имени `glass` или любого имени, содержащего `glass` без учёта регистра, checkbox включён по умолчанию. Для остальных выключен; пользователь может вручную переопределить.
- При сохранении уже опубликованного дома с изменённым checkbox выполняется Real Estate Studio Sync (если доступен). Studio обновляет `Transparency = 0.02` у шаблона и управляемых экземпляров в Workspace. Снятие флага сбрасывает прозрачность в 0 **только** если её установила эта же система (проверка атрибута `Game1RealEstateGlassApplied`).
- При изменении только checkbox повторная публикация Model/Image не нужна. Новая настройка применяется к текущему экземпляру в Studio и последующим загрузкам через синхронизацию.

## Имя repair → restoration

- Для новых FBX используйте mesh `restoration`. Уже опубликованный FBX с mesh `repair` не переименовывается автоматически и остаётся рабочим. В интерфейсе показывается `restoration (legacy: repair)`; реальное имя, риг и Asset ID остаются прежними.
- Для физического переименования нужно сменить имя mesh в исходном Blender/FBX и зарегистрировать новую версию, после чего потребуется новый Model Asset ID для изменённого rig.

## Проверки

- Тесты: новый checkbox по умолчанию/явное значение/сохранение, передача настроек в Studio, архивирование при удалении, запрет удаления при зависимостях/фоновой публикации, автоматический Studio Sync после обновления checkbox.
- Проверять вручную в Studio на стеклянном mesh и на уже размещённом доме.
