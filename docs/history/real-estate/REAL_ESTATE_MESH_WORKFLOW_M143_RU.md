# M143 · Real Estate — единый workflow мешей

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Что решено

- Каждая часть дома имеет кнопку **Manage mesh**. В одном модальном окне находятся операции **Choose FBX → Publish Model → Sync Studio**. Слово `rig` в пользовательском действии заменено на `model`: наличие деформирующего рига не обязательно.
- Меню не закрывается после выбора FBX: выбранный файл проходит существующий `mesh-inspect`, записывается в независимую неизменяемую ревизию после подтверждения, публикация отдельная.
- **Sync model** работает и с управляемым шаблоном ServerStorage, и со всеми найденными управляемыми экземплярами в Workspace с `Game1RealEstateSlug`. Ответ Studio содержит `workspaceModelsFound`, `workspaceModelsUpdated`, предупреждения. Неуправляемые копии принципиально не перезаписываются.
- **Sync entire house** теперь обновляет и визуальные модели уже расставленных домов, а не только текстуры/коллизии. Отдельный `StudioRealEstatePlacedVisualSync` изолирует эту ответственность; физический слой по-прежнему обновляется `StudioRealEstatePlacedCollisionSync`.
- Для двери при полном Sync сохраняется её текущий pivot (в том числе открытый угол); дом и другие части обновляются относительно house anchor. Объекты владельцев вне управляемых rig-моделей не пересоздаются.
- Вкладка **Texture · atlas** отдельно показывает четыре действия: использовать уже опубликованный Atlas Variant (reuse без upload); перепубликовать действующий вариант (новый Image ID, все его потребители); выбрать локальный файл и сохранить его; опубликовать изменённую текстуру и синхронизировать.
- Золотая точка и другие индикаторы проверяют активность по сохранённому `atlasVariantId`; для старых связей допускается лишь визуальный fallback по равенству эффективного `assetId` опубликованному ID. Это **не** меняет сохранённую привязку.
- Тосты показывают одну операцию за раз, закрываются крестиком, автоматически исчезают через несколько секунд кроме долгих операций; статус публикации дополнительно опрашивается у Host Agent и отражается в окне.

## Публикации и совместимость

Сохранение локального FBX не публикует ничего. `Publish changed model` создаёт **новый Model Asset ID**, не трогая остальные модели или Image IDs. Выбор опубликованного варианта атласа меняет только binding; повторный upload запрещён. `Republish atlas` создаёт **новый Image Asset ID** при изменённых байтах; старый остаётся в истории.

Нет изменений SQLite, таблиц атласов, Model/Image IDs при установке, FBX и трансформаций в архиве. Для новых вызовов Studio-плагин необходимо переустановить. Текущий Studio Sync не является игровым онлайн-обновлением активных серверов Roblox; он изменяет авторскую сцену в открытом Roblox Studio, результат которой надо сохранить/опубликовать отдельно.

## Проверка в Roblox Studio

1. Открыть `house_level4_01 / col_mesh` → Manage collision → Choose replacement FBX → подтвердить → Publish changed model → дождаться нового Model ID → Sync model.
2. По результату убедиться, что `template updated`, а счётчик `placed houses X/Y` соответствует реально помеченным `Game1RealEstateSlug` моделям.
3. Открыть дом, повернуть дверь, затем Sync entire house; местоположение дома и существующий поворот двери должны сохраниться.
4. Открыть `house / Texture · atlas`: текущий вариант выделен после загрузки страницы, выбор идентичного опубликованного варианта не создаёт upload; Republish создаёт новый Image ID только при изменённом содержимом.
5. Проверить закрытие тоста крестиком, замену старого уведомления новым, ошибки неактивной Studio.

Реальную Studio-проверку нельзя подтвердить по диагностическому ZIP. Автотесты покрывают маршрутизацию UI и контракт результата синхронизации; сборка исходников Studio Bridge проверена на полноту в `install.ps1` и `audit.py`.
