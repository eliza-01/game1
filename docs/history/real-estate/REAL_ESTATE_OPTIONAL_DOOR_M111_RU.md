# M111 · Real Estate: optional door and Blender error propagation

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


База: `game1_diag_2026-10-19_03-14-13.zip` (M110 применён).

## Авторский контракт

- `house` — обязательный Mesh, `door` — опциональный отдельный Mesh.
- Каждый присутствующий меш имеет собственную арматуру, если она есть. Кости и веса не обязательны, но **все имеющиеся кости** должны пережить подготовку.
- Посторонние меши и несвязанные арматуры с костями не отбрасываются молча: анализ требует исправить FBX.
- Источник активных частей — `skeleton.meshes`; `present_parts()` используется в реестре, публикации и Sync Studio.

## Публикация и синхронизация

- Дом без `door`: один `HouseRig` Model Asset, одна текстура `house`, один шаблон в `ServerStorage`.
- Дом с `door`: отдельные `HouseRig` и `DoorRig`, индивидуальные текстуры или общий атлас; прежние ID не переиспользуются при новой публикации.
- История старых Door Asset IDs остаётся в реестре публикаций, но не считается активным ресурсом, если текущий FBX не содержит `door`.
- В случае сбоя подготовка не затрагивает ранее опубликованные ассеты.

## Blender

`--python-exit-code 1` заставляет Blender сигнализировать об ошибке Python-скрипта через код процесса. При отсутствии отчёта диагностика выводит исходное сообщение ошибки, если оно присутствует, вместо вводящего в заблуждение «missing JSON report».

Проверки Python/JS и контрактов Studio-плагина **не заменяют** реальную проверку импорта FBX в Blender и Roblox Studio.
