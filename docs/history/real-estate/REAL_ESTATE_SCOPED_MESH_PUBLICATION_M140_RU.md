# M140 · Real Estate · независимые ревизии отдельных мешей

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Контракт

- `house_level4_01` сохраняет свой общий базовый FBX и существующие Roblox IDs.
- Каждый меш может иметь свою *immutable*, content-addressed ревизию исходного FBX в `assets/source/real-estate/<slug>/mesh-revisions/<mesh>/<sha256>.fbx`.
- Можно выбрать FBX, содержащий **только** `restoration`, либо полный FBX дома; из полного источника извлекается **только названный меш**. В текущем этапе нельзя таким способом добавить новый меш или переименовать существующий.
- Требуется точное совпадение имени меша, реальная связь Mesh ↔ Armature, проверка экспортируемых костей. Для `house` по-прежнему обязателен `house_armature`.
- `skeleton_json` обновляется для выбранной части, `mesh_sources_json` хранит независимый источник, а `model_rigs_json` — результат каждой независимой публикации. Остальные записи неизменны.
- Публикация нового Model Asset создаёт **новый Roblox Model Asset ID** и никогда не перезаписывает существующий. История сохраняется в `real_estate_publications`.
- Никаких новых Image Assets, FBX-публикаций других ригов и изменений Atlas Registry из этого пути нет.
- Полный FBX через старую кнопку по-прежнему заменяет базовую сцену и помечает все базовые риги изменёнными. Для выборочного обновления **используй «replace this mesh FBX»**, даже если выбрал полный FBX дома. После появления индивидуальных ревизий старое «replace full FBX» блокируется, чтобы не затереть неявно независимые скелеты.

## Как пользоваться

1. Real Estate → Registered Houses → `house_level4_01` → столбец Model Assets → нужный Mesh → раскрыть `Mesh source / Studio sync`.
2. `replace this mesh FBX` → выбрать FBX с этим мешем или полный FBX → подтвердить найденный меш, количество вершин/костей.
3. `republish <mesh> rig` → дождаться нового Roblox Model Asset ID только для этой части.
4. `sync this mesh` → заменить только управляемый `*Rig` в уже собранном шаблоне ServerStorage и в управляемых размещённых домах. Если шаблона нет, сначала сделать полный Sync Studio.

Кнопка **publish changed** опубликует все *действительно устаревшие* риги, а `republish <mesh> rig` — только выбранную часть. Без явного нажатия **ни одна** операция регистрации не создаёт Roblox Asset.

## Безопасность и ограничения

- При обработке через Blender копируется только выбранный меш и его реальный Armature; временный FBX анализируется после подготовки.
- В редактируемой строке SQLite добавляется только `mesh_sources_json` с DEFAULT `'{}'`. Старые строки и IDs остаются без изменения.
- Чужие / неуправляемые Workspace-объекты не заменяются. У существующих управляемых домов применяется относительный transform от house anchor; при отсутствии надёжного якоря объект пропускается с предупреждением.
- Studio PlacePart сначала проверяет импорт и только потом заменяет существующий риг. Скрипт не меняет `Bone.Transform`, Atlas Registry, скелеты других мешей и расположение предметов владельца.
- **Практическую проверку Blender и Roblox Studio выполнять на тестовом доме:** dump не содержит настоящих FBX, поэтому локальные тесты покрывают контракты и заглушки загрузки, но не геометрию реального Roblox импорта.
