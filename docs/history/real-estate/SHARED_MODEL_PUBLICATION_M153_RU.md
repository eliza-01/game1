# Общая подготовка Model FBX — M153

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


## Границы

Удалены StudioRealEstateSocketRecovery, его вызовы, метаданные authoredBones, статистика восстановления и отдельная real_estate_skin_policy. Studio больше не создаёт потерянные кости.

Общий `system/asset-manager/model_publication.py` владеет подготовкой весов, проверкой rest pose и настройками FBX. `bone_weight_survival.py` остаётся единственным чистым алгоритмом распределения влияний. Characters, monsters/NPC, real estate, location assets и weapons используют общий механизм. HTTP create/update уже был общим в opencloud_assets. Хранилища по-прежнему отвечают за IDs, историю публикаций и транзакции.

Real Estate экспортирует отдельный Model Asset для каждой детали: это граница независимых скелетов, а не отдельный алгоритм сохранения костей. Публикация дома целиком и выбранной детали использует одну подготовку.

## Контракт

Политика совпадает с characters: исходно невзвешенная кость получает влияние минимум 0.05 на одной вершине временной копии; назначаемый вес — 0.055, максимум четыре влияния на вершину. Имена, родители, rest pose и исходный FBX сохраняются. Это подготовка skin в публикационном FBX, а не настройка Roblox или реконструкция в Studio. Исключений по имени двери или дома нет.

Экспорт не запекает анимацию и не применяет трансформации объектов. Все авторские кости экспортируются без leaf bones, оси -Z/Y, масштаб FBX_SCALE_UNITS. Staging выполняется в отдельных background-процессах Blender. Location/weapon staging ограничен 240 секундами и удаляется после передачи файла HTTP-загрузчику, включая ошибки. Выходной FBX повторно импортируется для проверки скелета. Characters и Real Estate сохраняют свои проверки выходного файла.

Studio требует каждую зарегистрированную кость как Bone под нужным MeshPart. Потеря кости, подмена Attachment или неверная иерархия двери прекращают синхронизацию до замены шаблона. Пустой авторский скелет допустим для статических мешей.

База, манифесты и опубликованные IDs в задаче не изменялись. Старые облачные файлы автоматически не обновляются. Неполный Real Estate asset нужно перепубликовать штатной командой детали и затем синхронизировать. Семантика create/update и определения актуальности публикации сохранена: location assets публикуют модель при изменении исходного hash.

## Проверки

- 524 unittest: успешно, один пропущен; включён ResourceWarning-as-error.
- Полный реальный FBX house_level4_01: экспортированы и повторно импортированы house, col_mesh, door, restoration, window_frames_glass.
- Актуальный отдельный FBX двери: сохранены четыре кости, родители и rest-матрицы; три исходно невзвешенных сокета получили влияния. Тот же источник проверен через characters и общий Model staging.
- Статический col_mesh прошёл общий staging без создания скелета.
- SHA-256 исходных FBX не изменились.
- Дверь: 1968 вершин, 3954 треугольника, максимальная разница evaluated rest-геометрии 9.54e-7.
- Studio MCP Edit на изолированной модели: полный скелет принят; потерянная кость, Attachment и неверный родитель отвергнуты. PivotTo сохраняет локальную позу сокета. Тестовые Instances удалены.
- Rojo собрал generated/Game1Bridge.rbxmx без модуля восстановления.
- verify.py сообщает три ошибки путей текстур: lantern_01, test_window_01, big_tree_01. Эти данные задачей не изменялись.

Проверка реального upload через Roblox Open Cloud и Play-регрессия обновлённого облачного ассета не выполнялись. FBX round-trip не доказывает результат обработки Roblox. Установленный плагин и работающий Host Agent не заменялись.

QA исходной и выходной двери одинаково отмечает 282 ребра с inconsistent winding, отдельную одноточечную компоненту, non-manifold края и UV overlap. Геометрия не исправлялась в задаче публикации. Сокеты теперь участвуют в skin, как у characters: будущая анимация Bone.Transform сокета может затронуть его вершину. Текущее движение двери через Model:PivotTo не анимирует сокеты.

## Применение и восстановление

Патч построен относительно рабочей версии в начале задачи, включая предыдущие незакоммиченные изменения пользователя. Перед применением: git apply --check. В текущем workspace изменения уже внесены; проверяется git apply --reverse --check. Обратный патч откатывает только эту задачу. Миграции и откат данных не нужны.

После установки кода необходимо перезапустить только Host Agent/Asset Manager и обновить Game1Bridge штатным system/studio-plugin/install.ps1. Rojo перезапускать не нужно. Применение патча не перепубликовывает ассеты.
