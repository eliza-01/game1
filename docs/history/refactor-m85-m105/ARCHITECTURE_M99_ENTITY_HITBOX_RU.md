# M99 · EntityHitboxService — разделение обязанностей

> **Исторический документ.** Фиксирует состояние на момент указанного этапа; отдельные механизмы могли быть заменены. Действующие контракты: [актуальное ТЗ](../../spec/CURRENT_PROJECT_SPEC_RU.md), [архитектура](../../architecture/CURRENT_ARCHITECTURE_RU.md).


**База:** диагностический архив `game1_diag_2026-10-16_10-23-07.zip` (после M98).
**Цель:** сохранить текущий серверный контракт боевых хитбоксов и разделить загрузку мешей, построение определения, трансформации костей и пространственные запросы.

## Границы ответственности

| Модуль | Владеет | Не владеет |
|---|---|---|
| `EntityHitboxService` | Привязка `Model`/`visual`, список доступных для урона сущностей, публичный API, атрибуты и Studio debug folders, Heartbeat serial | EditableMesh, кэш определений, SAT и ray математикой |
| `HitboxMeshGeometryCache` | Загрузка исходных вершин через `AssetService`, кэш по идентификатору меша, ожидание загрузки, освобождение временного EditableMesh | Применение урона и мировые трансформации |
| `HitboxDefinitionBuilder` | Масштабирование вершин, привязка к костям, построение локальных OBB и головы, кэш готовых определений по ригу/масштабу | Сеть, Heartbeat и пространственные запросы при атаке |
| `HitboxRuntimeFrames` | Пересчёт мировых CFrame из костей, не более одного раза на binding/Heartbeat serial | Хиттест и загрузка геометрии |
| `HitboxSpatialQueries` | Broad-phase сфера, пересечение OBB, нахождение ближайшей точки, конечный луч прицеливания | Реестр сущностей, выстрелы, урон и редактор |

## Совместимость

- Сохранены `EntityHitboxService.Start`, `Attach`, `Detach`, `QueryDamageablesInBox`, `RaycastAimRegions` и их возвращаемые данные.
- Сохранены значения `MIN_BOX_AXIS`, `BODY_BOX_PADDING`, `HEAD_BOX_PADDING`, `BROAD_RADIUS_PADDING`, `SAT_EPSILON`; тело и голова вычисляются по прежним формулам.
- Проверка головы по-прежнему выполняется первой; при точном совпадении расстояний headshot-классификация предпочтительнее тела.
- Многократные контакты с разными сущностями и `excludedTargets` сохранены.
- При `Detach` удаляются debug-папки и диагностические атрибуты. Definition cache и source mesh cache, как и прежде, живут до завершения серверного процесса.
- Миграций, изменений RemoteEvent, схем данных, AI и навигации нет.

## Проверки и ограничения

- `python system/verify/verify.py` и `python -W error::ResourceWarning -m unittest discover -s system/verify -p test_*.py -q`.
- Девять новых статических контрактных проверок M99. Сверкой исходных секций подтверждено, что тело процедур построения определений, обновления CFrame и пространственных вычислений перенесено без изменения алгоритмов (изменены только сигнатуры/передача serial и вызов соседнего модуля).
- **Roblox Studio не запускался в среде подготовки патча.** После применения проверить атаку по нескольким Monster/NPC, headshot у движущейся цели, быстрый респавн и включение визуализации хитбоксов в Studio.

## Не входит в M99

Улучшение точности хитбоксов, новые геометрические эвристики, обход препятствий, изменение damage/bounce, политика очистки кэшей по TTL. Эти вопросы требуют отдельного этапа с измерениями и Studio Play тестированием.
