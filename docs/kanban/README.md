# Eyesland — Development Kanban

**Статус:** CURRENT tooling, **карточки:** PROPOSED, **версия:** M339 / 2026-11-13.

Карточки: `cards/KBN-XXXX.json` · Полные рабочие документы: `specs/KBN-XXXX.md` · Журнал: `history/KBN-XXXX.jsonl` (появляется после первой записи).

Источник истины — Git. UI Asset Manager показывает карточки, их документацию, чек-листы, критерии приёмки, подтверждения и историю. SQLite не изменяется. Локальные резервные копии каждой записи: `.control-center/backups/kanban/<id>/`.

Редактирование через UI использует `expectedRevision`, проверку SHA256 документа, атомарную запись и журнал. При ручных изменениях Markdown в Git обновить `specSha256` в карточке тем же коммитом (SHA256 UTF-8); иначе API выдаст конфликт и запретит запись. Исторические `docs/history` и первоначальные пользовательские ТЗ не переписываются автоматически.

**Принятие:** отметка задачи — не проверка; `PASS` требует текстового доказательства, а `DONE` блокируется до выполнения всех задач и проверок. Для изменения документа вне `PROPOSED/ON_HOLD` UI требует отдельного подтверждения политики и причины. Изменения старых контрактов должны проходить review diff.

**API:** GET `/api/kanban`, `/api/kanban/<id>`, `/api/kanban/<id>/history`, `/api/kanban/export`; POST `/api/kanban/<id>` с `expectedRevision` и `action=task|task-add|acceptance|acceptance-add|item-title|status|spec`; создание — `POST /api/kanban`. Доступ через существующий авторизованный Host Agent. Записи живут в Git; истории и backups откатываются вместе с файлами при ошибках записи.

Новые карточки создаются в Kanban через «+ Новая механика», получают следующий постоянный ID и попадают в Git вместе с документом; существующие IDs не перенумеровываются. Документация и код не переписываются агентом автоматически по отметке чекбокса.
