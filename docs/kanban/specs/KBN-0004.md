# KBN-0004 — Контракт Location Assets: FULL / LOD1 / Collision

**В работе.** Текущий приоритет — только Location Assets. Real Estate отложен по решению владельца проекта.

## Источник истины

- Один `slug` зарегистрированного Location Asset; имя/категория/appearance относятся к ресурсу в целом.
- `FULL` — существующая опубликованная Model и её версии; действующий `model_asset_id` не переиспользуется для LOD.
- `LOD1` — **необязательная** отдельная FBX-ревизия и опубликованный Roblox **Model Asset ID**. История публикаций сохраняется. Не загружать LOD в существующие экземпляры автоматически.
- `Collision Blueprint` — отдельная физика из Roblox Parts, доступная независимо от визуальной версии и дистанции; COL mesh не возвращаем.
- Atlas и Roblox Material/Color обслуживаются существующим режимом Appearance, не вводится второй Atlas Registry.

## Pivot и масштаб

Model:GetPivot(), MeshPart:GetPivot(), MeshPart.CFrame и PivotOffset — разные свойства; оси и начала могут отличаться. Нельзя переписывать их при регистрации LOD. Совпадение Pivot FULL и LOD должно **проверяться относительно фактической визуальной геометрии**, не предполагаться. Повороты на 90 градусов или исправления Size «на глаз» запрещены. Требования к автоматическому выравниванию LOD будут утверждены после реального тестового FBX.

## Стандарт имени LOD

LOD1 для `asset_slug` называется `asset_slug_lod1` (FBX `asset_slug_lod1.fbx`, Roblox Model display name `asset_slug_lod1`). Это дочерняя ревизия, не отдельный Location Asset. Регистрируем только файл с ожидаемым именем, не переименовываем исходные файлы пользователя.

## Сейчас реализуется

- `LOD1` появляется в редакторе Location Asset как самостоятельный ресурс (выбор FBX → Register → Publish).
- Состояния: NOT_REGISTERED, STAGED, UPDATE_AVAILABLE, PUBLISHED, SOURCE_MISSING.
- Реестр экспортирует `lod1ModelAssetId` **только если опубликованная ревизия актуальна**, отдельно от `modelAssetId` FULL. Снимок JSON хранит дополнительные данные для диагностики.
- Авторский FBX сохраняется в `assets/source/location-assets/.../lod/lod1.fbx`, старые ревизии архивируются. Нет нового Place/Sync/Roblox runtime кода.

## Следующие шаги (без привязки к номерам патчей)

1. Подготовить один реальный LOD1 FBX для статичного Location Asset и проверить геометрию, ориентацию, UV и материалы.
2. Проверить публикацию через Open Cloud на реальном аккаунте и отдельный Model ID.
3. Реализовать отдельный preview/validation FULL ↔ LOD1 без изменения исходных Pivot.
4. Только после этого — клиентский FULL / LOD1 / UNLOADED.

## Приёмка и откат

Тесты SQLite, истории, rename, retire, API и экспорта могут пройти без FBX. Реальная публикация/Studio/телефон остаются NOT_RUN, пока не проверены. Перед применением изменений сделать резервную копию базы; новая таблица аддитивная. Возврат патча не должен удалять уже опубликованные Roblox Asset ID. Спецификация не объявляет Streaming реализованным.
