# KBN-0013 — Collision Blueprint (Part) и удаление COL Mesh

**Приоритет P0.** Архитектура M342 окончательно выводит `col_mesh`/`COL_*` из Real Estate и Location Assets. Физика домов временно отсутствует до реализации Part Blueprint. **Никаких legacy fallback и no-op COL rigs.**

## Утверждённые инварианты

1. Источник активного дома — `house` визуальный меш, остальные визуальные меши, сокеты/дверь и опубликованные Asset ID. Отдельный `Col_meshRig` больше не существует.
2. При загрузке FBX и публикации устаревшие COL-меши отбрасываются из временной сборки; мастер-файл не перезаписывается.
3. В Studio после Sync либо при открытии/вставке управляемой модели устаревшие COL-экземпляры удаляются из шаблонов и размещённых домов. Это согласованное намеренно деструктивное действие.
4. Real Estate сохраняет авторский Pivot визуального `house` и Plot Bindings, дверь и сокеты; массовый Place и Clear не переписываются.
5. Новая коллизия строится из `Parts` как отдельный версионируемый Blueprint; координаты относительно `house:GetPivot()`, серверный жизненный цикл независим от FULL/LOD.
6. Визуальные MeshParts по умолчанию неколлидирующие; точность коллизии любого намеренно collidable MeshPart не принуждается к Precise.

## M342R — корректировка фактической миграции в Studio

Обнаружено после применения M342 в Windows: миграция реестров прошла, но
профильный тест не закрыл SQLite handle (`WinError 32`) и установка Studio
Bridge не запустилась. Старые объекты в Workspace оставались на месте.
Дополнительно Place Registry продолжал требовать обязательный COL-меш.

Коррекция M342R (`docs/workflows/M342R_COL_MESH_CLEANUP_FIX_RU.md`):

- Явное закрытие соединений SQLite в тесте.
- Удаление обязательных проверок COL в Place Registry и Location UI.
- Очистка старых неразмеченных размещений в `Workspace.Places` и
  `Workspace.Plots`, а также серверных шаблонов, при запуске плагина в Edit Mode.
- Исполнение и сохранение Place проверяет владелец Roblox Studio; до проверки
  шаг миграции KBN-0013-T12 остаётся **не выполнен**.
- Старые Roblox Model Asset IDs остаются неизменными; в новые Instance COL
  больше не должен поступать.

## Следующая реализация Collision Blueprint

- В Asset Manager → Real Estate → Collision: Capture / Preview / Validate / Restore revision.
- Сохранять `houseSlug`, `revision`, `housePivot` reference, список Roblox Part типов с `Size`, `Shape`, относительным `CFrame`, `CollisionGroup`, `CanCollide`, `CanTouch`, `CanQuery`.
- Генератор размещает одни и те же коллайдеры независимо от поворота Plot; серверные Parts не принадлежат клиентскому LOD.
- Тесты первого дома, 2 Plot с разными поворотами, затем 50 Plot со сложным домом, мультиплеер, Android.

## Последовательность

M342: удалить старую систему (код + SQL миграция + очистка Studio) → M343: схемы/хранение Blueprint → M344: Capture/Preview → M345: генерация Parts в существующем Real Estate → M346: стресс-тест 50 Plot и замеры.

## Проверенные зависимости и откат

- `StudioRealEstateHouseFrame` — действующий контракт авторского pivot `house`; нельзя заменять на корневой `Model:GetPivot()`. Старый **legacy-model-pivot** из Place Bindings учитываем при миграции размещения, но не используем как pivot новой коллизии.
- `Col_meshRig` — удаляется из Studio и активного реестра; возврат этой модели не допускается. `PreciseConvexDecomposition` больше не выставляется автоматически.
- **Location Assets** — вторая область удаления устаревших COL-мешей, без отключения коллизии у обычных визуальных MeshParts.
- **Rollback** — резервные копии SQLite/манифестов создаёт мигратор, Place сохраняется владельцем до запуска Studio Bridge. Откат старой коллизии не является поддерживаемым runtime-режимом; восстановление Place — только аварийная операция из сделанной владельцем копии.
