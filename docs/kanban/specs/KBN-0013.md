# KBN-0013 — Real Estate: Collision Blueprint и безопасная миграция с `col_mesh`

**Решение владельца:** подтверждено в диалоге 2026-11-13. **Технический контракт:** READY; **реализация/миграция:** НЕ НАЧАТА.
**Приоритет:** P0 (одна из первых механик перед массовой подготовкой LOD/домов).
**Область:** зарегистрированные дома Real Estate; другие категории Location Assets, монстры, NPC и персонажи не мигрируют автоматически.
**Источник для оценки существующего кода:** `game1_diag_2026-11-13_23-38-18.zip` + установленный M339R. Перед правками повторно сверить актуальный репозиторий.

## 1. Цель и утверждённая политика

Для каждого зарегистрированного **типа дома** (`houseSlug`) создать переиспользуемый **Collision Blueprint** из стандартных Roblox `Part`/`WedgePart`/`CornerWedgePart`, один раз собранный в Roblox Studio. Blueprint содержит геометрию физических препятствий в локальной системе координат **авторского pivot меша `house`**. `Place`/`Place all` на любом Plot создают серверные коллайдеры в правильном положении и ориентации; клиентские FULL/LOD1/UNLOADED на физику не влияют.

**Дефолт:** невидимые anchored Roblox Parts с простыми физическими формами. `MeshPart` разрешён как *явно документированное исключение* для формы, которую нельзя экономно представить примитивами (и со своим обоснованием/замерами). Не делать глобального запрета `MeshPart`: другие Location Assets используют `col_mesh` и находятся вне сферы этой миграции.

**Миграция:** для домов Real Estate постепенно отказаться от старого `Col_meshRig`/`col_mesh` как основной геометрии коллизий. Никаких удалений без сохранённого нового Blueprint, проверенного round-trip и smoke-test двух Plot. Исключить наложение двух активных коллизий после переключения.

## 2. Подтверждённые зависимости текущего проекта

- `system/studio-plugin/modules/StudioRealEstateCollisionPolicy.luau` сейчас принудительно ставит `PreciseConvexDecomposition` всем collidable **MeshParts** и маркирует их `Game1RealEstateCollider`; эта политика не должна применяться к новым primitive Parts.
- `system/studio-plugin/modules/StudioRealEstatePlacedPhysicsGuard.luau` восстанавливает свойства коллизионных MeshParts у вставленных домов; после миграции нужен режим, различающий legacy MeshPart и новые Parts.
- `system/studio-plugin/modules/StudioRealEstateHouseFrame.luau` использует стабильный авторский `house:GetPivot()`; **не заменять** его `Model:GetPivot()` или геометрическим `house.CFrame`.
- `system/control-center/real_estate/placement.py`, M229/M230 различают **house-anchor-v2** и **legacy-model-pivot**. Blueprint не должен переписывать Binding, `houseAnchorLocalCFrame` или принудительно делать Re-Bind старых участков.
- `system/control-center/real_estate/store.py` хранит регистрацию Real Estate и версии в SQLite; модель данных/источник истины для Blueprint выбираем после аудита, не вводим дублирующие неуправляемые копии.
- Existing `HouseSocketService`, двери, лифты/площадки и Prompt должны сохранить независимую интерактивную физику. Коллизии стен не должны перекрывать дверной проём.
- У других **Location Assets** есть `col_mesh` и `MeshPhysicsCore`; эта карточка **не** удаляет и не переписывает их.

Связанные документы: `docs/workflows/REAL_ESTATE_COPIED_PHYSICS_M209_RU.md`, `REAL_ESTATE_PLACEMENT_ROTATION_M229_RU.md`, `REAL_ESTATE_PLACEMENT_LEGACY_COMPAT_M230_RU.md`, `docs/kanban/specs/KBN-0004.md`, `KBN-0008.md`.

## 3. Контракт данных Blueprint (проектируемый, НЕ действующий API)

Рекомендуемая структура (точное место хранения определить на аудите):

```json
{
  "schemaVersion": 1,
  "houseSlug": "house_level1_01",
  "revision": 1,
  "anchorKind": "authored-house-pivot-v1",
  "capturedModelScale": 1.0,
  "parts": [
    {
      "id": "wall_front_left",
      "className": "Part",
      "shape": "Block",
      "size": [5.0, 9.0, 1.0],
      "localCFrame": [0, 0, 0, 1, 0, 0, 0, 1, 0, 0, 0, 1],
      "canCollide": true,
      "canTouch": false,
      "canQuery": true,
      "collisionGroup": "Default"
    }
  ]
}
```

Значения `size` и `localCFrame` выше — **иллюстративный формат, не фактические размеры дома**. `localCFrame` — 12 компонентов `CFrame:GetComponents()`; хранить точность чисел без преждевременного округления. `part.id` стабилен внутри версии Blueprint. Валидатор запрещает дубли, нули и отрицательные размеры, NaN/Inf, непредусмотренные классы, неортонормальные CFrame, отсутствие `houseSlug`, несогласованный масштаб и неизвестные CollisionGroup. Без arbitrary scripts/instances из UI.

Свойства с фиксированными безопасными значениями **не обязательно сохранять для каждого Part**, они восстанавливаются из политики: `Anchored=true`, `Transparency=1`, `CastShadow=false`, `Massless=true` при необходимости только по проверенному физическому правилу. `CanCollide=true`, `CanTouch=false` по умолчанию. `CanQuery=true`, если требуются Raycast/Overlap; случаи без query — только после проверки игровой логики. Триггеры `Touched`, двери и лифт — отдельные системы, не заменяем их статическими частями.

Для `WedgePart`/`CornerWedgePart` форма определяется классом; `shape` используется только для `Part` (`Block`, `Ball`, `Cylinder`). `MeshPart` в v1 Blueprint не принимается без отдельного расширения формата.

### 3.1. Система координат и масштаб

Захват производится в **Studio Edit mode** из выбранного управляемого дома:

```lua
local houseAnchor = StudioRealEstateHouseFrame.Find(sourceModel)
assert(houseAnchor, "exactly one house MeshPart is required")
local anchorWorld = houseAnchor:GetPivot()
local relative = anchorWorld:ToObjectSpace(collider.CFrame)
```

Восстановление после позиционирования дома существующим Place:

```lua
local placedAnchorWorld = placedHouseAnchor:GetPivot()
local worldPartCFrame = placedAnchorWorld * savedLocalCFrame
```

При отличии масштаба placement от capturedModelScale позиции в локальных CFrame и `Size` должны масштабироваться **одним общим коэффициентом** по локальным осям, ориентации сохраняться; реализовать и проверить отдельно. Не допускать неравномерный масштаб. Не считать, что перемножения CFrame масштабируют координаты автоматически. Для старых `legacy-model-pivot` использовать **фактический** `placedHouseAnchor:GetPivot()` после штатного Place, не пытаться восстановить несохранённый исторический offset.

## 4. Authoring: создание и Capture Collision

1. В Studio Edit выбрать зарегистрированный `houseSlug` и разместить **авторскую копию** на тестовом Plot; сохранить резервную копию проекта.
2. Собрать `CollisionAuthoring`/`CollisionParts` (рабочее имя папки, утвердить в коде после аудита) из `Part`, `WedgePart`, `CornerWedgePart`. Стены разбивать с учётом дверей, окон и лестниц; избегать большого количества перекрывающихся Parts.
3. Система захвата через существующий Studio Bridge получает выбранный managed root, находит уникальный `house` anchor и **только** явно выделенную группу статических коллайдеров; игнорирует украшения, визуальные меши, двери/триггеры/чужие объекты.
4. `Preview Capture` показывает количество частей, покрытие, список изменений, размер/позиции и нарушения; **никаких записей** до явного подтверждения.
5. `Capture Collision` передаёт структурированный снимок через Bridge в Host Agent. Host Agent валидирует schema, slug, pivot frame, допустимые классы/размеры, источник и ревизию; сохраняет новую версию атомарно, ведёт историю и резервную копию. Нельзя доверять произвольным данным браузера как Roblox Instances.
6. `Preview Placement` на Plot размещает временную **неигровую** копию Blueprint для визуального контроля, не уничтожая старую физику.
7. `Validate` проверяет двери, проходы, лестницы, пол, отсутствие выступающих невидимых стен, collision groups, raycasts, корректность масштаба.

Рабочая папка коллайдеров в Studio — авторский источник. **После capture источник истины при генерации — сохранённый, версионированный Blueprint; изменения сцены без повторного capture не влияют на игровой сервер.** Публикация нового меша/текстуры для примитивных коллайдеров не нужна.

## 5. Генерация и независимость от LOD

- `Real Estate Place` сначала создаёт и выравнивает managed house по существующему контракту. После успешного выравнивания `CollisionBlueprintSpawner` восстанавливает набор Parts в серверном физическом контейнере/подразделе, привязанном к instance ID этого дома.
- В каждой размещённой копии хранить `houseSlug`, `collisionBlueprintRevision` и идентификатор placement, чтобы исключить дубликаты при повторном Place/Sync и выполнять stage-before-destroy.
- Коллизия принадлежит **серверу**. Клиентский FULL/LOD/NONE не создаёт и не уничтожает эти Parts. `Workspace.StreamingEnabled` отвечает за доставку физики клиенту по близости.
- При обновлении Blueprint сначала собрать новую группу и проверить геометрию, затем атомарно заменить старую управляемую группу; не удалять интерактивные или пользовательские unmanaged части дома.
- Учитывать дорогие операции сотен Parts при `Place all`: ограничение пакетной работы/метрики, без per-frame scans. Сам факт, что Part проще MeshPart, **не доказывает** ускорение для всех домов; тестировать число контактных пар и физический кадр.

## 6. Безопасная миграция (отказ от `col_mesh` **только для Real Estate**)

**Правило:** миграция — отдельный этап исполнения, не входит в этот документационный патч. Запрещено автоматически удалять старый `Col_meshRig`, пока новая физика не покрывает его назначение и не прошла acceptance.

### Stage M0 — read-only inventory и резервные копии

- Зафиксировать commit, версию Studio Bridge и состояние `ServerStorage/real_estate`, `Workspace/Plots`, SQLite Real Estate/Placements, экспортных манифестов и связанных шаблонов.
- Экспортировать фактические размеры/пути всех `Col_meshRig`/`col_mesh`, PrimaryPart/Pivot/Anchor, collision flags, ссылки/теги/скрипты. Проверить HouseRig, двери, анимации, Prompt/сокеты, `StudioRealEstateCollisionPolicy`, `PlacedPhysicsGuard`, Sync/Place/Undo.
- Backup SQLite через sqlite `backup()` (не копирование открытой WAL базы); сохранить исходный `.rbxl/.rbxlx` и manifest; проверить возможность восстановления.

### Stage M1 — реализация контракта и инструментов

- Определить и зарегистрировать формат Blueprint, валидацию, индексацию/хранение версий, API Preview/Capture/Restore, Studio Bridge команды с версиями wire protocol.
- Реализовать безопасную генерацию из **частей** и удаление только **управляемых** экземпляров; сохранить legacy path и toggle только для dev/staging.
- Добавить автоматические проверки CFrame, nonuniform-scale reject, missing anchor, stale revision, collisionGroup, idempotency и невозможность случайно удалить чужие объекты.

### Stage M2 — один дом, одна копия

- `house_level1_01`: вручную подготовить Part Blueprint в Studio, захватить, сравнить геометрию и проверить `Preview`.
- В отдельном тестовом Place сначала использовать **либо** legacy col_mesh, **либо** primitive Blueprint, но не оба одновременно. Сравнить walk-through, двери, пол, лестницы, raycasts и физические метрики.

### Stage M3 — Plot + multiplayer/Streaming

- Place/Place all на 2+ участках с разным CFrame/поворотом/масштабом, в том числе один legacy binding. Выполнить Clear/Undo, Sync, Insert/Copy в Studio Edit.
- Два игрока: server-authoritative collision при FULL/LOD/UNLOADED, корректность окна и двери, переход сектора и телепорт. Проверить слабый телефон и серверную физику.

### Stage M4 — переключение и вывод legacy из использования

- Только при PASS зафиксировать Blueprint revision для конкретного `houseSlug`, включить primitive policy для него, отключить old collider в **его** managed clones/templates и deprecated M209 restoration для migrated houses.
- Не удалять `col_mesh`, если он является `PrimaryPart`, источником pivot, опорой скрипта/сокета/риг-привязки: сначала переназначить ссылку, затем отдельно подтвердить удаление.
- Оставить совместимость со старыми домами без Blueprint, но дать предупреждение/статус `LEGACY_COLLISION`. Запретить массовое удаление `col_mesh` из Location Assets, разными домами проводить постепенный rollout.

### Stage M5 — очистка и архивирование

- После нескольких итераций успешных тестов и отдельного утверждения удалить только заменённые legacy colliders из управляемых Real Estate шаблонов/копий, обновить политики Studio и документацию. Старые публикационные IDs/исторические манифесты остаются в архиве; повторная публикация FULL не требуется без других причин.

**Rollback:** переключить дом в `LEGACY_COLLISION`/восстановить исходный шаблон и резервную копию регистра; для очередной миграции не переписывать уже занятые Placement bindings, DataStore, publication IDs. Сохранить копию Blueprint даже при откате.

## 7. Проверки и доказательства результата (Definition of Done)

- [ ] Точный round-trip локального `CFrame`, размера и поворота; повернутый дом на двух Plot с одинаковой относительной геометрией.
- [ ] Все двери, проёмы, лестницы, этажи, окна/сокеты/лифт работают; никаких невидимых блокировок.
- [ ] FULL / LOD1 / UNLOADED не меняют серверные коллизии; клиенты могут иметь разные LOD у одного дома.
- [ ] Нет удвоенной коллизии и дублей при Place/Place all/Copy/Sync/Clear/Undo.
- [ ] Старые Real Estate дома без Blueprint продолжают работать до миграции.
- [ ] Location Assets `col_mesh` вне Real Estate не изменены.
- [ ] Повторные операции не создают утечек Instances; старые Copies/Bindings/IDs не теряются.
- [ ] Проверены `verify.py`, профильные тесты, Studio Edit/Play, Eyesland DEV на смартфоне; baseline и новая физика измерены одинаковыми сценариями.
- [ ] Подтверждён rollback на тестовой копии, история миграции и доказательства PASS прикреплены в Kanban.

## 8. Границы этого документационного патча

В этой версии **только регистрация утверждённой механики и плана в Kanban**. Не создан Capture API, не изменён `RealEstateStore`, не выполнены миграции SQLite/Studio, не удалён `col_mesh`, не изменена физика текущих домов. Отдельным последующим патчем — Stage M0/M1; его применение допускается после проверки живого проекта и backup.
