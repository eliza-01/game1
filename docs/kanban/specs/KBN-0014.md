# KBN-0014 — Location Assets: Collision Blueprint + Atlas / Roblox Material

**Версия архитектурного контракта:** 1.2 · **Приоритет:** P0 · **Статус:** M343A1 + M343B1 (Studio multi-selection Capture/Preview, требует проверки в Roblox Studio).

## Принятые решения

1. **Location Assets — сначала.** Real Estate продолжает работу по KBN-0013 отдельно; никакой правки Place/Clear домов до готовности сложного тестового дома.
2. **Физика:** статическая коллизия Location Asset описывается Roblox `Part`, `WedgePart`, `CornerWedgePart` относительно `Model:GetPivot()`. `col_mesh`, `COL_*` и прочие специальные MeshPart-коллайдеры не возвращаются в стандарт.
3. **Идентичность:** один blueprint привязан к зарегистрированному `Location Asset slug`, не к отдельной точке размещения. Для каждого Placement создаются собственные серверные Parts с тем же локальным расположением.
4. **Графика и физика не смешиваются:** созданные на сервере коллайдеры не принадлежат клиентскому FULL / LOD и не удаляются при выключении визуала.
5. **Внешний вид:** два режима `atlas` и `material`. Для новых моделей **предлагаемый** стандарт `material / SmoothPlastic / #FFFFFF`, с изменением через контролируемый выбор при публикации. Существующие модели остаются `atlas` до явного перевода владельцем.
6. Существующее `surfaceMaterial` означает **физический материал / семейство звуков**, а не выбранный визуальный материал. В новой схеме используются независимые `appearanceMode`, `robloxMaterial`, `colorHex`.
7. При `atlas` необходим опубликованный Image ID и актуальная привязка. При `material` публикуется только Model; выбранные `Enum.Material` и `Color3` применяются к визуальным MeshParts на явном Studio Sync.
8. Sync `atlas` ↔ `material` атомарен на уровне размещённой модели: подготовка, проверка актуальной ревизии и сохранности pivot, изменение внешнего вида, Undo, запись результата в историю. Он не должен заменять геометрию лишь из-за смены цвета.
9. Для `material` устанавливаются `MeshPart.TextureID = ""`, `MeshPart.Material`, `MeshPart.Color`. Цветовая текстура `SurfaceAppearance.ColorMap` не должна перекрывать материал: отдельно определяем её безопасное удаление/сброс после проверки тестовой модели. Не удаляем произвольно Bones, welds, children или неавторские поверхности.
10. Для многоцветной модели режим одного `Material+Color` **не раскрашивает разные полигоны по-разному**. Профиль задаёт default для ассета; для нескольких самостоятельных визуальных MeshParts в следующем этапе предусмотреть именованные per-part overrides (не по позиции в массиве). Для разных цветов в одном MeshPart нужен атлас либо разделение геометрии при авторинге.

## M343A — готовый безопасный фундамент

Код хранит Collision Blueprint в `location_asset_collision_blueprints` (SQLite, самостоятельная таблица, без миграции данных FBX/Atlas). Ревизии монотонны; одинаковый повторный Capture не создаёт новую ревизию; stale Capture отвергается. История сохраняется при удалении (в архиве), slug rename переносит историю.

**JSON v1**:

```json
{
  "schemaVersion": 1,
  "pivot": "Model:GetPivot()",
  "parts": [{
    "id": "wall_01",
    "name": "Wall 01",
    "shape": "Block",
    "size": [8, 5, 0.5],
    "localCFrame": [0, 0, 0, 1, 0, 0, 0, 1, 0, 0, 0, 1],
    "collisionGroup": "Default",
    "canQuery": true,
    "canTouch": false
  }]
}
```

- `localCFrame = registeredModel:GetPivot():ToObjectSpace(part.CFrame)`; 12 чисел возвращает `GetComponents()`.
- Восстановление: `part.CFrame = placementPivot * CFrame.new(table.unpack(localCFrame))`. Масштабирование, изменение root/pivot и слепое сохранение импортированных RootPart на данном этапе **не поддерживаются**: отдельные тесты масштабирования предшествуют подключению к размещениям.
- Обязательные параметры созданного коллайдера: `Anchored=true`, `CanCollide=true`, `Transparency=1`, `CastShadow=false`. `CanTouch` и `CanQuery` задаются рецептом; группа коллизий должна существовать.
- `shape` допускает `Block`, `Ball`, `Cylinder`, `Wedge`, `CornerWedge` — исключительно Part-классы. Не смешивать `MeshPart` с Part.
- Ограничения: максимум 256 примитивов; неотрицательные размеры/конечные координаты, ортонормальная ориентация без отражения, уникальные ID, строгие типы, защита от устаревшей ревизии.
- `GET /api/location-assets/{slug}/collision-blueprint` возвращает blueprint или `{revision:0,blueprint:null}`.
- `POST /api/location-assets/{slug}/collision-blueprint` принимает `{expectedRevision:int, blueprint:{...}}`; авторизуется обычным Control Center API. **Не вызывает Studio Capture или Sync.**
- Сводка в `GET /api/location-assets`: `collisionBlueprintRevision`, `collisionBlueprintPartCount`.

## M343B — Studio Capture / Preview / Validate

1. Studio-плагин работает в Edit Mode; пользователь одновременно выбирает одну Model уже размещённого Location Asset и 1–256 произвольных Parts где угодно внутри Workspace. Без специальной папки.
2. Сверяет полный набор визуальных Mesh ID Model с зарегистрированной историей опубликованных Model; имя или атрибут slug недостаточны. Pivot используется существующий, не редактируется. Имена Parts произвольные, ID назначаются автоматически для дубликатов/не-ASCII.
3. Показ предварительного списка; **Capture** записывает одну полную новую ревизию через backend, но не меняет текущий Place.
4. **Preview** строит временные клиенту/редактору контуры, не включая удвоенную физику. Clear Preview гарантированно удаляет временное.
5. После повторного Capture отображаем diff и историю ревизий, проверяем race против `expectedRevision`.
6. Валидатор читает **только явное Studio Selection**, отклоняет лишнюю Model, MeshPart и объекты за пределами Workspace; никакого массового поиска кандидатов и изменения выбранных объектов.

### M343B1 — исправленный протокол (код готов, Studio NOT_RUN)

- Новый отдельный API `POST /api/location-assets/{slug}/collision-studio` принимает только `phase` (`validate`, `capture`, `preview`, `clear-preview`). Он никогда не делает массовое размещение.
- Сервис синхронизирует одну Studio-команду с backend: **одна Model + выбранные Part-примитивы** (без папок), в том числе в `Workspace.Places/Plots`. Авторизация Model выполняется по опубликованной сигнатуре визуальных Mesh ID, с проверкой отсутствия двусмысленной сигнатуры у другого зарегистрированного ассета. Текущий Pivot модели не изменяется. `CanCollide` и имена Parts не требуют ручного редактирования. `Model:GetScale()` должен быть равен 1 до отдельной поддержки масштабирования.
- `Capture` канонизируется Python-валидатором и сохраняется только при ожидаемой ревизии. `Validate` возвращает diff, не пишет в SQLite. `GET /api/location-assets/{slug}/collision-history` возвращает историю сохранённых ревизий.
- `Preview` использует сохранённый Blueprint и временную помеченную папку в Workspace c прозрачными `Part`-призраками без столкновений, касаний и пространственных запросов. `Clear Preview` удаляет только помеченную папку; при выгрузке плагина тоже очищается.
- Новый Luau-модуль загружается через защищённый `pcall(require)` **после** создания Plots и DecoManager. Ошибка Collision Authoring не должна отключить Place Registry и Plots.
- Studio-Playtest, реальный контроль Pivot и масштабирования, а также UI-функциональная приёмка **не выполнены** на момент создания патча. Они обязательны перед M343C.

## M343C — безопасное размещение/Sync коллизии

1. К существующему Location Place/Sync добавить **отдельную операцию** обновления серверных коллайдеров, а не переписывать управление визуальным rig.
2. Строить Parts из Blueprint по экземпляру `placementPivot`, сохранять маркеры `Game1CollisionBlueprintSlug/Revision/PlacementId`. Для отсутствующего Placement ID обязателен подтверждённый owner/root, случайный массовый Repair запрещён.
3. Выполнять проверку готовой сборки до замены: конфигурация, Pivot, масштаб, CollisionGroup и количество Parts. При ошибке — никаких изменений работающего Place.
4. Сохранять Undo через ChangeHistoryService. Повторный Sync той же ревизии не создаёт дубликатов.
5. Протестировать `stone_fence_01`, `christmas_tree_01`, лестницу/мост и модель с Bones. Динамическая/движущаяся коллизия вне этого этапа.

### M343C implementation (2026-11-14; Studio NOT_RUN)

- DecoManager Place creates managed collision Parts from the currently saved Blueprint. Place Registry Scan/Sync handles collision-only pending rows in the existing explicit Sync transaction; new Parts are invisible and anchored.
- Generated Parts are direct Model children with `Game1LocationCollisionOwned` marker; no user authoring folders. Existing Blender Pivot is read-only; relative part frames and sizes adapt to `Model:GetScale()`.
- The generator stages, commits, rolls back and finalizes its own Parts, and child-rig history ignores those parts. Missing/ambiguous owners remain blocked. No automatic startup repair.
- Persistence comes from saving the modified Studio Place. Gameplay uses physical Roblox Parts; no runtime-generated dynamic/animated colliders in this patch.
- Full Studio acceptance (placements, rotations, scale, Undo, physics in Play and saved Place) remains **NOT_RUN**, so task T08 stays pending.

## M343D — режим публикации Atlas / Roblox Material и Sync

1. Валидируемый перечень Roblox `Enum.Material`, HEX/RGB-пикер, default `SmoothPlastic / #FFFFFF`; необязательные настройки отдельно для зарегистрированных визуальных MeshParts. Для плоских alpha-листьев режим без атласа может быть непригоден.
2. Персистентный выбор `appearanceMode`, `robloxMaterial`, `colorHex`, версионирование, экспорт в LocationAssetRegistry и манифест.
3. Регистрация **без атласа** допустима в режиме `material`, Model FBX необходим, отдельная публикация Image не запускается. Существующие Atlas-привязки сохраняются для отката и не удаляются автоматически.
4. UI в Registration и Edit/Publish: явный переключатель режимов, `Atlas`-панель только в соответствующем режиме; `Material`-панель с цветом, выбор должен сохраняться до публикации.
5. Studio размещение и Sync учитывают режим и смену цвета без повторной публикации FBX. Для `material` устраняют старые TextureID/ColorMap; для `atlas` восстанавливают выбранный опубликованный Image ID.
6. Полный проход `Find → Preview → Sync → Find(current)` с явной проверкой `appearanceRevision`; запрет немого применения к другим Location Assets.
7. Тесты для старых Atlas-моделей, новой модели без атласа, переключения обоих направлений, моделей с Bones, очистки Material/ColorMap и отсутствия дублирования публикаций.
