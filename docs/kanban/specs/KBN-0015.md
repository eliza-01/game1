# KBN-0015 — Instance Manager: замена старых масштабированных Location Assets

Статус: **код M351 подготовлен, приёмка в реальной Roblox Studio не выполнена**.
Область: **Asset Manager → Location Assets → Instance Manager**. Не затрагивать Real Estate, публикацию FBX, старую систему COL или архитектуру Collision Blueprint.

## Основание

Существующие размещённые заборы `stone_fence_01` до перехода на Collision Blueprint часто изменялись через `MeshPart.Size` (по отдельным осям) и могли получить изменённый `PivotOffset` при прежних Sync/Repair. В результате `Model:GetScale()` обычно равен 1, но реальная геометрия отличается от публикации. Новый Replace M347 переносил только `Model:GetScale` и `Model:GetPivot`, поэтому у старых размещений менялись масштаб, положение и направление, а новые заменялись правильно. M350 уже поддерживает неравномерный Size для коллизий — M351 дополняет именно замену визуального ассета.

## Утверждённые ограничения и контракт

1. Старое размещение полностью неизменно до Commit, удаление через `Parent=nil`, одна запись Studio Undo. `Destroy` исходной Model запрещён.
2. `Preview` доказывает принадлежность старой модели по текущему каталогу и конкретному ID исторической публикации. Модель публикации загружается только для чтения; одинаковые ID кэшируются на Preview.
3. Основа для восстановления — реальный `MeshPart.CFrame` и геометрия исторической публикации. **НЕ** изменяем `MeshPart.PivotOffset` старой или новой модели и не приближаем по Bounds.
4. Если исторический `PivotOffset` визуального меша отличается от опубликованного, вычисляем каноническую опорную точку через `oldMesh.CFrame * sourcePublishedMesh.CFrame:Inverse() * sourcePublishedModel:GetPivot()`. Если нет подтверждённого rebasing, сохраняем `oldModel:GetPivot()`. UI показывает число восстановленных Pivot.
5. Изменённый вручную Size вычисляется как отдельные коэффициенты `oldMesh.Size / (publishedMesh.Size * oldModelScale / publishedModelScale)`; у target сохраняются **его** исходные размеры, умноженные на эти коэффициенты с доказанным соответствием осей.
6. Для растянутых исходников разрешён только уникальный **статичный** визуальный MeshPart у target без Bones, Attachments, Welds и иных зависимостей. Если исходный и целевой basis требуют shear, не пытаемся угадать размер: Preview отказывает до изменения Place.
7. Сохраняются ручные опоры **Pivot новой Model** и **Pivot нового MeshPart**. Для доказанного одиночного визуального MeshPart source/target добавляется рекомендуемая опора **геометрия MeshPart.CFrame → геометрия MeshPart.CFrame**, чтобы не наследовать исторические 90° между Model Pivot и фактическим мешем. Речь не о Pivot старого MeshPart (он может быть перебазирован).
8. `Collision.Prepare` вызывается на полностью подготовленной Model, уже с перенесённым `MeshPart.Size`. M350 использует те же размеры и CFrame при генерации коллизии.
9. У исходных многомешевых моделей с неизменённым Size применяется существующая M347-механика. Подозрительные индивидуальные изменения Size многомешевых моделей блокируются — пока нет доказанной карты соответствий.
10. Связка Control Center ↔ Game1Bridge переходит на **location-instance-replace-v4**, чтобы устаревший плагин не мог молча выполнить M347-замену.

## Групповые контейнеры и ориентация геометрии

- Группы оград без собственного опубликованного Model ID и прямых BasePart, но с отдельно опубликованными дочерними размещениями, не являются Location Asset экземплярами. При `Replace All` такие группы остаются на месте, дочерние ассеты обрабатываются поштучно; `Selected` на группе раскрывает её размещения.
- Для настоящих опубликованных вложенных/чужих Model, Real Estate и House Preview продолжает действовать запрет замены. Несопоставимые/неполные размещения вызывают понятную ошибку, а не молчаливый пропуск.
- Preview сообщает число размещений, у которых ориентация Model Pivot отличается от физической ориентации MeshPart. Если у source и target по одному доказанному визуальному MeshPart, `Геометрия MeshPart · CFrame` выбирается по умолчанию.
- Эти правила не меняют уже размещённые Model во время Preview, не очищают старые атрибуты контейнеров автоматически и не затрагивают LOD Manager.

## Порядок приёмки на Place

1. Сохранить `.rbxl` и остановить Play. Выбрать **один** `stone_fence_01` со старым `Size` и выполнить Preview. Проверить отметки `исторический Pivot` и `изменённый Size` по фактическим данным.
2. Replace Selected → **Геометрия MeshPart · CFrame**. Проверить мировой `MeshPart.CFrame`, размер по каждой оси, Collision Blueprint, визуальное положение и отсутствие поворота на 90° после Scan. Ручные Pivot новой Model / MeshPart проверить отдельно.
3. Ctrl+Z: исходный экземпляр, CFrame, Size, PivotOffset, ID и Part-коллизии возвращаются. Ctrl+Y: замена снова применена. Проверить редактором Studio, а не только количеством объектов.
4. Второй такой же объект — Replace Selected → Pivot **нового MeshPart**. Сравнить выбор с Preview, убедиться, что это **не Pivot MeshPart старого экземпляра**.
5. Повторить тест на новом (неисторическом) размещении — регрессии быть не должно.
6. Если target имеет сложный rig/несопоставимые оси, проверить отказ до Commit, исходные Model/коллизии и Undo-history не изменяются.
7. Только после этих тестов Replace All (начать с малого набора и одного участка). M351 не даёт автоматического разрешения на массовую замену.

## Диагностика ошибок

- `Cannot verify historical source transforms`: старой публикации нет, mesh inventory неоднозначен или устарела связь ID. Не выполнять Repair вслепую.
- `Manually resized multipart Location rig`: запрещено терять пользовательские Size у многомешевых моделей.
- `Non-uniform legacy Size cannot map`: оси source/target не являются перестановкой локальных осей (потребуется отдельная доказанная карта осей).
- `requires a single, unrigged target MeshPart`: для target сложной иерархии нельзя бездумно применять локальный scale одного MeshPart.

**Что не обещаем:** точное равенство абсолютных размеров двух разных моделей. Сохраняются *коэффициенты пользовательского растяжения* относительно опубликованной исходной геометрии. Точная физическая форма нового ассета всё равно определяется его Mesh ID. Тесты Python проверяют логику и API, но не заменяют фактический Studio Undo/визуальный тест.
