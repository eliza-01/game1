## Границы

Только Asset Manager → Location Assets. Пользователь выбирает LOD1 FBX, сохраняет отдельную ревизию и независимо публикует её в Open Cloud. Существующие FULL Model ID, Atlas ID, Appearance, Collision Blueprint, Studio Sync, DecoManager и Place не меняются. Нет клиентского переключения LOD и автоматического изменения существующих размещений.

## Контракт

- Ключ `(asset_slug, 'lod1')`. Отдельные `sourcePath`, `sourceSha256`, `publishedSha256`, `modelAssetId`, `revision`, `moderationState`, статус.
- Сохранение `sourcePath` не вызывает публикацию. Одинаковая SHA — идемпотентно, не увеличивает revision.
- `Publish LOD1` создаёт **новый Model Asset ID**, не перезаписывает FULL; `location_asset_publications(kind='lod1')` сохраняет историю.
- Только опубликованная актуальная SHA экспортируется в `LocationAssetRegistry.luau.lod1ModelAssetId`. При отсутствии LOD ID пустой и не блокирует FULL.
- Rename переносит LOD-метаданные на новый slug без изменения FBX-пути и ID; retirement архивирует историю и сохраняет исходные файлы.
- Публикация использует существующие Blender staging и Roblox Open Cloud, без отдельной системы аутентификации.

## Приёмка

- Отсутствующий LOD1 не меняет статус зарегистрированного FULL.
- Stage → Stage тем же SHA не создаёт новую ревизию; Stage другим SHA оставляет прежний опубликованный ID в истории, но экспортирует пустой активный LOD1 ID до републикации.
- Ошибка stale revision не меняет запись; неправильный путь не принимается.
- Реальные LOD1 FBX, публикация Open Cloud, подготовка геометрии, материалы, проверка Pivot и загрузка в Roblox Studio **не проверены**.

## Утверждённый стандарт имени

- Для slug `stone_fence_02` файл источника — **`stone_fence_02_lod1.fbx`**.
- Roblox Model display name при отдельной публикации — **`stone_fence_02_lod1`**.
- Формат: `<asset_slug>_lod1`, строчные латинские буквы, цифры и `_` из основного slug.
- LOD1 **не** создаёт новый Location Asset: ключом остаётся родительский slug.
- Collision Blueprint, Atlas/Material и Placement ID принадлежат основному ассету.
- В Blender рекомендуем назвать корневой объект тем же именем. Пока FBX-инспектор НЕ проверяет имя корневой ноды, поэтому не утверждаем, что это автоматически валидируется.
- При Rename родительского slug опубликованный Roblox ID не перепубликуется, старые FBX-ревизии не переименовываются задним числом. Новый файл для регистрации следующей ревизии должен соответствовать **новому** slug.

Это правило проверяется при Register LOD1 по имени выбранного FBX и при Publish — по имени создаваемого Roblox Model. Существующие локальные внутренние пути `.../lod/lod1.fbx` остаются стабильными.
