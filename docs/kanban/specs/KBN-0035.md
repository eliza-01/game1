# KBN-0035 — Performance Profiler · baseline и диагностика

**База:** M605 · 27.11.2026. **Статус:** IN_PROGRESS. План согласован на уровне очереди работ; точные реализации и бюджеты уточняются измерениями.

## Цель, исходные замечания и границы

Следующий этап после функционально принятого M609 (исключение владельца для KBN-0037-T02): создать единую диагностическую инфраструктуру до остальных оптимизаций. Текущая база — M609; для креплений сравнить с сохранённым M605 в отдельной сопоставимой сцене/сборке. Не откатывать рабочий DEV. Ревью M605 — статический анализ, не измерение миллисекунд, FPS или долей CPU. Существующие карточки KBN-0003 (Android baseline) и KBN-0010 (сравнение на устройствах) сохраняют свои задачи и приёмку; результаты этого этапа использовать в них, не дублировать измерения.

Единый диагностический контракт для client/server: время работы и число вызовов подсистем, счётчики Raycast, активных sampler, AI-агентов, запросов навигации, кандидатов хитбоксов, LOD-операций и сетевых событий. Метки MicroProfiler, агрегирование без вывода каждого события; по умолчанию OFF. Не добавлять постоянные дорогостоящие обходы ради диагностики. В опубликованном DEV доступ только в рамках действующего контракта Debug; никакой диагностики для обычного релиза. CPU, GPU, RAM и сетевые показатели измерять раздельно, не выдавать длительность скрипта за полный GPU/frame time.

Зафиксировать воспроизводимый маршрут, версии, число игроков/сущностей, настройки графики, устройство, cold/warm запуск, FPS и p95 времени кадра, RAM, сетевую статистику и 15 минут прохода. Сравнивать одинаковые условия. Эмуляция мобильного в Studio не заменяет физический телефон.

## M610 · Network Motion (блокирующий сценарий)

Два игрока: собственное движение плавное, удалённый персонаж периодически меняет визуальную скорость при ровном беге. Владелец подтвердил, что это не пропуски кадров и не анимация. Десять серверных снимков показали корректное владение NavigationRoot; 458 кадров за 8 с на принимающем клиенте и одинаковая дистанция root/visual не доказывают равномерность скорости. M610 добавляет синхронный 8-секундный read-only замер через Camera Debug → Network motion, один запрос и два ответа, максимум 2 серверных сессии, 2048 samples на канал, 12 с cooldown. Сервер и клиент измеряют горизонтальную позиционную скорость и AssemblyLinearVelocity; клиент также GetRenderCFrame. Время берётся из GetServerTimeNow; mean взвешен по dt, p05/p95 по кадрам, полусекундные bins экспортируются в [NETMOTION]. При закрытии панели клиент прекращает запись, сервер завершает ограниченную сессию. Это первый диагностический сценарий, не исправление причины и не полный profiler. Сетевое владение и движение не изменены. Реальная Studio/DEV приёмка и остальные метрики открыты.

## M611 · Три точки измерения

Получен скриншот M610 от владельца: клиент 8.0 s / 57 Hz, Position и Render 16.1 [13.0–19.0], Velocity 16.0 [16.0–16.0], frame p95/max 21.9/29.2 ms; сервер 8.0 s / 60 Hz, Position 16.0 [14.5–17.7], Velocity 16.0 [16.0–16.0], frame p95/max 18.0/56.9 ms. Диапазон p05–p95, не максимум ошибки. Пульсация есть в измеренной позиционной скорости, причина не доказана: нет одновременного замера на локальном клиенте цели. M611 добавляет такой замер автоматически в том же 8-секундном окне; OWNER — локальный клиент целевого игрока, не подтверждение сетевого владения. GetServerTimeNow используется только для согласования окна; dt измеряется os.clock локально. Отчёт клиента диагностический, не доверенный gameplay state. Не менять движение до сравнения трёх точек. [Workflow](../../workflows/M611_NETWORK_MOTION_OWNER_RU.md).

## M655 · Возврат к диагностике Published

**M655 · Global Published Debug.** `Options → Debug / TestPlace → Enable debug / test buttons`: одна глобальная галочка `debugUi.showPublishedControls`, независимо от Place ID, устройства, владельца и ранга. Все подключённые игроки опубликованного Place (включая compiled Runtime) при ON получают server-owned authorization; OFF не запускает опубликованные debug-сервисы и блокирует debug-вызовы. Studio и отдельные Studio-only инструменты GP/AG/Buffer сохраняют прежний контракт. Перед публичным релизом выключить debug: ON предоставляет тестовые полномочия всем игрокам. Миграция прежних PC/Mobile flags — OR, Place ID удаляется; default OFF для новой конфигурации. Нативная Published-приёмка открыта. Приоритет: диагностика регрессии GPU/CPU (владелец сообщил 25 → 125 ms GPU в покое), не снижение качества. Причина пока неизвестна. См. `docs/workflows/M655_GLOBAL_PUBLISHED_DEBUG_RU.md`.

Сначала LD / MicroProfiler захват и baseline, затем локализация регрессии. Не изменять качество/LOD ради скрытия проблемы.
