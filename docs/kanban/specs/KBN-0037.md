# KBN-0037 — Client Performance · sampler, attachments, LOD, UI

**База:** M605 · 27.11.2026. **Статус:** PROPOSED. План согласован на уровне очереди работ; точные реализации и бюджеты уточняются измерениями.

## Цель, исходные замечания и границы

### 1. Анимационные sampler — подтверждённый дефект
MonsterAttackLocomotionController.luau:226–289 считает активные sampler во время обхода, поэтому может превысить лимит 32. NPC-аналог уже содержит корректный подход. Единый бюджет Monster/NPC, сначала учёт существующих, затем выделение; приоритет ближайшим видимым активным существам, отдельная конфигурация мобильного бюджета. Не менять death/DeathIdle и боевые переходы; sampler своевременно освобождать.

### 2. Крепления волос и оружия
BoneMountedAttachmentController.luau:66–94,137–140 обновляет всех загруженных NPC/игроков каждый RenderStepped, повторно ищет компоненты. Событийная регистрация, Attachment LOD: собственный/близкие — каждый кадр, средние 20–30 Гц, дальние 5–10 Гц, вне визуальной дистанции пауза. Частоты — стартовая гипотеза до измерений. При возвращении сразу актуализировать pose, не допускать визуальных отрывов.

### 3. Runtime LOD Streaming
LocationWorldStreamer.luau:214–305 раз в 0,25 с пересчитывает и сортирует все записи даже при неподвижности. Бюджет 8 ограничивает только смену моделей, а стоимость большой сборки искусственно ограничена сверху. Сохранить существующую архитектуру, использовать индекс статических placements, очередь пересечений порогов с hysteresis, кэш готовности прототипов, реальный бюджет работы и порционную сборку. Связь с KBN-0007/0017, не переписывать collision contract.

### 4. Сокеты, двери и замки
HouseSocketPromptController.luau и DoorInteractionRaycast.luau: до 440 prompts × 10 Гц (пример последнего лога, не замер). Индекс ближайших сокетов, кэш door meshes по жизненному циклу и LOD, исключить регулярное переключение CanQuery. Raycast по двери по-прежнему только внутри socket reach; препятствия, выбор нужной двери, lock/unlock, PC/mobile и серверная валидация сохраняются.

### 5. Overhead UI
OverheadHealthController/NpcOverheadController заранее создают BillboardGui и соединения всем загруженным существам. Пул/ленивое выделение только близким и имеющим право на отображение, событийное обновление HP; сохранить показ имени, уровня, агрессии, цели, портреты GP и правила видимости. Не допустить stale UI при переиспользовании.

## Приёмка

- [ ] Общий лимит sampler никогда не превышен; смерть/DeathIdle, атака и locomotion без restpose регрессий
- [ ] Волосы и оружие не отрываются; дальние/невидимые крепления не выполняют полную работу каждый кадр
- [ ] Неподвижный игрок не вызывает глобальную пересортировку LOD; большие сборки бюджетируются; streaming/коллизии/телепорты работают
- [ ] Дверь, замок, сокеты и препятствия корректны в Authoring/Runtime и PC/Mobile; Raycast только в зоне; не меняется CanQuery на каждом запросе
- [ ] Overhead пул ограничен и очищается; HP/имена/уровни/GP корректны; нет роста соединений после циклов streaming
- [ ] Сравнение CPU/frame time, RAM и FPS на фиксированной сцене DEV и телефоне сохранено

## Проверка и откат

Каждое изменение — отдельный проверяемый патч поверх актуальной ревизии, с профильными тестами, verify.py и сравнением до/после. Для runtime обязательна Studio/DEV-приёмка на реальных устройствах. Не считать статические проверки замером производительности. Откат отдельно для каждого патча; миграции только с резервной копией и проверкой совместимости. Не оставлять дублирующие рабочие реализации. Статусы и evidence находятся в JSON карточки; все проверки пока NOT_RUN.
