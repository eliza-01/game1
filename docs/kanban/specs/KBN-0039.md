# KBN-0039 — Asset Pipeline · hitboxes и приоритетный прогрев

**База:** M605 · 27.11.2026. **Статус:** IN_PROGRESS (M648). План согласован на уровне очереди работ; точные реализации и бюджеты уточняются измерениями.

## Цель, исходные замечания и границы

### Предрасчёт hitbox geometry
HitboxMeshGeometryCache.luau:19–106 и HitboxDefinitionBuilder.luau:127–325: сервер строит bone-local bounds через EditableMesh, включая грани, веса костей и вершины (в логе модель 47 616 вершин). EditableMesh уничтожается, но исходная геометрия остаётся в кэше. Перенести предрасчёт в Control Center на подготовку/публикацию; versioned manifest по mesh revision, rig и scale, runtime читает готовые bounds. Проверить parity с действующим алгоритмом, не ухудшать точность и не удалять кэш до миграции всех производителей/потребителей. Явные ошибки при несовпадении ревизий, контролируемая миграция/откат, без скрытого fallback и зависимости от EditableMesh в обычном Runtime после полной миграции.

### Прогрев
M605 уже дедуплицирует world clips, прогревает один раз за сессию пакетами 16, без новых Animator. При росте каталога — приоритет собственный персонаж → существа текущей области → остальные в фоне. Сохранить deadline, отсутствие блокировки входа при отказе API и корректные Death transitions. До M648 CharacterCreationVariantPrewarm запрашивал до 24 сборок внешности с дедлайном 75 с. M648: этот путь удалён; два настоящих default preview загружаются первыми; optional warm получает разрешённые сервером уникальные компоненты (4 публикации в текущем каталоге), типизированные MeshPart и Image URI. Бюджет 24 публикации, 96 общих источников, 16 MeshPart на компонент, 20 с клиентского фонового ожидания и один слот typed preloader. При первом редактировании геометрии или уходе из creation прогрев отменяется, on-demand сохранён. T05 CODE_COMPLETE, native A03/A04 NOT_RUN. См. `docs/workflows/M648_CHARACTER_ASSET_PREWARM_RU.md`. Не утверждать, что прогрев устраняет любой restpose: отдельно проверить переходы анимаций. Не оптимизировать без измерений SVG, удержание атаки/прыжка, quick weapon cache, Auto Aim, Bow Aim, pooled Hit Sparks и ограничение Debug: по ревью нет основания менять их.

## Проверка и откат

Каждое изменение — отдельный проверяемый патч поверх актуальной ревизии, с профильными тестами, verify.py и сравнением до/после. Для runtime обязательна Studio/DEV-приёмка на реальных устройствах. Не считать статические проверки замером производительности. Откат отдельно для каждого патча; миграции только с резервной копией и проверкой совместимости. Не оставлять дублирующие рабочие реализации. Статусы и evidence находятся в JSON карточки; все проверки пока NOT_RUN.
