# M245 · Неизменяемая идентичность публикаций после Rename Location Asset

## Симптом

`Publish and connect atlas` останавливается до загрузки изображения с ошибкой
`asset audit unavailable; mutation refused: audit operation identity belongs to a different asset`.
Одна конфликтная запись общего MySQL-аудита блокирует операции публикации и у
других ассетов: `api/write_dispatch.py` вызывает `audit.sync_all()` перед ними.
Сообщение на странице Location Assets само по себе **не означает** ошибку Studio Sync.

## Первопричина

M242 изменяет `asset_slug` всех старых записей `location_asset_publications` и
`consumer_id` прежних `texture_atlas_legacy_publications`, чтобы авторская база
работала с текущим slug. В MySQL эти записи уже импортированы под прежним slug,
и их `operationId` (детерминированный по имени исходной таблицы и ID строки)
не меняется. Новый импорт получает ту же операцию, но с другим `assetKey`;
защитная проверка справедливо отказывает в изменении истории.

## Исправление

`asset_audit_historical_identity.py` восстанавливает **slug на момент публикации**
из истории `location_asset_slug_aliases`. Это чистая функция, работающая с
одним источником данных, с учётом последовательных переименований.

`sqlite_asset_audit_importer.py` использует исторический slug только как
`assetKey` импортируемой записи для двух затронутых источников:
`location_asset_publications` и старых `texture_atlas_legacy_publications`
(только при `consumer_type=location_asset`). Цепочка `previousAssetId` по-прежнему
формируется по текущему авторскому slug.

- MySQL-таблицы, уже записанные операции и опубликованные ID **не меняются**.
- Другие домены, включая Real Estate, не переводятся на новую идентификацию.
- Подозрительные несвязанные подмены `assetKey` продолжают блокироваться.
- Сама публикация атласа, Studio Bridge и логика Sync **не менялись**.
- Схемы SQLite/MySQL не изменены; миграции и переустановка Studio-плагина не нужны.

## Проверка

1. Перезапустить Host Agent после применения патча.
2. Повторить `Publish and connect atlas` на ассете, где возникала ошибка.
3. Проверить новый Image ID в Atlas Registry и запись в Database / Asset History.
4. Не повторять публикацию, если сервер вернул успешный Image ID, но показал
   предупреждение об импорте аудита после публикации — сначала проверить историю.

Если ошибка `audit operation identity belongs to a different asset` сохранится,
нужна отдельная диагностика конкретной записи MySQL: возможен конфликт из-за
восстановления SQLite из другого состояния или повторного использования ID строк.
В таком случае автоматическая перезапись аудита недопустима.
