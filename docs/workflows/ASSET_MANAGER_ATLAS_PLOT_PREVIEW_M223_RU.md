# M223 — Asset Manager: порядок разделов, Atlas, Plot Place/Clear

**Дата:** 2026-11-04. **Базовая ревизия:** M222. **Статус:** реализовано в коде; требуется Studio smoke на отдельной копии Place.

## Архитектурные границы

- `static/asset-section-order.js/css` владеет исключительно порядком UI в localStorage (`game1.assetManager.sectionOrder.v1`). В навигации у каждого корневого раздела шесть точек, которыми его можно переместить; клавиши ↑/↓ тоже работают. Подменю Database перемещается вместе с ним. Ни один серверный порядок ассетов не меняется.
- `real_estate/placement.py` продолжает быть **единственным** источником авторских `plotIndex + houseSlug → localCFrame + scale`. Это не механика покупки недвижимости.
- `api/real_estate.py` отвечает за проверку запроса; `studio_house_placement_bridge.py` за одноразовую адресную команду; `StudioHousePlacementPreview.luau` за изменение только авторской копии в Roblox Studio. В HTTP-запросе нет координат: Host Agent берёт их из сохранённого Binding.
- `services/texture_atlas_registry.py` **единственный** владелец зависимостей и перемещения привязок атласов. API `read_world.py/write_world.py` не содержит дублирующих SQL/правил выбора качества. `atlas-library.js/css` — представление, не меняет Studio.
- `sqlite_asset_audit_importer.py` отражает замену Image ID в уже существующем M217 MySQL audit. Основной SQLite сохраняет историю **даже при недоступной MySQL**; импорт выполняется при последующем чтении Database → Asset History.

## Real Estate → 04 Placement

В выборе Plot появились стрелки `◀` / `▶` с циклическим переходом 01–50. Выбранный участок переживает перезагрузку страницы. Таблица Bindings содержит кнопки `Place` и `Clear` непосредственно слева от номера участка.

`Place`:

1. Требует сохранённой привязки `(plotIndex, houseSlug)` и Roblox Studio в **Edit Mode**.
2. Находит `Workspace.Plots/NN/plot_NN_volume` (поддерживает `plot_N_volume`).
3. Берёт актуальную **синхронизированную** модель из `ServerStorage/real_estate/<slug>/model/<slug>`.
4. Готовит клон **вне Workspace**, применяет сохранённый масштаб и `plot_volume.CFrame * localCFrame`.
5. Размещает его в `Workspace.Plots/NN/Houses/<slug>` со снятым `Game1RealEstateTemplate` и атрибутами `Game1PlotHousePreview`, `Game1PlotIndex`, `Game1RealEstateSlug`, `Game1PlacementRevision`.
6. Начиная с M224, повторный Place заменяет предыдущую управляемую авторскую копию на участке, даже если это был другой зарегистрированный дом. Неуправляемые модели не удаляются.

`Clear` удаляет только модель с правильным slug **и всеми авторскими маркерами**, созданную этой операцией; никакие исходные модели, plot volume, другие дома, Studio-шаблоны и неуправляемые объекты не удаляются. В обеих операциях используется `ChangeHistoryService` (Undo). Текущие расположения существующих домов не синхронизируются и не перестраиваются автоматически.

**Первый запуск Place/Clear выполнять в копии Place.** Контракт CFrame задаёт pivot клонированной модели; если pivot исходной модели при Bind отличается от pivot синхронизированного шаблона, **визуальный дом может сместиться относительно ожидаемой геометрии** даже при совпадении `GetPivot()`. Такое несовпадение требуется решить отдельно через авторский pivot, не перемещая существующие экземпляры. Studio-runtime тесты и проверка undo в настоящем Place здесь недоступны.

## Atlas — центральная библиотека

Каталог `GET /api/texture-atlases` включает все **активные** варианты центрального Atlas Registry из Real Estate, Location Assets и компонентов персонажей. Старые независимые Weapon/Monster/NPC slot-stores остаются отдельным legacy-контрактом — они не являются частью этого общего реестра.

Клик по строке открывает модальное окно. `GET /api/texture-atlases/variants/<id>/retirement` показывает все привязанные потребители, Image ID, опубликованные замены, предложение ближайшего по площади разрешения **только с тем же `atlas_key`**, и обязательный token подтверждения актуального состава привязок. Ручная замена может выбрать любой опубликованный вариант; выбор другого atlas key — явное действие пользователя, а не автоматическая эвристика.

`POST /api/texture-atlases/variants/<id>/retire` принимает `token`, `replacementVariantId` (для ручного выбора) или `autoClosest=true`; оба одновременно запрещены. Если потребителей нет, замена не нужна. Если есть — атомарно перепривязываются **все**, с инкрементом ревизий для обязательной последующей адресной Studio Sync. Изначальные Image ID и файлы **не удаляются**: «удаление» реализовано как **retirement/tombstone** (исключает вариант из активного списка и новых регистраций), поскольку без сохранения истории откат был бы небезопасен. Имя+разрешение удалённого варианта резервируются; для новой регистрации нужен новый atlas key.

### Новые таблицы / миграция

Однократно при старте `AtlasRegistry`:

- резервная копия `.control-center/backups/before_atlas_retirement_m223_<uuid>.db`;
- `texture_atlas_variants.retired_at` (`NULL` = активный);
- `texture_atlas_retirements` — старый/новый variant ID, полная копия потребителей, дата;
- `texture_atlas_binding_migrations` — тип/ID потребителя, старый/новый Roblox Image ID, новая ревизия и время.

Если выгрузка отдельных manifests после фиксации транзакции не удалась, API возвращает **HTTP 200 с `exportWarnings`** (сами привязки уже изменены), а UI требует устранить проблему экспорта; это предотвращает ошибочный повтор удаления. Данные не мигрируют автоматически в Studio. Старые архивные публикации и локальные PNG/JPEG не удаляются. Если MySQL M217 недоступна, SQLite-журнал остаётся целым, но раздел Database будет сигнализировать о недоступности до восстановления MySQL.

### Восстановление

Перед первым удалением сделайте резервную копию `.control-center/game1.db` **при остановленном Host Agent**. Для полного возврата к предыдущему состоянию восстановите SQLite из подходящего бэкапа и проверьте экспорт manifests; не откатывайте отдельно одни JSON или опубликованные Roblox ID. Миграция схемы обратимо совместима с M222 на уровне данных, но возвращать старый код поверх новых retirement-записей без бэкапа не рекомендуется.

Для отдельного возврата ошибочной замены используйте список из `texture_atlas_binding_migrations` как журнал и заново привяжите нужный опубликованный atlas в штатном интерфейсе; это создаёт новую ревизию и потребует явного Sync затронутого slug. **Никаких массовых Studio Sync при удалении/перепривязке нет.**

## Приёмка

1. Перетащить раздел sidebar за шесть точек, перезагрузить Control Center — порядок сохранён; клики переходят в нужные разделы, подменю Database доступно.
2. Проверить стрелки 01 → 50 и 50 → 01, ранее выбранный участок, табличные Place/Clear.
3. В **копии** Studio Place выполнить Place на участке с сохранённым Bind, сравнить pivot/scale с ожидаемым, проверить структуру `Plots/NN/Houses`, Undo, повторное Place, Clear. Убедиться, что оригиналы Workspace и другие участки нетронуты.
4. Atlas: модалка показывает всех потребителей; при отсутствии опубликованной замены автоматический чекбокс заблокирован; удаление используемого атласа без замены запрещено.
5. На копии БД заменить атлас с тремя потребителями через Auto и через ручной выбор, проверить атомарность и рост revision; проверить SQLite и MySQL Asset History, потом явную Studio Sync только выбранных потребителей.
6. Проверить отступы Database при узкой и широкой панели.

**Невыполненная проверка:** реальные операции Place/Clear и восприятие UI в Roblox Studio/реальном браузере — доступны только на пользовательской среде. Python, JS-синтаксис, Luau preflight и Git apply проверяются отдельно при передаче.
