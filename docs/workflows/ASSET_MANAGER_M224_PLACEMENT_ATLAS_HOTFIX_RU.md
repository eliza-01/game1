# M224 · Asset Manager hotfix: Placement Anchor/Free, Atlas, Database, sidebar

**База:** M223. **Цель:** минимальные изменения поверх существующего Placement + Atlas Registry без нового движка Sync. **Studio Play/Edit:** проверка на копии Place обязательна.

## 04 · Real Estate Placement

- У каждого Binding появилась сохраняемая настройка `anchored` (по умолчанию `true`). Значение сохраняется в SQLite `.control-center/game1_real_estate.db`, возвращается в `/api/real-estate/placements` и экспортируется в `assets/manifests/real-estate-placements.json`. Прежние CFrame, scale, revision, plot identity не изменяются.
- Миграция существующих БД: `ALTER TABLE real_estate_placements ADD COLUMN anchored INTEGER NOT NULL DEFAULT 1 CHECK(...)`; существующие бинды получают `true`. Миграция идемпотентна и перед первым ALTER автоматически создаёт SQLite backup в `.control-center/backups/before_placement_anchor_m224_<uuid>.db`. **Всё равно рекомендуется сделать резервную копию Place и SQLite при остановленном Host Agent.**
- В левом столбце — ⚓ (Anchored) либо ≋ (Free). Каждая строка переключается отдельно. Заголовок столбца переключает **все bindings**, даже если таблица отфильтрована по дому: из смешанного состояния сначала Anchor all, из полностью Anchored — Free all. Внизу предусмотрены явные кнопки Anchor all / Free all.
- `POST /api/real-estate/placements/anchors` принимает `anchored: boolean`, `scope: one|all`. Только сервер выбирает зарегистрированные `(plotIndex, houseSlug)`; браузер не отправляет CFrame, список целей или произвольные инстансы. Команда отправляется в Roblox Studio Edit Mode через **тот же одноразовый аутентифицированный bridge**. Изменяются `BasePart.Anchored` **только в управляемых авторских копиях** внутри `Workspace.Plots/NN/Houses`, помеченных `Game1PlotHousePreview`, `Game1PlotIndex`, `Game1RealEstateSlug`. Studio Undo через `ChangeHistoryService`. После подтверждения Studio настройка сохраняется в SQLite. Если Studio недоступна — настройка не выдаётся за применённую.
- При **Place** состояние `anchored` копируется из Binding на все BasePart клона, включая вложенные. Старые управляемые preview текущего участка заменяются новыми без отдельного Clear. Неуправляемые объекты, исходники `ServerStorage` и plot volume не изменяются. Если чужая модель имеет то же имя, операция безопасно отклоняется. Clone готовится до изменения Workspace.
- **Clear** сразу удаляет только копию с правильной служебной идентичностью; браузер больше не показывает confirm. Studio Undo доступен.
- Действия работают с авторскими **предпросмотрами**, а не с игровыми домами, купленными игроками. Массовое Anchor/Free не должно изменять неуправляемые или runtime-дома.

## Atlas

- Каталог `/api/texture-atlases` возвращает активные варианты с `consumers`; одна строка соответствует **одному variant ID (файл + разрешение)**. Список связанных моделей отображается ниже мелким текстом, без строк-дубликатов на каждого потребителя. Привязки читаются одним SQL запросом (без N+1), а общий Registry остаётся источником истины.
- Модальное окно предлагает сначала ближайший **опубликованный вариант того же atlas key / модели**. `Use closest quality from the same atlas family` заполняет Replacement atlas выбранным ID и блокирует ручное редактирование до отключения чекбокса. Если вариант того же key отсутствует, автоматическое предложение недоступно; случайный атлас другой модели не подставляется.
- Кнопка называется **Delete atlas**, но фактически выполняется та же транзакция retirement M223: вариант исчезает из **активного каталога**, а оригинальные изображения, Roblox Image ID и история замен остаются для восстановления и аудита. Используемый атлас нельзя удалить без перепривязки зависимостей; история не теряется.
- `Sync with closest atlas` — видимая **отключённая заглушка**, никаких скрытых вызовов Sync нет.

## Database / rail

- Hero и Asset History panel имеют отдельный вертикальный отступ. Основной `.content` получает верхний отступ.
- При desktop-layout `.rail` ограничен высотой окна, колёсико мыши прокручивает его **самостоятельно**; scrollbar скрыт CSS. На узком экране возвращается обычный вертикальный поток.

## Тест и откат

1. На **копии Place** проверить Anchor/Free одной строки, заголовка, Anchor all / Free all, два Plots и неуправляемый объект. Убедиться, что чужой объект не меняет Anchored.
2. Сделать Place с `anchored=false` — все BasePart должны получить `Anchored=false`; повторный Place с новым Binding на том же Plot должен удалить только старые управляемые Preview; проверить Undo.
3. Проверить Clear без браузерного диалога и отсутствие удаления неуправляемых моделей.
4. Проверить SQLite миграцию, reload Host Agent, Manifest, неизменность CFrame/scale и ревизии Binding.
5. В Atlas открыть вариант с несколькими потребителями; проверить единственную строку, подсказку replacement, синхронизацию селекта и checkbox, кнопку Delete, неработающую заглушку Sync.
6. Проверить прокрутку sidebar с колёсиком внутри rail и Database gap.

**Откат:** восстановить код M223 и SQLite backup одновременно, если менялось anchored; обновлённый M224 manifest содержит дополнительный ключ `anchored`. Установка старого кода сама по себе не вернёт вручную перемещённые в Studio объекты; Studio Undo / сохранённая копия Place остаются способом восстановления. Legacy таблицы Atlas не мигрируют в M224.
