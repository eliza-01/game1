# M225 — Atlas отступы и проверяемый Anchor/Free при Place

## Причина и исправление

`M224` добавил `anchored` в Placement, но сохранил имя и версию команды
`house-placement-preview` / `schemaVersion=1`. Старый установленный плагин M223
мог принимать новую команду, размещать дом с прежним `Anchored=true` и
возвращать «успешно», хотя в Asset Manager отображалось ≋ (данные SQLite уже
`anchored=false`). Это **совместимость на уровне протокола**, а не ошибка самого
чтения SQLite; без проверки конкретной версии плагина в Studio нельзя
утверждать, что причина именно эта.

- Авторский `capture` оставлен на `house-placement-capture`, schema 1.
- `Place`, `Clear` и `Anchor/Free` используют `house-placement-preview-v2`,
  schema 2. Старый плагин не распознаёт новое имя команды, поэтому не должен
  изменять Workspace. Требуется **переустановить Game1Bridge** и полностью
  переоткрыть Roblox Studio.
- Сохранённый Binding обязан содержать `anchored: boolean`; больше нет
  неявного превращения отсутствующего значения в `true`.
- При `Place` все BasePart у подготовленного дома настраиваются до вставки в
  Workspace и **повторно проверяются после вставки в Workspace**. Если часть
  не получила требуемое значение, операция отменяется; старый управляемый
  preview не уничтожается. В ответе Studio передаются фактические
  `anchored` и `anchoredPartsVerified`. Host Agent отклоняет успех без них.
- `Anchor/Free` существующих превью также проверяет фактическое значение
  частей; при ошибке пытается откатить изменения через Studio Undo.
- Операции меняют только управляемые авторские дома в `Workspace.Plots/NN/Houses`.
  CFrame, Scale, Bind координаты, Atlas/Model ID и Real Estate Sync не меняются.
- `panel atlas-library-panel` получил отступы 14px сверху и 22×24px внутри;
  на узких окнах — 15×12px.

## Проверка на тестовой копии Place

1. После установки M225 переустановить Game1Bridge через
   `system/studio-plugin/install.ps1`, закрыть и вновь открыть Roblox Studio.
2. Выбрать уже сохранённый Binding с ≋ (Free) и нажать **Place**. В Studio
   выбрать `Workspace.Plots/NN/Houses/<slug>`, проверить атрибут
   `Game1PlotHouseAnchored = false`, а также `Anchored = false` у **каждого**
   вложенного BasePart. Ожидаемый успешный ответ: `anchored = false`,
   `anchoredPartsVerified > 0`.
3. Нажать ⚓, затем **Place** — атрибут и все BasePart должны быть `true`.
4. Проверить Undo, один другой участок и одну неуправляемую Model: они не
   должны измениться.
5. Сымитировать старый плагин: новая команда должна закончиться ошибкой
   несовместимости/тайм-аутом, но не менять Workspace.

Полноценное поведение Anchored в настоящей Roblox Studio невозможно подтвердить
одними Python/Luau-проверками. Перед первым применением на основном Place
необходима тестовая копия.
