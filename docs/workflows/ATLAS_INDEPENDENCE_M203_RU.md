# M203 · Атлас — самостоятельный Asset; модель — только потребитель

## Архитектурный инвариант

Для **Real Estate** и **Location Assets** единственный источник правды об изображении — `texture_atlas_variants` внутри Atlas Registry (`.control-center/game1.db`).

- Идентичность атласа: `atlas_key` (имя файла до разрешения), вариант, размер, исходные байты/SHA-256, собственный Roblox Image Asset ID и история публикации.
- Идентичность потребителя: `(consumer_type, consumer_id)` в `texture_atlas_bindings`, ссылается только на `variant_id`.
- Несколько моделей и частей могут ссылаться на **один и тот же variant_id**. Между ними нет отношений «владелец — наследник».
- Удаление или переименование регистрации модели не меняет вариант атласа и его публикацию. После удаления slug свободен немедленно.
- Замена FBX не меняет Image Asset; замена PNG — отдельная операция Atlas Registry. Один и тот же ключ/размер с другими байтами не перезаписывается при регистрации модели.
- Поля `texture_path`, `assetId` и т. п. в экспортируемых JSON/Luau — **проекция** данных Atlas Registry для существующего Studio/runtime API, НЕ поля владения в БД модели.

`Characters` уже использует Atlas Registry со своей областью (`texture_atlas_scopes`). Character-части не преобразуются в модели-владельцы атласов. Публикация FBX/Model Asset ID по всем разделам сохраняет прежний принцип.

## Миграция существующих данных (запуск автоматически и через migrate.py)

1. Инициализируется Atlas Registry и читаются **оба** хранилища: Location Assets и Real Estate.
2. По историческим `location:<slug>`, `estate:<slug>:<part>`, `mesh:house`, в том числе снимкам удалённых владельцев `retained_shared_textures`, разрешаются реальные исходники изображения. **Неопубликованные** атласы тоже мигрируются.
3. Читаются и проверяются PNG/JPEG/WebP, размеры и SHA-256. Исторический опубликованный ID принимается только если его `published_sha256` соответствует исходнику. Две разные публикации с разными Image Asset ID никогда не сливаются по совпадению пикселей.
4. Копия каждого исходного файла сохраняется в собственном каталоге `assets/source/texture-atlases/<key>/<resolution>/migrated/<sha>/`; копия проверяется по SHA-256. Существующие независимые варианты, чей `source_path` ещё находится в папке модели, тоже переносятся. Исходные файлы сохраняются.
5. До изменения данных создаются независимые резервные копии обеих SQLite-баз в `.control-center/backups/before_m203_atlas_independence_*.db`. Дальнейшее изменение записей выполняется одной транзакцией SQLite с `ATTACH`.
6. Ставятся самостоятельные bindings, старые `textures_json` заполняются только пустыми неавторитетными записями для контракта модели, **семь устаревших колонок** Location Assets удаляются, таблица `retained_shared_textures` удаляется. Сиротские bindings удалённых моделей удаляются.
7. Перегенерируются manifest и Luau реестры. Миграция повторно запускаема и не вызывает Open Cloud.

При отсутствующем/изменённом изображении или несовместимом опубликованном хеше миграция останавливается **без изменения регистраций**. Не нужно использовать другой slug. Нужно восстановить корректный PNG из проекта/резервной копии. Файл лога сообщает точную ссылку; пользователь должен исправить данные перед возобновлением миграции.

**Важно о транзакции:** создание копий PNG предшествует SQL-транзакции. При откате базы лишняя, но проверенная копия может остаться; она не используется без записи варианта.

## Рабочий сценарий

- Загрузить `restoration_01_2048x2048_atlas.png` в Atlas Registry.
- Выбрать один и тот же вариант для `house_level5_01/door`, `house_level6_01/window_frames_glass` и Location Asset.
- Удалить любую регистрацию: её bindings удаляются, атлас и остальные bindings остаются. Модальное окно показывает других потребителей, но **не разрешает каскадно удалять их только потому, что они используют ту же текстуру**.
- Создать новый дом со старым slug — он не получает чужой атлас автоматически и выбирает свой `atlas_variant_id`.

## Сфера изменений и отдельные пайплайны

M203 завершает ликвидацию **исторического общего owner/reuse механизма Real Estate и Location Assets**. Character-атласы уже подключены к центральному Registry. **Weapon/Monster/NPC texture slots используют другой, более старый публикационный механизм `weapon_textures`/`monster_textures`, а не `estate:`/`location:` ссылки.** Эти текстуры НЕ мигрируются M203 в Atlas Registry. Нельзя считать всю систему Asset Manager универсально переведённой на единое владение, пока этот отдельный механизм не будет заменён. Это сознательно отмеченное оставшееся несоответствие, а не скрытый fallback.
