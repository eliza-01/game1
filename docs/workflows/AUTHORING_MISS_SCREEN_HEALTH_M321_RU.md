# M321 · Runtime authoring cleanup, Miss feedback, screenshot-style HP

База: M320. Изменения распространяются на обычный опубликованный Roblox сервер и Studio Play, но не на Studio Edit.

## 1. Game1Authoring

`Game1AuthoringCleanupService` первым в серверном bootstrap уничтожает целиком **runtime-копию** `Workspace.Game1Authoring`: `Locations`, `MonsterSpawns`, `NpcSpawns` и все дочерние preview-объекты. Он подписан на появление позднего корня. Авторские данные Studio Edit и registry/местоположения/публикации при этом не изменяются. Удалены дублирующие частичные очистки из MonsterSpawnerService и NpcSpawnerService. Ни размещённые дома, ни декор, ни NPC/монстры из опубликованных реестров не затрагиваются.

## 2. Miss

Единственная серверная дорожка `CombatFeedbackService.PublishMissOverPlayer` доставляет miss только игроку, над которым нужно показать надпись:

- игрок завершил **одну подтверждённую** melee-атаку, а суммарный применённый урон равен нулю (без многократных Miss по кадрам/целям);
- стрелок выпустил валидный hitscan, но фактический урон равен нулю (промах, препятствие, защита цели);
- монстр или боевой NPC достиг Hit-момента анимации, но не смог нанести урон выбранному живому игроку.

Промахи отбиваются на сервере и показываются непосредственно над игроком, а не над противником. Уничтоженная/сменившаяся модель игрока игнорируется. Прерывание melee bounce и техническая ошибка ожидания snapshot у лука не означают подтверждённое завершение удара и не создают Miss. Отправляется один маленький `CombatFeedback` payload, без новой сети и без клиентских прогнозов повреждений.

## 3. Боевой интерфейс

По скриншоту возвращена **только** красная верхняя полоса HP `текущее / максимальное` со скруглённой подложкой и чёрной обводкой, с плавной анимацией изменения заполнения. Индикатор скорости атаки не возвращён. Локальная полоска над персонажем M320 остаётся условной (бой или неполное HP). Над монстрами — расширенная полоска/контрастная подпись; видимость по прицелу или агрессии сохраняется. Цвет полосы монстра и верхней полосы игрока красный, как в референсе; локальный overhead сохраняет пороги 30% и 65%. Уровень монстра выводится жёлтым **только если реально опубликован** в `stats.Level` — существующая схема регистраций gremlin пока такого поля не содержит, фиктивный `12` не присваивается.

## Проверка в Studio Play

1. Запустить Play/Start Server/опубликованную игру. `Workspace.Game1Authoring` должен исчезнуть в runtime-мире целиком; после Stop папка в Studio Edit сохранена.
2. Взмах мимо цели → один `Miss` над игроком в конце атаки. Удар с несколькими положительными попаданиями → Miss не показывать. Удар, поглощённый защитой → один Miss.
3. Стрела в пустоту и в стену → Miss после Release. Успешное нанесение урона → только числовое повреждение.
4. Монстр ударил в пустоту (игрок отошёл), либо его урон целиком поглощён защитой → `Miss` над игроком. Аналогично для боевого NPC.
5. Вне боя верхняя полоска видна, overhead игрока скрыт при полном HP; в бою или при потерянном HP — overhead также виден. Монстры показываются при прицеливании/агрессии; обе полосы плавно обновляются.
6. `Level` без зарегистрированного значения не подменять выдуманным числом. На существующем gremlin будет имя без числа.

## Границы

Физика, прицел, механика попаданий и серверный авторитет M317–M320 не менялись. Новая подсистема лишь получает итоговый урон и использует существующий presentation-канал. Схема опубликованных ассетов не мигрирует.

Статические проверки не подтверждают рендер, положение BillboardGui, сетевое латентное состояние или Roblox-анимации; требуется Studio Play.
