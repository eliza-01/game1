# M315 · Надёжность Bow Release и контакта с поверхностью

**Основа:** M314. **Область:** только серверные Bow Release / projectile geometry и профильные тесты. Рукопашный бой, Bow Draw, камера, поворот корпуса и публикация ассетов не меняются.

## Две причины нестабильности, найденные в исходниках

1. Клиент делает один снимок прицела приблизительно за 100 мс до авторского `Release`. Сервер назначал выпуск по собственному таймеру. Если `BowAimUpdate` прибывал позже, сервер молча выпускал стрелу по **лучу из начала атаки**, который мог заметно отличаться. Результат зависел от сетевого тайминга.
2. Для обычных поверхностей отрезок Raycast стрелы завершался ровно в точке камерного контакта. Поскольку реальная точка выпуска смещена относительно камеры, проверка на точной границе поверхности может не вернуть контакт из-за погрешностей.

## Исправление

- Остаётся **один** `BowAimUpdate` на выстрел. Клиентская задержка до Release не меняется: 100 мс.
- Если снимок приходит после серверного момента Release, он принимается максимум в течение **0,20 с**. При получении снимается ожидание и выпускается ровно одна стрела. Если снимка нет — запись атаки закрывается **без стрелы**, с диагностикой `capture_timeout` в Studio при включённых Combat DebugLogs. Устаревший луч начала атаки не используется.
- Для **подтверждённого камерного попадания в поверхность** отрезок серверной проверки продлевается на **0,20 studs** за снимок. Для захваченного актёра сохраняется **0,35 studs**, для пустого направления — прежняя дальность. Общий `Range` лука ограничивает эти прибавки.
- Положение и направление стрелы не пересчитываются после Release. Попадание и застревание по-прежнему требуют **настоящего пересечения** серверным Raycast/хитбоксом; автопопадания нет.

## Логи Studio

При `AttackConfig.DebugLogs=true`:

- `capture actor=world:...` — камера захватила реальную Query-поверхность.
- `capture actor=none` — луч не пересёк доступный для Query объект; проверить `CanQuery`, фильтры и точку прицела.
- `release ... capture=on_time/late delay_ms=...` — снимок использован при выпуске, с указанием опоздания.
- `capture_timeout` — сетевой снимок не получен в допустимый период, устаревшая цель не подставлялась.
- `no_contact target=world/none/...` — проверка полёта закончилась без реального контакта.

## Приёмка в Studio Play

1. На стационарной стене или Part с `CanQuery=true` сделать 20 выстрелов в одну точку. Проверить отсутствие случайной подмены луча начала атаки.
2. Повторить с высокой/низкой частотой кадров и при искусственно высокой сетевой задержке в Studio. При задержанном снимке ожидается `capture=late`, при тайм-ауте — отсутствие стрелы и сообщение, **не выстрел в другую сторону**.
3. Проверить `Range`, столкновения со стеной перед целью и попадания в голову/тело. Тестировать разный поворот камеры и положение точки выпуска.
4. Если `capture actor=none` на видимой стене, проверить `CanQuery` — Roblox Raycast не пересекает запрещённые для Query части. M315 намеренно не меняет физику или настройки ассетов.

Автоматические проверки не заменяют Studio Play, и этот патч не доказывает устранение всех промахов без повторяемого теста в Roblox.
