# M178 · Animations: безопасное сканирование и семантический профиль

Дата: 2026-10-31. База: M177.

## Текущее поведение

- Раздел Animations работает с **Character ID**. В том числе с `visual_mode=assembly`. `animation_profiles`, `animation_clips` и `animation_bindings` по-прежнему принадлежат персонажу, **не** общему ригу. Миграции на rig-owned profiles нет: это отдельно проектируемое изменение, которое должно сохранить существующие Roblox Animation Asset ID, профили и совместимость runtime.
- Верхний **Animation Profile** отображает все зарегистрированные семантические слоты. `Show missing` добавляет отсутствующие слоты из серверного `filenameRules`; настройка сохраняется в Local Storage. Слоты с `variants=01..n` отображаются как один ожидаемый слот с примером варианта `01`, а не как бесконечный ряд вариантов.
- Заголовки `context`, `slot`, `variant`, `status` сортируются по возрастанию и убыванию. По нажатию на строку Filename Rules редактор переходит к соответствующему слоту, автоматически включив `Show missing`.

## Scan folder → Register + Publish

1. `POST /api/animations/preview`: только чтение. Формирует `NEW`, `LOCAL_UPDATE`, `UNCHANGED`, `REPLACE_REQUIRED` и список файлов с неправильными именами. **Не** изменяет SQLite, реестр или содержимое `assets/source`, **не** публикует.
2. Модальное окно показывает все найденные файлы. Выбираются `NEW` и ещё не опубликованные `LOCAL_UPDATE`. `UNCHANGED`, опубликованные изменённые и неподдерживаемые имена нельзя включать в пакет.
3. `POST /api/animations/register-selected` сверяет пути, семантические слоты и SHA256 с актуальным содержимым папки. При изменении файла после сканирования требует повторное Scan. Регистрируются только отмеченные файлы; затем интерфейс последовательно вызывает существующий `/api/animations/<clip>/publish` **только для них**.
4. Модалка остаётся открытой; показывает количество зарегистрированных и опубликованных файлов и ошибки. При сбое Open Cloud созданные LOCAL_ONLY регистрации сохраняются, можно нажать Publish из соответствующей строки. Нельзя считать это общей ACID-транзакцией с Open Cloud.
5. Старый `/api/animations/scan` сохранён для обратной совместимости с внешними клиентами, но веб-кнопка `Scan folder` его больше не вызывает.

## Замена уже опубликованной анимации

1. Кнопка `replace` расположена в строке опубликованного клипа.
2. Пользователь выбирает новый `.rbxm`/`.rbxmx` во внешней папке; `POST /api/animations/<clip>/stage-replacement` обновляет локальную ревизию **без публикации и без смены Roblox Asset ID**.
3. Вручную выполняет reimport в Roblox Studio **в прежний Roblox Animation Asset ID**.
4. `POST /api/animations/<clip>/check-replacement` вызывает общий механизм подтверждения новой одобренной версии и проверяет только нужный клип. При ожидании остаётся `CHANGED`; после подтверждения возвращается `PUBLISHED` с прежним Asset ID.
5. Публикация новой ревизии через Open Cloud запрещена на серверном уровне для клипов с уже присвоенным ID.

## Архитектурные границы

- `animation_core/scan_review.py`: только поиск, предварительная классификация и явно запрошенная регистрация/подготовка замены.
- `animation_core/publication.py`: существующая публикация и верификация версии Roblox.
- `api/write_animations.py`: HTTP-маршрутизация без бизнес-логики.
- `static/character-animation-ui.js` и `character-animations.css`: отдельный интерфейс Animations; не размножаем ответственность `character-assets.js`.
- `services/native_pickers.py`: Windows Explorer, выбор файла замены.
- Ни одна из новых операций не удаляет старые ассеты/профили и не делает миграций SQLite.

## Ручная проверка

1. Открой Animations для сборки `human_male` и для legacy `human_female`. Оба профиля доступны, но НЕ обязаны иметь одинаковые клипы.
2. Нажми `Show missing`, проверь пустые слоты, выключи/включи, обнови страницу — настройка сохраняется.
3. Нажми названия в Filename Rules: прокрутка к слоту в профиле, фильтр на правильный context.
4. Отсортируй таблицу по `context`, `slot`, `variant`, `status`; повторное нажатие меняет направление.
5. Scan folder в существующей папке: показаны новые, неизменённые, опубликованные изменённые и файлы с неправильным именем. Закрытие окна ничего не регистрирует, не публикует и не меняет ID.
6. На тестовой новой анимации выбери только одну запись и Register + Publish: зарегистрирована и опубликована только она. Проверка реальной публикации расходует Roblox Open Cloud.
7. На **тестовой опубликованной** анимации `replace`: выбор файла → подготовка → ручной реимпорт в тот же Asset ID через Studio → Проверить Roblox. Пока версия не Approved, статус CHANGED. После проверки ID прежний.
8. В случае неуспешной публикации проверяй, что LOCAL_ONLY остался в профиле и доступна отдельная Publish из строки.

Не проверять Replace на боевой анимации без резервной копии исходного `.rbxm`/`.rbxmx`.
