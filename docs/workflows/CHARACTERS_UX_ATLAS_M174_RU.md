# M174 — Characters: таблицы, atlas workflow, редактор assembly

**База:** M173 (UI компонентных персонажей); legacy whole-model остаётся параллельно и не мигрируется автоматически.

## Интерфейс

1. В таблице Rig & parts `name`, `part`, `set` сортируются нажатием заголовка (стрелка и `aria-sort`). Слева ✓ — все проверенные зависимости актуальны, `!` — отсутствует текущая публикация, ожидается новая ревизия, незавершённая операция или атлас требует внимания. Причина — в подсказке при наведении на значок. У опубликованных актуальных моделей вместо серой кнопки — **✓ published**, не кликабельная надпись; незавершённые можно выбрать для очереди.
2. Character Atlas имеет отдельную таблицу и **Register Atlas**. Каталог отфильтрован **на стороне Host Agent**: новые варианты помечаются scope=`character`, существующие связи `character_part` доступны для совместимости. Существующие Location/Real Estate без связи с Character не попадают в список. Общая база публикационных Image Asset ID не дублируется.
3. После выбора PNG/JPG сервер читает только изображение и возвращает уменьшенное превью (максимум 256×256), имя, SHA-256, данные уже зарегистрированного варианта. До подтверждения **ничего не регистрируется и не публикуется**. Если совпали ключ+разрешение — слева старый вариант, справа выбранный. Для изменения пикселей у опубликованного варианта нужен явный checkbox; Roblox выдаёт **новый** Image Asset ID. В модалке показываются этапы и итог. Окно закрывается только пользователем, не автоматически.
4. Если имя неправильное или разрешение в имени не совпало с изображением, модалка показывает ожидаемое имя и **Show in folder**. Файл **не переименовывается автоматически**; пользователь исправляет имя и выбирает его повторно. Имя соответствует `<atlas_key>_<width>x<height>_atlas.png` (также `.jpg/.jpeg`). Коллизия с атласом другого раздела требует другого имени, прежние ID не перезаписываются.
5. В assembly длинный текст перенесён в `?`. Для 8 слотов — 32×32 иллюстративные значки: это **не снимки реальных FBX-мешей**. Кнопка `Edit recipe` заполняет редактор выше таблицы, делает прокрутку к редактору и фокусирует имя; сохранение всё ещё отдельное явное действие.

## Границы безопасности

- Хранилище `AtlasRegistry` — владелец фактических файлов и внешних Image Asset IDs; `CharacterAtlasAuthoring` — только инспекция, scope, проверка целостности и workflow. UI никогда не знает путей публикационных данных помимо выбранного файла.
- Добавляется *только* аддитивная таблица SQLite `texture_atlas_scopes(variant_id,scope)`. Перед её первым созданием Host Agent делает одноразовую SQLite online-backup в `.control-center/backups/before_character_atlas_scope_*.db`. Старые записи, ID, привязки и публикации не переписываются. Вариант, ранее привязанный к `character_part`, остаётся видимым для совместимости даже без нового scope.
- Проверяются SHA-256 выбранного файла, прежний ID варианта и опубликованный Image Asset ID перед изменением, отказ без согласия на replacement. Upload/SQLite не образуют общую ACID-транзакцию: при неоднозначном ответе повторный upload блокируется существующим pending guard, а UI сообщает ошибку и требует новую инспекцию.
- Реальное применение опубликованной текстуры в живой Roblox Studio требует отдельной проверки; успешный ответ Open Cloud ≠ подтверждение работы в Studio.

## Ручной чек-лист (Windows)

1. Rig & parts: сортировка name/part/set в обе стороны; при hover у `!` читается причина. У актуальной записи — зелёный `published`, не кнопка. Выбор нескольких неопубликованных в очередь по-прежнему работает.
2. Register Atlas: выбрать файл с неправильным именем. Видны превью, ожидаемое имя и Show in folder; опубликованных или новых вариантов нет. Исправить имя **вручную**, выбрать снова.
3. Выбрать совершенно новый Character atlas. Модалка показывает правое превью, позволяет Publish. Ожидается Done! и Image Asset ID; модалка остаётся открытой до Close, после закрытия новый атлас в таблице. Реальную публикацию проводить только на тестовом изображении.
4. Выбрать изменённый файл с тем же именем и разрешением: старая/новая картинки слева/справа, без галочки подтверждения публикация недоступна; после подтверждения отображаются прежний → новый ID.
5. Проверить, что атласы `structures_01`, `house_level4_01` и другие, не привязанные к Characters, отсутствуют в селекторе компонентов и Character Atlas table. Существующие legacy character-binding не теряются.
6. Нажать Edit recipe для сборки из нижней таблицы — экран прокручивается к заполненному редактору, выбранная строка подсвечивается; Reset восстанавливает рецепт. Зелёная Save появляется только после изменения.
7. `python system/verify/verify.py` и `$LASTEXITCODE` = 0; `python -W error::ResourceWarning -m unittest discover -s system/verify -p 'test_*.py' -q` = OK. Для UI/Host Agent требуется перезапуск Control Center; Roblox Studio/Rojo не требует перезапуска только из-за UI.
