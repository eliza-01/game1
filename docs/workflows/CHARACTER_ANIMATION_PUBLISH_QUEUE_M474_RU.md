# M474 · Очередь публикации Character Animations

## Назначение

`Characters → Animations → Publish All` публикует зарегистрированные, но ещё не опубликованные клипы всех Character-профилей и `human_common`. Очередь относится **только к публикации анимаций**, не к игровой механике.

## Контракт

`GET /api/animations/publish-queue` возвращает `{items, publication}`. Каждый элемент содержит `clipId`, `characterId`, `name`, `scope`, `slot`, `variant`, `status=LOCAL_ONLY`. Этот метод **read-only**, не создаёт Roblox ID, не изменяет SQLite и исключает уже опубликованные клипы, `CHANGED` (ручной Replace), процедурные `.animation.json`, клипы без подготовленного файла и повторные ссылки на один `clipId`.

Публикация каждого элемента идёт через прежний `POST /api/animations/{clipId}/publish`. Каждое успешное подтверждение должно вернуть числовой `asset_id` и `status=PUBLISHED`. Очередь не заменяет серверную проверку SHA256/публикации, запись истории и экспорт Registry. Попытки параллельной публикации **одного clipId** блокируются в процессе Host Agent.

## Очередь и ошибки

Визуальные состояния: `pending`, `uploading`, `published`, `failed`. Показываются название, источник, ID клипа, выполнено/всего, число успешно опубликованных и прогрессбар. Пользователь может остановить **после** текущего HTTP-запроса, затем продолжить. Если запрос завершился ошибкой (включая Open Cloud 500), очередь останавливается; ошибочный элемент **не повторяется автоматически**. Явная кнопка «Пропустить ошибку и продолжить» обрабатывает оставшиеся клипы.

Roblox HTTP 500 или сетевой таймаут при `create` не доказывают, что ассет не был создан. Прежде чем **вручную** повторять такой клип, нужно проверить результат в Roblox. Существующие успешные ID и записи SQLite не откатываются. Никаких автоматических retry POST.

`Register + Publish` использует ту же очередь, поэтому прогресс дублируется внутри диалога сканирования. `Publish All` выбирает неопубликованные записи из сервера, а не из текущего фильтра UI или видимого пола.

## Проверки

`system/verify/test_m474_animation_publish_queue.py` — серверная выборка и блокировка параллельных запросов; `system/verify/animation_publication_queue_m474.js` — последовательность, HTTP 500, Stop/Continue, состояния UI; `test_character_animation_scan_publish_m193.py` — интеграционный контракт регистрации через очередь. Внешний Roblox Open Cloud не эмулируется как проверенная реальная публикация. Studio Play и реальное Open Cloud размещение требуют проверки в пользовательском окружении.
