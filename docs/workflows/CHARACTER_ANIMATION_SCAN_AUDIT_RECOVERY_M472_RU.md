# m472 · безопасное сканирование и аудит анимаций

## Контракты

- `animation_core.scan_review` принимает в одной выбранной папке явные `human_male_*`, `human_female_*`, `human_common_*`; доверяет зарегистрированному семейству, не выбранной вкладке. Общий клип имеет единственного владельца `human_common` и один Roblox Animation ID. Префиксы неизвестных персонажей остаются отклонёнными.
- Публикация работает через существующую `AnimationPublicationMixin`; никакого обхода MySQL Asset Audit. Если Common-запись зарегистрирована, но не опубликована, она видна в Common → Publish и не попадает в Runtime до подтверждения публикации.
- `animation_publications.id` — неизменяемый `sourceRecord` MySQL Asset Audit. `clip_id` может меняться при канонизации номера версии, но `assetKey` исторической операции должен оставаться прежним. Таблица `animation_publication_audit_keys` хранит исходный `clip_id` для каждой операции и проверяет `asset_id` и `operation_path`. Триггер фиксирует ключ для новых публикаций до любой будущей миграции.
- `SqliteAssetAuditImporter` остаётся read-only. MySQL Audit нельзя очищать, подменять или переимпортировать под новым ключом. Новые публикации создают новые строки истории, не перезаписывая старые.

## Миграция после m470

Запустить **один раз до запуска Publish**:

`python system/control-center/migrations/m472_animation_audit_identity.py`

Миграция проверяет сохранённый снимок `.control-center/backups/m470_animation_versions_*.db`, сверяет ID записи, Roblox Asset ID и путь операции, затем резервирует текущую SQLite и записывает оригинальные ключи. Если снимок утрачен или противоречит опубликованным данным — останавливается и ничего не исправляет приблизительными заменами. Повторный запуск безопасен.

Далее перезапустить Control Center, обновить страницу и повторить Publish у неопубликованных записей. В версии M472 реестры Animation ID, модели, анимационные данные, Studio и Runtime напрямую не изменяются; после новых публикаций потребуется обычная подготовка Registry и Rojo Sync.

## Приёмка

- Смешанная папка из 3 префиксов сканируется из Male и Female одинаково; регистрация каждого клипа происходит один раз. Иные семьи не регистрируются.
- Публикация непройденного Common-клипа доступна из раздела Common, даже если сканер пометил исходный файл `UNCHANGED`.
- До/после миграции все старые `sourceRecord` должны давать неизменные `assetKey` в Asset Audit; публикации после миграции используют новые корректные `_01/_02` ключи.
- Плохой backup или несовпадение опубликованного ID приводит к явному отказу, без удаления истории.
- Studio Play и настоящую загрузку в Roblox Open Cloud нужно подтвердить в пользовательской среде, статические тесты их не заменяют.
