# M193 · Character Animations: разблокировка Register + Publish после Scan Folder

## Причина

В `character-animation-ui.js` функция `scanFolder()` ставила `busy=true`, затем вызывала
`renderScan()`. Эта функция выставляла `animation-register-selected.disabled=true`
даже при наличии новых (`selectable`) файлов. В `finally` выставлялось `busy=false`,
но вызывался только `api.render()` — внешний рендерер таблицы анимаций не обновляет
кнопки внутри модального окна Scan Folder. Поэтому `Register + Publish` оставалась
недоступной до следующего полноценного открытия/сканирования.

## Исправление

- `syncScanPublishButton()` отдельно вычисляет доступность действия по флагу `busy`,
  текущему `animationCharacter` и **отмеченным** файлам со `selectable=true`.
- После завершения асинхронного Scan Folder кнопка пересчитывается при `busy=false`.
- Выбор/снятие чекбоксов в окне обновляет доступность без перерисовки отчёта.
- Результат сканирования для старого персонажа отклоняется, если выбор изменился
  до ответа сервера; старый отчёт нельзя отправить для другого персонажа.
- Ошибка регистрации оставляет выбранные файлы для повтора. После успешной
  регистрации повторная отправка того же отчёта блокируется, даже если один из
  запросов публикации завершился ошибкой: неопубликованные строки остаются в
  профиле и публикуются через `publish` в таблице.

## Не изменялось

`/api/animations/preview`, `/api/animations/register-selected`,
`/api/animations/{clipId}/publish`, SQLite, механизм Open Cloud, идентичность клипов,
публикация/замена постоянного Animation Asset ID и runtime анимаций.

## Приёмка

1. Выбрать Character и каталог с новыми файлами `.rbxm`, выполнить **Scan folder**.
2. Окно Scan Folder показывает `NEW` с отмеченными чекбоксами;
   **Register + Publish** доступна сразу после окончания сканирования.
3. Снять все отметки — действие недоступно. Вернуть — доступно.
4. Нажать **Register + Publish** — выбранные файлы регистрируются и публикуются;
   после регистрации тот же отчёт нельзя применить повторно.
5. Ошибка регистрации позволяет попробовать ещё раз без повторного Scan Folder.
6. После смены персонажа старое сканирование нельзя опубликовать.

Автоматизированный тест: `system/verify/character_animation_scan_publish_m193.js`
запускается из `test_character_animation_scan_publish_m193.py`. Реальную Roblox
Open Cloud публикацию тесты не выполняют.
