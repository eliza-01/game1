# M276 — миграция Character Atlas Registry

Операция выполняется **один раз вручную**, после остановки Host Agent. Не вызывается при старте и никогда не обращается к Roblox Open Cloud. Новые Model/Atlas Asset ID не публикуются.

## Идентичности

Текстуры называются `<human>_<male|female|common>_mNNN_tNNN_<slot>_<W>x<H>_atlas.png`. Это исторически выбранный формат Character texture authoring. `m001` указывает совместимый набор геометрии, но **не делает атлас собственностью MeshPart**: Armor Appearance продолжает ссылаться на независимый вариант Atlas Registry по ID и может переиспользоваться несколькими комплектами. `t001` — цветовая/материальная вариация, а не номер публикации.

Запланированные соответствия в `services/character_atlas_migration.py`:

| Старый ключ | Новый ключ | Обоснование |
|---|---|---|
| `head_01_male` | `human_male_m001_t001_head` | Старый ресурс явно мужской, не объявлять общим |
| `newborn_boots` | `human_common_m001_t001_boots` | Базовая общая текстура |
| `newborn_gloves` | `human_common_m001_t001_gloves` | Базовая общая текстура |
| `newborn_lower` | `human_common_m001_t001_lower` | Идентичная новая запись уже существует; безопасное объединение |
| `newborn_upper` | `human_common_m001_t001_upper` | Разрешения сохраняются как варианты одной семьи |
| `pinky_upper` | `human_common_m001_t002_upper` | Отдельная окраска, не перезапись t001 |

## Защита данных

- По `--dry-run` (или запуску без аргументов) только печатается план, никаких файлов и БД не меняется.
- По `--apply` сначала проверяются существующие байты каждого исходного изображения по SHA-256; новые канонические копии создаются **без удаления оригиналов**.
- Перед SQL-переименованием создаётся SQLite backup `.control-center/backups/before_character_atlas_names_m276_*.db`.
- Если новый и старый варианты одной разрешающей способности уже имеют **одинаковые** source SHA и published ID, старый вариант помечается историческим, привязки/appearance переадресуются на существующий канонический вариант. При различии данных выполнение останавливается.
- `published_id`, `published_sha256`, история публикаций, `original_filename` не переписываются. Архивные v1-привязки `character_part` переносятся в таблицу `character_atlas_legacy_bindings_m276`, но **не** назначаются автоматически новым Armor Set.
- Перезапуск идемпотентен: обработанных записей в активном каталоге больше нет. Никакой автоматической миграции других доменов.

## Запуск и восстановление

Из корня game1 после остановки Host Agent: `python system/control-center/migrate_character_atlases_m276.py`, затем при верном плане `python system/control-center/migrate_character_atlases_m276.py --apply`. Запускать только с копией текущей БД; диагностический архив намеренно не содержит изображений.

Для восстановления остановить Host Agent, сохранить текущую DB отдельно и вернуть `game1.db` из указанного backup. Скопированные канонические файлы можно оставить: они не перезаписывают исходники и не являются причиной изменения опубликованных Asset ID. После отката БД старые пути остаются работоспособными.

## Проверки после применения

Atlas Registry: восемь активных разрешений Character под шестью новыми ключами; опубликованные Image Asset ID должны совпасть с предпросмотром. `newborn_lower` и `human_common_m001_t001_lower` не должны показываться как две отдельные активные записи. В новом Armor Catalog выбрать Appearance для каждого слота вручную — миграция имен **не** приписывает текстуры комплектам без задания заказчика.
