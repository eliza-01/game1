# M280 · Ориентация Bone socket и цвета глаз/бровей

## Единый контракт направления

**Фасад объекта смотрит от Tail к Head Blender Bone.** В Blender локальная
`+Y` кости — от Head к Tail; после Roblox FBX импорта Bone `UpVector` — это
локальная `+Y`. Поэтому `forward = -BoneFrame.UpVector`, а не `LookVector`.
Обычный `Attachment` (не Bone) использует стандартный `LookVector` (`-Z`).

Единственный вычислитель этих осей —
`src/shared/world/SocketFacing.luau`:

- `Forward(frame, isBone)` — направление без изменения позиции и roll;
- `FullFrame(frame, isBone)` — полная ориентация с сохранением второй оси
  Bone (его `LookVector` задаёт UP) для жёстких предметов, причёсок, сундука;
- `HouseSpawnOrientation.Upright` берёт тот же `Forward`, но специально
  проецирует его на горизонтальную плоскость и использует мировой `Y` как UP
  для стоящего персонажа. Нельзя напрямую копировать roll кости в аватар,
  иначе персонаж может лечь на бок.

Сервер при сборке `CharacterHairComponent` и клиент в каждом обновлении
используют одинаковый `SocketFacing.FullFrame`. Крепится Pivot **корневого**
`hair` MeshPart; `extra_XX` сохраняют положение относительно него.
Угол `90°` в виде индивидуального компенсатора не добавляется. Если фасад
неверен, сначала проверяют ориентацию авторской `hair_mount` Bone в Blender.

Для процедурных сундуков/замков направление читается по тому же контракту.
Дверные ручки, лифты и дымовые эффекты сохраняют механику своих сокетов:
не каждый сокет является направленным объектом.

## Цвет глаз и бровей

`eye_l`, `eye_r`, `eyebrow_l`, `eyebrow_r` — самостоятельные MeshPart с
однотонной окраской. В Character Assembly v2 у них **нет выбора Atlas**.
Вместо этого у каждой выбранной части свой `#RRGGBB` (`face_colors`).
Слоты `head` и `hair` пока сохраняют прежний необязательный Atlas picker;
для rigid hair отдельно существуют `hair_colors` primary / extra_XX.
Armor Catalog никак не меняется.

Пример рецепта:

```json
{
  "face_colors": {
    "eye_l": "#112233", "eye_r": "#112233",
    "eyebrow_l": "#5A321E", "eyebrow_r": "#5A321E"
  }
}
```

Resolver отказывает некорректным значениям и цветам без выбранного MeshPart.
Runtime использует один `CharacterColorBinder` для глаз, бровей и каналов
составной причёски: при отсутствии `SurfaceAppearance` меняется `MeshPart.Color`,
при наличии — `SurfaceAppearance.Color`. Для произвольных оттенков
исходные материалы должны быть нейтральными (без запечённой цветной текстуры).
Старые рецепты без `face_colors` сохраняют цвет, импортированный вместе с
мешем; прежние ссылки на Atlas глаз/бровей больше не участвуют в resolver.
Опубликованные Model ID / Image ID не меняются, миграция БД не нужна.

## Проверка Studio Play

1. Повернуть голову и проверить, что root волос и `extra_XX` следуют за
   `hair_mount`, сохраняя фасад Tail → Head.
2. Сравнить крепление на новом риге после переспавна и поворота.
3. Проверить, что тестовые сундук/спавн не потеряли ориентацию; на spawn
   персонаж остаётся вертикальным.
4. Выбрать разные цвета для двух глаз и двух бровей и проверить их в Play,
   включая `FacePresentation` display copies и эмоции.
5. Убедиться, что голова/броня продолжают работать с опубликованными Atlas.

Фактическое поведение Roblox Studio и live Blender FBX не проверяется
Python-тестами; проверка в Play обязательна.
