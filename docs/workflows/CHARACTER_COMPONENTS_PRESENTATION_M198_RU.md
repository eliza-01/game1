# M198 — Characters: регистрация FBX, публикация и ранжирование атласов

Дата: 2026-11-02. База: свежий `game1_diag_2026-11-02_22-17-52.zip` (после M197).

## Изменения (только интерфейс)

1. `cp-publish-all` перенесена из заголовка таблицы `cp-table` под таблицу, вправо. Обработчик и серверная публикационная очередь не менялись.
2. Убрана отдельная кнопка `cp-register` снаружи диалога. Теперь FBX Inspect открывает `cp-conflict` и **единственная** кнопка `cp-confirm` запускает регистрацию выбранных новых частей / подтверждённых замен напрямую. Отмена не изменяет данные. Серверный `/api/characters/components/register`, токен Inspect и payload остались прежними.
3. В `cp-table` зарегистрированные, но не опубликованные ревизии всегда вверху; ручная сортировка `name / part / set` действует внутри двух групп. Определение опубликованности — прежнее: `model_asset_id` + `published_revision == revision`.
4. В `shared atlas` для каждой части первыми идут варианты семейства с **точным именем части** (также явно пронумерованные версии `<part>_01`), по убыванию площади, ширины и высоты. Остальные Character-атласы продолжают быть доступны; привязка чужого семейства не изменяется автоматически.
5. Под таблицей регистрации остаётся одна четырёхколоночная таблица Character shared atlases; семьи получили визуальные разделители. Внутри семьи варианты ранжированы по площади и отмечены цветной точкой. Палитра соответствует Location Assets: золото, фиолетовый, синий, зелёный, серый (для рангов от 5 и далее — серый). Выбранный вариант выделяет border соответствующего `select`. Это **только отображение**: текущие привязки, классификация на сервере, Asset ID и операции публикации не меняются.

## Ответственность модулей

- `character-atlas-presentation.js` — чистая политика сортировки, соответствия части семейству и цветового ранга. Нет сетевых запросов.
- `character-components.js` — регистрационный UI, таблица компонентов, выбор shared atlas.
- `character-atlas-ui.js` — оформление каталога Image Assets и модалка публикации атласов.
- `character-publications.js` — существующая очередь публикации, не переписана.
- `character-components.css` — представление групп и рейтинга.

**Ограничение диагностики:** в приложенном дампе `verify.py` уже возвращает ошибку отсутствующего authoritative timeline для зарегистрированной `human_male__weapon__hands__attack__01`. Она воспроизводится *до и после* UI-изменений, в рамках M198 не исправляется. Полный Python-suite содержит три соответствующие исходные неудачи. Состояние game1 DB, анимаций и таймлайнов не изменялось.
