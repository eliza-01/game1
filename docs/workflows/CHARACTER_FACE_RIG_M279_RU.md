# M279 · Character: лицевые слоты, Bone-анимации и hair_mount

## Лицевые компоненты

`human_*_mNNN_eye_l/r` и `..._eyebrow_l/r` публикуются по одному MeshPart на сторону.
**Раздельная геометрия не означает раздельных анимаций**: общий Animator проигрывает один
KeyframeSequence с Pose-каналами `face_eye_l/r` и `face_brow_l/r`.

В `FacePresentation` эти же четыре Bone являются опорными для экранных копий
глаз/бровей и процедурных оверлеев. В прежнем M271 ошибочно использовались
`face_eye_ctrl_l/r` и `face_brow_ctrl_l/r`, которых нет в зарегистрированном
`human_female` (77 Bones). Поэтому Presenter возвращал nil.

`FaceAnimationController` не переносит клипы между ригами автоматически.
При отличии документа `rig.asset_id` от `CharacterRigAssetId` клип не
исполняется и пишет предупреждение о несовместимости.

## Из архива emotions.7z

- 13 документов эмоций, из них 5 skeletal: idle, combat_idle, sad, look_around,
  raised_eyebrow. Все пять `.rbxmx` имеют совпадающий SHA-256 в sidecar JSON;
  анимируют `face_eye_l/r` и `face_brow_l/r` вместе с общей иерархией.
- Остальные 8 — процедурные JSON, не требуют Roblox Animation Asset ID.
- В пяти скелетных документах `rig.id=human`, revision 2, Model ID
  `99890351983275`. **Это не текущий `human_female` Model ID**.
- Сначала проверить совместимость анимируемых костей/bind pose с
  `human_female`, затем заново экспортировать либо явно адаптировать клипы
  к актуальному ригу и обновить `rig` в JSON. Нельзя просто стереть
  проверку или подставить ID без проверки.
- После подготовки положить файлы в отдельную папку, выбрать персонажа
  `human_female` во вкладке Animations, выполнить Scan Folder,
  Register + Publish, затем синхронизировать `CharacterAnimationRegistry`.
  Для procedural `.animation.json` не требуется публикация Animation ID.
- Графические варианты `*_happy_sharp_caret`, `*_happy_thick_caret`,
  `*_nausea_wave` и `*_spiral` должны существовать в `Game1FaceAssets`
  для соответствующих глаз. Одних event JSON недостаточно для их появления.

## Волосы

Корень причёски и `extra_XX` остаются одной составной моделью, и только
корневой Pivot управляет посадкой. Ориентация `hair_mount` у текущих
опубликованных `human` и `human_female` **отличается примерно на 90°**,
что воспроизводит проблему со скриншота. Причина в исходном риге, не в
количестве MeshPart. Для авторского правила «от хвоста к голове» сначала
нужно привести направленность Bone `hair_mount` в Blender к единому
контракту осей и подтвердить импортированную ориентацию в Studio.
Нельзя компенсировать разницу жёсткой поворотной константой в runtime —
это испортит другие причёски и риги. Roblox Bone не хранит явную длину
и координаты хвоста отдельными свойствами; полный конец кости нельзя
восстановить из одного `Bone.WorldCFrame` без принятого соглашения об осях.

M279 меняет только сопоставление костей лица и диагностику устаревших
скелетных анимаций. Механизм крепления волос **не изменён**.
