# M196 · Characters — независимое обнаружение корректных компонентов

## Причина

M195 устранил блокировку Replace Rig при ошибке FBX-компонентов, но его ветка
`Rig only` очищала **все** `parts` после первой ошибки. Поэтому корректная
`hair_03_common` исчезала из результата Inspect, если в том же FBX находилась
неподдерживаемая `eyebrows_01_l` или другая неисправная часть.

## Контракт

- Blender анализирует компоненты независимо. Он сохраняет `parts` для каждой
  корректной части, а ошибки остальных записывает в `part_errors` с именем
  исходного Mesh. Невалидные части не экспортируются.
- `hair_03_common` без Armature Modifier и deform weights по-прежнему имеет
  `attachment_mode=pivot`, `attachment=hair_mount`. Механизм M194 не менялся.
- Если нет **ни одного** корректного компонента, прежняя строгая ошибка остаётся;
  для уже зарегистрированного изменённого рига доступен восстановленный в M195
  режим **Rig only required**.
- Если есть и корректные, и ошибочные части, Inspect показывает каждый
  корректный компонент, ошибки поименованно, и помечает план
  `partial_required=true`. Такие части можно зарегистрировать **только** после
  отдельного подтверждения «Register ONLY validated components».
- Одобрение проверяет и backend (`allowPartial=true`). При его отсутствии
  изменения в регистрации отклоняются. Для опубликованных компонентов
  обязательно также обычное согласие на замену.
- `Rig only` при изменении рига по-прежнему разрешает замену **только** рига,
  не изменяя существующие компоненты и опубликованные Asset IDs.
- Перед коммитом повторный Blender-анализ замороженного FBX сверяет
  content hashes признанных корректными деталей и список ошибок адаптера.
  Если результат изменился, публикационный артефакт не регистрируется.

## Сценарий

1. Выбрать FBX с `human_armature`, `hair_03_common` (rigid pivot) и
   неподдерживаемой `eyebrows_01_l`.
2. Inspect должен показать `hair_03_common · rigid pivot → hair_mount`
   и отдельную ошибку `eyebrows_01_l`.
3. В окне подтверждения явно разрешить регистрацию **только корректных**
   компонентов. Если также изменился риг и по умолчанию отмечен `Rig only`,
   отключить этот режим, чтобы зарегистрировать волосы.
4. Register создаёт/обновляет `hair_03_common`, не регистрируя ошибочную часть.
   Обычная очередь публикации не меняется.
5. Если никакая деталь не прошла проверку, исправить исходный FBX или
   использовать M195 `Rig only` для уже зарегистрированного изменённого рига.

## Границы изменений

Не менялись naming standard (`eyebrows_01_l` по-прежнему не разрешено),
масштаб/ориентация Blender FBX, skinning, жёсткое крепление, сборка Studio,
реестры анимаций, SQLite, публикация или Model Asset IDs.

Проверки покрывают оба режима регистрации и сохранение текущих данных.
Работа реального Blender FBX-import и Roblox Open Cloud в тестовой среде
не запускалась.
