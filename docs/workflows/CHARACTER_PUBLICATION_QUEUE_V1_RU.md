# Characters: очередь публикации компонентов v1

В таблице **Registered sets / Rig & parts** между **shared atlas** и
**publication** расположены чекбоксы. Чекбокс заголовка отмечает все
неопубликованные/изменённые компоненты. Текущая опубликованная ревизия
не выбирается и не загружается повторно.

В заголовке столбца publication — **Publish all**: запускает только отмеченные
строки. **Publish / Publish replacement / Resume publication** отдельной строки
используют ту же очередь и то же модальное окно. Атласы публикуются прежними
кнопками своего каталога; эта очередь предназначена для rig/part Model assets.

## Поведение

- Одна очередь проекта, один компонент за раз; rig обрабатывается первым.
- Модальное окно показывает весь список, статус, текущий этап, ошибку/предупреждение
  и полученный Model Asset ID. Progress bar считает завершённые компоненты,
  процент переданных байтов не выдумывается.
- Этапы: ожидание блокировки, проверка FBX, upload, обработка Roblox либо
  продолжение сохранённой operation, запись ID.
- Ошибка одной строки не отменяет остальные. После завершения — итоговый тост;
  для одиночного Publish — имя компонента и ID/ошибка.
- Закрытие окна не отменяет worker. **Show publication queue** возвращает окно.
  Reload страницы восстанавливает отслеживание. Тост не повторяется бесконечно
  при reload и остаётся доступным поверх модального окна.
- Двойной запрос с тем же request UUID возвращает существующий job. Другая
  очередь во время активной получает conflict; пересекающихся uploads не создаёт.
- Выбранные ревизии проверяются при старте и перед каждой публикацией.
- Старые Model IDs остаются назначенными до успеха новой публикации. Уже
  опубликованные ревизии пропускаются. Сохранённая в SQLite Open Cloud operation
  используется при явной повторной попытке, без нового upload.
- Успех upload с ошибкой локального registry export показывается как опубликовано
  с предупреждением, а не как повод загрузить файл повторно.

Состояние последних 20 очередей (не более 100 строк в каждой) хранится в
`.control-center/character-publication-queue.json`, запись атомарная. Credentials
в progress-файл/GET response не попадают. После перезапуска Host Agent активная
очередь становится interrupted и сама не возобновляет внешние операции. Нужна
явная повторная публикация незавершённых строк; SQLite publication state сохраняется.

## API v1

- `POST /api/characters/components/publication-queue`:
  `{request_id: UUID, items:[{kind:"rig"|"part",id,revision}]}` → HTTP 202, job.
- `GET /api/characters/components/publication-queue` → `{schema_version:1,job}`
  с последней очередью либо null.
- `GET .../publication-queue/<UUID>` → конкретная очередь; неизвестная — 404.
- Конфликт активной очереди/ревизии/request UUID — 409; неверные данные — 400.

Старый синхронный `/publish` endpoint сохранён для совместимости. Новый интерфейс
использует фоновые jobs, не держит HTTP запрос открытым на время upload.
CharacterComponents остаётся владельцем ID/operations, queue service — состояния
и последовательности, UI — отображения и выбора. При успехе обновляются recipe
registries/готовность персонажей. Схема SQLite и runtime персонажа не меняются.

## Проверки

Unit: последовательность и rig-first, progress, продолжение после failure,
идемпотентность, конфликт очереди/ревизии, skip current, restart interruption,
отсутствие credentials в файле/GET, registry warning после успешной публикации.

Browser: настоящие UI и queue service на отдельном localhost fixture с имитацией
uploads. Batch с ошибкой, восстановление отчёта после reload, одиночный retry,
итоговый toast. Реальные Roblox uploads этим изменением не запускались.
