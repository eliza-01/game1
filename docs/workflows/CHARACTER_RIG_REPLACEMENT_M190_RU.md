# M190 · Замена и повторная публикация профиля рига персонажа

## Граница ответственности

Это изменение относится к **Characters / Rig & parts** в Control Center.
Пути импорта FBX, Blender extractor, source-only prepared FBX, Open Cloud
Create Model Asset, очередь публикации, Studio Sync и существующие
форматы каталогов **не меняются**. Ни один ранее опубликованный ID не перезаписывается.

## Сценарий

1. `Choose FBX · inspect` с ранее зарегистрированным `<profile>_armature`.
2. Если совпадают имена костей, их родители и bind-матрицы, старый профиль
   повторно используется, как раньше.
3. Если есть несовпадение (например `back_mount`), Inspect возвращает
   `rig.changed=true`, текст отличия, старый revision и опубликованный Model ID.
   Преждевременного `register a new rig profile` исключения больше нет.
4. Окно подтверждения содержит **отдельный** флажок `Replace RIG ...` и
   индивидуальные флажки опубликованных мешей. По умолчанию включён **Rig only**:
   подтверждение рига обновляет только запись рига; опубликованные меши остаются
   без изменений. Для одновременной замены мешей пользователь выключает Rig only
   и подтверждает каждый опубликованный меш. Без требуемых согласий база не меняется.
5. Register повторно проверяет immutable FBX snapshot, ревизии, pending upload
   и Model ID после Inspect. Затем выделяет компоненты и в одной транзакции:
   - записывает старый риг в `character_component_history`;
   - закрепляет текущие unpinned assembly-рецепты за старой published revision,
     сохраняя их собственную историю;
   - регистрирует новую revision того же `rig_id`;
   - при `rigOnly=true` полностью исключает части из commit (их ревизии, пути,
     bind-метаданные и Model IDs остаются прежними).
6. Новый риг становится `replacement_pending`; старый Model Asset ID остаётся
   активным до успешного Publish через стандартную очередь (rig first).
7. Повторная публикация создаёт **новый** Roblox Model Asset ID. Старые
   сборки остаются на pinned revision. Обновление рецептов/частей/анимаций
   под новый bind pose — отдельное осознанное действие.

## Инварианты

- Никакой неявной замены рига при регистрации частей.
- Регистрация не выполняет cloud-upload.
- Ошибки изменения исходника, конкурентной публикации и гонки ревизий
  должны приводить к `409 inspection_conflict` без изменения записей.
- Неизменённый риг не получает новую ревизию.
- Незатронутые части сохраняют свои опубликованные версии.
- Изменённые кости могут сделать старые компоненты несовместимыми с новым
  ригом. Никакой автоматический retarget / rebind не выполняется.

## Тесты

`test_character_components.py` — approval, историю, неизменённый старый
Asset ID, режим Rig only, запрет гонки Inspect/Publish, новую публикацию.
`test_character_assemblies.py` — сохранение существующих персонажей на
предыдущей ревизии при замене из **полного FBX**.

Реальную публикацию и сборку в Roblox Studio проверять после установки;
тестовый облачный upload заменён mock-ответом.
