# Предложение M450 · Выбор и создание персонажа (Lineage II — визуальный референс)

**Статус:** проектирование, НЕ реализовано. Референс — композиция и последовательность экранов Lineage II, не копирование чужих ассетов/интерфейсов. Не считать это утверждённой схемой хранения персонажей.

## Что подтверждено текущим Game1

- `src/server/character/CharacterService.luau` ставит `Players.CharacterAutoLoads = false`, но тут же вызывает `createCharacter` для каждого `PlayerAdded`. Сейчас полноценного обязательного выбора слота нет.
- `CharacterService.Respawn`, `CharacterRigService` и `CharacterAssemblyBuilder` уже предоставляют путь сборки игрового персонажа. Новый экран не должен дублировать их.
- `src/client/character/CameraController.luau` владеет обычной игровой `Scriptable` камерой с курсором/ПКМ/приближением. Меню должно передавать владение камерой явно, а не бороться с игровым RenderStep.
- `src/server/dev/TestLoadoutService.luau` предназначен для Studio Test Loadout и не является учётной записью MMO.
- По аудиту M447 полноценное сохранение персонажа, inventory, account slots и transaction safety в Runtime пока отсутствует.

## Рекомендуемая схема

**На первом этапе:** локальная 3D-сцена презентации и её собственная камера в текущем Place (без автоматического спавна игрового тела до подтверждения выбора); затем возможно вынести меню в отдельный Roblox Place внутри одной Experience. Отдельный Place полезен как масштабируемая граница, но вводит переход/повторную загрузку и не должен становиться условием для первого прототипа.

- `CharacterEntryService` (сервер): переходы `Loading -> Selection -> Creation -> EnteringWorld -> InWorld`, anti-spam и единственная точка допуска в игровой мир.
- `CharacterAccountRepository` (сервер, будущая реализация): по `UserId` список `characterId`, класс/архетип, имя, appearance, location/version. DataStore и блокировки/идемпотентность нужны до публикации аккаунт-системы.
- `CharacterPreviewAssembler` (клиент): для меню собирает только визуальную копию из действующих реестров/rig assembly; она не является `Player.Character`, не получает боевые сервисы и не записывается в игровой мир.
- `CharacterSelectionController` / `CharacterCreationController` (клиент): только UI, навигация слотов и локальный preview. Клиент не утверждает class/appearance/characterId как доверенные данные.
- `CharacterSelectionCameraController` (клиент): эксклюзивный camera mode с сохранением/восстановлением предыдущего состояния. **Игровой CameraController не должен писать в CFrame одновременно.**

## Презентация и камера

- Одна атмосферная сцена (в духе Lineage II: платформа/зал/ландшафт), с отдельными CameraAnchors; копируется/показывается локально, другие игроки не видят персонажа-превью.
- Выбор: персонаж целиком, почти фронтально, композиция с местом под UI; слоты и «Войти в мир» по краям/снизу.
- Создание: раса/класс/пол/внешность; боковой интерфейс + более близкая камера. Превью реагирует на изменение лица/волос без спавна настоящего игрока.
- Камера `Scriptable`, tween между authoring `CameraAnchorSelection`, `CameraAnchorCreation`, `CameraAnchorFace`; для контекста отдельных рас могут быть свои декорации/свет, но единый контроллер.
- Телефон/планшет: адаптивные зоны, безопасные отступы; не накладывать управление боем на экран создания. Кнопки инвентаря/атаки показываются только после входа в мир.

## Переход в мир

1. Вход игрока: сервер устанавливает состояние Selection, **не вызывает** `createCharacter` до подтверждения выбора/создания.
2. Клиент загружает разрешённый список слотов, показывает 3D-preview. Пустой слот открывает Create.
3. Создание: сервер проверяет слот, разрешённые archetype/appearance, имя, уникальность и ограничение количества; сохраняет запись и возвращает characterId.
4. «Войти в мир»: сервер проверяет `characterId` на принадлежность `UserId`, делает атомарное начало входа, загружает состояние и вызывает существующий CharacterService для сборки.
5. Когда игровой персонаж готов, передать управление обычной камере/движению, скрыть презентационный мир. Не использовать клиентский CFrame как точку спавна.
6. Сбой загрузки/телепорта: вернуть выбор с сообщением, не создавать второй персонаж и не терять слот.

## Минимальная приёмка будущего этапа

- Два персонажа одного аккаунта показываются отдельно, без подмены их appearance или инвентаря; другой пользователь не может выбрать чужой `characterId`.
- Пока открыт выбор, игрового персонажа в Workspace нет, боевые команды не работают, камера не перехватывается PC RMB/мобильным взглядом.
- После создания и повторного входа сохранены имя, слот, класс и внешность (только после интеграции с постоянным хранилищем).
- Переход Creation -> Selection -> Enter World -> Death/Respawn не создаёт лишних Camera/RenderStep/GUI/анимационных соединений.
- Studio Test Loadout продолжает действовать только в Studio и не обходит опубликованную авторизацию.
