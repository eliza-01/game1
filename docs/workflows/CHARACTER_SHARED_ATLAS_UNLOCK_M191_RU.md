# M191 · Character Shared Atlas: восстановление интерактивности таблицы

## Симптом и причина

После успешного выбора общей текстуры через выпадающий список `shared atlas`
появлялся статус `Atlas selected. Shared Image Asset ID reused; no mesh upload.`,
но все списки оставались неактивными до перезагрузки страницы.

`character-components.js` выполняет `run()` с `busy=true`, внутри запроса
обновляет таблицу посредством `refresh()/render()`, а потом снимает флаг
`busy` в `finally`. Новый DOM из `render()` создавался с `select.disabled=true`.
Старая `lock(false)` снимала блокировки только с верхних кнопок и
publication queue, но не с новых dropdown-элементов.

## Изменение

- `syncAtlasControls()` синхронизирует актуальные селекты в `#cp-rows` с
  двумя независимыми источниками блокировки: локальной операцией `busy`
  и состоянием `game1CharacterPublications.isRunning()`.
- `lock()` вызывает эту функцию при начале/завершении операции и при событии
  `character-publication-state`. Созданные заново строки корректно
  разблокируются; во время реальной публикации остаются заблокированы.
- У атласных селектов есть `data-cp-atlas-select` для точной адресации;
  остальные элементы таблицы не затрагиваются.
- Версия подключаемого скрипта изменена на `v=7` для сброса браузерного кеша.

## Границы

Не меняются HTTP `/api/characters/components/atlas`, опубликованные
Image/Model Asset ID, привязки Atlas Registry, SQLite, механизмы импорта,
очередь публикации, скрипты Studio и UI других разделов.

## Проверка

`test_character_shared_atlas_unlock_m191.py` выполняет реальный
`character-components.js` в Node.js с тестовой DOM-моделью: первый успешный
выбор Shared Atlas, немедленный второй выбор в другой строке, ошибка запроса,
блокировка/разблокировка при запуске и завершении очереди публикации.
Тест до исправления воспроизводит проблему блокировок.

В браузере проверить смену двух атласов подряд, повторное открытие dropdown,
и отсутствие доступности редактирования при работающей publication queue.
