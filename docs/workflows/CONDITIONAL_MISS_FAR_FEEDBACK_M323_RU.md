# M323 · Условный Miss / Far после атаки

База: M322. Схема M317 — серверный Hitscan для лука, один snapshot и один
Release — **не меняется**. Визуальный результат атаки не влияет на урон.

## Контракт

Сервер отправляет `CombatFeedback(kind="miss" | "far")` только когда завершённая
атака **не нанесла урон**. Правила классификации по приоритету:

1. Под прицелом **живой монстр**, но его точка контакта за текущим `AttackRadius`
   персонажа → `Far` (даже когда игрока кто-то преследует).
2. Игрока **преследует хотя бы один** зарегистрированный монстр/боевой NPC → `Miss`.
3. Под прицелом находится **живая уязвимая цель внутри** `AttackRadius` → `Miss`.
4. Ни одно условие не выполняется → **нет всплывающей надписи**.

Для меча / ближнего оружия `Far` ограничен одним показом в 10 секунд на игрока.
Для лука `Far` возможен на каждом **подтверждённом Release**. Урон и
попадания подавляют обе надписи. Отбившийся о препятствие удар или отклонённый
по сетевым/валидаторным причинам выстрел не выдают фиктивный результат.

## Архитектура

- `shared/combat/AttackFeedbackPolicy`: чистое правило приоритета и интервала.
- `server/combat/AttackFeedbackTargeting`: однократная серверная проверка
  прицельного луча по существующим Bone-хитбоксам; проверка стены через
  `Workspace:Raycast`; дальность вычисляется от `RootCollider`. Это **только
  классификация обратной связи**, не дополнительный способ нанести урон.
- `server/combat/AttackSessionStore`: последний валидированный луч прицела,
  сохранённый на длительность одной атаки мечом.
- `server/combat/AttackService`: при завершении ближней атаки или Release лука
  вызывает единственное определение результата, если урон равен нулю.
- `server/combat/CombatFeedbackService`: серверная дедупликация/10-секундный
  интервал, существующий RemoteEvent, сброс состояния при выходе игрока.
  Промах вражеского NPC/монстра передаётся только если за игроком по-прежнему
  закреплён преследователь в `HostilePursuitRegistry`.
- `client/combat/CombatFloatingText`: `Miss` и `Far` показываются над персонажем
  через общий визуальный компонент; `Far` выделен янтарным цветом.

Никаких новых RemoteEvent, кадровых серверных запросов или пересчёта
Hitscan, механики монстров, настроек HP и UI профилей M322.

## Ограничения

Кандидат определяется на сервере по существующей геометрии боевых хитбоксов
до `AttackConfig.MaxAimDistance` (420 studs); невидимые за стеной цели
не вызывают `Miss`/`Far`. Если хитбоксы цели не зарегистрированы или её точка
за пределом обзора, надпись не создаётся. Проверка проводится в момент
завершения атаки / Release, поэтому для двигающейся цели классификация
учитывает её текущее серверное положение, а не историческую позицию.

## Проверки Studio Play

1. Пустой мир, серия атак мечом и луком: без `Miss` и `Far`.
2. Здоровый монстр внутри радиуса под прицелом, атака нанесла урон: нет `Miss`.
3. Нулевой урон при наведении на цель внутри радиуса: один `Miss`.
4. Дальний монстр под прицелом (нет преграды), лук: `Far` на каждый Release.
5. Дальний монстр, меч: `Far` однократно, повтор не раньше 10 секунд.
6. За игроком гонится враг, меч мимо пустоты: `Miss`.
7. Монстр за стеной, без погони: надписей нет.
8. Монстр и NPC промахиваются по игроку при активном преследовании: `Miss`.
