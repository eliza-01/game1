# M339 — Development Kanban в Asset Manager

**Дата:** 13 ноября 2026 · **Статус:** CURRENT tooling · **База:** game1 diagnostic dump 2026-11-13, до интеграции M339.
**Границы:** только локальный Control Center / Host Agent / docs/kanban. Roblox gameplay, Asset IDs, Studio Bridge, SQLite, Existing world assets не изменены.

## Назначение

Единый трекер инженерных работ. Карточка содержит ID, приоритет, назначенного исполнителя, зависимости, обязательные задачи, критерии приёмки, ссылку на одну Markdown-спецификацию, историю и ревизию. Никакие задачи не считаются выполненными только по нажатию чекбокса, если не прошла приёмка.

## Физическое хранение

- `docs/kanban/cards/KBN-XXXX.json` — каноническая карточка (Git).
- `docs/kanban/specs/KBN-XXXX.md` — каноническое ТЗ/документация (Git).
- `docs/kanban/history/KBN-XXXX.jsonl` — append-only журнал изменений (Git; создаётся после первой записи).
- `.control-center/backups/kanban/KBN-XXXX/*` — локальные снимки предыдущей версии, не включаются в Git.

`KanbanStore` не открывает и не изменяет существующие базы SQLite. Новые 12 карточек — предварительный план со статусом `PROPOSED`, не подтверждение реализации механик.

## Публичный API (локальная авторизованная сессия Control Center)

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/kanban` | Список карточек и счётчики |
| GET | `/api/kanban/KBN-XXXX` | Карточка и полная документация |
| GET | `/api/kanban/KBN-XXXX/history` | 100 последних операций |
| GET | `/api/kanban/export` | Markdown-сводка для Codex |
| POST | `/api/kanban` | Создать новую карточку с автонумерацией |
| POST | `/api/kanban/KBN-XXXX` | Обновить одну карточку (см. actions) |

`POST` требует JSON `expectedRevision: int`. Для одной из `action`: `task` (`itemId`, `done`), `task-add` (`title`), `acceptance` (`itemId`, `status`, `evidence`), `acceptance-add` (`title`), `item-title` (`itemId`, `title`), `status` (`status`), `spec` (`spec`, `reason`, `confirmPolicyChange`). Старая ревизия → HTTP 409. `PASS` без `evidence` запрещён. `DONE` требует все tasks done, все acceptance PASS и свидетельства проверок. DONE-карточку надо сначала переоткрыть для новых изменений.

Для обновления документации после `PROPOSED` или `ON_HOLD` требуется `confirmPolicyChange=true`; причина обязательна. Предыдущая версия документа и карточки сохраняется локально, журнал изменения хранит дату, ревизию и причину. Сервис сверяет SHA256 документа, поэтому изменения Git вне интерфейса без коррекции карточки приводят к 409, а не к перезаписи.

## Типовой цикл

1. В Asset Manager открыть `development kanban`.
2. Раскрыть карточку; изучить документацию и зависимости.
3. Добавить/переименовать необходимые шаги и проверки, если план изменился; отметить выполнение только после работы.
4. Для фактической проверки выставить PASS с текстом (устройство, версия, коммит, лог).
5. Внести документационное изменение с причиной; для утверждённого контракта подтвердить решение владельца.
6. Для передачи следующему Codex нажать `Экспорт для Codex`, дополнить требуемыми исходными `.md`, так как экспорт — сводка, а не полный архив документов.
7. Все исходники, записи и история попадают в обычный Git commit/MR. Контракт Roblox меняется только отдельным патчем.

## Ограничения этапа

- Нет автоматического исполнения задач и синхронизации с Linear/GitLab.
- Нет автопроверки Roblox Studio или телефона: пользователь заносит доказательства вручную.
- Нет удаления карточек и переиспользования ID. При необходимости дополнять существующие задачи, не переписывать историю.
- История хранит метаданные изменений; полный diff восстанавливается из Git или локальных backups.
- Web UI ещё требует ручного browser smoke-test на машине автора.

## Откат

До внесения изменений — сделать Git commit или stash, чтобы не терять рабочую ветку. Для отката самого патча используйте `git apply -R` на **неизменённых** файлах; при уже сохранённых карточках сначала заархивируйте `docs/kanban`, потому что появившиеся после применения пользовательские записи не входят в патч. Для возврата одной карточки используйте Git history / `.control-center/backups/kanban`, восстановив JSON и Markdown согласованной ревизии. Roblox game assets и облачные публикации не затрагивались.
