# Правила ведения документации game1

**Дата:** 30 октября 2026.

## Статус и приоритет источников

1. Фактический работающий контракт в исходниках / конфигурации (и проверенный Studio runtime, если это runtime-вопрос).
2. [`docs/spec/CURRENT_PROJECT_SPEC_RU.md`](../spec/CURRENT_PROJECT_SPEC_RU.md) — требования и утверждённые продуктовые границы.
3. [`docs/architecture/CURRENT_ARCHITECTURE_RU.md`](../architecture/CURRENT_ARCHITECTURE_RU.md), [`REFACTOR_ROADMAP_RU.md`](../architecture/REFACTOR_ROADMAP_RU.md) и корневой `AGENTS.md` — архитектура, процесс изменений и технический долг.
4. `docs/history/**` — хронологические отчёты о выполненных этапах, **не** действующие контракты, если новый код их заменил.
5. Внешние и самостоятельные work packages (`docs/Eyesland_Character_Codex`, `roblox_character_ui_agents`) остаются в своей локальной структуре; они не изменяют автоматически основное ТЗ.

Старый `docs/PROJECT_SPEC_MILESTONE_1_RU.md` и однострочный `MILESTONE_1_IMPLEMENTATION.md` — историческое задание для запуска независимого проекта. Текущий Asset Manager шире Characters, так что старые ограничения «показывать только Characters» не действуют.

## Обязательный формат новых документов

Для текущего документа: название, дата/база, статус (`CURRENT`, `PROPOSED`, `HISTORICAL`), границы/owner, точные контракты (paths, inputs/outputs, schemas), runtime behavior, acceptance, проверки (`PASS`, `NOT RUN`, `BLOCKED`), миграции/откат. Историю не переписывать задним числом: указывать, какой последующий этап её заменил.

Использовать постоянные имена у живых документов (без M-суффиксов), milestone-номера — только для отчётов. При перемещении файла обновлять все относительные Markdown-ссылки, тесты и прочие ссылки на прежний путь. Сортировка истории по доменам, внутри — по этапам/датам, не по алфавиту из-за M9 vs M100.

## Что не следует писать

- «Тесты прошли в Studio», если был только unittest/Luau preflight.
- «Миграции не нужны» без проверки изменённого JSON/SQLite контракта.
- «Полностью завершён рефакторинг», если выполнено только извлечение одного сервиса.
- «Все системы работают» на основании исторического milestone-отчёта.
- Закрытые вопросы без свидетельства из источников. Сомнения помечать `NEEDS VALIDATION`.

## Автопроверка

При каждой документационной уборке: verify Markdown links, наличие исходных отчётов и ссылок в документационном индексе; тесты `system/verify`, отсутствие изменений `src`, `assets` и `system` от одного docs-only патча. Не удалять и не переименовывать `docs/ARCHITECTURE_AUDIT_2026-10-14_RU.md` без обновления `test_architecture_guardrails_m83.py`: этот путь закреплён контрактным тестом.
