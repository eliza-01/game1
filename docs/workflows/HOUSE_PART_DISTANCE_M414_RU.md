# M414 · Дистанции LOD частей дома

## Единый владелец настроек

- **Редактор:** `LOD Manager → 02 · LOD readiness → Real Estate`. В нём задаются `LOD1 from · studs`, `Unloaded from · studs` для каждого визуального MeshPart, а также режим `off / full / lod1` для типа дома.
- **Real Estate:** только FULL-геометрия, Appearance, коллизии, двери/сокеты и публикация; не редактирует дистанции.
- **Хранение:** `real_estate_part_distances` в той же базе Real Estate: ключ `(house_slug, part_name)`, `lod1_from`, `hide_from`, ревизия. Редактирование через отдельный API с `expectedRevision` (optimistic locking). Публикации Model ID не затрагиваются.
- **Runtime:** `house_runtime_compilation` читает пер-частные значения из этого хранилища и записывает в манифест как `lod1From` / `hideFrom`. Общих порогов дома в манифесте нет.
- **Клиент:** существующий `LocationWorldStreamer` вызывает `HouseVisualAdapter` в общем бюджете операций. Каждая часть независимо проходит `FULL → LOD1 → UNLOADED`, если LOD1 опубликована и режим `lod1` включён; иначе `FULL → UNLOADED`. Расстояние — до геометрической границы конкретной части, не до общего pivot дома. Гистерезис 10 studs через общую `LocationLodDistancePolicy`.

## Миграция

При первой инициализации обновлённого `RealEstateStore` создаётся резервная копия SQLite, затем однократно переносятся исторические `distanceStreaming/loadDistanceStuds` каждого MeshPart в его `lod1_from`. Для `hide_from` берётся прежний порог выгрузки дома (с проверкой зазора); если значения нет, используются безопасные значения по умолчанию. Устаревшие поля из `mesh_options_json` удаляются после переноса. Повторный запуск не меняет перенесённые записи. Исторические `real_estate_lod1` значения остаются для истории, но Runtime их не использует.

## Проверки и ограничения

Перед подготовкой Runtime требуются корректные положительные пороги с зазором >20 studs, подтверждённые публикации LOD-частей, сохранённые Plot bindings и валидный source Place. Изменение дистанций инвалидирует ранее выполненный Preflight. `publishAllowed=false` не снимается; публикация DEV требует отдельного Studio Play и мобильной проверки.
