# M431 · Ориентация камеры после телепорта

`HouseElevatorService.Move` и отладочный `HouseSocketService.TeleportDebug`
по-прежнему рассчитывают вертикальный CFrame через HouseSpawnOrientation
(для кости — Tail → Head). После успешного PivotTo и сброса скоростей
они передают тот же CFrame в CharacterCameraSync.

Контракт `Game1Remotes/CharacterCameraAlignV1`: однонаправленный RemoteEvent
сервер → владелец персонажа, v1 payload `(Model, Vector3 worldForward)`.
CharacterService создаёт remote до создания персонажей; клиент принимает
только событие для своего текущего персонажа и валидный горизонтальный
вектор. Запросов клиента, репликации на других игроков, таймеров и нового
кадрового обработчика нет. При отсутствии remote выдаётся предупреждение,
телепорт остаётся работоспособным. При несовместимом payload камера его
игнорирует. При замене протокола обновить обе стороны одновременно.

CameraController меняет только yaw в собственном orbit state, очищает
мобильный auto-aim и пропускает устаревший mouse delta при RMB. Pitch, zoom,
коллизии камеры, положение курсора и модель движения остаются прежними.
Отложенное событие не применяется к новому персонажу после respawn.

## Проверка в Studio Play и Runtime

- На каждом доступном этаже повернуть камеру вбок, вызвать лифт; камера
  смотрит по направлению персонажа в целевом spawn socket (не лифта).
- Повторить подъём и спуск, включая два разных сокета с одинаковой ориентацией.
- Проверить E/F, мобильную кнопку, RMB во время перехода, auto-aim и debug spawn.
- Проверить сохранение zoom/pitch, обычный свободный orbit сразу после перехода,
  отказ при недоступном этаже и отсутствие поворота камеры другого игрока.
- Проверить после respawn, также в опубликованном Runtime; серверная и клиентская
  ревизии должны быть одинаковыми.
