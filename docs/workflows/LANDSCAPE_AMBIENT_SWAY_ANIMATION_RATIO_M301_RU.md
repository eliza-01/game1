# M301 · Гравитационная поза и постоянное покачивание · UI масштабирования анимаций

## Landscape Painter

С M300 по-прежнему используется **один событийный клиентский контроллер**, без физических подвесов и активных Constraints. M301 расширяет его базовым поведением фонарей: каждые 2,5 с определяются ближайшие активные модели (не более 48, в радиусе 140 studs); для них запускается ограниченное обновление 24 Гц. Вдали от игрока визуальная анимация не считается. При входе в зону за 1,8 с объект переходит из выставленного в Studio положения к условной гравитационной позе, затем продолжает бесконечно и не синхронно покачиваться на ~1–2°. При выходе из зоны модель возвращается в положение равновесия; при повторном входе не начинает падать с исходной позы заново.

**Поза равновесия — геометрическая имитация, не настоящая физика.** Верхняя точка верёвки — сохранённый `LandscapeSurfacePoint`, нижняя — исходный `Model:GetPivot()`/pivot рига. Сначала направление верх→низ приводится к мировой вертикали, затем центр `LandscapeSwayTarget` (приближённый центр видимой геометрии) приводится под pivot вращением **всей модели**. `rig_carrier.PivotOffset`, сами кости и исходный Asset ID не меняются. Если центр совпадает с pivot, второе вращение не применяется: геометрия не задаёт плеча силы. Без галочки покачивания обычная `Anchored` модель не двигается.

Попадание стрелы и удар по-прежнему проходят через серверный `LandscapeSwayService.Impact` и существующий `LandscapeSwayEvent`. Фоновая волна (1,8°), ударная затухающая волна (13°) и ветер (до 4° при силе 1) складываются в одном визуальном контроллере; нет второго рендера или «ветряного» контроллера. `LandscapeSwayService.Wind(strength, seconds)` остаётся публичным входом для погодной системы. Звук включится только после установки опубликованного `WindSoundId`.

**Тест в Studio:** для старого объекта с механикой M299 включи галочку покачивания и сделай Apply, чтобы создать `LandscapeSwayTarget` без старых Constraints. Затем Rojo Sync → Play. В режиме Studio Edit модель остаётся в авторской позе; при Play возле игрока плавно выравнивается. Для теста попади стрелой / ударь и проверь последующее затухание без остановки фонового покачивания.

## Movement Debug · Animation Ratio

У Studio Debug значение Run/Walk после серверной валидации передаётся **клиенту владельца Animator** через `MovementDebugAnimationRatioChanged`. Клиент устанавливает Run/Walk-атрибут и вызывает `CharacterAnimationController.Refresh()`, чтобы скорректировать текущий `AnimationTrack:AdjustSpeed` без перезапуска анимации. NPC/монстры обновляются на сервере по реально играющим трекам с сохранением их знака и действующего множителя скорости (например, pursuit multiplier).

В Control Center `Custom scaling animations` теперь компактная таблица вместо карточек: поиск по опубликованным анимациям для добавления, отдельный поиск уже созданных overrides, 40 строк на страницу, редактирование stat и units рядом с именем, Save/Remove в строке. Запросы API, идентификаторы записей и формат БД не меняются.

Валидация кода не заменяет Play-тест с реальным Animator, поэтому отдельно проверь изменение ratio на уже идущей Run/Walk-анимации Player и NPC/Monster.
