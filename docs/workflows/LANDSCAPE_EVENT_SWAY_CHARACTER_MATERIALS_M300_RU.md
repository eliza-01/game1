# M300 · Событийный подвес, материалы персонажа и Animation Ratio

## Landscape Painter

M297–M299 нативная система подвеса удалена из текущей сборки. Ассеты всегда `Anchored`; декоративный цилиндр соединяет авторскую точку крепления с исходным pivot модели. `rig_carrier.PivotOffset` и кости не меняются.

У Landscape Painter новая галочка **«Покачивание от ударов / ветра»**, доступная при включённом подвесе. Старая сохранённая настройка `physicsEnabled: true` читается как `swayEnabled: true` только при загрузке старого профиля; при новой записи сохраняется только `swayEnabled`. Для уже размещённых фонарей необходим `Apply`, чтобы удалить прежние физические Constraints и создать `LandscapeSwayTarget` — невидимую `CanQuery=true`, `CanCollide=false`, `CanTouch=false` область для попаданий. Альтернатива — разместить фонарь заново.

Серверный `LandscapeSwayService` получает столкновения стрел и swept melee volume из действующей боевой системы. Он сообщает о событии только ближайшим игрокам; клиентский `LandscapeSwayController` плавно качает закреплённую модель и визуальный подвес по затухающей синусоиде. `RenderStepped` отключается, когда активных фонарей больше нет. Это **визуальное** смещение, не серверная физическая симуляция: фонарь не толкает персонажа; столкновение используется только как триггер. Максимальная область рядом с игроком и настройки волн находятся в `src/shared/world/LandscapeSwayConfig.luau`.

### API будущего ветра

В будущей серверной системе погоды вызвать:

```lua
require(script.Parent:WaitForChild("LandscapeSwayService")).Wind(0.7, 8)
```

`Wind(strength, seconds)` отправляет клиентам событие. Каждый клиент в своей активной зоне выбирает несколько фонарей со случайным направлением и небольшим сдвигом по времени. В конфигурации предусмотрено `WindSoundId`; **звука не будет, пока в поле не указан реальный опубликованный Roblox Sound ID**. Идентификатор не подставляется произвольный. Этот API — интерфейс интеграции, погодная система и автоматическое расписание ветра не добавляются.

## Лицо и материалы

В Control Center лицо собрано в компактные строки (деталь + appearance + материал). Для частей брони доступны отдельные материалы: `upper`, `lower`, `gloves`, `boots`. Материал также доступен для `head`, `eye_l`, `eye_r`, `eyebrow_l`, `eyebrow_r`, `hair`. Пустой пункт `Исходный` оставляет материал опубликованного меша. Изменение для существующего чистого рецепта автоматически сохраняется; при других несохранённых изменениях надо нажать общую `Save`. Новый материал применяется при **следующей сборке персонажа**, а не к уже запущенному экземпляру в Play. FBX, атласы, кости и pivot не переписываются.

## Animation Speed и Movement Debug

В разделе `Animation Speed` каждая анимация оформлена компактной строкой с единицами на +1%, примером и кнопкой сохранения. `Animation Ratio` в Studio Debug переопределяет скорость run/walk даже при индивидуальном правиле скорости клипа, без изменения самого опубликованного правила. Сервер принудительно обновляет активные NPC/monster AnimationTrack; клиент игрока уже подписан на изменение атрибута скорости.

## Установка и проверка

1. Применить Git-патч. Переустановить Landscape Painter, Studio Plugin, запустить Control Center; синхронизировать `src` через Rojo.
2. Для старого физического фонаря нажать `Apply` с активным «Покачивание». Убедиться, что `RopeConstraint`, `BallSocketConstraint`, `LinearVelocity` удалены, и что объект `Anchored`.
3. В Studio Play ударить/попасть стрелой по фонарю; он должен визуально качаться и успокаиваться.
4. Проверить отправку тестового `Wind` с сервера при установленном `WindSoundId` — в Play, на двух клиентах.
5. Проверить `Animation Ratio` на движущемся NPC и персонаже, затем сохранить материал выбранной детали и пересобрать персонажа.

Автоматические тесты проверяют структуру и контракты. Реальное воспроизведение в Roblox Studio Play, звук и визуальные материалы требуют отдельной проверки.
