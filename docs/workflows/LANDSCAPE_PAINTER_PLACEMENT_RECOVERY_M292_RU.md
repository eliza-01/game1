# M292 · Landscape Painter · восстановление размещения ассетов

## Область изменения

Исправлена уязвимость Edit-mode сессии: до M292 `LandscapePainter.server.luau`
объявлял `active = "asset"` **после** вызова `assets:Start()`, который сразу
рисует первый предпросмотр. Исключение в начальном обновлении курсора могло
оборвать `start` раньше регистрации активного инструмента. Тогда ни `mouse.Move`,
ни `mouse.Button1Down` больше не выполняли размещение, а ошибка уходила в
Studio Output вместо видимой панели.

Дополнительно нормализуется только локальная *отсоединённая* копия загруженной
модели: `Archivable=true` для корня и вложенных объектов, чтобы импортированные
экземпляры с нестандартным `Archivable` не терялись при клонировании. Исходный
Model Asset ID, MeshPart/Atlas ID и экземпляры на Place не меняются.

## Поведение после исправления

- При запуске требуемый эксклюзивный `PluginMouse` проверяется; при его
  отсутствии показывается объяснение, а не ложное «активно».
- Состояние `active` задаётся до первого `UpdateCursor`; ошибки запуска
  обрабатываются с очисткой сессии и сообщением.
- Расчёт попадания / Pivot отделён от отображения: неисправный временный
  `ghost` или CoreGui-маркер не должен препятствовать фиксации уже валидного
  попадания по ЛКМ. Ошибка предпросмотра видна в панели и Studio Output.
- Отсутствие поверхности/стебля под лучом показывается явно.
- Если другой Studio plugin активирует мышь, текущая сессия закрывается с
  сообщением вместо молчаливого исчезновения курсора.
- Диагностика выводится рядом с «Начать · Размещение ассета», не только внизу
  общей длинной панели.

## Границы

Затронуты только `system/landscape-plugin`. Сохранены общие `DecoAssetLoader`,
каталог Host Agent, фильтрация луча, StemTarget, профили, Undo/Redo, имя папок,
привязка атласов и политика безопасности Studio Sync. Нет миграций базы,
изменения опубликованных ассетов и изменений игрового Runtime.

Установка: после Git-патча выполнить `system/landscape-plugin/install.ps1`
(сборка и установка отдельного Game1LandscapePainter.rbxmx), затем полностью
закрыть и заново открыть Studio. Rojo-синхронизация игрового Place для этого
плагина не нужна.

## Ручная проверка в Roblox Studio Edit

1. Открыть Landscape Painter, выбрать опубликованный Location Asset. Под кнопкой
   Start должна отображаться текущая диагностика. Нажать «Начать»; в поверхности
   должны появляться маркер и полупрозрачная модель.
2. В режиме «Только поверхность» разместить 2 экземпляра на Terrain/Part.
   Проверить `Workspace.Game1LandscapeDecor/Assets`, Undo/Redo, отсутствие
   предосмотра после завершения.
3. В режиме «Авто» прицелиться на существующий `Stem_XX`, проверить размещение
   внутри `Branches/<branch>/Attachments`, затем прицелиться на землю.
4. Переключиться другим Studio-инструментом в активном режиме: панель должна
   сообщить, что захват мыши потерян. Запустить размещение заново.
5. При неуспешной загрузке ассета убедиться, что отображается реальная ошибка,
   а кнопка не создаёт ложную сессию. Проверить отдельно static/skinned.

Автотесты проверяют архитектурные и обработочные контракты. Реальное поведение
Studio `PluginMouse`, CoreGui, `LoadAssetAsync` и перемещения моделей на
конкретном Place невозможно подтвердить без запущенного Roblox Studio.
