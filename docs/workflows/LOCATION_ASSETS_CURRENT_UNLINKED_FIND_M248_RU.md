# M248 — Find Mesh IDs после изменения slug

## Причина

`StudioPublishedMeshHistory.Scan` отбирал размещённый MeshPart только при
совпадении с **устаревшим** Mesh ID (`previousIds`) либо наличии действующего
управляемого владельца (`Game1DecoAssetSlug` и `Game1DecoInstanceId`).
Это исключало MeshPart с **актуальным** Mesh ID, если он был вставлен в Studio
вручную, находился внутри группировочной Model или сохранил прежний slug
после Identity Rename. При этом публикация, Mesh ID и история в SQLite не исчезали.

## Исправленный контракт

- Сканирование также распознаёт актуальные **визуальные** Mesh ID из
  опубликованного Model inventory. Коллизионные ID не используются для
  обнаружения неподписанных объектов; COL не получает текстуры.
- Наличие Mesh ID не предоставляет право на изменение Place. Не имеющие
  подтверждённого владельца меши отображаются как диагностические,
  `managed=false`, и не добавляются в Sync All.
- Для неподписанного текущего MeshPart опорной единицей отчёта является
  сам MeshPart; произвольные пользовательские группировочные Model нельзя
  объявлять одним экземпляром Location Asset.
- `Select in Studio` использует сохранённую ссылку на конкретный объект,
  а не поиск ближайшего предка с классом `Model`.
- Для создания корректной модели, обновления устаревшего slug и Placement ID
  используется явный `Repair` в **Place Registry**; `Find` остаётся read-only.
- Ранее известные полные исторические модели могут по-прежнему использовать
  существующую операцию Link; этот хотфикс не расширяет её полномочия и
  не снимает проверки принадлежности.

## Проверка в Studio

1. На копии Place открыть `stone_pillar_01` (ранее `stone_fence_pillar_01`).
2. Нажать `Find Mesh IDs · Studio`: размещённые визуальные MeshPart с ID
   `112049281261824` должны находиться, даже если их `Game1DecoAssetSlug`
   отсутствует или отличается от нового slug.
3. Для неуправляемого MeshPart использовать `Select in Studio`. Выделяется
   конкретный меш, а не большая группировочная `land_fence`.
4. Проверить, что Find не меняет Place; до Repair нет разрешения на Sync.
5. Использовать отдельный Place Registry для нормализации структуры/атрибутов,
   затем повторить Find для подтверждения состояния.

**Ограничение:** полный список актуальных объектов доступен только при
сканировании открытого Place. Предыдущий архив Workspace — отдельный снимок,
не гарантия, что все его объекты остались размещены.
