# M242 · Location Assets — изменение Name + Slug, именование MeshPart

## Границы

`Identity` позволяет исправить название и slug существующего Location Asset без публикации Model/Atlas. Смена slug — **отдельная** операция `POST /api/location-assets/{old}/rename-identity` с `expectedRevision`. Обычная регистрация остаётся create-only; изменение slug нельзя имитировать созданием другого ассета.

`services/location_asset_rename.py` отвечает только за перенос изменяемого имени между таблицами реестра. Перед записью создаётся резервная копия `.control-center/backups/location_identity_before_m242_*.sqlite`. В одной SQLite-транзакции обновляются текущая запись, история Model ID, инвентарь Mesh ID, привязка Atlas Registry и список присоединённых вариантов. Исторические slug заносятся в `location_asset_slug_aliases`; повторное использование старого slug запрещено. Модель, текстура и Roblox IDs **не загружаются заново**. `model_path` остаётся прежним авторским источником, старый отчёт анализа FBX остаётся доступным через алиас; файлы не переименовываются.

`Place Registry` выдаёт каталогу текущий slug и все предыдущие алиасы. Старый `Game1DecoAssetSlug` поэтому считается своим *историческим* именем, а не чужим ассетом. На следующем Scan будет нарушение стандарта именования/метаданных, исправляемое явным Repair. Scan, как и прежде, ничего не меняет. Имя Model после Repair — `{slug}__{placement_guid_prefix}`.

`StudioLocationMeshNames` — общий единичный механизм именования для нового размещения через Deco Manager и для Repair. **Одиночный визуальный** MeshPart получает имя `{slug}` без уникального суффикса; имя `col_mesh`, его Mesh ID, физика и вложенные связи не меняются. В многовизуальных/скелетных иерархиях сохраняются отдельные авторские имена: переименование без схемы соответствия опасно. Repair использует Undo и сохраняет прежнее имя при откате.

В generated `src/shared/world/LocationAssetRegistry.luau` есть таблица `aliases`; `EnvironmentAssetService` разрешает старый slug в актуальное определение. Это позволяет старым размещениям не исчезать из игровых правил при переименовании Identity, ещё до их следующего Repair.

## Проверки и порядок

1. Сохранить копию Place и остановить Host Agent.
2. Применить патч, перезапустить Host Agent и переустановить Studio Bridge (новый модуль).
3. Изменить Name и Slug в `Location Assets → Edit → Identity` и нажать `Apply Changes`. Убедиться, что Model / Atlas IDs прежние и `Registered Assets` показывает новый slug.
4. В `Place Registry` нажать Scan: прежние размещения должны распознаваться по Mesh ID и требовать Repair имён/атрибутов; в режиме Edit запустить Repair одной секции, проверить её имя и Undo.
5. Пересканировать, затем тестировать Sync. **Не запускать Repair All на оригинальном Place без подтверждения на копии**.

Намеренно не переписываются JSONL/MySQL исторические события: они фиксируют идентичность на момент операции. Таблица алиасов связывает старый slug с новым, не уничтожая журнал. Ревизии Place остаются неизменяемыми и продолжают хранить состояние до переименования.
