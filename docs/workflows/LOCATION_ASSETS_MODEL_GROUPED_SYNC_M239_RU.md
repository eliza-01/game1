# M239 — отчёт Studio Sync по моделям

Применяется поверх M238. Регистрация, публикация и геометрия Place автоматически не меняются.

## Interface

- **Edit** из Registered Assets открывает `Identity`; **Sync Studio** открывает вкладку Model и сразу выполняет `Find`.
- `Find` проверяет ID в Studio без выделения и изменений Place. В отчёте **одна карточка на размещённую Model**; внутри визуальные MeshPart с отдельными статусами Mesh/Texture. COL отображается компактно: `COL ✓ · N`, либо `⚠ COL-меш не найден`.
- Для каждого управляемого экземпляра есть `Select in Studio` (только выделение в Explorer) и `Sync` (только pending частей этой модели; замена геометрии обновляет весь дочерний rig через `StudioManagedRigSwap`).
- **Select All · Studio** выделяет все найденные Model, включая исторические без привязки, **одним** безопасным вызовом Studio Bridge. Выделение не меняет геометрию, историю публикаций или привязку атласа.
- **Sync All** всегда отображается и доступен для опубликованного ассета; при отсутствии отчёта сначала запускает Find. Если обновлять нечего — обычный ответ без изменений Place. Иначе требует подтверждения, обновляет только управляемые pending MeshPart. Чекбоксов For Sync, Mark all, Clear и Sync selected нет.
- Историческая модель без атрибутов не получает Sync, пока не пройдёт явно подтверждённый Link из M238.

## ID опубликованных ресурсов

После `Find` Roblox Studio отдаёт инвентарь Model ID и Mesh ID. Для текущей публикации в кэше SQLite сохраняются имена визуальных MeshPart (`visualNames`) без изменения схемы, записей истории и физических COL ID. В Registered Assets отображаются только эти визуальные ID, с префиксом `Model N` и именем меша. Для старого кэша без `visualNames` первая проверка актуальной опубликованной модели дополняет записи; до неё UI показывает, что Mesh ID не считаны.

В разворачиваемой истории указано, какие Model ID являются текущей и предыдущими публикациями и какие Mesh ID входят в каждую. Там COL ID остаются — они необходимы для исторического поиска и проверки целого rig.

## Studio Bridge protocol 9

`scan` возвращает на каждую часть `modelName`, `modelPath`, `isCollider` и обновлённый инвентарь ID. `select` принимает `scanToken` и массив `partKeys`; валидирует каждую часть, удаляет повторы моделей, единожды выполняет `Selection:Set`, возвращает `selectedCount` (имя/путь — только для одной модели). `attach` и `replace` сохраняют прежние ограничения по правам и scoped one-time-token. Старый плагин protocol 8 несовместим: **обязательна переустановка Studio Bridge и перезапуск Roblox Studio**.
