# M233 · Location Assets: строго раздельная публикация Model и Atlas

## Симптом и установленная причина

В M232 кнопка **Republish Model · new ID** вызывала `scope=model`, однако общий Blender-staging для Location Assets по-прежнему выполнял `export_model(..., embed_textures=True)`. Это позволяло переносить внутрь опубликованного FBX растровые изображения, которые Roblox мог импортировать как зависимые image-ресурсы. Это **не** подтверждает отдельный вызов Atlas Registry: по текущему коду при `scope=model` он не вызывается. Состояние конкретного Open Cloud аккаунта после инцидента без свежего журнала недоступно.

## Контракт после M233

- **Republish Model · new ID** обращается только к `POST /api/location-assets/{slug}/publish-model`, с `forceModel` и описанием. Старая версия Host Agent эту ручку не знает и откажет вместо неявной общей публикации.
- Host Agent вызывает существующий `LocationAssetStore.publish(scope='model')`: создаёт только Roblox Model Asset, записывает только Model ID и историю публикации. Роут возвращает `resourceKind=Model`, `atlasUnchanged=true`, предыдущий/текущий Atlas ID.
- `model_publication_service.staged_model(texture_mode='geometry_only')` подготавливает FBX без Blender-материалов и Image bindings, без вложенных текстур. Перед Open Cloud проверяет отчёт после повторного импорта: `textureMode='geometry_only'` и нулевое количество material slots; при отсутствии подтверждения загрузка запрещена.
- Этот режим **только** для Location Assets. Weapons продолжают пользоваться прежней модельной публикацией со встроенными текстурами. Real Estate имеет собственный подготовщик частей и не затрагивается этим патчем.
- Atlas по-прежнему публикуется только через отдельную ручку общего реестра `/api/texture-atlases/variants/{id}/publish` и явно подтверждённые действия редактора текстур.
- `DecoAssetLoader` при размещении или Studio Sync назначает уже существующий `row.texture_asset_id` отдельно от модели; Roblox модель не обязана содержать встроенную картинку.
- Источники FBX/PNG, SQLite, существующие Model/Image ID, размещённые экземпляры и Place при установке патча не изменяются. Старые опубликованные версии остаются в истории.

## Диагностика конкретного инцидента

1. В `Database → Asset History` проверь новые события `Model` и `Atlas` для нужного slug и atlas variant.
2. Если изменился **только** Model ID, отдельная публикация атласа в нашем Atlas Registry не происходила. Roblox мог обработать встроенное изображение исходного FBX как подресурс модели.
3. Если изменился **Atlas Image ID в общей базе**, необходим журнал `/api/texture-atlases/variants/.../publish|republish` и данные о том, какая версия Host Agent обслуживала запрос. Не повторяй публикацию до сверки.
4. Для следующего теста используй непродуктивный FBX с материалом и вложенной текстурой: новая staging-процедура должна создать геометрию без материалов; Image ID в Asset Manager должен остаться неизменным.

## Проверка и ограничения

Автоматические тесты проверяют сериализацию ресурса, явность API, отсутствие вызова Image upload при публикации Model, отказ при непроверенном отчёте и совместимость с Weapon. Сам Roblox Open Cloud и Blender в тестовом окружении недоступны; визуальный результат новой Model и отсутствие изображения в удалённой библиотеке нужно проверить на тестовом ассете. Не применять Studio Sync автоматически: это отдельное действие.
