# M235 · Location Assets — выбор авторского pivot для составных FBX

**Версия:** поверх M234. **Область:** Studio Plugin; опубликованные ID, Atlas Registry, Host Agent и размещённые корневые Model не изменяются.

## Причина отказа

В M222 `DecoPlacedAssetSync.anchors()` собирал пары MeshPart с совпадающими именами и требовал **ровно одну** пару. У обычного составного FBX (например `trunk`, `branches`, `COL_mesh`) подходящих пар бывает несколько. Такая модель ошибочно отклонялась с `unique MeshPart name required`. До ошибки транзакция не выполнялась (`no Place geometry modified`).

## Единый механизм

`StudioAuthoringMeshAnchor.luau` — общий модуль идентификации авторского MeshPart pivot. Его используют `DecoPlacedAssetSync` и `StudioRealEstateHouseFrame` (в Real Estate прежнее правило «ровно один MeshPart с именем house» сохраняется). Изменение положения и атомарная замена дочерних ригов остаются ответственностью уже существующего `StudioManagedRigSwap`.

Правила выбора ориентира:

1. Единственный MeshPart в обеих моделях — старый совместимый случай.
2. В составных моделях сопоставляются **уникальные полные пути** в иерархии, включая тип и имя. Одинаковые имена в разных папках допустимы; одинаковые полные пути *не* считаются уникальными.
3. Если импорт изменил только контейнер и общих путей нет, допускается пара по имени, **уникальному в каждой модели**.
4. Ранее сохранённый `Game1DecoAuthoringAnchorPath` обязателен для последующих обновлений; иначе приоритет имеет `PrimaryPart`, если он MeshPart и имеет однозначную пару.
5. Если подходящих пар несколько, для каждой сравнивается преобразование её **авторского pivot**, а не центр bounding box. При согласии как минимум двух и отсутствии равносильных конфликтующих групп выбирается детерминированная пара. При несогласии — отказ **до изменения Place**, без угадывания по порядку дочерних объектов.
6. Выбранный путь сохраняется на размещённой корневой модели **только после успешного commit**. При ошибке возвращается прежний атрибут.

Никакого автоматического удаления, переназначения `PrimaryPart`, изменения корневого `CFrame` или обновления других Location slug. Реальный `Bone` и `Wrap*` остаются внутри заменяемого дочернего рига; индивидуальные MeshPart не подвергаются `ApplyMesh`.

## Проверка в копии Place

1. Установить новый Studio-плагин после применения M235, закрыв все окна Roblox Studio перед `install.ps1`.
2. На **копии** Place записать `GetPivot()`, `GetScale()`, `PrimaryPart`, `Game1DecoInstanceId` и дерево MeshPart/Bone двух размещённых экземпляров `christmas_tree`, а также любого другого slug.
3. Нажать `Sync Model + Atlas · Studio` у `christmas_tree`. Модель с несколькими однозначно совпадающими MeshPart **не должна** получать ошибку `unique MeshPart name required`. Сверить обновлённые Mesh ID, root CFrame/scale/parent и атлас. Посторонний slug не меняется.
4. Повторный Sync без новой публикации — `geometryUpdated = 0`. При несовместимом FBX должна прийти точная ошибка `no uniquely matching MeshPart path/name` либо `multiple MeshPart authoring pivots disagree`, **без модификации Place**.

**Ограничение:** наличие нескольких стабильных имен не гарантирует одинаковую локальную геометрию нового FBX. Настоящая проверка трансформаций и костей должна быть выполнена в Studio. Проверки Python — лишь тесты контракта исходников.

## Откат

При проблеме *до* сохранения Studio использовать Undo или открыть копию Place. Код M235 откатывается через `git apply -R game1_m235_location_multi_mesh_authoring_anchor.patch`, затем переустанавливается Studio-плагин. Откат исходников не восстанавливает ранее сохранённый Place автоматически.
