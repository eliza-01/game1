# M215 · Location Assets — синхронизация размещённых моделей и атласов

## Что было сломано

После повторной публикации FBX `Sync Studio` использовал только
`DecoPlacedAssetSync.RefreshTextures`: менялись `MeshPart.TextureID` и
`SurfaceAppearance.ColorMap`, **но не геометрия**. Даже новый Model Asset ID
не заставлял плагин перестроить уже расставленные в Studio экземпляры.

## Новый контракт

- Единственная точка авторской идентификации — атрибут `Game1DecoAssetSlug`
  размещённой модели. Совпадение имени, геометрии или расположения ничего не
  означает. Не размножаем модели и не импортируем их в ServerStorage.
- `model_asset_id` + `model_published_sha256` из опубликованного реестра —
  источник истины о версии геометрии. На размещённых моделях записываются
  `Game1DecoPublishedModelAssetId` и `Game1DecoPublishedModelSha256`.
- При явном Sync Studio экземпляры с устаревшей версией заменяются клоном
  последней опубликованной модели, загруженной через `DecoAssetLoader`.
  Все модели требуемых типов сначала загружаются и проверяются, **до**
  начала каких-либо замен. Ошибка загрузки не удаляет размещённые модели.
- Сохраняются мировые `GetPivot()`, `GetScale()`, имя, папка-предок,
  `Game1DecoInstanceId`, корневые атрибуты и CollectionService tags.
  Пересоздаются дочерние части/кости/визуал — это и есть цель обновления FBX.
  Ссылки на старые `MeshPart` и вручную добавленные дочерние объекты, не
  входящие в опубликованный FBX, **не сохраняются**. Перед первой синхронизацией
  старых размещений сделайте копию Place.
- Смена только атласа обновляет `TextureID`, `SurfaceAppearance.ColorMap`,
  `AlphaMode` через общую `StudioTextureAppearance`, **не пересоздавая** Model
  и не меняя её CFrame, масштаб, геометрию или физику.
- Старые размещения без метаданных опубликованной ревизии обновляются при
  **первом явном Sync**. Новые размещения получают метаданные сразу в
  `DecoPlacement`, без отдельного нажатия Sync.
- Обычное открытие DecoManager / `Refresh registry` может обновлять атласы,
  но не пересоздаёт геометрию. Полная замена работает только из явно
  запрошенного Asset Manager `Sync Studio`.
- Ранее публиковавшиеся модели `status != PUBLISHED` не синхронизируются,
  чтобы старое содержимое не маскировалось как новая публикация.

### Границы ответственности

| Модуль | Ответственность |
| --- | --- |
| `location_asset_store.py` | Текущие опубликованные модель, SHA и атлас |
| `studio_deco_bridge.py` | Синхронный Studio Bridge с проверяемым результатом |
| `StudioDecoSyncCommands.luau` | Запрос явного sync и передача отчёта |
| `DecoManager.luau` | Оркестрация refresh модели, затем материала |
| `DecoPlacedAssetSync.luau` | Версия, поиск по slug, безопасная замена, обновление текстуры |
| `DecoAssetLoader.luau` | Загрузка последней опубликованной модели с атласом |
| `DecoAssetPreparation.luau` | Общая политика физических частей для placement и refresh |
| `DecoPlacement.luau` | Первоначальная расстановка + маркер версии |

Нет миграции БД, изменения runtime и новой записи ServerStorage. HTTP schemaVersion
остался 1/2; новые поля отчёта `replacedModels` и `matchedModels` необязательны
для совместимости со старым плагином. Отсутствие подтверждения от Studio по-
прежнему возвращает ошибку, а не ложный успех.

## Проверка в Roblox Studio (Edit Mode)

1. Сохранить резервную копию Place и убедиться, что в `Workspace.Game1DecoAssets`
   есть ранее размещённые модели с `Game1DecoAssetSlug` и `Game1DecoInstanceId`.
2. У одной модели записать исходные `GetPivot():GetComponents()`, `GetScale()`,
   `Name`, `Parent`, ID экземпляра и назначенный ID текстуры.
3. Переопубликовать её FBX с заметным изменением геометрии, затем её атлас.
   Дождаться `PUBLISHED` (актуальные опубликованные model и image IDs).
4. В Control Center нажать `Location Assets > Sync Studio` в **Edit Mode**.
   Отчёт должен показать число `matched` и как минимум одну `model rebuilt`.
5. Сверить новый визуал и атлас; CFrame, масштаб, имя, папка и ID должны
   совпадать с прежними. Новых размещений в Workspace быть не должно.
6. Повторить Sync без изменений: `model rebuilt = 0`.
7. Сменить только атлас и повторить Sync: `model rebuilt = 0`, изменится ColorMap.
8. Проверить два экземпляра одного slug с разными CFrame и Scale и экземпляр
   другого slug, затем кнопку `Retry` у точечного Atlas binding.
9. Перезапустить Roblox Studio, открыть сохранённый Place, убедиться, что
   никаких откатов к старой геометрии/атласу нет.

## Откат

Не сохранять Place, если после Sync замечено нежелательное изменение.
Использовать Undo или открыть резервную копию Place. Для исходников удалить
M215 обратным `git apply -R`; повторная установка плагина из M214 вернёт
прежнее поведение «обновлять только текстуры». На БД/manifest откат не нужен.

## Проверки без Roblox Studio

- Профильные тесты и HTTP round-trip Studio Bridge: OK.
- `verify.py` и Luau preflight: OK.
- Общее число упавших тестов совпадает с M214; новых имён ошибок нет.
- Физический результат `LoadAssetAsync`, `Model:ScaleTo`, Undo и сохранение
  в реальной Studio **не проверены здесь**.
