# M220 · Location Assets: управление ресурсами по принципам Real Estate

**Статус:** действующий контракт интерфейса и публикации; **ограничение reference-only Sync ниже отменено M221**, см. `LOCATION_ASSETS_INPLACE_GEOMETRY_SYNC_M221_RU.md`. **Предшественник:** M219 (форма регистрации внутри Edit), отменён именно в части редактора. **Приоритет безопасности:** правила M216 остаются обязательными.

## Причина

В M219 кнопка `Edit` открывала старую общую форму регистрации в модальном окне. В отличие от `Real Estate → Manage Atlas`, в ней смешивались регистрация, изменение исходника, публикация FBX, общий атлас и Studio Sync. Публикация Location Asset также могла обновлять старый Roblox Model ID *in place*, что делало журнал замен ID неполным. При этом экземпляры, размещённые из обновлённого DecoManager, получали свежую модель, а старые экземпляры из Place оставались со старым MeshPart — что ошибочно воспринималось как успешное обновление геометрии через Sync.

## Разделение операций

### Register new asset

Форма регистрации предназначена **только** для новых slug. При существующем slug сервер возвращает ошибку; никакой тихой перезаписи существующей регистрации. Указываются имя, категория, FBX и новая или переиспользуемая вариация атласа. После регистрации открывается самостоятельный `Edit` для публикации. Создание регистрации само по себе не публикует Roblox ID и не меняет Studio.

### Registered Assets → Edit

Каждый экземпляр библиотеки имеет собственные `Edit` и `Sync Studio`. `Edit` открывает отдельный ресурсный диалог, построенный на общих с Real Estate компонентах `game1AssetWorkflowDialog.tabs/step`. Старая регистрационная форма не перемещается и не переиспользуется как Edit.

- **Identity:** изменение имени, категории и `destructible` без публикации; защита `expectedRevision` от перезаписи устаревшей ревизии.
- **Model · FBX:** выбрать локальный FBX → сохранить его ревизию → опубликовать Model через Roblox Open Cloud → при необходимости явно запустить адресный `Sync Studio`. Опубликованный Model Asset ID виден отдельно от источника.
- **Texture · atlas:** показать текущий опубликованный Image ID → выбрать готовую опубликованную вариацию без загрузки → опубликовать изменённые пиксели варианта → выбрать и сохранить новый локальный атлас → опубликовать его → адресный `Sync Studio`. Переключение атласа **не запускает Sync автоматически**.

Варианты атласа принадлежат **общему** `AtlasRegistry`, а не конкретному Location Asset. `Republish` общей вариации создаёт новый Image ID для всех её потребителей, но **не изменяет Place**: каждый потребитель синхронизируется отдельно. Источники атласа и операции публикации должны проходить через общий `game1AtlasWorkflow` / серверный `AtlasRegistry`, а не через локальные дубликаты.

### Раздельная публикация

`POST /api/location-assets/{slug}/publish` принимает `scope = model | atlas | changed`, `forceModel = false | true`. Старый вызов без `scope` сохраняет значение `changed` для совместимости. `forceModel` разрешён только со `scope=model`. Публикация FBX создаёт **новый Model Asset ID**, не вызывает обновление предыдущего ID `in place` и сохраняет прежний ID до подтверждённого успешного ответа Roblox. История `location_asset_publications` остаётся append-only; M217 агрегирует её в Database → Asset History. Публикация атласа не публикует FBX, публикация FBX не повторно загружает атлас.

`POST /api/location-assets` поддерживает `createOnly`, `editOnly` и `expectedRevision`: новые операции используют эти ограничения, старые клиенты по умолчанию сохраняют прежнюю совместимость. Изменение БД или миграция не требуются.

## Аварийное ограничение M216 — без исключений

`Sync Studio` адресован **только одному slug** и проходит по **всем управляемым размещённым экземплярам этого slug**. Он меняет допустимые ссылки Model ID / Texture ID и фиксирует историю M216/M217. Он **не заменяет** уже размещённые Model/MeshPart и не применяет `ApplyMesh`, `PivotTo`, `ScaleTo`, изменения `CFrame`, `Size`, коллизий или иерархии.

**Model Asset ID не равен MeshPart.MeshId.** Заменить внутреннюю геометрию старых размещённых экземпляров только записью Model ID нельзя. *Новые* экземпляры, созданные из DecoManager, берут актуальную опубликованную модель, но старые продолжают использовать свою геометрию. Это документированное ограничение, а не успешная замена FBX; диалог предупреждает о нём непосредственно перед Sync.

Возвращать модельную подмену из M215 в этот workflow **запрещено** без отдельного архитектурного решения и проверки в реальной Roblox Studio на резервной копии Place.

## Порядок работы и проверки

1. На копии Place зарегистрировать новый ассет, открыть `Edit`; проверить, что библиотека не теряет существующие slug и новая форма не перезаписывает старый.
2. В `Model · FBX` сохранить изменённый FBX. Проверить состояние `UPDATE_AVAILABLE` и прежний опубликованный ID. Затем `Publish Model` должен получить новый ID, а прежний оставаться в `Database → Asset History`.
3. В `Texture · atlas` переключиться на опубликованный вариант: запрос меняет только привязку; не должно быть автоматического HTTP Sync. `Republish atlas` должен обновлять общий Image ID для всех потребителей, но не Place.
4. В строке библиотеки нажать `Sync Studio` для одного slug на резервной копии Place. Проверить все экземпляры этого slug и ни одного другого; сравнить CFrame, Size, Scale, иерархию, MeshId до/после. Atlas ID и ссылочные метаданные могут изменяться, физические экземпляры — нет.
5. Если в Studio требуется **новая геометрия уже размещённых экземпляров**, **не** повторять Sync в ожидании её замены. Такой отдельный инструмент требует независимой разработки и безопасной геометрической верификации.

## Проверки / откат

Запускать `python system/verify/verify.py`, профильные тесты M220, браузерный smoke и полный unittest. Наличие старых failures/errors следует сравнивать по именам с исходной M219, а не по одним числам. Сами новые операции с Place не выполняются при открытии редактора.

Откат к M219 возможен обратным Git-патчем, но это вернёт старый редактор и публикацию Model `in place`; для рабочих сред предпочтительно исправлять причины проблем на M220. Перед применением — сохранить текущие БД/Place и чистое состояние репозитория. Новые уже опубликованные Roblox Model ID не удаляются при откате кода.
