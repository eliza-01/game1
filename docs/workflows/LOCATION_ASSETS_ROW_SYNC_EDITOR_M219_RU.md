# M219 — Location Assets · адресная Studio Sync и редактор карточки

**СТАТУС: CURRENT.** Дополняет правила безопасности M216, M217, M218. Отменённая M215 логика замены Model/FBX не восстановлена.

## Проблема

Ранее кнопка `Sync selected asset IDs` находилась в общей форме, а выбранный slug сохранялся в UI state, хотя список ассетов и редактирование не делали очевидным, что синхронизируется именно он. Выбор версии атласа запускал Studio Sync без отдельного нажатия пользователем; уведомление `1 FBX geometries unchanged` выглядело как неудача Sync, хотя M216 намеренно запрещает перестраивать геометрию.

## Новый UX

- В строке **каждого зарегистрированного Location Asset** есть `Edit` и `Sync Studio` рядом друг с другом. `Sync Studio` доступен после публикации текущего ассета; при открытии редактора другой строки синхронизация не меняет цель: обработчику передаётся **slug строки**, а не `decoAssetState.selected`.
- `Edit` открывает модальное окно в стиле `Manage atlas` из Real Estate: заголовок slug, закрытие, вкладки `Identity`, `FBX · Atlas`, `Publication`, сохранение. Внутрь модального окна **временно переносится существующая форма**, поэтому её ID, состояние, обработчики регистрации, выбора FBX, выбора атласа, публикации и удаления едины. После закрытия она возвращается на прежнее место. Отдельной реализации сохранения нет.
- Выбор опубликованной версии атласа **сохраняет привязку**, но не запускает скрытый Studio Sync. Кнопка `Sync Studio` в строке явно выполняет обновление всех отслеживаемых размещений этого slug. Общий атлас, используемый другими ассетами, не вызывает Sync для соседних slug.
- Статус сообщает количество найденных размещённых моделей, изменений Image ID / Model reference и количество мест с устаревшей/непроверенной FBX-геометрией. `pendingGeometry` — диагностика, а не ошибка обновления атласа. Надписи `0 model ID references` не скрывают количество затронутых размещений.

## Важный неизменный контракт M216

`Sync Studio` для Location Assets не меняет `MeshPart.MeshId`, `PivotTo`, `ScaleTo`, `CFrame`, `Size`, `Parent`, collision, не удаляет и не пересоздаёт объекты. Изменяет только существующие ссылки Model Asset ID (метаданные) и `MeshPart.TextureID` / существующий `SurfaceAppearance.ColorMap`. **Это не загрузка новой FBX-геометрии.** Все уже размещённые экземпляры с `Game1DecoAssetSlug == slug` и валидным `Game1DecoInstanceId` обрабатываются независимо от размещения внутри Workspace; неатрибутированные модели не считаются управляемыми.

История остаётся в MySQL M217, WAL M216 и атрибуте `Game1DecoSyncHistory`; читать её можно через `Database → Asset History` M218.

## Тест на копии Place

1. Сохранить отдельную копию Place. Выбрать два или более размещённых экземпляра `campfire_01` и один экземпляр другого slug. Записать `GetPivot`, `GetScale`, `MeshId`, `CFrame`, `TextureID`, `Parent`, `Game1DecoInstanceId`.
2. Открыть `Edit` у `campfire_01`: проверить табы, сохранение имени/Destructible, закрытие/повторное открытие. Другой зарегистрированный asset не изменяется.
3. Перепривязать уже опубликованный атлас; проверить, что ничего на Place не произошло без нажатия `Sync Studio`.
4. Нажать `Sync Studio` в **строке campfire_01** даже если в общей форме до этого был открыт другой asset. Статистика должна показывать число всех размещённых campfire, а соседний slug — остаться без изменений.
5. Проверить атлас и историю старого/нового ID, отсутствие новых/удалённых моделей, неизменность pivot/scale/mesh/physics. Повторный Sync не должен записывать фиктивные замены ID.
6. Для изменившейся FBX убедиться, что сообщение явно предупреждает о старой геометрии, но не предпринимает её автоматическую замену. Проверить Studio Undo, сохранить копию и переоткрыть её.

## Применение и откат

M219 применяется поверх M218. Изменения содержат только браузерные файлы, проверочные тесты и документацию; нет миграции SQLite/MySQL, изменений опубликованных Asset ID или Studio-плагина. После применения достаточно перезапустить Host Agent и обновить Asset Manager через `Ctrl+F5`. Roblox Studio переустанавливать не нужно. Откат `git apply -R <патч M219>` возвращает прежний UI, не меняя данные и Place.

**Ограничение:** настоящая работа с Edit Mode и Place не проверяется статическими/Node/Python тестами; первый запуск в Studio делать на копии.
