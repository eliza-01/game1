# M253 · Location Assets — единый шаг первой публикации

## Первопричина

`Register new asset` сохранял исходный FBX и копировал атлас в общий `AtlasRegistry`.
`AtlasRegistry.bind(... allow_unpublished=True)` намеренно не создавал Roblox Image ID.
Ранее редактор показывал привязанный **неопубликованный** вариант как отключённую точку,
а `Upload new atlas` заново спрашивал файл. Первую публикацию сохранённого источника
из модального окна выполнить было нельзя.

## UX

После регистрации нового ассета открывается вкладка **Publish**. Она также появляется
при наличии неопубликованных ресурсов (Model и/или активного Atlas), показывает их
отдельно и предлагает одну основную операцию **Publish ready**. В `Texture · atlas`
неопубликованная точка открывает эту вкладку; рядом с обычными действиями доступна
ссылка `Publish this atlas`. Изменения общих опубликованных вариантов должны проходить
старый сценарий сравнения источников и явного подтверждения — здесь они не публикуются.

Операция показывает текущий этап запроса: **Atlas → Model**. Никаких фиктивных
процентов. Если Atlas опубликован, а Model не удалось опубликовать, его Image ID
остаётся сохранённым. Следующая попытка работает только с непрошедшей частью.
Самостоятельные кнопки изменения FBX / общей замены атласа сохранены для осознанных
действий над уже опубликованными версиями.

## Контракты и безопасность

- `location-publication-state.js` — чистая политика определения готовности, без API.
- `location-asset-workflow.js` — единственный координатор последовательной публикации.
- `POST /api/location-assets/{slug}/publish-pending-atlas` — принимает `variantId`
  и `expectedRevision` (оба целые), проверяет существование Location Asset,
  **активную привязку** и ожидаемую версию; затем делегирует Atlas Registry.
- `AtlasRegistry.publish_initial` — под тем же `RLock`, что и стандартная публикация,
  запрещает повторно публиковать вариант с уже существующим `published_id`.
  Общие операции загрузки, dedup, аудит и восстановление зависших загрузок
  продолжают выполняться в `ensure_published`.
- `asset_replacement_audit` импортирует историю до и после публикации; ошибка
  импорта после успешной загрузки возвращается предупреждением, а не сигналом
  к повторной загрузке.
- Сервер возвращает `resourceKind=Atlas`, `publishedAssetId`, `studioSyncRequired=true`.
- Публикация Model выполняется старым `/publish-model`, подтверждает независимость
  атласа (`atlasUnchanged`); плагин Studio и Place не изменяются автоматически.
- Исходники уже сохранены в проекте. Новый выбор файла при первой публикации не нужен.

## Проверка после установки

1. На тестовом ассете выбери FBX и PNG/JPG, затем `Register new asset`.
2. На вкладке Publish проверь две независимые строки, счётчик и доступную кнопку.
3. Опубликуй: сначала дождись Image ID, затем Model ID. При каждом запросе
   отображается индикатор текущего этапа.
4. Повторно открой ассет — `Publish` не должен требоваться.
5. Убедись, что `Texture · atlas` показывает активный опубликованный вариант.
6. Проверь, что Sync в Studio выполняется **отдельно** и не стартует от публикации.
7. Изменение пикселей уже опубликованного общего атласа не должно попадать в
   `Publish ready`: используется существующий reviewed republish.

Проверить работу Open Cloud на настоящем ассете и восстановление при потере сети
во время публикации можно только в Host Agent. Наличие Image ID следует проверять
в Registry/Asset Manager до повторного запроса. Реальная Roblox Studio не тестировалась.
