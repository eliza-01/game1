# M254 · Location Assets — публикация по нажатию неопубликованного атласа

## UX

В `Edit → Texture · atlas` неопубликованный вариант (даже если он пока неактивен) отображается доступной для нажатия пунктирной точкой. Нажатие **не** загружает файл и **не** меняет активный вариант, а раскрывает рядом подтверждение:

- название/разрешение и отсутствие Image ID;
- `Опубликовать атлас` / `Отмена`;
- пояснение, что Roblox создаст Image ID без автоматического Studio Sync.

Отдельный выбор нового файла не требуется. После подтверждения отображается статус текущего запроса, успешный Image ID сохраняется в Atlas Registry, результат обновляется без закрытия модального окна. В случае ошибки интерфейс оставляет предложение для повторной проверки, но публикация с неопределённым исходом защищена серверным журналом pending upload.

## Контракт

- Общий редактор `asset-atlas-editor.js` остаётся презентационным: флаг `offerPublication` включает новый элемент **только** для Location Assets; Real Estate сохраняет прежний порядок выбора опубликованных вариантов.
- Команда `onPublishAtlas(variantId)` принадлежит координатору `location-asset-workflow.js` и вызывает **ту же** ручку `publish-pending-atlas`, что и вкладка `Publish`.
- Сервер допускает первую публикацию только текущего либо видимого в подключённом семействе атласа Location Asset, с проверкой binding revision. Связанные варианты другой семьи не публикуются.
- Публикация не меняет активную привязку, версию Model и Place; опубликованный ранее Image ID не перезаписывается, и `AtlasRegistry.publish_initial` продолжает блокировать скрытую републикацию.
- JS/CSS обновлены с `?v=254`. Миграции SQLite и переустановка Studio-плагина не нужны.

## Проверки

`node system/verify/location_unpublished_atlas_prompt_m254.js` и `python -m unittest discover -s system/verify -p 'test_location_unpublished_atlas_prompt_m254.py'` покрывают предложение на отключённой ранее точке, подтверждение, отсутствие привязки после публикации и отказ для чужого семейства/старой ревизии.
