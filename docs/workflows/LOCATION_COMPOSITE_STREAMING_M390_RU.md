# M390 · Runtime Streaming составных Location Assets

## Границы

- Общий планировщик остаётся `LocationWorldStreamer`; отдельного цикла для `rig_carrier`/светильников/статуй нет.
- `rig_carrier` остаётся в серверном Runtime Place со **всеми** дочерними Bone, Attachment, Fire, Light, ParticleEmitter и прочими объектами. AnimationController / Animator и связи сохраняются на своих местах. Эти системы не воссоздаются из придуманного набора метаданных.
- Каждый *визуальный* MeshPart исходного автора (кроме `rig_carrier`) в изолированной Runtime XML копии становится невидимым `Part` с прежними Referent/CFrame/Size, оригинальными Weld/Attachment и физическими свойствами. Исходный `.rbxlx` и Scan не меняются.
- Компилятор сверяет всю иерархию, Mesh ID/трансформы каждой визуальной части и carrier с последним Scan. Важные несоответствия блокируют Preflight.
- Сервер загружает опубликованную FULL-модель **один раз на тип**, проверяет Mesh ID и выдаёт в существующий `Game1LocationLodTemplates` только очищенную группу визуальных MeshPart. В произвольные скрипты, Fire, Lights и Bone-компоненты шаблона сервер не превращает отдельные экземпляры; живой carrier уже существует в Workspace.
- Клиент восстанавливает группу по одному общему FULL-решению LOD, через те же бюджеты. Скрепляет графику с серверными прокси `Weld`, чтобы сохранить механическую и скелетную связь; в LOD/UNLOADED удаляет клиентскую группу.

## Гарантии и ограничения

- Сокеты, свет, огонь, звуки, кости и серверная физика **не удаляются** из Runtime Place и сохраняют авторские значения. Это важно для gameplay. В дальних зонах технический carrier, эффекты и серверная логика могут оставаться активными; **полностью выгружаются только визуальные MeshPart**.
- Кеш одного FULL-шаблона на тип остаётся в `ReplicatedStorage`, как и в исходном Location LOD. Поэтому не обещается освобождение внутренних кешей мешей и текстур или полная выгрузка *всего* визуального ресурса из памяти.
- Избыточные эффекты (особенно активные ParticleEmitter/Fire/PointLight) требуют отдельного профилирования; до проверенного ownership-контракта нельзя глушить их серверное состояние наугад.
- Поведение скелетной деформации и client-only Weld относительно серверного Animator должно быть проверено в Studio Play / опубликованном DEV; статический XML-тест не доказывает GPU-рендер или репликацию анимационных Bone.
- Отдельные Model внутри Location, исполняемые Script и небезопасные физические MeshPart блокируются Preflight. Это осознанная защита, а не тихая потеря деталей.
- `publishAllowed=false` остаётся обязательным до Studio/mobile smoke-тестов.

## Smoke-тест

Включить типы `christmas_tree_01`, `wooden_post_01`, `statue_01`, затем Scan → Save as XML → Preflight → Verified Backup → Runtime Draft. В Studio Play проверить: вблизи все визуальные части и исходные эффекты, на дальнем расстоянии только carrier/технические Part, возврат, анимацию, ориентацию, светильники и отсутствие дублей MeshParts. Повторить на мобильном DEV после открытия publish gate отдельной процедурой верификации.
