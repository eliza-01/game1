# M262 · Миграция исторического Location rig новой публикацией

## Причина

После переименования Location Asset старый `Game1DecoAssetSlug` оставался
зарегистрированным alias, но scoped Find принимал владельцем только Model с
точным текущим slug. Поэтому четыре старые Model с visual + COL отображались
как восемь независимых исторических объектов. Дополнительный structural guard
M255–M261 запрещал Sync старой структуры даже при наличии новой канонической
публикации.

## Контракт

- `StudioLocationPlacementOwner` считает текущий slug и его серверные aliases
  одной идентичностью, но по-прежнему останавливается на ближайшей иначе
  маркированной Model.
- Find группирует MeshPart по подтверждённому корню и Placement ID: четыре
  двухчастных размещения отображаются как четыре Model, не восемь ассетов.
- Плохая **текущая публикация** остаётся заблокированной. Миграция разрешена
  только если входящий Model ID имеет SHA-bound канонический manifest.
- Исходящая структура может быть старой. Перед любым изменением её полный
  MeshPart ID multiset и иерархия сравниваются с одной immutable исторической
  Model-публикацией.
- Новая Roblox Model загружается целиком и передаётся в общий
  `StudioManagedRigSwap`. Нет `ApplyMesh`, синтетического carrier, клонирования
  или замены размещённого корня.
- Сохраняются корневая Model Instance, parent, pivot, scale, Placement ID и
  размещение визуального anchor. Новый visual, COL, rig_carrier и Bones берутся
  из опубликованной Model. Alias и Model ID обновляются только при commit.
- Все экземпляры проходят preflight до первого изменения. Ошибка возвращает
  старые дочерние rig, slug, имя и ID; команда участвует в Studio Undo.

## Проверка

1. На резервной копии Place выполнить Find для `christmas_tree_01`: ожидать
   `8 MeshPart · 4 модели`, четыре управляемые Model и четыре pending geometry.
2. Записать для четырёх корней Instance identity, Parent, GetPivot, GetScale,
   Placement ID и CFrame/Size старого visual.
3. Явно выполнить Sync All. Ожидать четыре model replacements; внутри каждого
   корня должны быть новый visual, COL и настоящий опубликованный rig_carrier
   с Bone. Старых Mesh ID быть не должно.
4. Сравнить все значения из шага 2; проверить Undo и повторный Find без pending.
5. Добавить неизвестный child/joint в один экземпляр: общий preflight должен
   отменить всю пакетную операцию без частично мигрированных моделей.

Статические и Node-тесты не заменяют этот Edit Mode smoke test.
