# M240 — Place Registry · Location Assets only

## Границы системы

Новый раздел **Place Registry** выполняет учёт **только тех** MeshPart,
чьи реальные `MeshPart.MeshId` однозначно входят в историю **опубликованных
Location Assets**. Публикация нового ID не стирает предыдущие версии.
`col_mesh` используется для проверки структуры, но **сам по себе не подтверждает
принадлежность**. Имя контейнера и наличие `Game1Deco*` никогда не являются
доказательством регистрации.

Нет чёрного списка для Real Estate, NPC, монстров, света, characters,
Game1Authoring, границ и спавнов. Неопознанные объекты вообще не входят в
операции. Дополнительная fail-closed защита уважает явный атрибут владельца
другого домена. Если Mesh ID принадлежит нескольким Location Assets, объект
остаётся диагностическим, не ремонтируется и не синхронизируется автоматически.

## Контракты и владельцы

| Компонент | Ответственность |
| --- | --- |
| `services/place_registry/catalog.py` | Построение positive allowlist из реестра и ID-публикаций |
| `StudioPlaceRegistryInventory.luau` | Разрешение реальных Mesh ID, дерево размещений, диагностика, read-only Scan |
| `StudioPlaceRegistryRepair.luau` | Явная нормализация Model, GUID и простого COL с Undo |
| `StudioPlaceRegistrySync.luau` | Явная замена управляемой геометрии через **StudioManagedRigSwap**, текстуры через **StudioTextureAppearance** |
| `StudioPlaceRegistryCommands.luau` | Транспортный диспетчер и одноразовый Studio scan token |
| `studio_place_registry_bridge.py` | Ограниченная сессия GET command / POST result, loopback и токен |
| `services/place_registry/coordinator.py` | Контракт операций, проверка реестра, сохранение результатов |
| `services/place_registry/revisions.py` | Append-only SQLite ревизии и журнал Repair/Sync |
| `static/place-registry.js` | UI, явное подтверждение операций, таймер read-only Scan |

**Не добавляется ни один игровой Runtime-сервис.** Процедурная генерация
Real Estate и работоспособность NPC/Monster/Character не зависят от системы.

## Read-only Scan

- Считывает опубликованные Model IDs, текущие Atlas IDs и сохранённые Mesh ID
  всех исторических версий Location Assets. Исторические ID, которых ещё нет в
  кэше, читаются из опубликованного Roblox Model Asset через существующий
  `DecoAssetLoader`, без публикации новых ассетов.
- Если хотя бы одну публикацию не удалось прочитать, Scan сохраняет **неполную**
  ревизию и явное предупреждение, но Repair/Sync на её основании запрещены.
- Находит MeshPart по реальному Mesh ID в Workspace, в том числе после Ctrl+C/V,
  независимо от того, как он сгруппирован и каким способом первоначально создан.
- За единицу размещения берёт Model только при совпадении всей опубликованной
  Mesh ID-мультимножества. Иначе — отдельный визуальный MeshPart. Устаревшие
  секции одного вручную созданного контейнера не становятся «одним ассетом».
- Проверяет актуальность Mesh и Texture/ColorMap отдельно, COL, GUID, имя,
  наличие отдельной Model, неоднозначные исторические версии и дубли GUID.
- Регистрирует иерархию, CFrame/Size, физику, Mesh/Texture/ColorMap, Bone,
  свойства и атрибуты **распознанных** объектов без Source скриптов и секретов.
- Никакие Instance ID, Selection, pivots, модели, коллайдеры и атласы при Scan
  не меняются. `Select All · Studio` меняет только выделение в Explorer.

## Repair

Операция явная и требует подтверждения резервной копии `.rbxl`.

- Исправляет дублированные GUID и назначает новые только объектам без уникального
  Placement ID. Служебные идентификаторы не определяют доменную принадлежность.
- Сохраняет исходные группировочные контейнеры. Для отдельных исторических
  MeshPart создаёт собственную Model с именем `<slug>__<guid8>`, не изменяя
  CFrame и Size. Не отсоединяет MeshPart, используемый как PrimaryPart
  внешней модели; ручные сложные связи остаются заблокированы.
- Для уже актуального одиночного простого меша допускает восстановление
  `col_mesh` из текущей публикации с проверенным преобразованием и
  авторскими настройками через общий `MeshPhysicsCore`. Для устаревшей
  геометрии COL прибывает вместе с актуальным rig во время Sync.
- Массовая операция использует `ChangeHistoryService:TryBeginRecording` и
  собственный журнал отката. После Repair токен Scan сбрасывается.

## Sync

- Текстура без замены геометрии обновляется через `StudioTextureAppearance`;
  коллайдеры никогда не получают текстуру.
- Геометрия — только через **StudioManagedRigSwap**; исходная размещённая
  Model сохраняет родителя, идентичность и pivot. Нет прямой записи `MeshId`
  или `ApplyMesh`.
- Старый одиночный не-риггед MeshPart может иметь индивидуальный,
  в том числе неравномерный масштаб. Его коэффициенты восстанавливаются по
  **старой опубликованной версии**, а новая геометрия и COL масштабируются
  относительно **новой опубликованной версии**. Для skinned/multi-part rig
  неоднозначный масштаб блокирует замену до изменения Place.
- Перед операцией проверяются все выбранные ссылки и снимки трансформаций;
  для каждого успешного размещения хранится история изменений в атрибуте
  `Game1DecoSyncHistory`. Подготовка всех геометрических транзакций происходит
  до начала мутирующей фазы; ошибки в подготовке отдельного экземпляра
  возвращаются как `skipped`.
- Операция имеет Studio Undo и требует нового Scan после завершения.

## Ревизии / резервирование

База: `.control-center/location-place-revisions.sqlite` (новая самостоятельная
SQLite, не изменяющая основную игровую БД). Схема создаётся идемпотентно,
старые SQLite-файлы и истории публикаций не мигрируются и не удаляются.
Снимки компактно сжаты, append-only, дедупликация точных повторов по SHA256,
раздельные записи явных Repair/Sync. Есть список, сравнение и экспорт JSON
для внешнего резервирования. Неудачная публикация/Repair не должна записывать
ложное успешное событие.

**Важно:** эти JSON/SQLite-ревизии — подробный учёт Location Assets, а НЕ
полная резервная копия Roblox Place. Они не содержат Terrain-voxels,
скрипты/бинарные модели и остальные объекты Workspace. Для восстановления
целого Place необходимо продолжать сохранять `.rbxl/.rbxlx`. Обратный импорт
ревизии в Studio намеренно НЕ запускается без отдельного механизма проверки
источников: слепой replay может уничтожить геометрию и связи.

## Как проверить после применения

1. Остановить Host Agent, закрыть Studio, применить патч M240 поверх M239.
2. Переустановить Studio plugin через `system/studio-plugin/install.ps1`, открыть
   Studio заново, перезапустить Host Agent, обновить Asset Manager (`Ctrl+F5`).
3. Сохранить `.rbxl` под отдельным именем. Открыть `Place Registry`, нажать
   **Scan Place**. Убедиться, что нет чужих домов, NPC, спавнов и т.д.
4. Проверить `stone_fence_01`: прежние одиночные секции должны быть отдельными
   размещениями, не 13 искусственно сгруппированными публикациями.
5. Проверить `Select All · Studio`: выбираются только распознанные Location
   Assets. Создать Ctrl+C/V-копию, повторить Scan, проверить дубли GUID.
6. На **копии Place** выполнить Repair для одного исторического MeshPart,
   проверить неизменность CFrame/Size и родительского группировочного контейнера.
7. Повторить Scan и затем Sync **одной** подходящей секции. При отказе
   прочитать сообщение; не нажимать Sync All до подтверждения геометрии/COL.
8. Сравнить ревизии, экспортировать JSON и проверить Studio Undo.

## Регрессионные границы и честные ограничения

- Нельзя считать прочитанным Mesh ID опубликованной модели, которая недоступна
  текущему аккаунту Roblox Studio. Тогда допускается только read-only Scan.
- Если опубликованные модели используют неоднозначный общий Mesh ID,
  автоматическое присвоение владельца запрещено.
- Skin/Wrap/сложные Motor6D, индивидуальное деформирование многомешевого
  rig и произвольные внешние constraints требуют ручной подготовки и не
  «лечатся» автоматическим созданием COL.
- `ChangeHistoryService` и реальные Roblox загрузки моделей нужно обязательно
  проверять в Studio. Python/Node и source-level preflight не заменяют Play/Edit.
