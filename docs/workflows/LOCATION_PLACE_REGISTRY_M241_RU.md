# M241 · Place Registry — интерфейс, групповой Repair, журнал и Undo

## Границы

Раздел относится **исключительно к опубликованным Location Assets**, распознанным по сохранённым Mesh ID и истории публикаций. Классификация и защита из M240 не изменены: Real Estate, NPC, персонажи, служебные точки и неизвестные Mesh ID не становятся объектами Repair/Sync. Запрос `Scan` остаётся read-only, выбор в Studio не меняет Place.

## UI

- Поля и карточки получают локальную сетку/отступы в `place-registry.css`, без изменений других разделов Asset Manager.
- Подтверждение существующего `.rbxl` находится в **первом блоке**, над всеми массовыми действиями. Подтверждение не создаёт бэкап автоматически.
- Вверху находятся Scan Place, Select All, Repair All и Sync All.
- Для каждой группы по slug доступен `Repair group (N)`. В обработку идут только однозначные размещения с нарушениями структуры/ID; другие группы не затрагиваются.
- Положение страницы, положение списка и набор раскрытых групп сохраняются при перерисовке.
- После успешного Repair, Sync или Undo интерфейс автоматически запускает новый Scan, записывает новую ревизию и обновляет журнал. Если Scan не удался, прежний отчёт остаётся видимым, но запись помечается устаревшей и мутации блокируются до повторного Scan.

## Журнал

`services/place_registry/journal.py` — отдельный SQLite-репозиторий `location_place_operation_journal` в существующем `.control-center/location-place-revisions.sqlite`. Схема создаётся аддитивно и идемпотентно; **перед первой миграцией создаётся резервная копия SQLite в `.control-center/backups`**. История `location_place_actions` из M240 сохраняется и показывается как legacy, без ненадёжного Undo.

В каждой новой записи: идентификатор операции Studio, дата, Place ID, ревизия до изменения, действие Repair/Sync, состав выбранных объектов, количество изменений, пропуски и состояние (`applied`, `undone`, `no_changes`). Любая успешно обработанная операция журналируется, включая `changed=0`.

## Undo

В Plugin используются нативные `ChangeHistoryService:TryBeginRecording/FinishRecording` с отдельным уникальным именем `G1PlaceRegistry:<operationId>` для **каждого** запуска Repair/Sync (групповой Repair — одна атомарная операция, одна запись Undo).

Кнопка Undo действует по принципу стека. Studio сначала подтверждает через `GetCanUndo`, что **последний waypoint** точно соответствует запрошенному Operation ID, только после этого вызывается `ChangeHistoryService:Undo()`. Если после Repair пользователь двигал объекты или выполнял другие действия, Place Registry **не отменяет чужое действие**; сначала требуется разобраться с новыми шагами Undo в Studio. Прошлые операции доступны последовательно после отмены более новых. Undo через собственную кнопку подтверждается журналу только после успеха Studio; снимки SQLite не являются исполняемым механизмом отката.

Важно: пользователь может отдельно выполнить обычный Ctrl+Z в Roblox Studio. Такое внешнее действие отменяет геометрию по правилам Studio, но состояние SQLite-журнала не получает автоматическое уведомление. Проверьте результат новым Scan; кнопка Undo этой записи далее может быть недоступна, поскольку её waypoint уже отсутствует в стеке Studio. После закрытия и повторного открытия Studio история Undo может быть очищена — журнал всё равно остаётся доступным для аудита.

## Контракт

- `GET /api/location-place-registry/actions?limit=40` — чтение журнала, лимит 1–100.
- `POST /api/location-place-registry`, `phase=undo`, `actionId=<int>` — сервер проверяет последнюю доступную к откату запись, вызывает Studio Bridge с точным `undoOperationId`, принимает подтверждение и обновляет журнал. Публикации/реестры Model/Atlas не меняются.
- Для остальных фаз контракт M240 не изменяется. Studio Bridge принимает дополнительную фазу `undo` в версии схемы 1; для M241 необходима переустановка Studio-плагина.

## Проверки и ограничения

Профильные тесты: `test_location_place_registry_m240.py`, `test_location_place_registry_m241.py`. Дополнительно `verify.py`, проверка синтаксиса JS и Luau preflight. UI проверен в Chromium с тестовым Studio Bridge. **Реальный Undo и групповой Repair в Roblox Studio остаются непроверенными до локального испытания**. Сначала следует выполнить одну операцию Repair на копии Place, затем проверить Undo и точное восстановление CFrame, Size и иерархии.
