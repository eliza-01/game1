# M246 · Place Registry — Repair вложенного PrimaryPart

## Причина

Ранее `StudioPlaceRegistryRepair.safeForWrapper()` безусловно пропускал
одиночный визуальный MeshPart, если он совпадал с `PrimaryPart` вручную
собранного родительского контейнера. Поэтому часть группы оборачивалась в
индивидуальную `Model`, а последний `PrimaryPart` оставался без оболочки и
Placement ID. Операция возвращала `changed=0`, `skipped=[...]` и попадала
в журнал как «Без изменений», без видимой причины.

## Поведение

- Новый дочерний `Model` создаётся без переноса общего контейнера.
- Если старый меш был `PrimaryPart` родителя, родитель продолжает ссылаться
  на тот же MeshPart, теперь являющийся его вложенным потомком.
- Проверяются прежний `Model:GetPivot()`, `PrimaryPart`, `MeshPart.CFrame` и
  `MeshPart.Size`. Несовпадение приводит к откату всей операции Repair.
- Встроенные JointInstance/Constraint по-прежнему блокируют автоматический
  перенос: нельзя угадывать владельца связей.
- Причины пропусков выводятся рядом с соответствующей записью журнала,
  включая старые записи M241–M245, если их отчёт содержит `skipped`.
- Для новых экземпляров используется обычный GUID, история публикаций и
  принадлежность определяются прежним allowlist по Mesh ID.

## Проверка в Studio

На копии Place выберите группу `ground_torch_01`, сохраните `CFrame`, `Size`,
`PrimaryPart` и `GetPivot()` родительской модели. Выполните Repair одного
оставшегося прямым дочерним MeshPart. Убедитесь, что под родителем появилась
новая вложенная Model, `PrimaryPart` остался тем же MeshPart, размещение не
изменилось. Затем проверьте Undo и повторный Scan.

Если нет `PrimaryPart` либо есть внешние связи/Constraint, требуется отдельная
проверка: безопасность при миграции важнее безусловного исправления.

Реальный Roblox Studio в среде подготовки патча недоступен; статические тесты
не заменяют тест на резервной копии Place.
