# M244 · Синхронизация Location Assets: отчёт, Size/CFrame, устаревшие метки

## Область

Только Studio-авторинг зарегистрированных Location Assets. Real Estate не изменяется.
Никакой автоматической публикации и никаких изменений Place во время Find / Scan.

## Location Assets → Sync Studio

- Найденные MeshPart остаются в модальном окне на время Sync; однократный
  `scanToken` после начала операции считается непригодным для повторного Sync.
- После успешного Sync интерфейс запускает повторный Find автоматически.
- После отказа Bridge также предпринимается безопасный повторный Find. Если
  Studio недоступна, показывается последний снимок с предупреждением; повторное
  изменение заблокировано до нового Find. Прокрутка модального окна сохраняется.
- `Select in Studio` не выполняет Sync, не меняет Place и недоступен на
  просроченном снимке.

## Сохранение индивидуальной геометрии

`StudioLocationPlacedGeometry` — общая политика подготовки *только Location*
между `DecoPlacedAssetSync` и `StudioPlaceRegistrySync`. Физическое применение
дочернего rig по-прежнему принадлежит `StudioManagedRigSwap`.

Для простой геометрии (по одному визуальному MeshPart, без Bones/Joint/Wrap/
Attachment) из предыдущей публикации и нового rig:

- предварительно проверяется точная историческая структура и Mesh ID;
- визуальный MeshPart новой публикации получает **точные CFrame, Size и
  PivotOffset** размещённого визуального MeshPart;
- новые COL и другие вспомогательные BasePart получают относительное положение
  и размеры с учётом индивидуального масштабирования по каждой оси;
- Anchored переносится с текущей визуальной секции;
- весь новый дочерний rig готовится и проверяется **до** замены; корневая
  размещённая Model, её родитель, Pivot и Scale не меняются.

Для сложной иерархии допускается только ранее подтверждённое модельное
масштабирование. Нестандартный индивидуальный Size блокирует операцию; это
предпочтительнее утраты пользовательской расстановки. Технически обработка
одной сцены по-прежнему требует подтверждения в Roblox Studio.

## Place Registry · чужой slug

Совпадение с историей опубликованных **визуальных** Mesh ID определяет
кандидат на Location Asset. Атрибут `Game1DecoAssetSlug`, полученный при
копировании, может быть устаревшим. «Чужой ассет» подтверждается только при
совпадении *полного* опубликованного Mesh ID инвентаря заявленного владельца.

При старой/неверной метке и однозначной истории объекта:

- Scan объясняет `старый slug → реальный slug по Mesh ID`;
- Sync заблокирован до явного Repair;
- Repair записывает истинный slug **и исторический Model ID**, найденный
  по полному набору Mesh ID; чужой SHA удаляется;
- затем требуется повторное сканирование и только потом Sync.

При неоднозначной идентичности или действительном конфликте двух владельцев
Repair не разрешён. Чужие игровые домены не попадают в allowlist Location.

## Проверка после применения

1. На резервной копии Place открыть Location Asset, выполнить Find и одиночный
   Sync. Отчёт остаётся на экране и обновляется после операции.
2. Изменить Size одной простой декорации по одной оси. При Sync проверить
   точное совпадение `CFrame`, `Size`, `PivotOffset` нового визуального MeshPart;
   COL должен следовать масштабу и позиции и не получать атлас.
3. Для сложного скелетного rig с вручную изменённым Size проверить отказ **до**
   изменения Place.
4. У скопированной модели с ошибочным slug и подтверждённым Mesh ID проверить
   предупреждение, Repair, повторный Scan, Sync и Undo.
5. У Real Estate Edit/Sync убедиться в неизменности поведения.

`verify.py`, JS, Luau preflight и Python-тесты проверяют контракты;
физические CFrame/Size и Studio Undo требуют реального Editor smoke test.
