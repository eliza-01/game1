# M332 · Monster overhead HP: видимость и первый спавн

## Контракт игрового отображения

Для каждого монстра по отдельности клиент показывает **имя и HP вместе**, только если одновременно выполнены условия:

1. Монстр жив (`LifeState == "Alive"`).
2. Монстр находится в радиусе `healthUi.<device>.monster.maxDistanceStuds` от **персонажа игрока**, а не от камеры (по умолчанию 100 studs для ПК и мобильных).
3. **Хотя бы одно** из двух боевых условий:
   - Прицел игрока сейчас указывает на этого монстра (или мобильное автонаведение удерживает именно его).
   - Монстр **сейчас** выбрал этого игрока целью: `MonsterCombatActive == true` и `MonsterTargetUserId == LocalPlayer.UserId`.

Не учитывается история атак, урон, нанесённый ранее, или факт убийства другого монстра. Преследование должно прекратить показ, как только сервер сбросил текущее состояние. Выход за радиус скрывает HP независимо от агрессии и прицела.

## Почему раньше нарушался контракт

- Studio-панель `HP Debug` вызывала `Settings.Preview(...)` при каждом открытии. `OverheadHealthController` трактовал любой такой предпросмотр **как приказ показать всех монстров**. Закрытие панели не сбрасывало предпросмотр. В итоге нейтральные монстры показывались вне боевой логики.
- `OverheadHealthController.bindMonster` ждал `RootCollider` лишь 5 секунд. `MonsterSpawnerService` сначала помещает модель в `Workspace.Monsters`, **потом** выставляет runtime-атрибуты и создаёт `RootCollider`. При задержке репликации (особенно при StreamingEnabled) клиент мог пропустить первоначальную модель и увидеть полоску только после нового спавна.

## Реализация

- Подключение первой и повторно появившейся модели событийное: `ChildAdded` + изменения `Game1MonsterRuntime`, `MonsterSlug`, `LifeState`. Создание происходит один раз, только когда готовы метаданные и `RootCollider` (ранний навигационный root не подходит для визуального размещения). Не используется ограничение ожидания на пять секунд и не вводится цикл опроса на каждый спавн.
- Отключение подписок и удаление BillboardGui при исчезновении модели/смене папки единые. Если StreamingEnabled выгрузит только RootCollider, при его повторной подгрузке индикатор создаётся заново с теми же условиями видимости.
- Изменение профиля внешнего вида в Studio **не включает** массовый показ HP. Для этого есть отдельная кнопка **All HP: ON/OFF** в HP Debug. Она действует лишь в Studio и лишь для активного предпросмотра; закрытие окна или `Stop preview` сбрасывают флаг.
- В опубликованном TestPlace режим Studio Preview недоступен. Никакой записи серверных combat-атрибутов на клиенте нет.

## Проверка в Studio Play / опубликованной игре

1. Запустить игру **без открытия** HP Debug. Ближайшие нейтральные Gremlin не должны иметь имени/полоски.
2. Навести прицел на одного нейтрального Gremlin ближе 100 studs: HP и имя появляются **только у него**; убрать прицел — исчезают.
3. Дать другому Gremlin выбрать игрока целью: его имя и HP остаются при преследовании, даже когда прицел направлен в сторону. После прекращения агрессии скрываются.
4. Отойти за 100 studs: обе подписи скрываются. Подойти обратно — логика восстанавливается без убийства монстра.
5. Проверить первое появление монстров при холодном старте и появление после убийства, включая StreamingEnabled.
6. В Studio открыть HP Debug: обычный предпросмотр размеров **не показывает всех монстров**. Включить `All HP: ON`, затем закрыть окно — массовый показ прекращается.

Проверка реального стриминга, анимаций, позиции над skinned MeshPart и UI в разных устройствах требует Roblox Studio: статические тесты не заменяют этот этап.
