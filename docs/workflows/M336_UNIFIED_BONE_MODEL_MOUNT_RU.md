# M336 · Один механизм закрепления оружия и составных париков

## Причина

В M325/M328 оружие использовало `Anchored` для всех частей модели и один
`Model:PivotTo` на клиенте. У rigid-pivot парика был `Anchored` только
основной MeshPart, а остальные меши следовали за ним через
`WeldConstraint`. Это добавляло физический шаг, которого нет у оружия,
и могло давать запаздывание, особенно на слабых телефонах.

## Единый контракт

- `src/shared/rig/BoneModelMount.luau` — единственные формулы сокета
  (анимированный parent Bone + исходная локальная `CFrame` сокета),
  канонического grip и `Place(Model, Attachment, socketFrame)`.
- `src/client/character/BoneMountedAttachmentController.luau` — один
  `RenderStepped` для оружия игрока/NPC и rigid-pivot парика персонажа.
  Перемещает **исходные** модели, без клонирования на каждом кадре.
- `CharacterAssemblyBuilder` собирает одну модель парика и делает **все**
  её MeshPart `Anchored=true`; никакого `CharacterHairExtraWeld`.
- `CharacterRigService` сохраняет Anchored всех частей этого компонента
  после клонирования шаблона, не только его PrimaryPart.
- `WeaponEquipService` использует тот же `BoneModelMount` для постановки
  оружия, сохраняя опубликованные модели и боевой OBB.
- Studio Timeline Preview обращается к тому же `UpdateCharacter` для
  обновления зафиксированной позы (не запускает второй render-loop).

Ориентация разная **по контракту исходных ассетов**: парик использует
Blender Bone-facing через `SocketFacing.FullFrame`, а оружие —
канонический поворот -90° по X. Методы получения сокета, преобразования
world-grip в `Model:PivotTo` и жизненный цикл при этом едины.

## Удалено

`HairAttachmentController.luau`, `WeaponAttachmentController.luau`,
`CharacterHairExtraWeld` и старый режим `runtime-canonical-grip-v1`.
Никаких новых локальных визуальных клонов и отдельной системы движения
парика не добавлено. Skin-based аксессуары по-прежнему используют
`CharacterMountJoint` — это другой тип ассета, не rigid-pivot парик.

## Проверка в опубликованном Eyesland Dev

1. После спавна на ПК и телефоне парик находится точно на `hair_mount`.
2. В беге, при повороте на месте, атаке и прыжке дополнительные меши
   парика не отстают и не дрожат относительно основного меша.
3. Второй игрок видит тот же результат на чужом персонаже.
4. Переключение меча и лука не меняет смещения оружия, боевой volume,
   точку выпуска стрелы или регистрацию урона.
5. StreamingEnabled: при выгрузке и повторной загрузке персонажа
   крепление корректно возобновляется.

Статические тесты не заменяют эти проверки в реальном Roblox-клиенте.
