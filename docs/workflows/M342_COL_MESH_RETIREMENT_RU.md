# M342 — окончательный отказ от выделенных COL-мешей

**Статус:** утверждённая архитектура, реализация удаления в коде; проверка в Roblox Studio обязательна.
**Область:** Asset Manager → Real Estate и Location Assets, Blender FBX, Studio Bridge, активные реестры.
**Предыдущие решения:** M340 / M341. M342 **отменяет** поэтапный legacy-режим M340–M341, но не отменяет будущую Collision Blueprint.
**База патча:** M341 поверх M340/M339R.

## Решение

Старый механизм выделенного FBX-меша `col_mesh`, `COL_*`, `*_col`, `*_col_*` полностью выводится из активного пайплайна. **Сохранять старую коллизию до ввода Part Blueprint не требуется.** Дома временно могут не иметь физического корпуса. Запрещены особые правила «Physics-only Mesh Asset», автоматическая публикация COL Mesh и автоматическое принудительное `PreciseConvexDecomposition` у всех collidable MeshParts.

Это **не** запрет на `MeshPart.CanCollide` вообще: у обычных визуальных мешей остаются вручную назначаемые `No Collide` и `CollisionFidelity` (например, для интерактивного сложного объекта). Новая статическая физика домов будет отдельной Part-сборкой.

## Пять границ операции

1. **Мастер-FBX и опубликованные Roblox Asset ID неизменяемы.** Ни один FBX не переписывается; фильтрация удаляет выделенные COL-меши из временных сцен при инспекции/публикации. Опубликованные модели Roblox нельзя изменить задним числом.
2. **Активные записи SQLite очищаются.** `skeleton_json`, `mesh_options_json`, `model_rigs_json`, `mesh_sources_json`, `textures_json` Real Estate больше не ссылаются на COL. У Location Assets очищаются настройки COL, плюс анализы FBX на диске. Исторические ревизии и файлы исходников не удаляются.
3. **Новый Real Estate Studio Sync не загружает COL-меши.** При синхронизации очищает старые управляемые `Col_meshRig` внутри шаблона и размещённых домов. Копирование/вставка управляемого дома также удаляет obsolete COL в Edit Mode.
4. **Location Studio Sync фильтрует COL.** При загрузке существующего опубликованного модели импортированная сборка ещё проверяется по её неподменяемому опубликованному описанию, затем COL удаляется из рабочей сборки; после успешного Sync очищаются и ранее размещённые копии. Внешние чужие модели и персонажи не трогаются.
5. **Запуск Studio Bridge выполняет разовую очистку управляемых объектов** в Workspace и ServerStorage в Edit Mode; только объекты с `Game1RealEstateSlug` или `Game1DecoAssetSlug` могут быть затронуты. Это не миграция к новому набору коллизий.

## Целевая политика после M342

### Real Estate — visual rig

- В реестре активны только действительные визуальные MeshParts и риги с Bone/Socket.
- Новый визуальный меш по умолчанию `CanCollide=false` (флаг `noCollide=true`).
- Если конкретный визуальный меш намеренно имеет коллизию, её `CollisionFidelity` определяется сохранённым параметром, без принудительного переключения на Precise.
- Studio Sync использует тот же авторский Pivot `house`, что и Place / Place All; никаких преобразований позиций Plot не выполняется.
- `col_mesh` больше не имеет отдельной публикации, вкладки модели, текстурного исключения или роли Collider.

### Location Assets

- `COL_*` исключается из инспекции FBX, экспорта публикаций и текущих `meshOptions`.
- Обычные визуальные меши сохраняют настраиваемую коллизию; за пределами Real Estate **не навязываем** отключение всех столкновений, чтобы не лишить лестницы/деревья/структуры физики без отдельного решения.
- При построении активной сборки старый COL-объект удаляется; его загруженный опубликованный Mesh ID остаётся только историческим фактом.

### Новая система (следующая механика)

`Collision Blueprint` — Part/WedgePart/Cylinder/Ball, `localCFrame=housePivot:ToObjectSpace(part.CFrame)`, `Size`, `Shape`, `CollisionGroup`, `CanCollide`, `CanQuery`, `CanTouch`; один Blueprint на тип дома, версии, Capture/Preview/Validate, генерация серверных Parts на каждом Plot. Изменение геометрии/размеров Full/LOD не должно менять серверные столкновения. Capture этой сборки **не входит в M342**.

## Порядок применения

1. Остановить Control Center, закрыть открытый Studio Play. Убедиться, что M341 установлен.
2. Сделать Git commit/резервную копию актуального Place `.rbxl` (не включён в Git patch).
3. `git apply --check`, затем применить M342.
4. `python system/verify/m342_retire_col_mesh.py --dry-run` — инвентаризация; без записи в базы.
5. `python system/verify/m342_retire_col_mesh.py --output artifacts/reports/m342_retirement.json` — миграция. Создаёт копии двух SQLite через backup API и копии изменяемых манифестов в `.control-center/backups/m342_col_retirement_...`.
6. `python system/verify/verify.py`, профильные M342-тесты, Luau и JS валидаторы.
7. `./system/studio-plugin/install.ps1`; открыть Studio в **Edit Mode**, открыть актуальный Place, дождаться отчёта удаления. Сохранить Place вручную после визуальной проверки.
8. Выполнить Sync Real Estate и Location Assets на выбранной модели, убедиться, что `COL_*` отсутствует в ServerStorage и в Workspace. Ручные проверки Collision Blueprint и серверных коллизий выполнятся позже.

## Приёмка M342

- Нет роли `collisionMesh=true` у активных элементов Asset Manager.
- Реестры и новые публикации не содержат `col_mesh`/`COL_*` как самостоятельных ригов.
- Studio не восстанавливает старые физические MeshParts при Sync/Place.
- Сохранены Asset IDs действующих визуальных частей, Authoring Pivot, Plot Bindings, House Socket и DoorAssembly.
- Владелец проекта подтверждает работу Real Estate Place / Place All / Clear, поведение дверей, корректность шаблонов и отсутствие ошибок Studio после очистки.
- Удаление старой коллизии является ожидаемым результатом, а **не** дефектом M342.

## Риски и пределы гарантии

- Автоматическая очистка в Studio необратима через обычный Sync; файл Place нужно сохранить заранее. Резервная копия SQLite **не содержит** Workspace/ServerStorage.
- Модели, опубликованные раньше, навсегда содержат COL-геометрию внутри своего старого Immutable Asset ID; старая геометрия удаляется из рабочей сборки и не используется как активная коллизия.
- Внешние непомеченные/неуправляемые объекты не затрагиваются. Если такой объект содержит `col_mesh`, его нужно удалить вручную или зарегистрировать в Asset Manager.
- Некоторые старые тесты, утверждавшие `COL_*` как действующий контракт, устарели. При смене этих тестов ориентируемся на новые M342 требования, но не маскируем несвязанные сбои.
