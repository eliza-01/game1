# M344 — Location Assets Instance Manager / Compact Registration

## Интерфейс

Модуль **Instance Manager** расположен **в самом низу Location Assets** после Collision Blueprint.
Раздел `01 · New Registration` по умолчанию свёрнут до заголовка и кнопки `+ New asset`.
В раскрытом виде поля сгруппированы в компактную сетку; серверный контракт регистрации
и все id полей остались прежними.

## Полная замена модели

1. Выбрать **исходный** и **целевой** зарегистрированные Location Assets.
   Целевой ассет должен иметь действующую публикацию Model (`PUBLISHED`).
2. Выбрать `Только выделенные в Studio` или `Все экземпляры в Workspace`.
3. Нажать **Preview replacements**. Studio проверит исходные объекты,
   историю публикаций Mesh ID, уникальность Placement ID и визуальные габариты
   с учётом существующего Pivot и Scale. Предварительный результат не мутирует Place.
4. Проверить список, сохраниться в `.rbxl`, нажать **Replace Models** и подтвердить.
5. Выполнить **Place Registry → Scan** и проверить новые Asset/Mesh/Collision ID.

Транзакция создаёт *полностью новую Model* из опубликованной модели целевого
ассета. Старую геометрию, старые Parts-коллизии и её старые эффекты **не переносит**.
Визуальная структура (включая другое количество MeshParts, Lights, Attachments)
и новая Collision Blueprint берутся из целевого ассета. Сохраняются строго:
исходный `Model:GetPivot()`, `Model:GetScale()`, родительский каталог Workspace,
`Game1DecoInstanceId`. Новые публикационные атрибуты и slug присваиваются
из целевого Asset Registry.

**Безопасность:** операции доступны только в Studio Edit Mode и выполняются через
аутентифицированную команду `location-instance-replace-v1` с `schemaVersion=1`.
Источник должен быть одной подтверждённой зарегистрированной Model с известной
историей публикаций, а не посторонним объектом с похожим именем. Подмена
блокируется, если в Place обнаружены дубли её Placement ID, неоднозначность
происхождения, иные габариты или устаревший Preview. Также запрещена замена
вложенных/чужих объектов и более 1000 экземпляров за один проход.

На стадии `Replace` все новые модели и коллизии подготавливаются **до**
изменения Workspace. Если предварительная проверка не пройдена — ничего
не меняется. Установка происходит в одном `ChangeHistoryService` Recording;
при ошибке размещения модели возвращаются, запись Undo отменяется.
Восстановление успешной операции — стандартный **Undo Roblox Studio**
(лучше сразу после замены, до любых иных действий).

**Граница этапа:** выборочные Appearance Overrides и Reset Overrides в
Instance Manager остаются отдельной задачей — пока их не имитируем глобальными
изменениями Registry, которые затем будут потеряны при Sync.

## Установка

Только один Git-патч M344 поверх M343C. Отдельная миграция SQLite не требуется.
Проверка проекта — `python system/verify/verify.py`. Изменяется исходный код
Game1Bridge, поэтому нужен `system/studio-plugin/install.ps1` и перезапуск Studio.
Rojo с запущенной синхронизацией не требует отдельного ручного перезапуска.

## Приёмка в Roblox Studio (обязательная)

- Preview+Replace одной и нескольких выделенных моделей с отличающимся
  количеством MeshParts (и Lights) и одинаковыми Pivot/визуальными границами.
- Замена всех экземпляров, несколько поворотов/масштабов, точные CFrame
  и Placement ID, новая Collision Blueprint и материал.
- Повторное Scan Place Registry, Collision Status и Undo.
- Заблокированная операция при несовпадающих границах, невалидном происхождении,
  дубле ID и попытке изменить иной Workspace-объект.
- Studio toolbar **Plots**, Place Registry Scan/Sync и DecoManager работают
  независимо от Instance Manager.

Автоматические тесты проверяют протокол/маршруты и структуру интерфейса, но не
заменяют эти реальные Studio-проверки.
