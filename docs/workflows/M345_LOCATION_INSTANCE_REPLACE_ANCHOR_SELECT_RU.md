# M345 · Instance Manager: выбор Pivot при полной замене

**Основа:** M344 (M344A НЕ применять).

## Поведение

1. В Location Assets → Instance Manager выбрать исходный и новый опубликованные ассеты, область `Selected` или `All`.
2. Нажать **Preview replacements**. Studio сверяет источник с реестром и показывает число экземпляров, а также доступные Pivot новой опубликованной Model: `Model Pivot` и отдельный пункт для каждого **визуального MeshPart** (в том числе вложенного). Пункты `MeshPart N` позволяют различить даже повторяющиеся имена.
3. Выбрать `Pivot новой Model` либо `Pivot MeshPart N` в поле **Совместить с Pivot исходной Model**.
4. Нажать **Replace Models** и подтвердить действие. Pivot исходной Model становится точкой совпадения с выбранным Pivot новой Model/MeshPart. Перемещается только целиком заменяемая модель. Pivot самих MeshParts не перенастраиваются.
5. Дочерняя структура, коллизии, визуальные материалы и эффекты берутся из **нового опубликованного ассета**, а Place-путь, Placement ID, масштаб экземпляра и история Undo сохраняются.

## Что намеренно снято

- Сравнение старых и новых **visual bounds / размеров** в Preview и Replace.
- Требование совпадения Origin старой и новой геометрии.
- Любые попытки исправить Pivot в Blender, FBX или опубликованной модели.

## Что осталось защищено

- Принадлежность исходных Model зарегистрированному ассету подтверждается историей опубликованных Mesh ID и Placement ID.
- Preview связывается с выбором, состоянием исходных экземпляров и ревизией нового ассета. Если что-либо изменилось, нужен новый Preview.
- Anchor ID разрешён только из списка, выданного Studio в Preview; сверяется опубликованный Mesh ID выбранного MeshPart. Список привязан к данной публикации.
- Стадирование всех экземпляров выполняется до удаления старых Model; ошибка стадирования ничего не изменяет.
- После Commit доступен Undo Roblox Studio.

## Контракт координат

Обозначения: `S` — `CFrame` исходной Model; `M` — текущий `CFrame` новой Model после ScaleTo; `A` — `CFrame` выбранной опоры новой Model (для Model — `M`, для MeshPart — `MeshPart:GetPivot()`). Параметр для `Model:PivotTo`:

`targetModelPivot = S * A:Inverse() * M`

После перемещения выбранная опора новой геометрии совпадает с `S`. Контроль выполняется по CFrame опоры, а не по bounds или Pivot новой Model (который может отличаться от опорного MeshPart).

## Установка и риски

Только M345 поверх M344. Меняется UI, backend команда Studio Bridge версии v2 и Studio Instance Replace. Требуется переустановка Game1Bridge, запуск Control Center; **Rojo не меняется**. Не запускает миграцию SQLite. Roblox Studio runtime проверяется владельцем на одном экземпляре, затем на `Replace All`. Точное визуальное совпадение не гарантируется, если размеры/ориентация новых мешей действительно отличаются: проверку размеров удалили намеренно.
