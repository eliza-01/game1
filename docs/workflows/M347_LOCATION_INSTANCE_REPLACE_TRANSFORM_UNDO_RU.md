# M347 · Location Instance Manager — target anchor / Undo / duplicated IDs

Основа — актуальный диагностический дамп `game1_diag_2026-11-14_17-24-57.zip`. M345/M346 остаются историческими описаниями и **не определяют действующий контракт**.

## Утверждённое поведение

`Replace` выполняется над подтверждёнными **исходными Model**. Для каждого старого размещения сохраняется его реальный `Model:GetPivot()` и `Model:GetScale()`. В Preview можно выбрать **опорный Pivot нового опубликованного ассета**:

- `Pivot новой Model` — по умолчанию;
- `Pivot нового MeshPart N · путь` — включая визуальные MeshParts внутри вложенных Models (кроме rig_carrier и физической геометрии).

В обоих случаях **выбранный Pivot НОВОГО ассета совмещается с Pivot СТАРОЙ Model**. Не подменять старый Pivot на Pivot старого MeshPart. Не редактировать `PivotOffset` или опубликованную геометрию. Полная замена сохраняет старый родительский Folder, масштаб всей Model и проверенный Placement ID (кроме явно обозначенных конфликтов). Новые материалы и Collision Blueprint принадлежат новому ассету.

Вычисление `CFrame` после `clone:ScaleTo(old:GetScale())`:

- `S = old:GetPivot()` — неизменяемая точка назначения;
- `M = clone:GetPivot()` — Pivot нового Model после применения масштаба;
- `A` — выбранный `clone:GetPivot()` или `newMeshPart:GetPivot()` после масштаба;
- `clone:PivotTo(S * A:Inverse() * M)`.

Проверяется точное совпадение выбранного Pivot с `S`, а **не** обязательное совпадение Pivot новой Model с `S`, если выбран MeshPart. Нет сравнения границ или попыток исправлять старые FBX. Индивидуально отредактированный `MeshPart.Size` старого размещения не является `Model:GetScale()` и не интерпретируется как uniform scale.

## Конфликт Placement ID

Причина ошибки M346: Preview безусловно требовал уникальности `Game1DecoInstanceId` по всей Workspace, тогда как Place Registry Repair может отказывать для неканонического rig. Preview теперь обнаруживает дубли, не меняя Workspace, и показывает **исходный → будущий ID**. При подтверждённом Replace новым GUID переиздаются **только выбранные экземпляры с конфликтующими ID**; посторонние объекты не изменяются. При новом Preview план переиздания создаётся заново; ID резервируются в памяти только на время Preview → Replace. Изменение состояния источника или количества старых ID между ними блокирует Replace.

Это не универсальная кнопка Repair Place Registry: она не исправляет размещения вне выбранной операции и не маскирует конфликты Mesh ID или неподтверждённое происхождение.

## Undo и безопасность

`Instance:Destroy()` необратимо блокирует Parent и **не совместим** с отменой удаления через Studio ChangeHistoryService (подтверждено инженером Roblox в DevForum). M346 уничтожал исходную Model до `FinishRecording(Commit)`. Теперь одна запись `TryBeginRecording` → `Commit` охватывает `old.Parent=nil` и `new.Parent=originalParent`, без `Destroy()` старого экземпляра. Отмена Ctrl+Z должна восстановить старую Model на исходной позиции/масштабе с исходным ID, убрать новую и отменить переиздание конфликтного ID. Если запись Undo недоступна, Place не изменяется. При ошибке замены включается rollback и `FinishRecording(Cancel)`.

Только новые *временные* клоны, не являющиеся частью записанной истории, уничтожаются при preflight/rollback. Возвращать `Destroy` на старую модель нельзя.

Контракт обмена Studio Bridge поднят с `location-instance-replace-v2 / schemaVersion=2` до `v3 / schemaVersion=3`, чтобы старая установленная версия Game1Bridge не могла незаметно использовать неверные pivot semantics. `Game1Bridge` остаётся опциональным обработчиком относительно Plots/Place Registry. Новых схем SQLite и миграций Registry нет. Rojo игровых скриптов не меняется; **переустановить Game1Bridge и обновить Control Center необходимо**.

## Ручная приёмка в Studio (обязательна)

1. Сохранить отдельный `.rbxl` и открыть **Edit Mode**. Перезапустить Studio после установки актуального плагина.
2. Создать два новых опубликованных ассета, у одного из которых Pivot Model и Pivot MeshPart различаются и по **позиции**, и по **повороту**.
3. В Instance Manager `Selected → Preview` выбрать `Pivot новой Model`, заменить один экземпляр: проверить положение/поворот/масштаб; Ctrl+Z должен вернуть точную старую Model, не только её внешний вид. Повторить с `Pivot нового MeshPart`.
4. Скопировать старый экземпляр в Studio (`Ctrl+D`), создать дубликат Placement ID. `Preview` не должен падать, должен показать новые ID. `Replace` затрагивает только выбранное размещение; Ctrl+Z возвращает оба исходных экземпляра и исходные ID.
5. `Replace All` на двух экземплярах разных ScaleTo, затем Ctrl+Z. Проверить, что все старые модели и их дети вернулись, новые исчезли, нет новых ошибок Plots/Place Registry.
6. Проверить 1-2 экземпляра, которые старый DecoManager уже заменял корректно: режим Pivot новой Model должен сохранить прежний результат.

До этих проверок поведение Undo и реальное размещение моделей на конкретной версии Roblox Studio **не считается подтверждённым**.
