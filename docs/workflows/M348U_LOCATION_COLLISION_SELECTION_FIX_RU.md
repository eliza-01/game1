# M348U · Collision Capture: корректная обработка Studio Selection

## Причина

M348 прерывал `Validate` на `StudioLocationCollisionAuthoring:69`, если
`Selection:Get()` содержал хотя бы один сгенерированный `__Game1Collision_`
Part. При этом код не показывал фактический список объектов, полученных от
Studio Selection, и ошибочно заставлял пользователя искать лишнее выделение.
Сам код **не обходит дочерние объекты Model** во время выделения. Поэтому
причина расхождения UI и Selection:Get() пока не доказана.

## Исправлено

- Все элементы `Selection:Get()` рассматриваются явно; служебные Parts
  (`Game1LocationCollisionOwned=true` или префикс `__Game1Collision_`)
  исключаются из Validate/Capture без изменения пользовательского выделения.
- Служебные Parts никогда не сохраняются как исходные Collision Blueprint Parts.
- Если не осталось ни одного исходного Part, Validate/Capture завершается
  без записи Blueprint. Сообщение выводит число полученных Studio элементов,
  число исключённых служебных и первые восемь фактических путей объектов.
- Выбор одной Model и 1–256 оригинальных Part/WedgePart/CornerWedgePart
  остаётся обязательным; вложенные Parts по умолчанию не собираются, чтобы
  не принять визуальную геометрию за коллизию.
- Pivot, размещения, генерация/Sync коллизий, SQLite и Asset ID не затрагиваются.

## Ручная приёмка

1. После установки Game1Bridge выполнить Validate с прежним выделением.
2. Если выбранная Model была единственным элементом Selection, должно
   появиться сообщение `1..256 ORIGINAL collision Parts` с перечислением
   увиденных Studio объектов; перед Capture выбрать исходные Parts явно.
3. Если Studio дополнительно передала служебную коллизию, но выбран
   исходный Part, Validate должен пройти без включения служебной геометрии.
4. Убедиться, что Capture не изменил исходные Parts и Studio Selection.

Тесты Python проверяют контракт исходника; реальное поведение Roblox Studio
остаётся предметом ручной проверки.
