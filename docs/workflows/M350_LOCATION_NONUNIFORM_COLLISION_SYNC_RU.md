# M350 · Location Collision Blueprint: non-uniform MeshPart Size

## Подтверждённая причина (2026-11-14)

Свежий диагностический ZIP содержит `StudioLocationCollisionParts.luau`: в
`referencePivot` три отношения `placedMesh.Size / blueprint.anchor.size`
обязательно требовались равными. При несовпадении ошибка выбрасывалась
**до** изменения Place (`Collision Sync staging failed; Place unchanged`).

Проверен экспорт `game1snapshot.rbxm` от 14 ноября, 16:22 UTC. Для Mesh ID
`139744616815788` (`stone_fence_01`): всего 183 визуальных MeshParts,
9 соответствуют равномерному масштабу, 174 неравномерно изменены по осям.
В `location_asset_collision_blueprints` для `stone_fence_01`, ревизия 3,
визуальный anchor имеет `Size=(3.407264,5.484735,17.768490)`.
Пример старого забора в `Workspace.Plots.01`:
`Size=(3.407264,7.832839,7.385962)`; `Model:GetScale()=1`.
Несовпадение Pivot/PrimaryPart само по себе **не вызывает** эту ошибку;
старый Studio Sync мог независимо менять `PivotOffset`.

## Изменение алгоритма (без миграции базы)

- Capture JSON v2 и опубликованные Asset IDs не меняются.
- Система находит единственный визуальный MeshPart по сохранённому Mesh ID.
- Использует **его CFrame** и отношения текущего `Size.X/Y/Z` к размерам
  оригинального anchor; Pivot Model и PivotOffset MeshPart не изменяются.
- Для равномерного масштаба остаётся точный ранее действовавший алгоритм.
- Для неравномерного масштаба **Block**: сначала переходит в координаты
  исходного визуального MeshPart; переносит центр исходного коллайдера
  аффинным масштабом X/Y/Z, сохраняет ориентацию блока относительно
  визуального меша, рассчитывает минимальные размеры охватывающего
  прямоугольного Part при фиксированной ориентации.
- Неравномерный масштаб вместе с произвольным поворотом примитива может
  создать *shear*. Roblox Part не представляет наклонный параллелепипед:
  поэтому размеры результирующего Box могут оказаться немного больше
  аффинной исходной геометрии. Если увеличение хотя бы одной полной
  размерности превышает **и 0.20 studs, и 10%** исходного размера в этой
  ориентации, операция отклоняется до изменения Place. Это явное
  ограничение, а не молчаливая компенсация Pivot.
- `Ball`, `Cylinder`, `Wedge`, `CornerWedge` при неравномерном масштабе
  пока отклоняются: нельзя гарантировать нужную геометрию простым Part.
- `Collision.Current` и `Collision.Prepare` используют один алгоритм,
  чтобы Scan не показывал ложное `Collision ✕` после успешного Sync.
- Sync и генерация при размещении работают через общий модуль, Undo
  и существующая защита атомарности не изменены.

## Порядок приёмки в Roblox Studio

1. После установки Game1Bridge в Edit Mode сделать резервную копию Place;
   для одного `stone_fence_01` с изменённым `Size` выполнить Scan → Sync.
2. Проверить совпадение поверхности визуала и коллизии, включая поворот
   нестандартного исторического Pivot и укороченный забор.
3. Повторить Scan: коллизия должна стать `✓` без требования Sync.
4. `Ctrl+Z` / `Ctrl+Y`: геометрия модели, Placement ID и Pivot остаются
   неизменными; коллизия откатывается и восстанавливается.
5. Выполнить аналогичный тест на недавно размещённой Model; проверить
   отсутствие новых расхождений на нормальном размере.
6. Проверить `Place All` только после успешной проверки одного экземпляра.
   Не применять `Sync All`, пока эти проверки не пройдены.

**Статус:** алгоритм и числовые тесты проверены вне Roblox Studio; проверки
реальной физики, отрисовки, Undo и Studio Bridge требуют ручной приёмки.
