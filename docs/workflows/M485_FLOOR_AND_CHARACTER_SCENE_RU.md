# M485 — этаж лифта и жизненный цикл Character Creation

База: diagnostic dump 2026-11-25_03-26-24 (M484). Без миграции, изменений Place,
публикации моделей или идентификаторов ассетов. Сервер и клиент разворачиваются вместе.

## Контракт лифта

- `HouseElevatorPolicy.CurrentFloor` выбирает наиболее близкий вертикальный интервал
  от authored floor spawn + половина высоты root до spawn + 3 studs (существующий
  teleport clearance). При близости к границе двух интервалов в пределах 0.15 studs
  этаж неопределён. Геометрия пола и фактическая посадка требуют проверки в Studio.
- `HouseElevatorFloor` использует живые CFrame Bone/Attachment именно зарегистрированного
  дома. На каждом серверном prompt находится папка `Game1ElevatorFloorReferences`,
  `FloorCount` и ObjectValue на каждый действительный floor spawn. При неполном
  streaming клиент скрывает действие. Это не клиентский источник авторитета.
- Клиент проверяет этаж до AIM-селекции, сборки панели и отправки запроса;
  сервер независимо вычисляет его по своему socket registry перед PivotTo.
  E/F, дистанция, физика, камеры, authored spawn и другие интеракции сохранены.
- HS → RANGES: рядом с лифтом строка current / socket / OK или BLOCKED; `?` —
  недостаточно данных или неоднозначная высота. Это ближайший сокет, не ретикл.

## Контракт создания персонажа

- `CharacterCreationStatus` — авторитетный этап loading → creation → selection → world;
  `CharacterCreationPending` остаётся серверным gate для текущих потребителей.
- Сервер сериализует create, enter, manage; клиент использует epoch и revision,
  отбрасывая ответы прошлых этапов, в том числе после ожидания template.
- Создание и выбор разделены. Вход разрешается после загрузки сохранённого профиля,
  модели и камеры. Смена сцены под шторкой; face/full — плавно внутри creation.
- `CharacterSelectionScene.Resolve` возвращает единую пару preview/camera. Сервер
  объявляет `Game1CharacterSelectionScene`, выделяет дополнительный replication focus
  для отдельной сцены. Отсутствующая пара использует существующую creation сцену;
  ожидаемая, но не реплицированная пара — ошибка с возможностью повторить запрос.
- `CameraController` остаётся единственным владельцем камеры. Handoff закрыт до
  появления игрового RootCollider, затем орбита сбрасывается в текущие настройки.
- Локальный `PlayerGui.Game1CharacterSceneInputBlocked` блокирует world input до
  завершения перехода, включая keyboard, touch, прыжки, удары и house prompts.
- Сохранение DataStore / схема профиля не изменены. UI-строки добавлены в источник
  локализации и синхронно сгенерированы для всех 10 языков.

## Acceptance в Studio Play и опубликованном Runtime (обязательно)

1. Дома на 1, 2, 3 этажа: TP через HS на каждый authored spawn, обычное движение,
   прицел на соседний этаж при максимальных USE/AIM, клавиатура и touch; проверить
   маршруты E/F, отказ неправильному сокету, двоих игроков на разных этажах.
2. Войти новым игроком: загрузка, оба пресета, body/face, переключение пола и вкладок,
   быстрый выбор волос, палитра Apply/Cancel, возврат к overview. Нет лишнего аватара.
3. Создать → selection: только сохранённый персонаж, отдельная сцена с обоими
   маркерами и без них; StreamingEnabled в обоих случаях, retry при задержке модели.
4. Войти в мир: нет пролёта через карту; FOV, направление и орбита восстановлены;
   WASD/RMB/атаки/touch/лифт работают после шторки. Settings → change character →
   снова войти; сохранённая позиция и внешность, запрет смены во время боя.
5. Проверить небольшие desktop окна, mobile portrait/landscape, десять локалей,
   отсутствующий DataStore и ошибки загрузки, повторные клики, respawn и обычный
   Test Loadout. Проверить Console на ошибки Luau и streaming.
