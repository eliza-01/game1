# M501 · Runtime readiness stabilization

База: `game1_diag_2026-11-25_18-40-00.zip` (M500). Без миграции профилей, Asset ID, FBX, текстур и геометрии. Не меняет пользовательский Options/LOD профиль.

## Runtime XML

- LOD Manager Preflight требует `place/game1_runtime_source.rbxlx`, обычный файл XML Place. Ошибки отсутствия, пустого файла, превышения 150 MiB и неправильного XML разделены. Лимит не снят: в метаданных дампа предыдущий XML занимал 58 732 341 байт.
- RuntimePlaceBuilder сопоставляет Rojo `default.project.json` с фактическими путями, классами и Source всех Luau/ Lua-скриптов в трёх управляемых деревьях. Лишние, пропущенные, устаревшие, отключённые Script/LocalScript останавливают Preflight. Переводы CRLF/LF и BOM нормализуются; иные изменения не скрываются. Сценарии с геометрическими тестовыми fixtures без Rojo mapping сохраняют прежнюю возможность независимого тестирования; production LOD Manager требует mapping.
- Проверки выполняются также перед преобразованием и после повторного чтения созданного XML. SHA256 исходника сверяется до/после Preflight и при подготовке, хэш verified backup обязателен. Количество скриптов и digest исходников входят в отчёт, не заменяя SHA256 самого XML. Неавторизованные debug-инструменты закрыты как прежде; опубликованный Place с Runtime manifest выключает даже авторизованный published debug, Studio остаётся доступной. Лог версии обновлён до M501. Неавтоматизированные сторонние скрипты вне управляемых Rojo деревьев не удаляются.
- Рабочий порядок: завершить Rojo Sync → открыть authoring Place → Scan Place → Studio File > Save to File > Roblox XML Place (.rbxlx) → сохранить строго `place/game1_runtime_source.rbxlx` → Preflight → Verified backup / Runtime draft. Не переименовывать .rbxl в .rbxlx. Не использовать runtime draft как authoring source. Публикация по-прежнему запрещена автоматически.

## Character scene / loading

- Исторический M501 (заменён M648, см. `M648_CHARACTER_ASSET_PREWARM_RU.md`): VariantPrewarm использует существующий серверный RPC и готовые модели, по одной подстановке на слот, не размножая все комбинации. Максимум 24 шаблона и 75 секунд бюджета; поздние/неудачные варианты загружаются по запросу. Не весь Workspace. Для текущего каталога это семь комбинаций с дефолтами. Cache limit сервера 32 сохранён. Предзагрузка не заменяет engine streaming.
- MeshPreloader: до четырёх общих in-flight запросов, один запрос на ID; результат только при AssetFetchStatus.Success, повторная сверка статуса кэша; лимит ожидания модели 25 секунд. Сначала геометрия, потом текстуры. При отсутствующей геометрии старое preview остаётся; при недоступной текстуре возможна отложенная отрисовка (PBR пакеты движок грузит самостоятельно). Проценты не являются байтами; при неполном прогреве loader переходит в indeterminate.
- RemoteFunction: один реальный запрос на remote, ограниченное локальное ожидание, ответы старого epoch/revision не изменяют GUI. Timeout не отменяет серверную операцию; авторитетны атрибуты стадии. Поздние RootCollider и смена Character во время входа обрабатываются повторно. После 20 секунд отсутствия root отображается ошибка и действие возврата к выбору через существующий CharacterCreationManage, без обхода серверных combat/save проверок. Если сервер не может выполнить возврат, остаётся возможность дождаться репликации или переподключиться.
- Server streaming request сообщает завершение для конкретной стадии, устаревшие ответы игнорируются, клиент ждёт ограниченно. Это не гарантия готовности каждого декора/LOD. Сохранён выбор пары selection camera+preview. Волосы проверяются перед handoff как M495.

## Mobile

- Панель редактора в портретной ориентации увеличена, три вкладки в одном ряду, компактный footer. Меню языков/настроек рассчитывает высоту списка и кнопки из фактической safe-area высоты.
- Палитра удерживает один InputObject; другой палец не меняет цвет и не освобождает первый. Закрытие или потеря фокуса сбрасывает захват.

## Acceptance в Studio и опубликованном TestPlace

1. Синхронизировать исходники, сохранить новый XML, проверить число скриптов и SHA в Preflight. Изменить один исходник без пересохранения XML: Preflight обязан остановиться; после восстановления/синхронизации пройти снова.
2. Новый игрок: выбор языка → оба preview → все причёски/брови, менять быстро, проверить Hair/Extra, текстуры, scroll и сохранение цветов. Имитировать недоступный asset/плохую сеть: старый preview не исчезает, ошибка позволяет Retry. Проверить повторный вход сохранённого игрока и смену персонажа из settings.
3. Studio device emulator: 360x640, 390x844, landscape 844x390; прокрутить редактор, открыть HSV, вести первый палец по яркости и коснуться вторым, проверить сохранение захвата; затем проверить джойстик/прыжок/атаку/house prompts после входа.
4. Runtime draft в Studio: все визуальные и игровые механики, камера/корень, LOD, NPC/монстры. В опубликованном Runtime проверить права на Mesh/Texture/Animation ID, отсутствие debug UI, реальный DataStore. Публиковать только после live acceptance.

Luau guard и Python/JS не заменяют Luau compiler / Studio Play. В диагностическом архиве сами .rbxl/.rbxlx и медиа отсутствуют; проверить конкретный текущий XML или облачные права офлайн невозможно.
