# M504 — составные Location LOD

Location LOD1/LOD2 может содержать 1–64 визуальных MeshPart, независимо от числа мешей FULL. Сервер сохраняет относительные трансформации, имена и SurfaceAppearance, исключает rig_carrier, COL и physics-only. Составной шаблон содержит ожидаемое число мешей и CFrame опубликованной модели в атрибуте (WorldPivot не реплицируется). House-part LOD и resident VFX остаются одночастными.

Один клиентский модуль `LocationLodAssembly` используется Studio preview и compiled Runtime. Для составного FULL/LOD используется общий ориентированный объём всех визуальных частей, единый масштаб по доминирующей оси LOD, совпадение центра основания и ориентации FULL. Непропорциональные изменения формы при упрощении могут изменить силуэт; это не покомпонентное растяжение. LOD с одним мешем и FULL с одним мешем сохраняют прежний путь. Материалы сопоставляются по имени, включая суффикс `_lod1`/`_lod2`; неизвестное имя при нескольких настройках не получает произвольный материал. Проверить названия LOD в Studio, при необходимости использовать исходное имя меша. Составной LOD — статическая геометрия; анимация отдельных суставов FULL не переносится на упрощённую сборку. Серверные прокси, коллизии и эффекты не изменяются.

При неполной репликации шаблона не скрывается FULL. Замена целиком в существующем LOD scheduler, без дополнительного Heartbeat. Проверка в Studio Play: перейти через границы LOD и Hide для Blossom Tree 02 и Mid Tree 02; проверить материалы, ориентацию, основание, масштаб, отсутствие дублирования и коллизии. Скрипт `system/verify/studio_multipart_location_lod_m504.luau` запускается в клиентском command bar и проверяет синтетическую трансформацию и два опубликованных шаблона. После Rojo Sync сохранить новый XML для Runtime Preflight.
