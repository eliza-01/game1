# M514 · Balance v0.1

Единый авторский источник `config/balance/gameplay.json`; `BalanceRegistry.luau` — воспроизводимая immutable-проекция. Database → Balance редактирует записи, а Weapons занимается моделями, атласами и публикацией. Asset History сохранён. API `/api/balance` GET/POST, schema 1, optimistic SHA revision, валидация, предыдущая JSON-копия `config/balance/gameplay.previous.json`, откат пары при ошибке записи. После изменения нужен Rojo Sync и новый Play; Runtime preflight проверяет новые модули вместе с остальными. Для восстановления предыдущей версии одновременно восстановить JSON и сгенерировать Luau через `services.game_balance.render`.

- Уровни 1–35, накопленный XP вычисляется из xpNext; уровень 35 — cap. Базовое HP и ATK (5), крит (8%, ×2), Headshot (×1.5) из Balance. AttackSpeed/RunSpeed архетипов сохранены. Урон по существующему melee arc / HitEnd и bow hitscan, без переписывания механики.
- Оружие: 1, 10, 20, 30; четыре типа на tier, внутренние ID weapon_001…016. Одна запись может обслуживать несколько визуальных моделей. При несовместимом типе или отсутствии привязки игроку оружие недоступно; NPC visual mount может использовать зарегистрированную модель независимо от игровой записи. Старые SQLite поля и экспортные metadata сохранены для совместимости с инструментами, но не определяют характеристики оружия игрока. API записи моделей больше не принимает статы. Модели привязаны к стартовому tier, dragon_divider — к tier 20. Отладочный выбор позволяет тестировать любой привязанный tier; обычный startup проверяет уровень.
- Броня: 1, 5, 10, 15, 20, 25, 30, 35, бонус HP ~35% базового на уровне комплекта, цена 50×level (старт бесплатно). Пока данные, не инвентарь/экипировка. Заточка +6.67% от базового бонуса атаки за ранг, максимум +10, цена попытки 30×level. Runtime использует +0; покупка, владение и улучшение ещё не реализованы. Оружие 20 +10 сопоставимо с 30 +0.
- Монстры 001…035: уровень, HP, урон, XP, золото. gremlin → monster_001; другие визуальные модели требуют привязки. Непривязанные монстры сохраняют старую настройку и не дают награды. Скорости, агрессия, respawn, крит и механика NPC/монстров прежние. Текущий мир не содержит все 35 уровней монстров. XP/Gold начисляются финальному игроку через авторитетное событие смерти. Группового распределения и лута пока нет. XP/Gold живут в текущем профиле, прежние профили получают нули; используются штатные checkpoints выхода из мира, PlayerRemoving, BindToClose. При аварийном завершении сервера возможна потеря несохранённой прогрессии. Неопубликованная Studio session-only. При отключённом Character Creation и отсутствии профиля прогресс session-only.
- На HUD под HP видны уровень, XP и G. В выборе персонажа реальный уровень. Только числовые идентификаторы базы, имена ассетов не переименовываются.

Модель экспериментальная: ранняя XP кривая взята из согласованной v0.1, после 10-го продолжена квадратично; HP и награды привязаны к ожидаемому развитию экипировки, не проверены на живых 15-минутных сессиях. Цена оружия 100×level, броня 50×level; реальную экономику валидировать после инвентаря и магазина. Все исходные значения редактируемы, тесты не требуют фиксированных цен пользователя.

Studio smoke: Rojo Sync, Play, Database → Model bindings: убедиться, что starter и gremlin имеют записи. Убить 5 gremlin при нулевом XP: ожидается LVL 2, XP 60, Gold 125, MaxHP 120. Перейти в выбор/войти повторно, сверить уровень. Проверить обычный body и headshot, выбор оружия Studio, смену пола, мобильный HUD. В опубликованной тестовой игре проверить сохранение и восстановление прогресса. Не публиковать новую сборку до этой проверки.
