# M523 · Баланс оружия: Interlude → Eyesland

Действующий стартовый баланс, 26.11.2026. Числа редактируются в Database; эта методика описывает начальное заполнение M523, не ограничивает дальнейшую настройку.

## Проверенный источник

`RobloxLineage_DIAG_2026-10-05_03-28-13.zip`, `RobloxLineage/system/combat-v2/data/normalized/weapons.json` (1217 записей, нормализация aCis Interlude, не официальный сервер L2OFF). Вся выборка DAGGER: 125 × AS 433; SWORD: 196 × 379; BIGSWORD: 64 × 325; BOW: 63 × 293, 30 × 227 и одна нестандартная запись × 433. Для единственного текущего типа лука выбран быстрый вариант 293. Репрезентативные записи одного S-grade: ID 6367 (246 ATK, 433 AS), 6364 (281, 379), 6372 (342, 325), 7575 (581, 293). Исходные значения critical: 12, 8, 8, 12 соответственно; это не готовые итоговые проценты крита персонажа. Не импортируем имена, модели или ID предметов.

## Формулы переноса

- `AS = round_half_up(180 × AS_Interlude / 379)`. В Database → Balance → Character `baseAttackSpeed = 180`, в записи оружия `attackSpeedDelta = AS − 180`. Итоговые AS: меч 180, кинжал 206 (+26), двуручник 154 (−26), лук 139 (−41). Без прироста по уровню или заточке. Существующие модификаторы экипировки применяются аддитивно; при редактировании базовой AS коэффициенты сами не пересчитываются. Баффы позднее проектировать отдельным контрактом.
- Сервер и клиент используют действующий `CharacterAttackCadence`: `T = 300 / clamp(AS, 25, 400)` секунд. Анимация вписывается в цикл. Для лука release остаётся в существующем цикле; дополнительной задержки нет.
- `S = baseDamage + damage_меча` на том же уровне (кривая меча из M522 не изменена). `ATK_тип = round_half_up(S × K)`; `damage = ATK_тип − baseDamage`, целое неотрицательное. Меч K=1, кинжал K=246/281, двуручник K=342/281.
- **Лук:** исходный 581/281 при AS 139 дал бы ~159.7% DPS меча без отдельной перезарядки. Поэтому `K = 180/139`, чтобы сохранить равный базовый DPS (`ATK × AS / 300`) при фактической целочисленной AS. Это осознанная адаптация, а не оригинальная формула L2. Не вводим дополнительный штраф за дальность, пока не измерим реальные попадания, headshot и движение.
- При заточке сохраняется действующая формула `ATK(+n) = baseDamage + round_half_up(damage × (1 + n × upgradePercent/100))`. Из-за общей неизменной базовой атаки (5) и округления DPS-отношения на +10 немного отличаются от +0; не маскируем это новым правилом заточки.

## Границы и проверка

`config/balance/gameplay.json` — канонические игровые параметры, `BalanceRegistry.luau` — генерируемая проекция; `CharacterStatsService` устанавливает AS из `Balance.Rules.baseAttackSpeed`, `WeaponEquipService` добавляет `attackSpeedDelta`. Поле AS в старом рецепте персонажа оставлено для совместимости авторинга и не определяет игровой AS; это явно обозначено в Control Center. GP и обычный runtime читают те же записи. Не изменены углы (кинжал 80°, меч 108°, двуручник 125°), дистанции, 8% крит персонажа, headshot, HP монстров M520, цены, XP, броня, ID и привязки. Отдельного массового бонуса или искусственного ограничения целей не вводим. Навыки, баффы и прирост AS по уровню пока не реализованы.

На LVL20 при +0 и без критов/промахов DPS: меч 48.0, кинжал 48.07, двуручник 49.79, лук 48.19. Это непрерывный DPS, не точный TTK дискретных ударов. У лука крит и headshot используют существующий DamageService; реальное попадание, число melee-целей, движение и анимации меняют результат. Перед следующей балансировкой измерить цикл и DPS в GP с четырьмя типами, +0/+10, одиночной целью и группой, убедиться в одинаковых AS при смене пола и возрождении. Для лука проверять интервал между Release, а не только длительность анимации. Studio Play ещё не проводился.

Миграция M523 — обратимый patch для исходника и его проекции, схемы API (добавлено обязательное правило `baseAttackSpeed`), runtime и документации. Перед применением сохранить пару JSON/Luau, если локально редактировали баланс; при откате возвращать обе версии вместе. `patch-logs.json` содержит одну запись M523; предыдущая M520 сохранена. После отката перезапустить Control Center и Play с синхронизированными исходниками.
