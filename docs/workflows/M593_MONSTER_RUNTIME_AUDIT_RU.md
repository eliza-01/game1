# M593 · Monster AI / Runtime / Debug audit

**База:** `game1_diag_2026-11-27_06-32-10.zip`, RuntimeVersion M592; архив содержит исходники, Options и зеркала авторинга, но не сохранённый исходный или опубликованный `.rbxlx`. Проверка источников не доказывает поведение физики или FPS в Roblox.

## Runtime

- До M592 `default.project.json` включает `src/server`, `src/shared` и `src/client` целиком, но `MonsterNavigationDispatch.Enabled` возвращал false вне Studio. Поэтому новый навигатор, Climb, Rescue Route, Blocked Pursuit, watchdog и вызов HomeRecall не использовались опубликованными монстрами. Home Leash / Death Chase и остальные общие механики не ограничены этим gate.
- M593: `Options → Monster Navigation → Enable in published Runtime` (`runtimeEnabled`, default false) + основной `enabled=true` выбирают Experimental вне Studio. Workspace override применяется только в Studio. Без override compiled Draft в Studio наследует те же две настройки, что и опубликованный Runtime. NPC и тестовые Guided/Skilled/калибровка не изменены. Снятие галочки возвращает Legacy после новой сборки.
- Runtime Draft Builder проверяет все Rojo-скрипты из сохранённого `.rbxlx` до/после преобразования. Удаляет editor-only `Game1Authoring`, не `Game1RescueRoutes`. Граф использует папку `Workspace.Game1RescueRoutes`, а не JSON Database. В зеркале текущего дампа 2 карты (2 маршрута / 5 сегментов и 15 маршрутов / 113 сегментов); это не подтверждение содержимого опубликованного Place. Нужны Save Options → Rojo Sync → Save to File source `.rbxlx` → Preflight → новый Draft. `publishAllowed=false` сохраняется; до выполнения KBN-0032 не считать релиз принятым.

## Нагрузка: источники и границы

| Этап | Фактическое поведение / M593 | Что остаётся проверить |
|---|---|---|
| AI цикл | Один цикл на агента с интервалом 0,1 с, случайное начальное смещение. При 200 монстрах до ~2000 решений/с (не измеренный CPU). | Idle, chase, attack, return отдельно. |
| Aggro | Без цели скан игроков каждые 0,3 с. M593 сначала проверяет дистанцию, затем life/territory/isolation только для конкурентных кандидатов; результат и порядок равных расстояний сохранены. | С ростом числа игроков стоимость O(M×P); spatial index/единый scheduler только после измерения, не вводить дублирующие циклы. |
| Граф | Построение раз в серверную сессию при активном Experimental. Поиск переходов — концы × авторские сегменты, максимум 2048 авторских сегментов; не per-agent. | Время старта на больших картах; отдельный бюджет построения при росте данных. |
| Вход | M593: свободная ближайшая проекция без построения/сортировки сетки; линия за радиусом отсекается. Иначе 20/4, кэш на поиск. | Узкие проходы, реальное число запросов при массовой блокировке. |
| Выход / переходы | Dijkstra, кэш входов, путей, результатов переходов на один поиск; аналитические выходы и fallback до 32 интервалов на сегмент. Collision ограничен 96 overlap parts и 8 углами. | Суммарная стоимость одного поиска не ограничена общим бюджетом Raycast на сервер; граф может целиком обходиться при каждом новом плане. Не менять выбор пути без профиля. |
| Direct / climb | Периодический контроль препятствий (recheckSeconds); физический прыжок до 1 с. | Нагрузка при повторных срывах уже выбранного плана и прыжках; не путать с отключённым повтором NoAccessiblePlan. |
| BlockedRetreat / Wait | Отступление использует ограниченные физические пробы на новый шаг, ожидание не ищет маршруты. M593: нет геометрического callback в Wait, таймер обновляет атрибут только при изменении целой секунды. | Проходимость отступления, повторный вход игрока в радиус лука, таймеры. |
| Репликация | M593: периодические диагностические замеры скорости/лучей и обновление текущей точки плана только Studio; основные состояния backend/mode, причина, счётчик секунд сохраняются. MONNAV Studio-only, без добавочных Raycast. | MicroProfiler / сетевой трафик; это не обещание нулевого CPU. |

Сохранены фактические значения из дампа: searchDistance 80, stuckReturnSeconds 20, routeConnectionHeight 2, blockedRetreatBuffer 2, скорости 1 / 1.5 / 1.5. Не менять баланс или физику ради статической оптимизации.

## Test Debug Hub

- `debugUi.startInHub=false` в дампе. В обычном Studio галочка Start in Hub управляет автозапуском; ручной GP остаётся доступным. В compiled Runtime Draft, запущенном в Studio, GP/AG/Buffer загружаются только при включённой Start in Hub. GameplayTestService, GameplayAggroService и GameplayBufferController не запускаются вне Studio.
- M593 проверяет доступ **до require/start** опциональных сервисов/контроллеров. В опубликованном compiled Runtime (`Game1LocationRuntimeManifest`) `PublishedDebugAccess` возвращает false независимо от галочек PC/mobile: нет подписки PlayerAdded авторизатора, GP arena, GUI, тестовых ремотов/Heartbeat стенда. В обычном опубликованном TestPlace галочки сохраняются; владелец либо group rank ≥200 обязателен. При обеих отключённых галочках нет debug authorization listener. Studio продолжает работать независимо от галочек TestPlace.
- Модули физически остаются в Rojo. Общие безопасные контракты GameplayTestIsolation, Loadout, Report и GameOptions используются боем/персонажами, даже когда сессии нет (короткие проверки/ранний return); вырезать папку dev из сборки нельзя. Нулевая нагрузка всего кода не заявляется. Нет активного Debug Hub в production; отдельно тестировать отсутствие ремотов/сессии на Runtime Draft.

## Приёмка (KBN-0032)

1. Studio: одинаковая сцена Legacy/Experimental, 50/100/200 **активных** монстров, 1 и 2+ клиента; idle/chase, непрерывный маршрут, заблокированные входы, отступление/ожидание, прыжок/возврат. Профиль CPU script/physics, server heartbeat, число пространственных запросов, длительность построения графа, сетевые обновления, peak при одновременном начале преследования.
2. Runtime Draft с обеими комбинациями галочек навигации: проверить `MonsterNavigationBackend`, `MonsterRecoveryMode`, физическое прохождение сохранённых маршрутов, M592 отступление независимо от экипировки, появление HomeRecall. В Draft Studio при выключенной Start in Hub проверить отсутствие GP/AG/Buffer; в опубликованном Runtime проверить также отсутствие debug UI и debug authorization, отсутствие зависимости от Control Center. На опубликованном TestPlace с разрешением проверить прежнюю авторизацию.
3. Не закрывать карточку / acceptance без Studio и Runtime evidence; не изменять `publishAllowed`. Статические проверки не заменяют эти измерения.
