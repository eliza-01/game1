# M596 · Character Roster

## Контракт

- Options → Character Creation: прежний переключатель. При включении доступны пять независимых персонажей на аккаунт, в Studio и в published Runtime. Debug не требуется.
- Выбор: стрелки переключают ID, карточка показывает пол и уровень, счётчик позиции в списке и занятых слотов. Новый персонаж открывает редактор, отмена возвращает в выбор (если есть сохранённые). При заполнении пяти слотов создание отключается.
- Удаление: нажать «Удалить персонажа», затем «Удалить навсегда» либо «Отмена». Только выбранный ID. Если удалён последний слот, открывается создание. Не требуется готовая 3D-модель для удаления.
- Внешность, XP, Gold и позиция независимы. Экипировка/inventory и HP не получили новых контрактов сохранения. Язык/палитра — общие для аккаунта.

## Хранилище и защита

`game1_character_profiles_v1` / `player_<UserId>`: прежний v1 становится первым персонажем `legacy`; схема v2 содержит `characters`, `selectedId`, `revision`. Миграция в DataStore происходит при первом успешном сохранении, создании или удалении, а не в цикле загрузки. Создание и удаление — `UpdateAsync` с проверкой исходной ревизии; повтор при неясной ошибке использует ту же ревизию операции. После конфликта или двух ошибок требуется новый вход. Другой аккаунт не может менять этот ключ; запрос выбора/удаления проверяет ID и стадию. При недоступном DataStore опубликованный сервер не использует временные данные вместо сохранения. Studio допускает session-only при недоступной базе, но не перезаписывает неизвестную схему.

**Перед миграцией:** остановить все старые серверы Experience (включая другие Place, использующие тот же DataStore); сделать резервную копию/снимок данных. Не откатывать код до v1 после миграции. Старый сервер не знает ревизий v2 и может перезаписать их. Удаление слота необратимо средствами UI.

## Приёмка (не выполнена в Roblox в рамках патча)

1. Сохранённый v1 (XP/Gold/позиция/цвета) → новый выбор; создать второй слот и проверить исходный. Сохранить и перезайти, сравнить оба.
2. Создать двух персонажей одного пола с разной внешностью; стрелки меняют конкретный ID и превью. Вход/выход через Settings → Character сохраняет только активный слот, не позволяет сменить в бою.
3. Заполнить пять слотов, проверить запрет шестого; удалить с отменой, затем подтвердить; удалить последний, создать заново. Проверить закрытый экран выбора при недоступном превью.
4. Подтвердить независимость XP/Gold/позиции, общую палитру/язык; повторный вход. Проверить сетевую ошибку и конкурентные записи; удалённый ID не восстанавливается.
5. PC и мобильный DEV Runtime: Rojo Sync в авторском Place → новый source rbxlx → Preflight → Runtime Draft → публикация DEV. Проверить безопасные области, читаемость кнопок, отсутствие второго аватара и запуск с Character Creation OFF.
