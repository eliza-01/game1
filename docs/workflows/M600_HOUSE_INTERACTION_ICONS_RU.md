# M600 — дверь, замок, имя NPC

- E — дверь, если незаперта и ретикл попал по полотну внутри USE-радиуса ручки. F — навесить замок на закрытую дверь; E на установленном замке — снять. Иконка показывает текущее состояние, сервер подтверждает его. Сообщения об отказе остаются. Состояние двери не меняется клиентом.
- Один общий raycast для ближайших допустимых дверей на прежнем 10 Hz обновлении UI; повтор при нажатии. Вне зоны USE нет луча. Прочие взаимодействия не изменены. В Runtime визуальный MeshPart связан с серверным proxy через слабый индекс; невидимый proxy не заменяет визуальный hit. Roblox raycast использует CollisionFidelity, не точное пересечение треугольников. Визуальные части временно участвуют в запросе только в синхронной функции, их исходный CanQuery восстанавливается. Сервер проверяет сокет, действие, дистанцию и cooldown, но не доверенный ракурс камеры (это клиентская презентация).
- SVG и PNG: `assets/ui/house-interaction`. RGBA из SVG встроены в `HouseInteractionIconData`; `HudSvgIcons` (с M605) создаёт до четырёх house EditableImage на клиент по требованию. Если Mesh/Image APIs запрещены в Experience или недоступна память, предусмотрены символы без текста. Для гарантированной оригинальной графики при отключённых API опубликовать четыре PNG в Roblox и вписать полученные ID в `published` модуля `HudSvgIcons` (с M605). ID намеренно не выдуманы.
- Только имя NPC в HealthBarView проходит форматирование без цифр. Игровые идентификаторы, данные, уровень и имена монстров не меняются.

Приёмка в Studio и опубликованном DEV: снять/навесить замок, открыть/закрыть дверь с обеих сторон, отвернуть камеру, выйти из USE, проверить открытое полотно и streaming FULL/LOD1, иконки на мобильном, NPC Guard 01/02 → Guard. Проверить права Mesh/Image APIs или опубликовать PNG. Проверить, что лифт, сундук, костёр и боевые лучи работают как прежде.
