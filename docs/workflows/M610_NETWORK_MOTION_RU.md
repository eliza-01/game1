# M610 · Network Motion — первый сценарий Performance Profiler

Пользователь наблюдает у удалённого игрока периодическое ускорение/замедление при ровном беге; собственное движение и анимации плавны. Network ownership на десяти серверных снимках корректен, root и visual проходят одинаковую дистанцию. Это не доказывает линейность скорости. Нативная интерполяция — гипотеза, не установленная причина. Не вводить вторую систему движения до диагностики.

## Запуск

1. Два клиента Studio или опубликованный разрешённый DEV; на телефоне открыть иконку камеры → Network motion.
2. Выбрать другого игрока (переключатель Target также позволяет self), на расстоянии до 160 studs. Нажать Record 8s, другой игрок начинает ровный бег по прямой на ровной поверхности. Окно стартует через 2.5 с по серверному времени, длится 8 с.
3. Сохранить скриншот результата или строку `[NETMOTION]` из клиентского Output. Повторить self на клиенте бегущего игрока в той же сцене. Не менять настройки графики/сети между прогонами.

## Метрики и границы

- Position: скорость горизонтального изменения `NavigationRoot.Position` / фактический dt. На клиенте это доступное состояние движка, не сырой сетевой пакет.
- Render: скорость горизонтального изменения `GetRenderCFrame().Position` / dt, только клиент.
- Velocity: горизонтальный модуль `AssemblyLinearVelocity`; это не измерение фактического пути.
- Mean взвешен по времени; p05/p95 — процентили измеренных кадров. Frame p95/max в ms; fps вычисляется из длительности и количества samples. Полусекундные bins, timestamp и остановки при velocity ≥ 2 включены в JSON. Интервалы начала/остановки и повороты влияют на показатели, поэтому нужен прямой равномерный бег. Сравнивать фактическое окно timestamps; при неполном окне повторить запись. Отдельный self-замер не синхронен с первым.
- Один клиентский запрос, start/result от сервера; без передачи координат по новым сетевым событиям. Строго Debug access, максимум две активные серверные сессии, cooldown 12 с, 2048 samples. Client RenderStepped и server Heartbeat только во время записи; серверная сессия завершается по дедлайну, даже если клиент закрыл окно. Debug OFF — нет измерительного цикла, обычный release не создаёт сервис. UI открывается из существующей иконки камеры.
- Не измеряет сырые physics packets, GPU или network ownership history; не исправляет движение. Полный profiler, реальные baseline и диагноз остаются открыты в KBN-0035.
