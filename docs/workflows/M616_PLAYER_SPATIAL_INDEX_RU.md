# M616 · Player Spatial Index

База M615. Цель: исключить полный перебор игроков на каждом Aggro scan, сохранив механику преследования.

## M616 · Player Spatial Index

- PlayerSpatialIndex / PlayerSpatialGrid: двумерный broad phase XZ, размер ячейки 32 studs (внутренняя константа, не радиус агро). Ленивый снимок при первом запросе в синхронном пакете ActorAIScheduler; за пределами пакета — свежий снимок. Нет новых физических объектов или Heartbeat. Большие радиусы перебирают только занятые ячейки, не бесконечную сетку.
- ActorTargetRoot сохраняет RootCollider → HumanoidRootPart → PrimaryPart; CanQuery не требуется. Точные проверки живого персонажа, горизонтальной дистанции, территории, Isolation, порядок равных дистанций по GetPlayers остаются у существующей policy. NPC остаются retaliation-only.
- Инвалидация при смене персонажа, входе/выходе игрока, GameplayTestArena.Warp, HouseElevator и HouseSocket teleport. Любые будущие синхронные переносы/замены root внутри одного пакета обязаны вызвать Invalidate; физические позиции обновляются при следующем пакете. Эталон сравнивается для одного снимка, Studio/DEV межкадровая приёмка открыта.
- M615 intervals 0,1/0,3 с, навигация, удержание цели, урон, прыжки, BlockedWait и HomeRecall неизменны. 1200 сравнений с полным перебором в Lua-модели; проверены границы клеток, tie order, разные этажи, допустимость, respawn/warp, очистка снимка. Замеры CPU и реальная физика открыты. Следующее: Adaptive AI LOD (только неактивные), затем ComputeAsync budget (Legacy/NPC).

## Приёмка и границы

- Проверить несколько игроков, одинаковую дистанцию, разные этажи, границу Aggro, изоляцию GP, перемещение/смену персонажа, house elevator и возврат. Сравнить выбранные цели и MONNAV до/после. NPC — только ответный бой.
- При одном запросе в кадре или малом числе игроков построение grid может стоить дороже прежнего обхода; не считать уменьшение кандидатов гарантией CPU-выигрыша. Проверить несколько численностей игроков/монстров; стоимость snapshot и sorting включить в измерения.
- M614 NativePartSpatialIndex не переиспользован как 3D-запрос: его конечная высота и CanQuery меняли бы контракт Aggro. Не создавать дублирующие боевые индексы или новые Parts.
- Откат M616: reverse patch или Git; схема данных/Options не меняется. Следующий этап AI LOD только после статической регрессии, runtime-приёмка остаётся обязательной.
