# M624 · Runtime LOD — приёмка и диагностический отчёт

База M623. Критерий KBN-0037-T03/A03 остаётся открытым. Этот патч добавляет инструмент сбора фактических данных и исправляет teardown Studio Preview, но не заменяет игровую приёмку. Рабочие пороги, manifest, серверные коллайдеры, механики и публикации ассетов не изменены.

## Как снять отчёт

1. Studio Authoring: проверить LOD Preview при Play, смену профиля и остановку. Обычный Authoring без Runtime Manifest не записывается новым инструментом.
2. Собрать отдельный Runtime draft через существующие Scan Place → Save to File (.rbxlx) → Preflight → Prepare Runtime. Не перепубликовывать модели/атласы. Проверить Studio Play с Runtime Manifest и отсутствие ошибок `[game1][LOD]`; затем опубликовать в DEV. Не заменять рабочий Production.
3. В Studio Runtime или опубликованном DEV (с разрешёнными Published Debug Controls для своего устройства и авторизацией владельца) открыть новый значок **LOD diagnostics** (столбики) в существующем debug dock. Нажать **Start capture**, закрыть панель её значком, выполнить один сценарий, снова открыть и нажать **Stop capture**. Панель содержит читаемые результаты, client Output — одну строку `[game1][LOD][capture] {JSON}`. В DEV на телефоне можно использовать скриншоты панели. Никакого GP/test hub в обычном Runtime и никаких новых RemoteEvents. Сбор по умолчанию выключен.
4. Для сравнения отдельно снять одинаковый маршрут на M625 и baseline до M619 (M618; отдельная копия, не откатывать DEV). У старой базы нет этого инструмента: сравнивать FPS/CPU/RAM и MicroProfiler одинаковыми внешними средствами, не сравнивать недоступные baseline-счётчики. Первый прогон — прогрев/нативная репликация, повторные — измерение. Для PC и физического телефона записать устройство, настройки качества, snapshot, Place/версию, число игроков, положение/маршрут, продолжительность, профиль off/full/lod1/lod2. Сравнивать одинаковый контент, не смешивать warm/cold и разные устройства. Отдельно проверять с выключенным capture, поскольку он имеет собственную стоимость.

## Как читать показатели

- `placements` — Location placements + независимые части домов. `visible` — запись с принадлежащей ей геометрией в Workspace, не GPU visibility. `localCandidates` и `queued` — gauges на момент Stop; `queueSize`, `stagingInstances`, `pendingAsync`, `retiredBundles` — peaks. `queueAgeMs` — максимум возраста заявок, созданных после Start (на observations); старые заявки учитываются в размере очереди, но не в latency. `stagingInstances` считает явные owned Instance (включая container/weld), не все дочерние SurfaceAppearance/Bone.
- `distanceResolves` — реальные вызовы threshold Policy при observation; `workDistanceChecks` — отдельная точная проверка queued/active work перед сборкой/commit. `localSorts` — действительные сортировки двух и более pending entries, не сортировка BVH при старте. `spatialQueries` — повторные BVH queries при смене камеры/позиции. `candidateVisits`, `taggedVisualVisits` показывают оставшиеся обходы. M625: `compositePathEvents` — совпавшие события пути; `compositeRootChanges` — bind/unbind; `compositeDiscoveryVisits` — разовое обнаружение descendants при bind; `compositeEffectEvents` — добавление/удаление эффекта или наблюдаемое внешнее включение скрытого эффекта; `compositeEffectVisits` — обход кэшированных эффектов конкретной записи при actual transition; `compositeEffectWrites` — реальные изменения Enabled. Старый `compositeVisits` удалён. События вне Heartbeat не входят в `callbackElapsedMs`.
- `prototypeRefreshes`, `contractChecks`, `retryScans` — разница существующих cache counters между Start/Stop. Никакого полного подсчёта cache каждый кадр. `meshClones` — явные вызовы Clone для MeshPart в job, не число потомков; `weldCreates`/`weldBindings` — явные runtime proxy joints; `cleanupUnits` — вызовы Destroy из bounded retirement (не рекурсивные потомки). `asyncStarts`, `asyncFailures`, `asyncDiscards` — FULL acquisition; raw stale result disposal учитывается отдельно, не в work units. `retryableAttempts` включает нормальный FULL pending / backoff / отсутствующий proxy; это не обязательно ошибка. `failedAttempts` и `staleJobCancels` отличаются от общей отмены.
- `heartbeatMs` — dt Heartbeat; это не render FPS или CPU time. `callbackElapsedMs` — измеренное os.clock время существующего LOD callback до записи frame sample (включая текущие наблюдения, moving/effects и часть стоимости диагностики); не CPU всего клиента. `queueResidenceMs` — от создания текущей заявки до её успешного commit, без reset при aging retry. `desiredToActualMs` — от наблюдённой смены desired в capture до commit соответствующего actual; fallback, незавершённые заявки и уже pending до Start не дают фиктивных latency. `count=0` означает нет наблюдений. Память — client Stats total MB на границах capture, если API доступен.
- На распределение хранится максимум 12 000 первых samples; `sampled` показывает охват. Mean/max учитывают все события, p50/p95/p99 — сохранённые samples. Для сравнения использовать короткие 30–60-секундные captures, проверять `sampled == count`. Отчёт не отправляется на сервер и не сохраняется в DB. Отключение/Stop не оставляет второй scheduler.
- Для CPU/frame time, render FPS, RAM/spikes использовать стандартные Roblox Performance Stats / MicroProfiler и одинаковые условия. Никаких процентов ускорения до фактических A/B. Если counters нулевые, но видимые проблемы или CPU spikes остались, не считать приёмку пройденной.

## Открытые вопросы

M625: проверить поздний stream-in root и отдельных эффектов в состоянии UNLOADED, FULL и reduced LOD, включённые/выключенные исходные эффекты, смену actual при неготовой сборке, повторный stream-out/in родительской папки и Stop/Start. Свет/дым не должны оставаться у выгруженной геометрии; выключенный авторский эффект не должен включаться при приближении. Не переименовывать скомпилированные технические пути в Runtime. Динамическое внешнее выключение уже скрытого Enabled=false не наблюдаемо без отдельного authoritative state; не использовать этот механизм для нового динамического управления эффектами. House/мельницы не изменены. Порционный Studio Preview отложен владельцем; tagged visual distance pass остаётся отдельным. Реальные Studio/DEV/PC/Mobile/двухклиентская и нагрузочная проверки открыты. Не отмечать T03/A03/A06 PASS без evidence.

## M626 · Короткая проверка на реальном телефоне

Владелец M625: опубликованная игра работает без заметного ухудшения; наблюдение на слабом телефоне — дальние дома появлялись раньше ближних частей забора. Полная матрица выше остаётся справочной и отложена; не требуется для следующего обычного входа. После M626 достаточно войти в игру и посмотреть, догружается ли окружение от персонажа наружу. При возможности повторить обычный respawn. Не требуется генерировать сотни объектов или записывать отчёт. `nearBandObservations` — число observations с открытым ближайшим кольцом; peak `priorityBand` — максимальный индекс такого кольца (0 = 0–32 studs). Таймаут 4 s без прогресса допускает дальние сборки при недоступной зависимости. Фактический порядок отрисовки native Roblox, включая текстуры, не гарантируется.
