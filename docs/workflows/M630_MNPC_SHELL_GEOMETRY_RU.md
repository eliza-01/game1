# M630 · MNPC Shell Geometry — M628, шаг 3

База M629 (fresh dump 2026-11-28_05-08-35 + M628 + M629). Действующее ТЗ: [MNPC](MNPC_LOD_SPEC_RU.md), KBN-0037-T08/A07 открыты.

## Реализовано

- Один общий `actor/MnpcRigGeometry` читает rest-геометрию опубликованного ServerStorage template без clone. Кэш по identity Instance (weak keys); immutable runtime template — контракт, замена Instance даёт новую ревизию, для контролируемого изменения на месте есть `Invalidate`. Кэш хранит CFrame/Size исходных деталей и pivot; для каждого spawn рассчитывается точный AABB при заданном yaw, ground alignment и локальные offsets относительно navigation root. Не кэшируется AABB от другого угла поворота. Сохранено различие ground bounds: Monster — wrapper, NPC — ImportedRig. Нет guessed bounds, нового Heartbeat или remotes.
- `MnpcEntityLifecycle.PrepareShell` создаёт существующий тип технического query RootCollider через `MnpcNavigationShell.CreateQueryCollider`, до `Clone` и независимо от ImportedRig. Shell остаётся неуязвимым (`Damageable=false`, `Game1MnpcRigReady=false`, RootCollider.CanQuery=false); физический HumanoidRootPart/коллизия не изменены. План привязан к entity root, collider, виду и identity/ревизии template. Prepared shell допускает публикацию без visual. `MnpcVisualRig.Attach` использует текущий root CFrame и сохранённый pivot offset, не PivotTo entity/root. Повторное/чужое подключение и stale plan отклоняются, clone failure не делает shell damageable. Существующий collider переиспользуется; VisualRootWeld (включая caster Weld) создаётся только при attach, затем включается CanQuery. Боевые OBB по-прежнему создаёт EntityHitboxService отдельно. Нет изменения combat math.
- Оба production spawner используют один API PrepareShell → AttachRig. Для пустых bounds или non-archivable template/subtree план недоступен: явно сохранён FULL путь расчёта по подготовленному clone, общий алгоритм bounds; такой тип ещё не готов к shell-only. Никакой новой фиктивной геометрии. Production пока по-прежнему выполняет AttachRig сразу, до Publish. Это подготовка к demand lifecycle, а не включение невидимых живых сущностей.

## Проверка и границы

`test_m628_mnpc_entity_foundation.py` исполняет общую реализацию через Lua double (translation/yaw): прежние fixtures плюс 20 сценариев (Monster/NPC × wrapped/unwrapped × 5 yaw), сравнение bounds с FULL путём, zero clone до publish, движение/поворот root до attach, сохранение identity collider, invalidation/stale rejection, clone failure; weld follow эмулируется вручную, не проверяет engine physics. `test_m630_mnpc_shell_geometry.py` проверяет production entrypoints, порядок и query gate. Native Studio, реальные Gremlin/Guard, rise/caster и A07 остаются NOT_RUN. Кэш предполагает неизменяемые runtime source templates; live mutation требует явного invalidation/reprepare, не обещана автоматическая поддержка изменений источника в Play.

Только затем включить shell-only production по потребности и индивидуальный MNPC LOD. До этого момента FULL сохранён для gameplay, нет заявленного прироста FPS. T08 не закрывать.
