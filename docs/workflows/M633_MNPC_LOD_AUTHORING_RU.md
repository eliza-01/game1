# M633 · MNPC LOD Manager — authoring foundation

## Реализовано

В Asset Manager → LOD Manager появилась вкладка MNPC. Один `MnpcLodResource` для Monster и NPC, identity `(kind, slug)`; данные берутся из действующих MonsterStore/NpcStore, NPC equipment и WeaponStore. Без Place Scan, без нового scanner/asset manager. Фильтр All/Monsters/NPC и последняя вкладка сохраняются. Настройки FULL/Unload/hysteresis наследуются от общего MNPC профиля, индивидуальный override сохраняется независимо от публикации. Defaults OFF, 100/200/10 studs — авторские значения, не пороги серверного demand M632.

M633 реализует первый проверяемый путь authoring: **подготовленный статический FBX и запечённая PNG/JPEG текстура**. Автоматический bake idle, объединение visible частей/экипировки, decimation и texture bake ещё не реализованы. Это не заменяется копированием FULL, export rest-pose или фиктивным Generate. Следующий шаг — автоматизация подготовки с проверкой материала, позы и variant identity. Native Blender и реальные FULL source meshes в текущей диагностической среде отсутствуют.

## Контракт

- Имя файла `<slug>_lod1.fbx`, внутри один mesh `lod1`, без armature, skin weights, shape keys, modifiers; одна UV map, не более одного material. Blender проверяет количество вершин/треугольников и scene bounds. Ограничение 20000 vertices/triangles — защитный authoring cap, не цель качества и не гарантия Roblox import. Готовая текстура PNG/JPEG до 4096×4096, 20 MB. Idle pose, соответствие FULL внешнему виду и root-relative Roblox alignment ещё требуют проверки; FBX scene bounds не объявляются координатами Roblox studs.
- `mnpc_lod1`, `mnpc_lod1_history`, `mnpc_lod_settings` — additive schema в существующей `.control-center/game1.db` с online backup при первом создании. FBX immutable под `assets/source/mnpc-lod/<kind>/<slug>/<sha>/`, старые ревизии не стираются. Текстура принадлежит существующему AtlasRegistry (content-addressed family, shared publication dedup); не отдельный atlas catalog. LOD pin содержит variant ID + sha и опубликованный Image ID, не меняет FULL atlas binding. В authoring изменение/retirement этого atlas pin помечает ресурс stale, а не автоматически подменяет изображение. До runtime export необходимо включить MNPC pins в правила shared atlas lifecycle/audit; текущая история принадлежит доменному ресурсу.
- FULL fingerprint включает Model ID, source SHA, публикационный pipeline, texture slots/atlas, NPC equipment hand identities и visual revision оружия. Metadata/HP/AI revision не инвалидируют геометрию сами по себе. Несовместимые/неопубликованные FULL или оружие блокируют staging. Staging CAS проверяет revision и актуальный fingerprint; изменение FULL/texture/file после staging отражается статусом stale. Один текущий authored вариант на тип, не на spawn. Нестандартные runtime варианты не считаются покрытыми.
- Publish: shared AtlasRegistry.ensure_published → immutable Image ID → общий model_lod_common.publish_geometry geometry-only → FBX roundtrip static one mesh → Model ID. Сохраняются этапы и partial result. Upload intent фиксируется до Model POST, operation path сразу после; при известной незавершённой операции Resume продолжает её, не создаёт новую. Явный terminal rejection операции освобождает intent. Если POST прервался до получения operation path, retry блокируется: нужен разбор операции, автоматическое восстановление неизвестного ID не реализовано. Atlas pending использует действующий контракт AtlasRegistry. Не обещать moderation/Studio import по одному Model ID.
- HTTP JSON schemaVersion=1: GET `/api/lod-manager/mnpc`, GET `.../{kind}/{slug}/history`; POST `.../settings`, `.../{kind}/{slug}/stage`, `.../{kind}/{slug}/publish`. Settings global CAS, stage/publish domain resource CAS. UI использует существующие file pickers и request transport. JSON view вычисляется из текущих реестров, не генерирует Luau/Place manifest: `runtimeEnabled=false`, `runtimeReady=false` всегда до фактического native import/alignment. Model ID не является Mesh ID.

## Открыто

Автоматическая генерация из опубликованной FULL конфигурации и проверка Blender на реальных ресурсах; проверка одного Monster + одного NPC в Studio после публикации, реальный MeshPart ID и root-relative alignment; версионированный Runtime export/consumers, shared atlas audit/retirement integration, индивидуальный клиентский FULL/LOD1/UNLOADED, production shell-only / combat reach / native isolation. Никаких изменений Runtime или M632 pilot, A07 NOT_RUN.
