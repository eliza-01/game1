# M636 · MNPC Geometry & Atlas Bake

Статус: код и host/SQLite/Pillow/JS проверки; native Studio/Blender/Open Cloud NOT_RUN. Общий authoring для Monster и NPC. Игровой Runtime остаётся FULL; M632 pilot default OFF. OBB, AI и репликация не изменены.

## Workflow

1. В Studio Edit синхронизировать текущие Rojo, Game1Bridge, FULL Model + Atlas и зарегистрированное оружие. Открыть LOD Manager → MNPC → Edit → Capture idle & geometry. M635 выбирает полный авторский ключ idle около фазы 0.35 и собирает временный клон. M636 читает фактические MeshContent через AssetService:CreateEditableMeshAsync, все веса, bind CFrame и UV каждого угла треугольника. Вычисляет позу в системе координат навигационного корня (studs, Y up), освобождает EditableMesh и временный clone. Кэш снимка атомарный, identity FULL/equipment/idle + SHA. Старые снимки M635 без topology доступны как metadata, но не подходят для bake — повторить захват. Никаких изменений Workspace.
2. Bake & stage LOD1: по умолчанию ≤1000 треугольников, атлас 512². Host разрешает только зарегистрированные локальные texture bytes соответствующего owner и asset ID, проверяет SHA-256. Общая упаковка цветовых текстур тела/экипировки, дедупликация одинаковых bytes+tint, edge padding 2 px, сохранение UV seams и alpha; solid color swatch для нетекстурированного меша. В Blender координаты (x,-z,y), UV от Roblox top-left к Blender bottom-left. Общий M634 finish/decimate/export и M633 FBX round-trip inspector; результат один `lod1`, одна UV, без rig/weights/animation. Stage через M633 / Atlas Registry; повтор с идентичными bytes и recipe не увеличивает revision. Исходники FULL не перезаписываются. Проверка idle/FULL/texture/capture после worker, предыдущий LOD сохраняется при ошибке. Публикация отдельной кнопкой.
3. Publish LOD1 через прежний Open Cloud pipeline: captured_idle recipe хранит idleFingerprint; при изменении idle статус IDLE_CHANGED, повторный upload блокируется. Pending Cloud operation восстанавливается даже если FULL/idle изменились. Опубликованный Model ID не является Mesh ID.

## Ограничения и gates

- M635 authored keyframe, не Animator blend/интерполяция. Skinning использует все веса с масштабированным bind (как геометрический контракт HitboxDefinitionBuilder, без изменения OBB); неоднозначные/отсутствующие bones, несовпадение rest bind (>0.05 studs / 2°) отклоняются. Реальная корректность `EditableMesh` skinning, UV orientation и положения относительно root на Gremlin/Guard должна быть подтверждена в Studio. FBX unit scale и pivot/size после импорта не считаются проверенными.
- Лимит 64 видимых MeshParts, 30000 input triangles, 1.9 MB bridge JSON, 110 s geometry capture, 120 s Blender. Превышение выдаёт ошибку без обрезания. Нет chunking; крупные варианты пока могут не проходить. Source texture PNG/JPEG/WEBP ≤4096², до 20 MB. UV только [0,1]. Частичная прозрачность MeshPart, цветные vertex colors/alpha, SurfaceAppearance Overlay с alpha и неподдерживаемые меши не bake автоматически; ручной статический M633/M634 import остаётся штатным fallback. PBR normal/roughness/metalness, особенности Material и освещение не запекаются: это упрощённый color LOD; native appearance review обязателен. Авторские нормали не экспортируются, Blender пересчитывает smooth normals. Atlas resize/decimation — приближения, не гарантия идентичности.
- Нативный Studio/Blender импорт, визуальная сверка позы и UV, публикация и разрешение MeshPart ID/root alignment — следующий этап M637. Только затем runtime export/client transitions и strict native carrier isolation. Производственный MNPC LOD и A07 не закрыты. Не заявлять экономию FPS на этом авторском этапе.
