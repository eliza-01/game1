# M639 · MNPC Runtime demand / qualified shell-only spawn

Владелец просит закончить Runtime без готовых LOD1. M638 red dummy и все три клиентских стадии сохраняются, authoring pipeline не изменён. M639 завершает код общего серверного demand path для обоих типов, но НЕ объявляет строгую изоляцию native Animator или нативную боевую приёмку выполненными.

## Режим и контракт

- M640: **Options → MNPC LOD → Server rig demand (Monster + NPC) → Save MNPC LOD**. Единственный источник `assets/manifests/options.json` (`mnpcDemand.enabled`) → generated `GameOptionsRegistry` → `GameOptions.MnpcDemandEnabled()` на сервере. Default OFF, прежний Workspace attribute больше не читается; при переходе с M639 один раз включить в Options. После Save выполнить Rojo Sync и перезапустить Play; для опубликованной игры опубликовать Place и запустить новый сервер. При OFF сохраняется визуальный M638, серверная выгрузка отключена. Нативная reattachment/teleport acceptance пока открыта.
- Общий серверный порог прогрева: max(FULL + hysteresis, максимальная дальность зарегистрированного оружия + половина диагонали RootCollider + 8, авторские aggro/attack радиусы) + 48 studs. В Studio/DEV с доступными debug overrides вместо каталожной дальности — MaxAimDistance 420. Освобождение требует ещё +32 studs и непрерывно 5 s без потребности. Консервативная горизонтальная дистанция по всем игрокам. Explicit OFF profile, активный бой/статусы/recovery/return/spawn и GP test исключают освобождение. Это запас, не гарантия готовности при произвольном телепорте/быстром движении.
- Стадии `full / shell / loading / preparing / full`; `Damageable` false и отсутствуют OBB bindings, Animator, rig lease у sleeping shell. Технический root, collider, Humanoid, HP, AI, spawn slot остаются. На первом успешном FULL соответствующего типа/шаблона, после подтверждения готовности и отсутствия потребности, общий owner кэширует квалификацию. Только последующие дальние спавны этого типа допускают initial shell-only; GP и Monster rise-from-ground сохраняют исходную первую визуальную сборку, а неподдержанные/нестабильные rig/loadout остаются FULL. Нет подмены геометрии боя.
- Восстановление через существующий AI scheduler / PlayerSpatialIndex; один общий admission slot, pending candidates сравниваются по расстоянию, повторная проверка актуальности перед стартом. Нет нового Heartbeat, remote, global sort или per-actor timer. Retry 5 s, timeout готовности 15 s после возврата acquire, нативный yielding вызов не отменяется насильно. Клиентская маска/observer не восстанавливают FULL во время `loading/preparing`: сохраняется placeholder до `full` и `Game1MnpcRigReady`. Строгая атомарность нативной репликации не доказана.

## Не закрыто

- Roblox instance streaming / PersistentPerPlayer не дают жёсткого индивидуального порога для репликации native Animator: nonpersistent clients всё ещё получают Atomic model в пределах streaming. Animator.EvaluationThrottled — read-only. M627 уже подтвердил: при реплицированном скелете без визуального меша кости продолжают двигаться, вне Workspace серверный native pose не обновляется. Не удаляем клиентские реплики Animator и не меняем OBB/боевую математику. Если другой игрок активирует FULL, дальний клиент может всё ещё получать и вычислять native skeleton. См. Creator Hub: https://create.roblox.com/docs/reference/engine/classes/Animator и https://create.roblox.com/docs/workspace/streaming . Строгое LOD1 zero native evaluation потребует отдельного доказанного решения; не выдавать visual LOD за этот результат.
- Нативное восстановление рига, движение shell, смена экипировки, спавн/телепорт непосредственно в боевой радиус и два клиента не проверены. До native acceptance не включать demand по умолчанию в production. Во время прогрева возможен красный placeholder и недоступность попаданий: существующие hitbox/pose readiness gates не снимаются. Для disabled demand прежний боевой путь сохранён. A07/T08 остаются открыты; не начинать очередные оптимизации/переписывание боя ради формальной галочки. Пользователь не обязан готовить реальные LOD1 или проводить стресс-тесты.

## Проверки

Lua doubles двух режимов (catalog/debug reach), shared qualification/initial shell, near-first admission, two domain requests, hold, pins, disabled profile, rollback/retry/timeout/cancel, M638 dummy до full readiness; source contracts обеих spawn веток и общего scheduler. Это не Roblox Studio/DEV/mobile native acceptance и не измерение FPS.
