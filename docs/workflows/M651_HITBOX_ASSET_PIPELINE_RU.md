# M651 · Hitbox Asset Pipeline — MNPC authoring

База M650. KBN-0039-T02: код Studio/Edit pipeline готов, реальные captures и приёмка открыты. M650 пользователь попросил продолжить, это не самостоятельное подтверждение near-first на телефоне. M648 native acceptance также открыта. M649 combat smoke принят владельцем.

## Авторинг

1. Установить патч и Game1Bridge, синхронизировать Rojo; открыть Studio в Edit (не Play), актуальный Place с синхронизированными FULL Model + Atlas. При необходимости после обновления модулей перезапустить Studio, чтобы избежать кэшированных require.
2. Asset Manager → LOD Manager → MNPC → `Capture all FULL hitboxes · Studio`. Пакет выполняет существующие локальные authenticated bridge команды последовательно, по одной публикации; ошибки отдельных ассетов явно выводятся, успешные записи сохраняются. Для отдельной модели открыть MNPC editor → Combat hitboxes · FULL → `Capture hitboxes · Studio`.
3. Не требуется LOD1, FBX, публикация или запуск AI. Патч не содержит придуманных bounds. Generated `src/server/combat/HitboxAssetRegistry.luau` сохраняется атомарно и синхронизируется Rojo; дождаться синхронизации перед новым Play. Реестр — файл проекта, его надо сохранить вместе с изменениями проекта. Захват повторять после смены опубликованного FULL/сборки; устаревшие подписи безопасно не совпадут. Автоматического запуска при Publish пока нет.
4. Проверить обычный ближний бой/лук/Headshot, respawn и shell → FULL. В Studio server Explorer на живой сущности `CombatHitboxDefinitionSource = asset` означает готовую запись; `runtime_migration` означает miss, `session` — прежний session cache, `root_bounds_fallback` — прежний permission fallback. Это диагностика coverage, не замер. Не считать «capture succeeded» доказанным runtime hit.

## Архитектура и v2

Новый `StudioHitboxAssetCapture` использует реальные опубликованные шаблоны (проверка Model ID), `MnpcEntityLifecycle.Create/PrepareShell/AttachRig`, `MonsterRigBuilder.EnsureRuntimeAnimationRoot`, NPC `NpcEquipmentService.Resolve/Equip` и `NpcAnimationRigBinding.Align`. Entity остаётся detached, collision-group setup выключен только для явно authoring shell в Studio Edit. Не публикуются модели и не регистрируются боевые bindings; временная сборка уничтожается даже при ошибке. Обычный спавн по-прежнему использует прежний физический контракт. Не применяется idle pose или LOD1 geometry. Путь авторинга вызывает `EntityHitboxService.CaptureAsset` с общим построением binding/leases и свежим `HitboxDefinitionBuilder.BuildUncached`, не session cache. Permission/fallback capture запрещён. Повтор authoring может заново запросить ранее failed geometry. `HitboxAssetDefinitions.AuthoringRow` проверяет JSON encode/decode production decoder и совпадение локальных размеров/центров/anchor и метаданных. Нативный запуск этой проверки пока NOT_RUN.

M649 v1 использовал root-relative frames и world-axis AABB sizes, которые зависят от yaw. v2 использует отдельный `AssetKey` с теми же mesh paths/IDs/scale/identity/head mapping, но без размеров AABB (они не участвуют в точном oracle, только в прежнем session key и fallback). Signature относительно первого mesh frame: относительные mesh/bone transforms, пути/выбранные bone mappings, фактические root center/up в том же базисе; шаг квантования 0.0001 как M649. Это устраняет зависимость от глобального поворота при том же относительном центре и вертикали; асимметричные сборки с изменившимся AABB center, GP/rise/pose могут не совпасть. Не обещаем полного покрытия случайных yaw. Не переносить bounds на несовпадающую сигнатуру и не менять существующую геометрию коллайдеров ради hit rate. Старый session key/порядок lookup сохраняются. Схема v2 заменяет v1, ранее экспортированные v1 captures требуется переснять (в M649 поставлялся пустой registry). `HitboxAssetRegistry.luau` в поставке пустой, никаких нативных данных в диагностическом дампе нет. При наличии ранее вручную изменённого v1 registry сохранить его отдельно, не перезаписывать force.

Control Center `hitbox_asset_authoring.py` проверяет FULL fingerprint до и после, опубликованный model ID, owner identity и валидирует результат существующим compiler. Existing `mnpc_capture_bridge.request_studio` — общий локальный транспорт, не новый runtime RemoteEvent. 110 s timeout на один offline capture, лимит bridge 1.9 MB, registry merge atomically, конфликт не перезаписывается. Без фоновых циклов в игре, без нового manifest/DB schema. Устаревшие записи пока не удаляются автоматически, строгий lookup исключает их использование. Для Character assembly variants остаётся существующий Studio Play capture API/CLI с новым форматом; автоматизированная миграция вариативных персонажей и доказательства coverage нужны отдельно. До полной миграции сохраняем Runtime EditableMesh miss и permission fallback, чтобы не ломать попадания.
