# M358 · Melee Arc Combat — проверка в Studio

## Назначение

Сервер рассчитывает пересечение дуги с боевыми OBB целей. Дуга ориентирована на горизонтальный `RootCollider.CFrame.LookVector`. По умолчанию ширина 108°, дальность берётся из настройки оружия. Высота — размер `RootCollider` ± 1.5 studs. Временное окно `HitStart/HitEnd` определяется существующей анимацией. Одна цель — один удар за окно, но целей может быть несколько. Сервер проверяет стены и использует точный луч наведения только для Headshot цели, уже вошедшей в дугу.

Старая ветка `WeaponAttackVolume` и `WeaponEnvironmentCollision` сохранена **только как LEGACY · DO NOT USE**: никакого runtime/fallback. Лук не изменён.

## Установка и верификация

- Выполнить профильные тесты `python -m unittest discover -s system/verify -p test_m358_melee_arc_combat.py -q`, `python system/studio-plugin/validate_luau.py`, `python system/verify/verify.py`.
- Перезапустить Control Center, затем синхронизировать Rojo.
- Выполнить `system/verify/studio_m358_melee_arc_smoke.luau` в Studio Command Bar с загруженным Rojo: ожидается 10/10.
- Открыть Test Loadout: `MELEE ARC` показывает дугу, вертикальные границы, луч прицела. `LEGACY VOLUME · DO NOT USE` не действует.
- В Asset Manager изменить Melee Arc Angle у **двух разных** оружий, например 60° и 180°, сохранив каждое; повторно синхронизировать Rojo. Убедиться, что диапазоны не совпадают и корректно переключаются при смене оружия.
- Проверить удар по 2–3 Training Dummy/монстрам внутри дуги и исключение тех, кто сзади/за стеной/над головой. Прицел на голове одного должен усиливать только его.
- Проверить 360° и персонажа другого масштаба; удар на Android/iOS и Studio Device Emulator.
- Проверить лук: ходьба, прицеливание вверх/вниз, попадания, Headshot, физика визуальной стрелы должны остаться прежними.

## Ограничения и безопасность

- Это исходный Git-патч, не подтверждённый реальными Roblox-симуляциями. Запретить публикацию Production до Studio и мобильного тестов.
- Сервер не принимает клиентские CFrame/Size оружия. От клиента передаются только намерение атаковать и прицельный луч, который валидируется и может усилить попадание, а не создать новую цель.
- Не использовать старые unit-тесты Weapon Volume для оценки нового контракта. Нужны проверки дуги/вертикали/Headshot/окклюзии в Studio.
