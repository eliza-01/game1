# M360 · HitEnd — единственная точка разрешения melee

## Владелец времени

- Asset Manager хранит авторскую длительность клипа и события. `HitEnd` — единственное событие, определяющее нанесение урона игроком; устаревший `HitStart` удалён из активного манифеста, Runtime Data и редактора таймлайнов.
- `AttackTimelineConfig.ResolveCharacterRuntime` вычисляет длительность действия по `AttackSpeed` и переводит нормализованное положение `HitEnd` во время от начала атаки. Скорость *визуального* трека при загрузке может изменяться для соответствия фактическому `AnimationTrack.Length`, но это не изменяет игровое время.
- При принятом сервером `AttackIntent` создаётся сессия/serial и один таймер `task.delay(hitEndEvent.time)`. На этом тике сервер читает актуальные позиции атакующего, хитбоксов, окружения и прицеливание и ровно один раз рассчитывает урон. Переносов на `HitStart`, середину окна и повторных сэмплов нет.
- Смерть, респавн, новое действие и отскок проверяются по текущей серверной сессии. Проверки геометрии не исполняются, пока не наступил `HitEnd`. При незагруженном визуальном треке игровой таймер всё равно срабатывает.

## Клиентская анимация

`CharacterAnimationController.PlayAction('attack')` начинает игровой временной интервал **до загрузки** прокси/трека и сразу возвращает метаданные. Верхний торс собирается в `task.spawn`. При опоздавшей загрузке клип ставится в положение прошедшего времени; при ошибке композиции урон не отменяется. Отскок при отсутствии готового трека не останавливает серверную отмену урона.

`AttackController` посылает `AttackIntent` один раз. Для необязательного headshot может отправить один свежий `MeleeAimUpdate` перед `HitEnd`; обычный урон не зависит от этой посылки. Лук сохраняет отдельное событие `Release`; монстры используют свой `Hit`. NPC в M360 не мигрированы на этот контракт: для них ещё существует fallback к `AnimationTrack.Length`, если их таймлайн отсутствует.

## Отладка и нагрузка

- Выключенные overlay Test Loadout отключают `RenderStepped` соединения полностью.
- Отрисовка сектора ограничена 15 Гц, цветных хитбоксов — 8 Гц; они никогда не влияют на серверный hit.
- Поиск целей отладки идёт через `CollectionService` тег `Game1CombatHitbox`, а не `Workspace:GetDescendants()`; визуализируются цели в радиусе 35 studs.
- Сервер делает один Arc-запрос за melee-атаку, а не 20 за секунду активного окна. Параметры Raycast препятствий создаются один раз на группу целей; учёт ранее поражённых целей внутри одной сессии удалён, поскольку каждая цель возвращается запросом единожды.

## Проверки в Studio

1. Установить анимацию с неверным Asset ID в тестовой ветке, оставить корректный `clipId` и его таймлайн. Атака должна нанести урон на `HitEnd` с предупреждением `visual unavailable; gameplay continues`.
2. Проверить один удар в сторону двух dummy: оба получают урон один раз только на `HitEnd`; цель за спиной не получает урон.
3. Подойти к зарегистрированной преграде без преследования и вызвать Weapon Bounce непосредственно на `HitEnd`. Урон отменяется, новая атака запрещена до окончания recovery.
4. Во время атаки умереть/сменить персонажа: отложенный урон не должен пройти.
5. Включить и выключить Test Loadout → MELEE ARC и TARGET HITBOXES. При выключенных оверлеях не должно быть работающих debug RenderStepped-подписок.
6. Сравнить MicroProfiler перед и после: CPU целиком и отдельное время `AttackService` при 10+ NPC / 10 игроках. Численных FPS/CPU результатов без Studio нет.
