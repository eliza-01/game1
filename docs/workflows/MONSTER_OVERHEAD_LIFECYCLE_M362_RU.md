# M362 · Monster overhead · восстановление после spawn/stream/respawn

## Граница ответственности

- **Server**: `MonsterSpawnerService`, `MonsterSpawnPresentation`, `MonsterAIService`, `MonsterCombatState`, `DamageService` — HP, `LifeState`, агрессия, смерть и новый Model после respawn. Не менялись.
- **Client**: `OverheadHealthController` владеет привязкой и видимостью; `HealthBarView` — только GUI, его смещением и обновлением HP. Изменены исключительно client и проверки.
- Для монстров HP и имя показываются **в радиусе** при наведении, мобильном захвате, агрессии в отношении данного игрока или явном Studio `All HP`. Дефолтно нейтральный монстр вне наведения скрыт. При `LifeState` не `Alive` скрыт. При `Return` сервер сбрасывает target, поэтому без наведения имя/HP закономерно исчезают.

## Исправленные failure modes

1. `PlayerGui` ещё нет, но Monster/RootCollider уже реплицированы: pending теперь переживает отсутствие GUI, общий PlayerGui listener пересоздаёт все текущие привязки после появления GUI.
2. `PlayerGui` заменён при respawn персонажа: старые `BillboardGui` удаляются, существующие монстры привязываются к новому GUI; фильтр Raycast обновляет исключаемого персонажа.
3. GUI или `RootCollider` исчезает при streaming/reset: `IsAttached` обнаруживает повреждённую привязку за ≤0,1 с и пересоздаёт; при отсутствии collider pending ждёт новое событие `ChildAdded` без таймаута.
4. Монстр появляется через fade/rise: оффсет подписи пересчитывается на `MonsterSpawning=false`, после восстановления прозрачности визуальных мешей.
5. Убит во время `Chase`/`Return`: старый Model отвязывается на `ChildRemoved`, новый после respawn получает новую View по событию `ChildAdded` без сохранения устаревшей агрессии/таргета.
6. Не создавать RaycastParams каждые 0,1 с, не Raycast при отсутствии monsterViews; длина луча зависит от выбранного радиуса (20–800), а не от фиксированных 420 studs; не переписывать неизменившиеся значения BillboardGui каждый тик.

## Обязательные Studio Play кейсы (PC + mobile)

1. Старт рядом со спавном: наведение до появления `RootCollider`, в период fade/rise и после завершения; после полного spawn имя/HP восстанавливаются без движения мыши.
2. Монстр атакует игрока; затем перестаёт получать урон игроком, возвращается домой. С наведением подпись видна, без наведения и без агрессии — скрыта по политике.
3. Убийство в `Idle`, `Chase`, `Attack`, `Return`, затем каждый respawn и повторное убийство. На трупе подписи нет, на новом живом экземпляре есть при наведении.
4. Два монстра одновременно, только один атакует игрока. Рядом с другим игроком должны показываться его целевые монстры, а не чужая агрессия.
5. StreamingEnabled: RootCollider выходит из stream и возвращается при сохранённом Model. Подпись восстанавливается, BillboardGui не дублируется.
6. Собственная смерть/respawn при существующих монстрах, без пересоздания монстров. Наведение и HP должны вернуться.
7. Радиус (внутри/снаружи), мобильный AutoAim и Studio All HP ON/OFF — без залипания после смерти и возвращения домой.
8. Проверка MicroProfiler/Instance count: `Game1OverheadHP` не накапливаются после 10 смертей/респавнов; в выключенном состоянии не создаются лишние лучевые запросы по пустому списку.
