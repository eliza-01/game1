# M184 · Real Estate · Положение независимых частей после Studio Sync

## Причина

У `house_level5_01.fbx` Mesh `house` и `door` принадлежат одной сцене,
но Roblox Model Assets публикуются по одному мешу. При независимой загрузке
MeshPart может получить собственный центр геометрии вместо общего смещения
в координатах дома. В исходном FBX центр геометрии двери относительно центра
дома составляет примерно `(2.447, -11.515, -7.488)` в Roblox-осях — отсюда
визуальное смещение приблизительно на 12 studs по одной из осей.

## Контракт

- Анализатор вычисляет bounds в **локальной системе меша `house`** с учётом
  мировой матрицы исходной сцены. Для осесогласованных частей фиксирует
  `authoredPlacement.version=1`, `centerInHouse`, `size` в Roblox-порядке осей.
  Вложенность ригов не меняется.
- Manifest сохраняется внутри уже существующего `skeleton_json` при
  **повторной регистрации исходного FBX**. Изменять таблицы SQLite не нужно.
- `RealEstateStudioSync` передаёт размещение в метаданных Studio Bridge,
  включая точечную синхронизацию отдельного меша.
- `StudioRealEstatePartPlacement` сравнивает импортированные размеры house и
  меша с сохранёнными авторскими размерами. Если масштаб или оси не совпали,
  синхронизация отказывает **до замены шаблона**, а не перемещает геометрию
  наугад. Поддерживается равномерный масштаб. Проверка не меняет позы костей.
- Положение восстанавливается с помощью `rig:PivotTo()` и разницы центров;
  поворот меша не трогается. Для двери это происходит **до** выставления
  `DoorAssembly.WorldPivot` по `door_01_hinge_socket`.
- Старые записи без `authoredPlacement` сохраняют прежнее поведение; никакие
  существующие Roblox Asset ID, атласы, сохранённые размещения и данные
  пользователя не переписываются.
- Для мешей с отличающимся поворотом или зеркальной осью относительно `house`
  анализатор пока не записывает новый placement (нет безопасной универсальной
  оценки повёрнутых осей); эти меши остаются на старом механизме.

## Применение к level5

1. Установить M184 поверх M182 и M183, перезапустить Control Center / Host Agent.
2. Переустановить Game1Bridge: `& .\system\studio-plugin\install.ps1`, затем
   **полностью закрыть Roblox Studio** и открыть заново, иначе активный мост
   продолжит использовать старый модуль.
3. В Asset Manager у `house_level5_01` **повторно выбрать исходный полный FBX**,
   выполнить Inspect / Register как редактирование существующего дома. Это
   обновит `skeleton_json` с `authoredPlacement`. Название, идентификаторы и
   опубликованные Model Assets не меняются при совпадении исходного FBX.
4. Выполнить **Full Studio Sync**; отдельная публикация новых моделей для
   одной лишь коррекции смещений не требуется. Проверить положение двери,
   шарнир, открытие и сокеты, затем уже Workspace-копии. При первом применении
   не заменять важные вручную настроенные дома без резервной копии Place.
5. После Studio Sync в ответе Bridge доступно поле
   `realEstateStats.authoredPlacementsRestored`: количество частей с применённым
   контрактом. Если `0`, проверить обновление регистрации FBX и плагина.

## Ограничения проверки

Контракт и сопутствующие тесты запускаются без Blender/Roblox Studio.
Внешняя проверка `LoadAssetAsync`, `MeshPart.Size` и реального визуального
смещения в Studio обязательна: источник геометрических данных здесь — исходный
FBX, а не достоверный снимок опубликованных Roblox MeshParts. Если размеры
не совпадут, Studio Sync безопасно сообщит об этом вместо неверного сдвига.
