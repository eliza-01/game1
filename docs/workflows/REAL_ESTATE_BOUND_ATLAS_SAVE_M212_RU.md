# M212 · Register / Save: существующий Atlas Registry binding

## Причина

До M212 форма Real Estate считала привязку активной только при
`atlasCurrent == true`. Для зарегистрированного, но ещё не опубликованного
атласа UI отправлял `textures[part]` с путём в каталоге Registry вместо
`textureReferences[part] = "atlas:<id>"`. Повторное сохранение цены/физики
запускало `AtlasRegistry.adopt_file`, словно был выбран новый PNG; в
частности, могло возвращать HTTP 400 `texture must be a real PNG or JPEG file`.

## Контракт после M212

- Для **любого** уже связанного варианта (опубликованного, неопубликованного
  или ожидающего переиздания) UI сохраняет ID связи в `textureReferences`.
- Dropdown показывает закреплённый неопубликованный вариант явно, хотя другие
  неопубликованные атласы нельзя выбирать в качестве reusable-публикации.
- Сервер защищает старые вкладки: если пришёл *тот же* путь источника, который
  уже закреплён за текущим атласом части, он сохраняет binding без повторной
  регистрации/проверки файла. Это не републикация и не новый источник.
- **Действительно новый** путь остаётся новой заявкой на регистрацию: PNG/JPEG
  проверяется как настоящее изображение; ошибки содержат имя части (`house`,
  `door`, и т. д.). Неверный файл не сохраняет данные модели.
- Atlas Registry остаётся единственным владельцем Image Asset ID и исходника;
  публикации, миграции БД, физика и Studio Sync не изменяются.

## Проверить вручную

1. Открыть зарегистрированный дом с неопубликованным/ожидающим публикации
   атласом, изменить `Purchase Price` и нажать `Register / Save`.
2. Проверить, что вариант атласа и Image Asset ID (если есть) остались
   прежними, а цена обновилась.
3. Выбрать действительно новый битый PNG: сервер должен отклонить его,
   указав конкретную часть дома.
4. Проверить обычный Save опубликованного дома и новый дом с PNG.

Повторная публикация ассетов и SQL-миграция для M212 не нужны.
