# M377 · Единый авторский pivot домов

## Контракт

- Один исходный `house_armature` в FBX. Никаких обязательных имён визуальных мешей.
- `rig_carrier` создаётся **только во временном FBX публикации** через общий
  `blender_rig_carrier.create_rig_carrier`, используемый Characters/Location.
  В Blender-файл художника носитель не добавляется.
- Опубликованный технический носитель владеет статическими сокетами;
  ни `chimney`, ни другой визуальный MeshPart не назначается владельцем скелета.
  Название визуальной части в Model Asset идентифицирует только загрузочный пакет.
- При подготовке каждого временного FBX геометрия запекается относительно
  **исходной матрицы** `house_armature`: смещение, вращение и масштаб автора
  входят в вершины; pivot объекта становится исходным origin скелета.
  UV и материалы не привязываются к этому преобразованию.
- Studio отклоняет неполную публикацию без `rig_carrier`, принимает
  `carrier:GetPivot()` за корень `house_levelN_VV`, собирает все статические
  MeshPart в `StaticAssembly` и соединяет их общим SkinnedMeshConnection.
- Дверь и ручки с весами `door_01_hinge_socket` остаются в отдельном
  `DoorAssembly`, независимо от имён MeshPart.
- `Sync entire house` и точечное обновление опубликованного MeshPart
  используют **одну полную пересборку**. Смешение ригов разных ревизий не
  допускается. Старые отдельные Model Assets необходимо **перепубликовать**.
- `Model:PivotTo(PlotCFrame)` не изменяет Plot/Level/Variant/привязки.
  Удаление дома из каталога не удаляет Plot-позицию; повторная регистрация
  того же `house_levelN_VV` использует сохранённые координаты.
- Технический носитель всегда невидим, без коллизий и TextureID.
- Не используется `AlignOrigin`, перенос по BoundingBox или вычисление
  смещения от выбранного визуального меша. Несовпадение pivot приводит к
  явной ошибке, не к молчаливой коррекции.

## Проверка перед публикацией

1. Экспорт FBX из Blender с единственным `house_armature`.
2. Publish всех Model Assets (новая ревизия с техническим носителем).
3. `Sync entire house`: проверить `StaticAssembly/rig_carrier`, полный состав
   статических MeshPart, и расположение дверных сокетов.
4. `Place all`: проверить Plot Pivot и существующие 39 привязок `house_level5_01`.
5. Сравнить CFrame/поворот всех частей и открыть/закрыть дверь в Studio.

Статические тесты не заменяют FBX round-trip и живой Roblox Studio smoke test.
