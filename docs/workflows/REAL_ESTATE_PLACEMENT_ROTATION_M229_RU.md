# M229 · Real Estate Placement — author house pivot and rotation

## Причина

M208 сохранял CFrame **корневой выбранной Model** и её масштаб. M223/M227
ставили **другую**, собранную публикационным Sync корневую Model из
`ServerStorage/real_estate/<slug>/model/<slug>` по тому же CFrame. У этих двух
контейнеров может отличаться `Model:GetPivot()` относительно реальной геометрии
`MeshPart house`: одинаковое положение/поворот *Model pivot* не гарантирует
одинаковое положение/поворот видимого дома. Именно поэтому сохранённая матрица
в базе может быть правильной, а `Place` визуально повёрнут неправильно.

## Обновлённый контракт

- `Bind` по-прежнему только читает один выбранный `Workspace Model` нужного slug.
  Теперь он дополнительно требует **ровно один `MeshPart` с именем `house`**,
  используя `StudioRealEstateHouseFrame.Find` (общий авторский anchor Real Estate).
- Новая команда Studio Bridge `house-placement-capture-v2`, `schemaVersion=2`
  измеряет `model:GetPivot()` и `house:GetPivot()`, а также вычисляет
  `houseAnchorLocalCFrame = model:GetPivot():ToObjectSpace(house:GetPivot())`.
- Сервер проверяет математическую согласованность исходных двух CFrame,
  относительного CFrame к plot и сохранённого house-anchor. При ошибке
  предыдущий Binding не изменяется.
- Поле `house_anchor_local_cframe_json` добавляется **неразрушающей миграцией**
  в SQLite. Перед миграцией выполняется штатный backup API. Неизменённые старые
  Binding остаются на месте с `houseAnchorLocalCFrame=null`.
- `Place` и `Place all` используют существующую `StudioRealEstateHouseFrame.Align`
  для выравнивания опубликованного `house` MeshPart по *авторскому* pivot,
  восстановленному из текущего plot volume и сохранённых двух относительных
  кадров. Это та же операция точного выравнивания, которую уже использует
  Real Estate Studio Sync. Нет новой реализации замены геометрии.
- Preview-команда `house-placement-preview-v3` требует свежий Studio plugin.
  Старый плагин не может молча принять команду с устаревшим контрактом.
- `Clear`, Anchor/Free, метаданные размещения и Undo не менялись. Корневые
  шаблоны ServerStorage не модифицируются: работа ведётся с клоном.

## Что делать со старыми Bind

Невозможно достоверно восстановить **несохранённый** offset между оригинальной
Model и MeshPart house по одному `worldCFrame`. Поэтому старые записи **не
переписываются и не интерпретируются как новые**: UI показывает `Re-Bind for
rotation`, а `Place`/`Place all` отказываются до Re-Bind нужных пар дом–участок.
При отказе существующие объекты в Place не изменяются.

Сначала проверь на **копии Place** один дом/участок:
1. Убедись, что актуальный `Game1Bridge` установлен и Studio находится в Edit.
2. Выдели исходный авторский Model `house_levelN_01` на нужном участке.
3. Нажми Bind, затем Place в строке этого участка.
4. Проверь визуальную ориентацию, состояние Anchored и текущую позицию дома.
5. После подтверждения повтори Bind для прочих пар, где требуется Place.
   Для разных участков локальные авторские frames могут различаться.

## Проверки и границы

Проверены сериализация вращения, относительный CFrame, непротиворечивость
математики, миграция legacy SQLite, запрет Place без нового anchor, версии
Studio Bridge и использование общего `StudioRealEstateHouseFrame`. Проверку
настоящей геометрии Roblox Studio выполняют только в копии Place.

Этот хотфикс не выполняет массовые операции самостоятельно, не изменяет
игровой runtime, опубликованные модели или Atlas Registry.
