# M181 — Real Estate: восстановление связи Mesh ↔ Armature

## Ошибка после M180

Вложенные `house_armature` / `door_armature` из `house_level5_01.fbx`
теперь восстанавливаются раздельно, но Blender FBX Importer может не создать
для `door` Armature Modifier: исходный skin мог импортироваться как связь
родительства с ошибочно объединённым `house_armature` или вообще без ссылки
на объект-риг. M180 переназначал существующий модификатор, но не создавал
отсутствующий. При удалении ошибочного parent терялась последняя связь
`door → door_armature`. Inspect выводил два предупреждения:

- `door is present without a linked door_armature (optional)`
- `Armature door_armature is not linked to a mesh and will not be published`

## Контракт M181

- **Источник истины** — исходные FBX `Skin → Cluster → LimbNode` (и допустимые
  FBX object-parent связи), уже прочитанные `real_estate_fbx_hierarchy.py`.
- При нормализации вложенных скелетов для каждого меша с установленным
  исходным владельцем ищем максимум один Armature Modifier. Если он есть —
  переназначаем; если нет — создаём `Game1RecoveredFBXRig` с тем же владельцем.
- Если Blender прикрепил меш к неверному объединённому Armature, отключаем
  только эту неверную parent-связь, сохраняя мировую матрицу меша.
- Не выбираем риг по названию меша, не меняем исходный FBX и веса вершин.
  Наличие нескольких Armature Modifier остаётся ошибкой.
- Один и тот же восстановитель вызывается до Inspect и до подготовки Publish.
  Стандартный `prepare_rig`/`assert_skin_complete` продолжает проверять веса
  и кости перед экспортом.
- FBX без вложенных скелетов не изменяются. Существующие записи SQLite,
  опубликованные Model Asset ID, Roblox-скрипты и рецепты не затрагиваются.

## Ожидаемое поведение для level5

- `door` связан с `door_armature`, а не с `house_armature`.
- `door_01_hinge_socket` — корневая кость дверного скелета.
- Остальные меши дома продолжают использовать `house_armature`.
- Указанные два предупреждения отсутствуют, если Blender сохранил прочие
  авторские свойства. Подавления сообщений в UI нет.

## Применение и проверка

1. Накатить M181 **поверх M180**, перезапустить Host Agent / Control Center.
2. Повторно выбрать исходный `house_level5_01.fbx` и выполнить Inspect.
3. В отчёте проверить `door.armature = door_armature`,
   `house.armature = house_armature`, а также родителя
   `door_01_hinge_socket` (пустой).
4. Для проверки публикационного пайплайна публиковать только новую тестовую
   версию дома; сравнить положение двери и сокетов в Roblox Studio.
5. Проверить старый FBX без вложенных Armature и вариант дома без двери.

Локально проверены чистые Python-контракты и загрузка исходных FBX-связей.
Реальный Blender round-trip и Roblox-публикация в среде подготовки патча
не выполнялись — их результат нельзя считать подтверждённым заранее.
