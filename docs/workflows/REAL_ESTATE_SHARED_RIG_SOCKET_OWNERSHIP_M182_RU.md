# M182 · Real Estate: владелец сокетов при общем `house_armature`

## Причина

Blender допускает несколько мешей с одним `house_armature`. Ранее Asset Manager
публиковал независимый Model Asset **для каждого меша**, принудительно копируя
в него **все** кости общего скелета — даже если у меша не было ни одного
исходного влияния костей. Roblox может отбросить отдельные дублированные
кости при конвертации. В Studio Sync получался отказ вида
`structures_01: published Model Asset lost authored Bones: land_spawn_01_socket`.

## Контракт владельца

- `house` — основной владелец всех костей `house_armature`, включая
  `land_spawn_01_socket`, `house_floor_*_spawn_*_socket` и интерактивные сокеты.
  Любая потеря этих костей в опубликованном `house` по-прежнему блокирует Sync.
- Меши с собственным Armature (включая `door`) сохраняют и проверяют все его
  кости. У двери шарнир и дочерние сокеты по-прежнему обязательны, если заданы.
- Меши с **реальными весами** к костям общего `house_armature` сохраняют все
  кости для независимой публикации: их скиннинг нельзя незаметно удалять.
- Меши **без реальных исходных весов**, лишь разделяющие `house_armature`,
  считаются статическими. В их публикационной FBX-сцене снимаются ссылки на
  риг с сохранением мировой матрицы; независимый Asset содержит только меш.
  Полный авторский реестр FBX/SQLite не редактируется.

Все определения исходят из общих именованных полей `name`, `armature`,
`influencedBones` и вычисляются одним чистым контрактом
`real_estate.rig_publication_policy.publish_bones_for_mesh`. Этот контракт
используется и при подготовке FBX, и в post-export проверке, и для
построения Studio Sync `expectedMeshes`.

## Миграция и уже опубликованные ассеты

- Нет изменений SQLite, сохранённых Model Asset ID, изображений или
  оригинальных FBX. Прежде опубликованные ассеты не переписываются.
- После установки M182 необходимо **принудительно переопубликовать Model
  Asset** ранее опубликованных статических мешей с общим `house_armature`
  (`col_mesh`, `restoration`, `structures_01`, `window_frames_glass`
  в `house_level5_01`), даже при неизменном исходнике. Для `house` и `door`
  такая переопубликация не требуется, если их Roblox Model Assets корректны.
- Если такой старый Asset содержит дубли костей, Studio Sync сообщает
  `static mesh Model Asset contains redundant Bones; republish...`, вместо
  принятия повреждённой копии. Все настоящие требуемые кости проверяются
  по-прежнему; ложная замена Bone на Attachment не выполняется.
- Публикация заменяет ID только после успешного завершения соответствующего
  шага. Переопубликовывать нужно **Model**, не атлас.

## Фактическая проверка в Studio

1. Переопубликовать каждый затронутый статический Model Asset отдельно.
2. Выполнить полный Studio Sync. У `house` должны сохраниться семь сокетов,
   у `door` — иерархия шарнира; у остальных перечисленных частей нет
   дублированных `house_armature` Bone.
3. Сверить визуальное положение всех мешей, геометрию коллизии, спавны,
   лифт и взаимодействия на уже расставленных домах.

Статический Python-verify не заменяет Roblox загрузку и фактическую
проверку трансформаций в Studio. Не изменять `.blend` ради обхода ошибки.
