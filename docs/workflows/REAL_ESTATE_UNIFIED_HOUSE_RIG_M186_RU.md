# M186 · Общий скелет дома и двери

Решение от 2026-11-02: в Blender дом и дверь используют один объект
`house_armature`. Отдельный объект `door_armature` для новых домов не нужен.
Это замена контракта авторинга; причины прежнего смещения в Roblox здесь
не исследовались, алгоритмы размещения M184/M185 не менялись.

## Авторинг

Коллекция `house` содержит `house_armature` и отдельные меши `house`, `door`,
`col_mesh` и остальные архитектурные части. Меш `door` остаётся отдельным.
Его Armature modifier и родитель указывают на `house_armature`.

В общем скелете `door_01_hinge_socket` является корневой костью. Сокеты
`door_01_handle_inside_socket`, `door_01_handle_outside_socket`,
`door_01_padlock_01_socket` остаются дочерними шарниру. Перенос существующей
цепочки сохраняет мировые rest/pose-матрицы, веса, мировые матрицы объектов,
вершины, UV и материалы. Сокеты дома не должны быть дочерними шарниру;
меш `house` не должен иметь влияний дверной цепочки.

У level1 двери не было: дверная геометрия и фиктивные кости не добавлялись.
В level2 перенесены 4 кости, всего стало 10; в level3–5 — по 4, всего по 11.
Исходные тестовые объекты вне коллекции `house` не входят в экспорт.

## Импорт и публикация

Единый скелет авторинга не означает единый Roblox Model Asset. Существующая
регистрация отдельных MeshPart и независимая публикация частей сохраняются.
`rig_publication_policy.py` задаёт единственный источник правил:

- `house` получает сокеты дома, исключая дверную цепочку.
- `door` получает шарнир, всех его потомков и зависимости фактических весов.
- Невзвешенные статические части получают пустой набор костей.
- Другие взвешенные части получают влияющие кости и их предков.
- Старые отдельные риги поддерживаются по прежнему контракту.

Для каждого меша `real_estate_staging_rig.py` создаёт временную копию скелета,
удаляет из копии не принадлежащие части кости, сохраняет rest-пространство и
иерархию. Общий исходный скелет не обрезается и не пополняется весами другой
части. Подготовка весов и экспорт выполняются внутри этого контекста.

Проверка опубликованного FBX и метаданные Studio Sync используют ту же
политику. HTTP-ответы Inspect и каталога дополняются вычисляемым
`publicationBones`; UI показывает именно эти кости. Полное поле `bones`
продолжает описывать исходный FBX. Вычисляемое поле не требует миграции БД
и заново формируется при чтении, включая старые записи.

## Подготовленные файлы и проверка

Проекты `house_level2_01_monolith.blend` … `house_level5_01_monolith.blend`
сохранены после переноса. Рядом с каждым домом подготовлен
`house_levelN_01.fbx` для levels 1–5. Бэкапы дискового и открытого состояния
находятся в `backups/before_shared_rig_<UTC>/`; прежние FBX — в
`backups/before_shared_fbx_<UTC>/`.

На фактических пяти домах выполнен цикл: экспорт → Inspect → подготовка
всех независимых частей → повторный импорт каждой части → проверка состава,
родителей, rest-матриц и геометрических границ. Наибольшее расхождение
границ меньше 0.00001 Blender units. На level2–5 проверен поворот шарнира
на 80° в отдельном процессе: дверь движется, геометрия дома неподвижна,
после возврата позы геометрия восстанавливается.

Геометрические замечания предыдущей инспекции не исправлялись: этот перенос
не является полной очисткой домов. В частности, 156 вершин ответной скобы
двери оставлены без весов в исходниках, как было задумано. Существующий
публикатор заполняет отсутствующие веса; объединение скелетов само по себе
не меняет эту политику и не решает неподвижность скобы после публикации.

## Ввод новой ревизии

В работающем Asset Manager проверен Inspect нового level5 FBX: 11 исходных
костей, публикация house=7, door=4, остальные части=0; предупреждений нет.
Host Agent и интерфейс обновлены. Зарегистрированные исходники, ID,
публикации Roblox и содержимое Studio не заменялись.

Для перехода существующей записи нужно выбрать новый FBX соответствующего
дома, подтвердить обновление существующей записи и перепубликовать модели
частей по обычному подтверждаемому процессу. Затем выполнить Studio Sync
и проверить положение, открытие двери и неподвижную ответную скобу.
Результат физики/позиционирования в Roblox пока не подтверждён.

## Восстановление

Перед открытием резервной копии сохранить текущие дополнительные изменения.
`*_live.blend` содержит состояние открытого проекта до переноса, включая
несохранённые изменения; `*_disk.blend` — прежний файл на диске. Откат кода
выполнять обратным применением поставленного M186 патча после проверки
контекста. БД и опубликованные ID этой операцией не мигрировались.
