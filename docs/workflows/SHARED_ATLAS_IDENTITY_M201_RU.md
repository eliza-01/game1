# M201 · Независимые имена атласов в Asset Manager

## Контракт

Имя атласа — свойство его источника, **не** первой модели, которая его
зарегистрировала. Нормализованное имя извлекается из исходного имени файла:

- `structures_01_2048x1024_atlas.png` → ключ `structures_01`, название `structures`, вариант `01`, разрешение `2048×1024`.
- `restoration_01_2048x2048_atlas.png` → `restoration_01`.
- `wall_torch_01.jpg` (старый файл без маркера разрешения) → `wall_torch_01`, разрешение неизвестно.
- `wooden_post_kit.png` → `wooden_post_kit`, без числового варианта.

Суффикс варианта — последний `_NN` (минимум две цифры). Числовое значение и
границы семейства не выводятся из имени дома, декоративного объекта или слота.

## Область изменения

Общий `static/atlas-identity.js` используется в **Real Estate**, **Location Assets**,
**Characters** (отображение групп атласов) и окне **Delete / shared assets**.
В выпадающих списках Real Estate группировка выполняется по имени атласа, а не по
разделу/категории модели, которая его впервые опубликовала. Несколько совместимых
legacy-ссылок на один `Image Asset ID` отображаются одним вариантом; выбранная
запись всегда сохраняет своё точное reference-значение.

В модалке удаления группы построены по опубликованному **Image Asset ID** (если
он известен), а ниже отдельно перечислены потребители: какие модели и их части
используют изображение. Теперь два старых «владельца», ссылающиеся на один ID,
не создают ложное впечатление двух атласов.

В Location Assets опции и таблица показывают имя текстуры, не slug исходного
модельного ассета. Все прежние опции публикации и reuse доступны.

## Совместимость и границы

На уровне API `RealEstateStore.texture_references()` публикует те же независимые
метаданные (`atlasKey`, `atlasName`, `atlasVersion`, `atlasResolution`).
Исторические `reference` и `assetId` не меняются.

**Никакой миграции SQLite, переименования файлов, пересоздания Image Asset ID,
публикации или перепривязки моделей нет.** Старые ссылки `estate:...`,
`location:...`, `mesh:house` и `atlas:<id>` остаются авторитетными техническими
идентификаторами. Они могут встречаться в исходных записях и диагностике, но
не должны изображаться как имя самого атласа.

Если исходное имя PNG содержало имя дома (например,
`house_level5_01_4096x4096_atlas.png`), показывается именно это имя:
автоматически угадывать «истинный» смысл чужого файла нельзя. Отделение такого
атласа под новым ключом потребует явного authoring-действия в будущем — M201
не меняет идентичность опубликованной публикации молча.

Проверка: `python -m unittest system.verify.test_atlas_independent_identity_m201`
и `node system/verify/atlas_independent_identity_m201.js`.
