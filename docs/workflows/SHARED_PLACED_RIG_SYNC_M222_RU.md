# M222 · Единая Studio-синхронизация управляемых ригов

**Статус: CURRENT / STUDIO SMOKE REQUIRED.** Предыдущий M221 (применение `MeshPart:ApplyMesh`) отменён. M215 (пересоздание корневых Model) по-прежнему запрещён. M216 остаётся источником требований к строгому scope, истории и сохранению корневых размещённых объектов.

## Причина

- `Sync entire house` в Real Estate подготавливает опубликованный риг, совмещает его **авторский MeshPart pivot** с существующим и подменяет дочерний управляемый визуальный риг. `Bone`, skinned meshes и вложенная иерархия перемещаются целиком.
- M221 для Location Assets независимо реализовал `ApplyMesh`; он запрещал любой Bone/WrapTarget и выдавал ошибку `skinned/wrapped meshes require manual geometry migration`. При этом Real Estate не использует этот алгоритм.
- Теперь **механизм замены един**: `StudioManagedRigSwap` (подготовка, transactional commit, rollback, finalize, выравнивание авторского якоря). Все упоминания `StudioMeshInPlaceSync` удалены из рабочего Studio-плагина.

## Ответственность модулей

| Модуль | Задача |
|---|---|
| `StudioManagedRigSwap.luau` | Доменно-независимая транзакция замены управляемых **дочерних** ригов, сохранение размещённого root, откат, авторский pivot |
| `StudioRealEstatePlacedVisualSync.luau` | Выбор размещённых домов и их именованных ригов; подготовка источников; вызов общей транзакции |
| `StudioRealEstateHouseFrame.luau` | Выбор `house` MeshPart; делегирование совмещения pivot общему модулю |
| `DecoPlacedAssetSync.luau` | Выбор только указанного Location slug и экземпляров по `Game1DecoInstanceId`; определение источника и якоря; сбор истории Model/Atlas ID; вызов общей транзакции |
| `DecoAssetLoader.luau` | Получение опубликованной Model из Roblox, очистка служебных объектов и применение опубликованного атласа |
| `StudioTextureAppearance.luau` | Единая операция назначения TextureID / SurfaceAppearance; отдельное обновление атласа без FBX |
| `studio_deco_bridge.py` / `StudioDecoSyncCommands.luau` | Строго scoped Studio Bridge **schemaVersion 5**. Старый плагин M221 (v4) отклоняет команду |

**Нет** отдельного алгоритма для декораций. Разделяются только правила идентификации, состав рига, идентификаторы публикаций и доменный отчёт.

## Алгоритм Location Assets

1. Команда должна явно содержать выбранный `slug`, модельный ID, Image ID, binding revision. Несовпадение реестра прерывает операцию. Сканируются только управляемые модели с этим slug и непустым `Game1DecoInstanceId`.
2. Для экземпляров с другим `Game1DecoPublishedModelSha256` один раз загружается текущий опубликованный FBX; на каждый экземпляр подготавливается **отдельная временная копия** полной иерархии (включая `Bone` / Wrap).
3. Копия приводится к масштабу старого экземпляра. Опорой служит единственный MeshPart либо однозначно совпадающее имя MeshPart; применяется то же правило выравнивания *авторского pivot*, что и для дома. Неоднозначность приводит к отказу ДО изменения Place.
4. Общий `StudioManagedRigSwap.Prepare` проверяет, что подменяются только прямые дочерние геометрические риги корневой Model; неприкосновенные соседние объекты с конфликтующими именами вызывают отказ. Все экземпляры проходят preflight до первого commit.
5. Commit подставляет содержимое под **тот же корневой Model**. Корневая Model, `Game1DecoInstanceId`, имя, parent, pivot и scale сохраняются. У старых дочерних ригов временные имена, они ещё доступны для отката. После успешного commit всех экземпляров и записи истории `Finalize` удаляет старые дочерние риги. `MeshPart:ApplyMesh` не вызывается.
6. Только после реального commit новой геометрии обновляются `Game1DecoPublishedModelAssetId`, `Game1DecoPublishedModelSha256` и ссылка в реестре. Запись `kind=model` фиксирует старый и новый Roblox Model Asset ID; `kind=atlas` — Image ID, `kind=model_reference` — только изменение ссылки. Журнал M217/MySQL и атрибут `Game1DecoSyncHistory` сохраняются.
7. Если FBX актуален, но атлас сменился, выполняется только общий `StudioTextureAppearance` в режиме обновления ID, без замены ригов.

## Ограничения и отказоустойчивость

- Не перетаскивать и не пересоздавать **корневую размещённую Model** — M215 никогда не возвращается. Подменяются только управляемые дочерние визуальные риги по шаблону Real Estate.
- Дочерние модели, содержащие MeshPart/BasePart, рассматриваются как управляемые частью опубликованного Location Asset. Пользовательские модификации *внутри них* не сохраняются, как и при `Sync entire house`. Внешние прямые дочерние объекты без BasePart сохраняются. Не хранить уникальные пользовательские данные внутри публикуемых ригов.
- Если изменилось имя/структура якоря, нельзя однозначно сохранить `PrimaryPart`, есть конфликт имён с неуправляемыми детьми или невозможна запись истории — отказ до/с попыткой отката, а не эвристическое смещение.
- Транзакция гарантирует **попытку rollback**, но сбой движка Studio, внешние связи на уничтоженные дочерние MeshPart, неоткатное действие стороннего плагина или изменение внутренних координат вершин FBX не исключаются статическими тестами.
- Для skinned meshes копируется целый опубликованный риг с Bones, а не поэлементно редактируется MeshPart. Скрипты и чужие временные данные чистятся `DecoAssetLoader` по его текущему контракту.
- Не выполняется глобальный Sync и не трогаются другие slug, даже если они используют тот же Image ID. Публикация в Atlas Registry не вызывает скрытый Sync.

## Проверка на копии Place

1. Сохранить отдельную `.rbxl/.rbxlx` копию, сделать снимок `GetPivot`, `GetScale`, `Game1DecoInstanceId`, `MeshId`, дерева `Bone`, Atlas ID двух размещённых экземпляров `campfirte_01` и одного постороннего Location Asset.
2. Установить M222 и переустановить Studio-плагин. Перезапустить Host Agent, полностью переоткрыть Studio **в Edit Mode**.
3. Нажать Sync Studio именно в строке `campfirte_01`. Ожидается `matchedModels=2`, `geometryUpdated=2`, `pendingGeometry=0`, появление новых опубликованных ригов/мешей и сохранение старых root Model/положений. Оба экземпляра сохраняют свои индивидуальные трансформации. Посторонний slug не меняется.
4. Повторный Sync должен быть idempotent: `geometryUpdated=0`, `parts=0` при актуальной публикации. Atlas-only Sync не меняет дочерние риги.
5. Проверить `Database → Asset History`, откат Studio Undo и отказ на несовместимом авторском якоре. Не проверять первый раз на основном Place.

## Откат

На тестовой копии Studio использовать Undo либо открыть исходную копию Place. Откат исходников Git (`git apply -R` для M222) возвращает M221, но **не откатывает изменения уже сохранённого Place**. M221 использовать повторно не рекомендуется. История замен ID не стирается при откате кода.
