# M283 · Studio Timeline: подтверждённые ключи опубликованного клипа

## Граница ответственности

`StudioTimelinePreview` загружает опубликованный Animation Asset через
`AnimationClipProvider:GetAnimationClipAsync`. Длительность из документа
Animation Registry / Attack Timeline не служит доказательством, что Roblox
вернул воспроизводимую последовательность ключей.

## Алгоритм

1. Проверить идентификаторы сессии и опубликованных Model/Animation assets.
2. Не больше пяти раз прочитать AnimationClip; после временно пустого ответа
   повторить запрос, сохраняя диагностику количества Keyframes, Poses,
   последнего ключа и `AnimationClip.Length`.
3. Принять только KeyframeSequence с Pose-каналами и ключами позже 0 секунд.
4. Если Roblox вернул CurveAnimation, сообщить об отдельном неподдерживаемом
   формате. Не выдавать его за пустую KeyframeSequence.
5. Лишь после успешной проверки клипа загрузить изолированную модель рига
   во ViewportFrame и проверить соответствие Bones/Motor6D.
6. При любой ошибке закрыть рабочую сессию, удалить временный предпросмотр
   и передать полную ошибку в Asset Manager через прежний Bridge-протокол.

Плагин не создаёт искусственные Keyframes, не берёт длительность из JSON вместо
клипа и не сохраняет HitStart/HitEnd без явного подтверждения пользователя.
Live gameplay, Character Animation Registry и Attack Timeline Store не меняются.

## Проверка в Studio (Edit Mode)

- С открытым Asset Manager перейти в `Timelines` → `hands_attack_01` → Open in Studio.
- При временном пустом ответе Roblox редактор должен повторить запрос и показать
  движущуюся модель, если опубликованный клип содержит ключи и соответствует ригу.
- При постоянно пустом клипе ошибка должна содержать Animation Asset ID и
  `keyframes`, `poses`, `last keyframe`, `loaded length`.
- Для CurveAnimation ошибка должна содержать его настоящий класс.
- После неудачного запуска кнопка подтверждения не должна отправлять событие.
- После успешного запуска вручную выставить HitStart и HitEnd и сохранить timeline.

Диагностический архив проекта не содержит исходного `hands_attack_01.rbxm`,
поэтому реальное содержимое облачного Animation Asset не проверено офлайн.
