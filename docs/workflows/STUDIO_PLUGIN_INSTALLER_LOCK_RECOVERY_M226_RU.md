# M226 — Studio plugin: безопасная установка при заблокированном `.rbxmx`

## Инцидент

После успешного `git apply M225` Rojo собрал `Game1Bridge-build-<PID>.rbxmx`,
но Windows отказалась перезаписать `generated/Game1Bridge.rbxmx` с ошибкой
«файл с открытой пользователем сопоставленной секцией». Это блокировка
сгенерированного бинарного пакета, **не ошибка Git-патча и не откат кода**.
При сбое до установки плагина в `%LOCALAPPDATA%/Roblox/Plugins/Game1Bridge.rbxmx`
может оставаться прежняя версия. M225 требует новый протокол Preview v2.

## Исправление установщика

- Сначала проверяется успешность Rojo build и содержимое собранного пакета.
- Файл с уже правильным SHA-256 не перезаписывается.
- При временной блокировке копирование повторяется ограниченное число раз.
- После каждого копирования сверяется SHA-256; общая проверка сверяет обе
  копии с исходной Rojo-сборкой.
- При постоянной блокировке установка **останавливается с ошибкой**, не
  удаляя старый плагин и не сообщая ложный успех. Принудительного обхода
  блокировки Windows нет.

## Восстановление после частичной установки M225

1. **Не применять M225 снова.** Закрыть все Roblox Studio окна; дождаться
   завершения параллельного Rojo/build/watch процесса, если он используется.
   Не требуется откатывать или публиковать Place.
2. При необходимости применить M226 поверх M225.
3. Запустить только `& .\system\studio-plugin\install.ps1` из корня game1.
4. Выполнить `python .\system\studio-plugin\audit.py` (read-only).
   `Generated / installed SHA256` и `Installed module inventory` должны быть OK.
5. Полностью открыть Studio заново. Проверить новый Preview на **копии Place**.

Если файл всё ещё заблокирован, закрыть приложение или процесс, удерживающий
`generated/Game1Bridge.rbxmx`. Повторять `git apply` не нужно. Не удалять
и не переименовывать установленный плагин при запущенной Studio.

## Границы

M226 не меняет Placement, Atlas Registry, Studio Bridge API, модели,
публикации, сохранённые Bindings и данные Place. Изменён только процесс
установки Game1Bridge и тестовый контракт. Запуск Windows PowerShell и реальная
разблокировка Windows-файла требуют проверки в Windows; Python-тесты не
могут имитировать kernel-level memory mapping.
