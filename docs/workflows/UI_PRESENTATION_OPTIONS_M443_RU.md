# M443 · UI presentation · Options и Studio Play

Одна конфигурация интерфейса хранится в `assets/manifests/options.json` → `uiPresentation.desktop` / `uiPresentation.mobile`. `OptionsStore` проверяет допустимые значения и генерирует `src/shared/GameOptionsRegistry.luau`. Исходный runtime-контракт чтения — `GameOptions.UiPresentationSettings(device)`; резервные значения для старого реестра определены в `UiPresentationContract.luau`. Два профиля редактируются и сохраняются независимо. `mobile` применяется на устройствах с Touch без клавиатуры, `desktop` — на ПК, включая гибридное управление.

Раздел **Control Center → Options → UI** состоит из четырёх независимых блоков. **Interaction** задаёт `offsetXPx`, `offsetYPx`, ширину кнопок и размер шрифта. **Status** отвечает за нижнее окно огня/готовки, заголовок, строки и таймер. **Notification** задаёт смещения, шрифт и задержку исчезновения уведомлений о взаимодействиях/переходах. **Resource** задаёт смещения, шрифт, расстояние всплытия и длительность затухания `−N` с иконкой ресурса. Позиции — относительные смещения в пикселях от текущих экранных якорей; оригинальные места сохраняются при нулевом смещении.

В Studio Play доступна кнопка **UI** в общей панели отладки (`StudioDebugDock`). Она открывает редактор с устройством PC/MOBILE, четырьмя вкладками и корректируемыми числовыми значениями. Результат немедленно отображается на реальных игровых окнах через клиентский `UiPresentationSettings.Preview`, плюс показывается демонстрационная панель, когда нужной механики поблизости нет. Изменение не затрагивает серверные игровые состояния и не сохраняет данные в Roblox.

Черновик проходит путь `UiPresentationDebugController` → `UiPresentationDebugService` (Studio-only, права, проверка полей, rate limit) → `Game1UiPresentationDebug.Payload` → существующий Studio plugin `StudioOptionsDraftBridge` с локальным контрольным токеном → `POST /api/options/ui-presentation-draft`. Он появляется в Control Center, но **не сохраняется**. Только кнопки **Import Studio UI Debug**, а затем **Save UI profile** меняют файл проекта. После синхронизации Rojo и нового Play runtime начинает использовать сохранённые значения. **Stop preview** или закрытие UI Debug возвращает активный локальный клиент к сохранённому профилю.

Графические пресеты `Fire` и `PointLight` костра (M443): **без котла** применяется референс костра, **с котлом** — пресет камина для обоих эффектов; при снятии котла происходит обратный переход. Обе ветки используют те же `Fire` и `PointLight`, меняются только параметры. `fuelEndsAt` и `fuelRevision` при переключении не изменяются; если пламя уже погасло, смена котла не зажигает его повторно.

Проверка в Studio Play обязательна: отдельно desktop и mobile, сворачивание/восстановление HUD шевронами и кнопкой «Инфо» без выхода из зоны, ПКМ при появлении окон и при открытом UI Debug, предметные уведомления, импорт черновика в Control Center, повторный Play после Save, визуальные переключения костра до и после котла.

## M444 · Уведомления о ресурсах и content padding

Уведомления о **получении и расходе** теперь обслуживаются одним `FloatingResourceFeedback.Show(items)`: сервер посылает `kind="resource"`, `amount > 0` означает `+N`, `amount < 0` — `−N`. После взятия блюда сервер отправляет `🍲 +1 Блюдо`; текстовый тост для этого события удалён. Сообщение «Блюдо готово» остаётся обычной нотификацией, так как получение блюда ещё не произошло. Инвентарь не подключён: это подтверждённое событие игровой stub-механики, не изменение базы ресурсов.

Уведомления ресурсов отрисовываются клиентским `BillboardGui` над HEAD персонажа: `head` Bone у авторского скиннинг-рига, обычный `Head` у Humanoid и запасной `RootCollider`/`HumanoidRootPart` если голова не найдена. Окно следует за персонажем, смещается вверх на `resource.risePx`, затем исчезает за `resource.durationSeconds`. Не создаются Parts и не блокируется ПКМ. Обычные подсказки о действиях/переходах остаются в нижней части экрана, но теперь их прямоугольник зависит от реального текста.

**Options → UI → PC/Mobile**: для групп `notification` и `resource` доступно `paddingPx` (**5 px** по умолчанию, диапазон **0–24 px**). Размер рамки вычисляется из текста соответствующим шрифтом + `2 × paddingPx`; ширина не фиксируется значением 280 или 240 px. Эти поля включены в `UiPresentationContract`, `OptionsStore` и Studio UI Debug (включая реальную привязку Resource-превью над головой). Миграция расширяет прежние профили без потери пользовательских смещений и длительностей; изменения в Play остаются черновиками до Import + Save.

## M445 · Сворачиваемый статус камина и костра

Нижняя статус-панель огня и готовки сохраняет общие `status.offsetXPx` / `offsetYPx` и шрифты из Options → UI. В M445 использовались ✓ и 🔥; это историческое поведение **заменено M446** на общий `InformativeWindowDock` со шевронами и нейтральной кнопкой «Инфо».

Клиент выбирает ближайший активный источник **без исключения свёрнутых сокетов**. Если появится более близкий камин/костёр, его статус выбирается по тому же правилу; состояние свёрнутости хранится отдельно для каждого сокета. После удаления сокета или выхода из радиуса состояние забывается, обе панели скрываются; при возвращении окно отображается в обычном виде. Элементы только клиентские, серверная логика топлива/готовки и события выдачи ресурсов не меняются. Положение компактной кнопки пересчитывается при изменении safe-area viewport и при Studio UI Preview.

## M446 · Общий контейнер информативных окон и изоляция запуска

`src/client/world/InformativeWindowDock.luau` — единственный владелец нижнего информативного окна, его шеврона вниз и нейтральной кнопки восстановления «Инфо» со шевроном вверх. Он принимает от отдельных presenter-модулей содержимое через `Pane(provider)`, отображает источник через `Present(provider, source, title, available)` и очищает свёрнутость через `Forget(source)`. Этот контракт предназначен для всех последующих информационных механик, а не только костра.

`HouseFireplaceController` теперь исключительно выбирает ближайший подтверждённый сервером источник и заполняет строки топлива/готовки. Даже пустой зарегистрированный камин показывает статус «Не горит». Состояние свёрнутости не изменяет серверную механику. Размер и положение берутся из Options → UI, кнопка восстановления располагается слева от зоны атаки по общей `MobileLayout.Resolve`: поле `gap` теперь **экспортируется на верхнем уровне** структуры (M445 его вычислял локально, но не возвращал). Раньше попытка сложить `nil` с числом на строке 179 останавливала `Game1Client` до запуска Studio debug-контроллеров.

Запуск необязательного информационного UI теперь защищён `pcall` в `init.client.luau` с предупреждением в Studio Output. Если он снова аварийно завершится, остальные визуальные сервисы и отладочные инструменты продолжают запуск. Это аварийная изоляция, а не подавление диагностики.


## Границы сохранения / Runtime · M447

Файл Options и генерируемый `GameOptionsRegistry.luau` сохраняют **авторские проектные профили** PC/Mobile. Они попадают в опубликованную игру только после синхронизации и новой публикации Place. Это не персональные настройки конкретного Roblox UserId: текущая игра не содержит подтверждённой DataStore-записи UI preferences.

`Studio UI Debug` является локальным незаписанным Preview до Import + Save; свёрнутость общего `InformativeWindowDock` живёт только на клиенте, сбрасывается при выходе из зоны/новой сессии. `FloatingResourceFeedback +N/−N` не подтверждает изменение persistent inventory. Перед приёмкой проверить ПКМ, касания, safe area, респавн головы и два клиента в опубликованном Runtime Place; см. [M447 audit](MECHANICS_RUNTIME_GAPS_M447_RU.md).
