# M309 — Weapons / Animations: resource editor and explicit replacement confirmation

## Источник проблемы

В M308 в Weapons добавили Atlas Registry, но оставили основную форму регистрации и таблицу как основной UI. В Location Assets применяется иной рабочий сценарий — компактная библиотека и модальное окно Manage с раздельными шагами Identity, Model · FBX, Texture · atlas. Старые опубликованные текстуры оружия не обязательно имели привязку к централизованному реестру.

Также существующая Animation Replace проверяла новую версию через Roblox Open Cloud. Если замену в Studio пользователь уже выполнил, но версия не обнаружена, запись оставалась CHANGED. Локальные реестры анимаций экспортируются в Luau, однако экспорт сам по себе не равен доставке файлов в Roblox Studio.

## Weapons — проверка по шагам

1. Weapons → Registered weapons: компактные строки, градации атласов обозначаются цветными точками. Для старого Image ID показывается **legacy-точка**, даже без привязки к общему реестру. Клик по точке открывает Texture · atlas без неявного сохранения.
2. Manage → Identity: имя, тип оружия, редкость, статы, дальность. Изменение типа **не публикует FBX** и не затрагивает Image ID. После изменения Registry требуется синхронизация Rojo.
3. Manage → Model · FBX: новый исходник регистрируется как отдельная ревизия; Publish Model вызывается только по явному нажатию и при изменении SHA256; Sync Studio отдельно.
4. Manage → Texture · atlas: общий компонент `game1ConsumerAtlasEditor`, включая Connect existing atlas, переключение разрешений, Upload new atlas, предварительный просмотр старого и нового изображения, подтверждение публикации и сохранение истории. Никакая публикация или Studio Sync не запускается автоматически.
5. Legacy: ожидаемое имя `<atlas_key>_<width>x<height>_atlas.png`; Image ID не переименовывается и не заменяется без явного действия. Индексация старых Image ID выполняется через уже существующий `index-existing-weapons`, с проверкой SHA256.
6. Arrow assets используют тот же редактор, а в строках библиотеки получают превью градаций.

Новая оболочка Manage использует `game1AssetWorkflowDialog`, а содержание Texture — `game1ConsumerAtlasEditor`. Публикации используют прежние API и центральный Atlas Registry.

## Animations — Replace и Studio

1. Загрузите или выберите новую версию анимации и `Stage replacement`. Поле статус должно стать `CHANGED`; постоянный Roblox Asset ID не изменяется.
2. Если Open Cloud обнаружит новую Approved-версию, используйте обычное `Проверить Roblox`.
3. Если реимпорт в Studio уже выполнен, а проверка Roblox не смогла его обнаружить, откройте `Подтвердить вручную`: введите постоянный Asset ID, отметьте явное подтверждение и примите диалог. Запись будет иметь состояние `USER_ATTESTED_NOT_CLOUD_VERIFIED`. Это *не* проверка Roblox и не новая публикация. История публикаций пополняется отдельным событием, предыдущий Asset ID сохраняется.
4. `Prepare Studio Sync` экспортирует `src/shared/character/CharacterAnimationRegistry.luau`, но НЕ вызывает синхронизацию Roblox Studio. После подготовки запустите/проверьте существующий Rojo Sync и **перезапустите Play**, поскольку `require` может кешировать загруженный ModuleScript.
5. Убедитесь, что тип экипированного оружия совпадает с нужным animation set, иначе опубликованные bow-клипы не будут выбираться в игре.

## Не проверено в автоматическом окружении

- Действительная отправка Image/Model в Roblox Open Cloud и заменa Studio-экземпляров.
- Реальное воспроизведение анимаций в Play (Roblox Studio не доступен в среде тестирования).
- Подтверждение пользователем уже заменённой в Studio версии не может подтвердить Roblox moderation state.

Проверено локально: регистрация и экспорт реестра, сохранение отдельной history-записи `user-attested`, JS синтаксис, открытие Manage и atlas-кнопок в headless Chromium с заглушенными API, общая регрессия Atlas UI, проверка применимости Git patch.
